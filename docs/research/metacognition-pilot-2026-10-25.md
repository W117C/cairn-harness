# Cairn 元认知：有界 pilot 与交付结论

日期：2026-10-25（Asia/Shanghai）。本轮实现与实测报告；初始论文、GitHub 和官方协议研究见[研究设计](../superpowers/specs/2026-10-25-metacognition-study-design.md)。

## 决定

**保留现有执行闭环作为默认，修复协议与评测基础，暂不默认启用新增元认知提示或提高思考档位。** 本次没有新增策略在同题配对中净胜基线。这个结果不足以证明策略等价、普遍无效或存在全局最优解。

用户授权的是先跑有界 pilot。本轮完成了协议核验、真实缺陷基线、五组对照、独立审查、修复与实际仓库集成；未进行权限、验收标准、进化内核的自修改或默认策略上线。

真实信号与解释边界：

- 失败触发组只在 C4、C6 两题实际触发，均未完成。其余四题没有新增提示，因此其中的成绩或速度差异不能归因于提示。
- 定期、随机组各在 C6 胜过基线、在 C5 输给基线，净胜为零。不能把它说成稳定增益或已经证明等价。
- 六题中，C1 的有效运行、C2、C3 都接近通过上限，C4 全组失败；区分主要来自 C5、C6，评价能力仍弱。
- 三趟出现可见验证通过、隐藏验收失败，分别位于失败触发、定期、随机组，均按失败计入。未另行人工标注模型自然语言的“虚假完成”率。
- 失败轨迹包括零改动、隐藏回归、不完整工具参数导致 JSON 解析失败。若干既有判卷文字写“改动越出 src/”，实际 `changedFiles=[]`，应理解为没有有效源码修改，不能据此认定越权。

## 实验怎样运行

- 模型为 `cn:deepseek-v4.1-flash`，经用户指定的本地 OpenAI 兼容端点。请求了 low/high 和显式 thinking，但代理是否精确执行内部 effort 预算仍不可核验。
- 基线复用现有 runLoop、createSessionProvider、BASE_SYSTEM、验证反馈和停滞提示；它本来已有规划与反馈能力。本研究比较的是追加策略的增量。按既有 loop-eval 装配，autoMemory、impactAnalysis、promptCache 在所有组同样关闭。
- 题内组序用固定 seed 随机；题序固定，每题每组一次。seed 控制调度与随机提示，不保证模型生成可重现。
- 请求 `max_tokens=4096`，`maxSteps=24`，runLoop 超时 120s，父进程另设 210s 终止线；验证和准备另有开销。并发为 1，记忆目录每次隔离。
- 定期每五次请求提示、随机概率 0.2；所有提示组最多两次，指导文字相同。实际提示次数没有严格配平，因此不能分离次数与时机的效应。
- 六题来自六次真实历史缺陷：畸形工具结果、截断修复轮次、用户引导后的停滞、provider 流内重试、LSP 语言身份、会话修改排序。先固定题目，才查看模型结果。
- 种子有 19 个应转绿、43 个应保绿的公开断言；六题参考修复及隐藏测试均在实验沙箱复验通过。隐藏测试在模型完成后安装。它们来自同一项目，部分涉及同一模块，不能当成六个跨项目独立样本；summary 中的 independentTasks 字段实际只计不同 taskId。

## 用量：保留未知，修复后另验

主比较记录到 419 次 fetch 调用（中断项的调用数无法恢复），但事件日志遗漏最终验证所属请求的 usage。五组总 token 均未知，未估补，未报告成本降低；没有价格配置，金额也未知。

根因是适配器在 tool_call 后产出 usage，而验证成功会提前关闭生成器。审查发现前移 usage 会破坏既有压缩校准，因此交付版复用了现有 RequestMeter，不改生产事件顺序。实验参数在序列化、计量前装配，回执哈希对应最终请求体；任一重试缺 usage 时，总数保持未知。

**独立 v2 接线验收通过**：C1 基线一趟通过公开与隐藏测试，依赖拓扑完整；20 次 fetch、20 份完整回执、19 个 usage 事件，总上报 token 为 445,388。它证明计量与保护接线可运行，不是新的策略收益样本，未混入上述 30 次比较。

另有两趟校准（1 通过、1 失败）与七次原生协议探针，均未混入主比较。

## 已交付的最小实现

- 在现有事件上增加可选原生推理状态；按端点、最终模型绑定来源，经上下文投影和压缩保留，防止跨模型、跨端点、worker 或截断响应污染。
- DeepSeek 官方原生端点上明确处理 thinking off；未知兼容网关保留其原请求惯例。真实网关标量探针可观察到 off 关闭推理；工具探针未返回推理正文，未复现“缺状态导致续轮失败”。状态连续性由真实适配器的合成端到端回归证明。
- 新增纯策略、调度和汇总模块，以及可选实验 hook。新增策略没有接入生产默认路径；没有引入新依赖或常驻规划代理。
- 续跑用独占尝试目录和开始回执；中断只记不可测，不自动重跑；损坏账本拒绝继续，原子写盘，代码、种子、隐藏判据内容均有哈希。
- 实验 shell 写入限制在试题目录，拒读已知源码/答案副本与旧试题目录，只放行本机回环网络以支持既有 HTTP 测试。交付 v2 另保护依赖目录非缓存写入，并校验模型前后依赖拓扑及新增影子依赖；变化接入既有判卷保护。
- v1 尚无上述依赖拓扑补强。独立审查覆盖全部 454 条工具调用，未观察到依赖替换、影子依赖写入或安装；已识别的原 checkout 读取尝试被拒绝。该结论是日志审查，不是完整文件取证或安全认证。

## 后续采用条件

当前默认方案是保留既有闭环，优先保证原生协议、错误可恢复性、独立验证和准确记账。新增元认知策略继续作为研究开关。只有在更多未见过、能拉开区分度的难题上，固定预算、完整回执、重复配对后出现可靠净增益，才有默认启用的依据。当前不支持引入另一套重型规划或自修改内核。

# Agent OS 桌面端设计与分阶段交付

日期：2026-10-29

状态：待用户批准。批准前不写产品代码。

## 目标与判断

Cairn 要从“能做任务的聊天客户端”升级为长期使用的本地 Agent OS：

- 对话仍是默认首页，也是最高频工作面。
- 插件、记忆、自动化和设置是可重复访问的稳定目的地，不再藏在设置页的“工作台”分组里。
- 侧栏同时承担全局能力切换与当前目的地的上下文导航，但不堆常驻说明文字或装饰。
- 插件市场必须真正完成发现、审查、信任、安装、启用、更新与卸载，不以静态假数据冒充市场。
- 记忆页必须让用户检索、阅读、创建、编辑、移动、固定和遗忘长期记忆，并处理待批外部引用。
- 统一页面骨架、空态、错误态、加载态、响应式与键盘行为，再逐步迁移其余页面。

这不是一个可以安全塞进单轮改动的小范围润色。它包含四个独立工作流：

1. Agent OS 外壳、全局导航与统一页面骨架。
2. 插件市场及安装/更新/信任后端。
3. 记忆库及写入/移动/待处理引用后端。
4. 设置、技能、自动化、工作树、用量等页面的统一迁移。

推荐按上述顺序交付。第一轮先建立不返工的外壳和页面契约；插件市场与记忆库各自独立验收；最后用同一骨架处理其余页面，避免每页各造一套布局。

## 已确认方向

| 决策 | 选择 | 含义 |
| --- | --- | --- |
| 桌面主心智模型 | **B · Agent OS** | 窄全局能力轨 + 目的地上下文侧栏；对话仍为默认首页 |
| 插件市场 | **B · 编辑精选货架** | “发现”页用精选、分类和货架组织内容；已安装与更新必须始终可见 |
| 记忆页 | **A · 记忆库** | 左侧主题列表、右侧详情/编辑器；“待处理”作为同一页签 |

以上由用户在可视化对照稿中确认。

## 现有基础

- 暖色工作台、双栏会话布局、右侧窗格、设置页、命令面板、明暗主题与减弱动效已存在。
- `apps/desktop/src/renderer/components/Sidebar.tsx` 已有项目、会话、筛选、搜索、置顶、归档和行级操作。
- `SidebarRail.tsx` 目前只承担收起后的七个快捷动作，不是完整全局导航。
- `settings-nav.tsx` 已把插件、自动化、技能、记忆和工作树并入设置分区；这些能力现在没有独立一级入口。
- `AppPage.tsx` 中已有插件快照、技能清单、MCP 状态和记忆主题正文；插件只能信任/配置本地插件，记忆只能查看与删除。
- `src/agent/memory/store.ts` 已有 `writeTopic`、`replaceTopicIfMatches`、`deleteTopic`、索引重建和目录级串行锁，可承接用户编辑与移动，但尚未暴露完整 IPC。
- 当前没有插件市场目录、下载、摘要校验、安装任务、更新或卸载的端到端产品链路。
- 当前工作树已有大量未提交设计、产品化和编排改动。本轮只新增本设计及其后续白名单文件，不重置、不暂存或提交无关修改。

## 对标证据

只做只读研究，不复制代码或资产。

- [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的插件管理分为发现、安装与运行态，并提供市场生成器和插件管理器；其市场强调目录、兼容性、安装状态和恢复，而不是单个“安装”按钮。
- [DSH Market](https://github.com/dsh-market/dsh-market) 使用“发现 / 收藏 / 已安装”等页签、来源与版本信息、截图、兼容性、更新状态和失败恢复。本项目采用其信息分层，不复制其视觉。
- [DSH Context](https://github.com/bowenliang123/dsh-context) 展示了上下文统计和来源浏览，但重度仪表盘不适合作为 Cairn 记忆页默认面。Cairn 以可管理的知识内容为先，统计和来源只在详情中按需出现。
- [Hermes Agent Desktop](https://github.com/NousResearch/hermes-agent) 的桌面设计明确把 Chat、Skills、Messaging、Artifacts 视为持久页面，要求扁平信息层级、无卡片套卡片，并把设置作为短任务覆盖层。该仓库当前未声明 SPDX 许可，因此仅参考结构与交互原则。
- [Hermes Desktop](https://github.com/fathah/hermes-desktop) 的侧栏把高频会话与低频管理动作分开，设置使用单一模态；本项目保留这种“会话优先、管理动作后置”的原则。
- 现有 OpenHands 参考源码位于 `cairn-refs/oh-src`，其插件页区分 installed / available / local，且安装与市场读取分属不同服务。Cairn 借鉴状态模型，不迁移其技术栈。

## 方案与取舍

### 桌面外壳

1. **对话优先。** 插件与记忆留在底部工具区或设置子页。窄、安静，但生态能力无法成为稳定目的地，长期会继续挤进“更多”。
2. **Agent OS（已选）。** 48px 全局能力轨承载对话、插件、记忆、自动化等一级目的地；其右侧上下文侧栏随目的地变化。对话为默认首屏，聊天下仍使用现有项目/会话侧栏。
3. **项目优先。** 先选项目，再在项目内进入会话、插件和记忆。项目上下文强，但全局记忆、插件市场和更新管理会绕路。

### 插件市场

1. **目录工作台。** 发现/已安装/更新三页签、网格和详情侧栏。效率高，但发现面较普通。
2. **编辑精选货架（已选）。** 发现页用专题、分类和新上架货架帮助发现；已安装/更新仍在同一页面顶部可达。需要严控营销化，卡片必须优先展示真实能力、来源和状态。
3. **已安装控制台。** 默认展示版本、启用、权限与异常，市场藏在次级入口。运维强，但首次使用难以感知生态。

### 记忆页

1. **记忆库（已选）。** 主题列表 + 详情/编辑器，待处理、时间线与来源按需切入。
2. **待审收件箱。** 先审 agent 新学到的内容，再保存、改范围或忽略。信任强，但不利于日常查找已有知识。
3. **关系图谱。** 主题、项目、来源可视化。辨识度高，但当前主题规模不需要，且容易牺牲可读性。

## 第一轮：Agent OS 外壳

### 全局能力轨

- 新增 `AppRail`，固定 48px；从标题栏下方开始，不侵占 macOS/Windows 窗口控制。
- 一级目的地：对话、插件、记忆、自动化；设置固定在底部。技能中心与工作树先保留为次级入口，是否升级为一级入口由真实使用频率再定。
- 每项使用现有 `lucide-react` 图标、可见焦点、`aria-current="page"`、Tooltip 与快捷键提示。常态只显示图标，不常驻文字标签。
- 活动项用珊瑚色窄指示与轻背景表达，不使用大色块。有真实更新/运行数时才显示 badge。
- 对话是启动默认页。插件、记忆等页面作为持久目的地，切换后保留搜索、筛选和滚动位置；返回对话不丢失草稿。
- 键盘优先：`Cmd+K` 可跳转所有一级页面；`Cmd+B` 控制上下文侧栏，不隐藏全局能力轨。

### 目的地上下文侧栏

上下文侧栏沿用现有 `Sidebar` 的宽度、分组、搜索与持久化规则，但内容随一级目的地变化：

| 目的地 | 上下文侧栏 |
| --- | --- |
| 对话 | 现有项目、会话、置顶、归档与筛选 |
| 插件 | 发现、已安装、可更新、收藏；分类列表 |
| 记忆 | 全部、项目层、全局层、最近使用、待处理 |
| 自动化 | 全部、运行中、已暂停、最近运行 |

插件与记忆页在窄容器中收起上下文侧栏，页面标题下提供同义下拉筛选。全局能力轨仍保留；低于可工作的最小桌面宽度时退回模态导航，不做无法阅读的图标堆。

当前 Electron 窗口最小宽度为 880px。880px 是真实窗口验收下限；更窄的容器只用共享组件测试承载，不能冒充应用窗口已支持。

### 项目与运行上下文

- 全局能力轨不另造“当前项目”。插件和记忆页面读取桌面外壳当前选中的工作区；普通聊天切换项目时同步更新，无会话时保留最后一次有效选择。
- 没有有效工作区时，全局插件与全局记忆仍可管理；项目层区域显示选择项目的空态，不静默回落到 `process.cwd()`。
- 插件安装目标分“全局”和“当前项目”。安装审查页必须写出实际目标路径的所属作用域；用户在页面切换项目后，未提交的安装审查关闭而不是换目标继续。
- 一次 run 在开始时固定插件启用集与内容摘要。安装、更新、停用和卸载只影响下一轮；仍有运行中的会话使用旧摘要时，UI 显示“下一轮生效”，不热替换代码。

### 页面骨架

新增统一 `PageFrame` 与 `PageHeader` 展示层：

- 页头只包含标题、一个主操作和必要的真实状态。删除重复页名、重复功能描述和“数据面：getState() 快照”等实现口径。
- 搜索、筛选、页签放在内容起始的一条工具带；页签使用文字，不用装饰性 pill 堆叠。
- 内容区优先使用无外框的分组、列表或重复卡片；不出现卡片套卡片。
- 空态说明“尚未发生什么”并给一个有效下一步；错误态区分读失败、离线、权限拒绝与空数据。
- 加载态保留稳定尺寸，避免页头和工具带跳动。
- 页面标题、搜索、页签和主操作在 1440、1120、880 真实窗口下不重叠；720px 只用于内嵌组件容器的边界测试。长中文和长标题优先换行，不用负字距。

第一轮只落外壳、页面骨架和路由。插件市场与记忆库先接现有真实快照，不启用不存在的市场或编辑按钮。

## 第二轮：插件市场

### 信息结构

- 顶部页签固定为“发现 / 已安装 / 更新”。更新数只来自真实版本比较。
- 发现页首屏按“精选 / 最近上架 / 分类”形成 2–3 个货架；不在页头放大幅营销 Hero。
- 插件卡片展示：名称、一句话用途、作者/来源、版本、真实能力类型（技能、命令、MCP、hooks、LSP）、兼容状态、安装/启用状态。
- 精选是运营编排，不伪造评分、下载量或“同事在用”。没有可信数据就不显示。
- 点击卡片在宽页打开右侧详情抽屉，窄页使用全高 sheet；详情展示来源仓库、版本/提交、能力清单、权限风险、配置项、发布说明和已安装状态。
- “已安装”使用紧凑列表，优先版本、作用域、启用、更新、信任和配置；不复制市场卡片网格。
- “更新”只列出可更新或更新失败的插件；支持单项更新，批量更新仅在逐项风险已展示时提供。

### 安装与信任

- 市场目录是版本化 JSON；应用校验大小、schema、URL 与条目数量。目录不可用显示缓存时间和离线状态，不显示空市场。
- 包安装使用暂存目录。下载后先校验内容摘要，再解析插件 manifest；不执行仓库安装脚本。
- 安装前审查页显示：来源、目标作用域、版本/提交、摘要、技能/命令/MCP/hooks/LSP 数量、需要的配置和敏感权限。
- 信任绑定到内容摘要，不绑定到可移动的显示名称。更新后摘要变化必须重新审查。
- 安装是显式任务状态：等待、下载、校验、解包、加载、成功、失败、可回滚。失败保留原因和重试入口，未完成的暂存不进入运行时。
- 卸载与停用分开：停用保留文件和配置，卸载需要确认。运行开始时固定插件启用集与内容摘要；运行中的 agent 继续使用旧摘要，更新/卸载与停用从下一轮生效。
- 支持“从 Git 仓库安装”和“从本地目录安装”作为受控次级路径；默认不执行第三方构建。

### 目录托管与发布

- 第一版只有一个第一方目录，地址与内置公钥随应用发布。目录快照使用版本化签名清单；应用校验签名、schema、大小和过期时间。
- “精选”与分类由 Cairn 维护者随目录发布。社区提交通过目录仓库的审查流程进入，不在客户端接受任意目录 URL。
- 目录不可验证时只读取上次已验证快照，并显示过期时间；没有已验证快照时显示不可用，不展示伪造条目。
- Git 与本地目录导入是独立入口，不拥有“官方目录”徽标，也不能写入精选货架。
- 公钥轮换至少保留当前与上一把公钥，并记录验证失败原因。私钥不进入桌面应用、测试夹具或构建产物。

### 所需能力

- `MarketplaceCatalog`、`MarketplaceEntry`、`InstallJob` 的共享类型与协议版本。
- 目录读取与缓存、摘要校验、暂存安装、已安装清单、版本比较、启用/停用、卸载与回滚。
- 与现有插件运行时信任指纹、userConfig 和 MCP 激活状态对接。
- 新的 preload/IPC 通道；渲染层只消费快照和命令结果。

## 第三轮：记忆库

### 页面结构

- 默认“主题”视图为左侧主题列表、右侧详情；选中项保持在滚动区可见。
- 顶部工具带：搜索、范围/类型筛选、排序、主操作“新建记忆”。
- 页签固定为“主题 / 时间线 / 待处理”。时间线基于真实 `modified`；待处理只列未批准外部引用与未来确认过的候选记忆。
- 搜索覆盖主题名、正文和来源标签；无结果与读取失败分开。
- 主题详情展示范围、类型、大小、修改时间、正文和索引摘要。来源、最近使用与关联主题只有后端提供真实数据时才显示。
- 编辑器使用显式“保存 / 取消”，存在未保存更改时切换主题或离开页面必须确认；不对长期记忆做隐式自动保存。
- 支持新建、编辑、置顶、移动作用域和遗忘。首版“置顶”只影响管理页的排序与快捷访问，不改变模型注入、衰减、休眠或 token 预算；界面不用“固定”暗示它会永久优先进入上下文。
- 移动是“写入目标层 → 校验索引 → 删除源层”的可恢复事务；失败不留下双份或丢失。
- 待处理外部引用提供“允许 / 拒绝”及作用范围；决议持久化后从队列移除。

### 外部引用语义

- 首版沿用现有全局 `external-refs.json`，允许/拒绝的是记忆文本中是否保留该 `@path` 引用，不授予文件读取权限。
- 决议绑定规范化后的引用 token，不绑定目录子树或文件内容摘要。路径内容改变不会自动撤销决议；实际读取仍必须经过文件工具、工作区边界、realpath 与权限门。
- 工作区内引用不进入待处理队列。工作区外、`~` 和 `..` 引用默认 fail-closed，直到用户明确允许。
- 同一条引用只允许存在于 approved 或 declined 其中一组；后一次决议撤销前一次。

### 所需能力

- 复用 `writeTopic`、`replaceTopicIfMatches`、`deleteTopic` 与目录级串行锁。
- 新增记忆创建/保存/移动/置顶和外部引用决议 IPC；每次写入返回新版本、字节数和索引状态。
- 主题名仍遵守现有 1–64 位字母/数字/连字符/下划线约束；用户界面实时校验，但服务端继续作为权威。
- 用户可写，模型仍不能删除。所有写操作保留原子替换与并发保护。
- 桌面主进程、CLI 与后台任务可能同时写记忆。跨进程写入使用目录锁租约加正文/索引版本摘要校验；锁获取有上限，失败可见。锁只包裹短写事务，不覆盖网络或模型调用。
- 时间线先由现有修改时间和外部引用决议生成；没有事件来源时明确省略，不编造“被使用 12 次”。

## 第四轮：其余页面统一

- 设置保留现有分区能力，但按真实任务分组：模型、外观与交互、权限、连接与用量、扩展、维护、关于。删除重复说明和卡片套卡片。
- 技能中心复用插件市场的搜索、详情和启用状态语言，但保持技能与插件两个产品名词。
- 自动化、工作树、用量、进化等页面迁入 `PageFrame`，共享页头、工具带、空态、错误和焦点规则。
- 所有页面都要能从 `Cmd+K` 直达；页面级搜索不得与全局命令面板承诺混淆。
- 页面切换保留滚动、筛选与草稿；后台任务更新 badge，不抢前台页面和焦点。

## 视觉与交互约束

- 延续现有暖米白画布、珊瑚品牌色和深色主题；不重做品牌，不引入紫蓝渐变。
- 字号不随视口缩放，字距保持 0。重复组件使用 8px 及以下圆角。
- 页面不是落地页。除记忆空态和插件精选货架外，不使用大幅展示性标题或营销文案。
- 工具按钮优先图标；只有主命令和需要解释的动作使用文字按钮。
- 不增加常驻快捷键说明书或功能说明段。必要提示只在空态、错误、Tooltip 和设置项说明中出现。
- 背景任务只更新数据与 badge，不自动切页、打开抽屉或移动焦点。
- `prefers-reduced-motion` 下所有非必要位移即时完成。
- 触控目标不小于 32px；密集桌面列表按钮不低于 28px，键盘焦点始终可见。

## 边界与非目标

- 不在第一轮处理真实市场安装脚本、第三方构建、云同步或远程插件仓库写入。
- 不为了插件市场引入评分、评论、下载量等没有真实来源的数据。
- 不在第一版加入记忆关系图谱、向量可视化或热度仪表盘。
- 不改变 agent 权限模型、审批规则、沙箱或事件日志结构。
- 不把插件运行在比当前更高的权限层；插件宿主边界必须在详情和设置中如实说明。
- 不承诺跨平台安装包、真实服务或真实模型验证；这些必须单独验收。
- 不在共享脏工作树中 reset、stash、clean 或提交无关文件。

## 验收

### 外壳

- 1440、1120、880 宽真实窗口下，全局能力轨、上下文侧栏、页面标题和主操作不重叠；720px 只作为内嵌组件容器的边界测试。
- 对话、插件、记忆、自动化均可一键切换；对话启动默认；`Cmd+B` 与 `Cmd+K` 行为稳定。
- 收起/展开、筛选、搜索、滚动位置和草稿在切换后保留。
- 窄页签与筛选键盘可达，焦点返回正确。

### 插件市场

- 目录可离线读取缓存；损坏或超时不会被显示成“没有插件”。
- 能够从真实目录安装一个 fixture 插件，并验证摘要、manifest、信任审查、插件加载与卸载。
- 更新后摘要变化必须重新审查；失败安装不改变已安装版本。
- 已安装、可更新、停用、失败、离线状态均有真实断言。
- 渲染层不直接下载、解包或读文件。

### 记忆库

- 新建、编辑、置顶、移动和遗忘均落盘；索引与正文保持一致。
- 并发保存不会覆盖较新的主题版本；冲突可见且可恢复。
- 未保存离开有确认；取消不写入。
- 外部引用允许/拒绝后从待处理队列移除，重启后状态仍在。
- 空、读取失败、索引超限和非法主题名分别可见。

### 通用

- `PageFrame`、插件和记忆的单元/组件测试通过。
- `pnpm --filter cairn-desktop test`、桌面构建、根类型检查、renderer 分层、desktop boundary、docs-check 通过。
- 真实 Electron 合成 API smoke 覆盖亮暗主题、窄窗、键盘、错误、空态和核心操作。
- 使用 `node /Users/ze/.codex/skills/impeccable/scripts/detect.mjs --json <changed targets>` 做一次静态检测。
- 证据注明工作树、合成 API、真实目录 fixture 与未验证的真实网络/发布边界。

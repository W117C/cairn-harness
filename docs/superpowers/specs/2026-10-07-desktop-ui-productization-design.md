# Cairn 桌面端 UI 产品化设计（六板块）

日期：2026-10-07 · 状态：已按业主指令（出计划→审查→执行）授权施工
范围：仅 `apps/desktop/src/renderer/` 与其测试；核心 `src/` 与 IPC 协议面零改动。

## 一、诊断：为什么开源桌面端像产品，我们现在不像

对标：Cherry Studio（provider 卡片接入页）、Claude 桌面端（composer 一级 effort 控件）、
Claude Code 桌面重设计（diff 视图/流式呈现）、Cline（审批卡）、Lobe Chat（模型菜单搜索+分组）。
它们做对的六件事，恰好就是业主点名的六个板块：

1. **模型接入**：不是「一个下拉＋一个 key 输入框」，而是 **provider 卡片列表**——每家一张卡，
   状态点（已配 key / env 在场 / 未配）一眼可读，点进去是 key 编辑＋模型清单＋能力徽标。
   空态/首跑场景有「先接入一家模型」的显式引导。我们现在是原生 select＋两行说明文字＋一段
   JSON 风格表单，能力齐全但无产品形态。
2. **模型选择＋思考档位**：Claude 桌面端把 effort 做成 composer 上的**一级分段控件**（低/中/强），
   模型选择是带搜索、分组、徽标的 popover。我们把思考档位塞在模型菜单里当四行普通菜单项，
   既难发现又误读成「模型的一种」。菜单无搜索，provider 无视觉身份（色点/徽标）。
3. **输出动效与等待**：**markdown 渲染是底线**——所有成熟客户端都渲染标题/列表/代码块（带语言
   标签与复制钮）。我们的 assistant 输出是裸文本；等待期只有三个 3px 的点；没有粘底滚动＋
   「回到底部」；没有 phase 感知的动画指示（思考/执行/等门）；运行中没有计时与 token 读数。
4. **图标与交互**：成熟产品用一套统一网格的线性图标。我们混用 emoji（👍👎⧉⟲⚠）与手绘 SVG，
   笔画粗细、视觉密度不一致；popover 无过渡动画；按钮无按压反馈差异。
5. **对话框（消息区）**：用户消息与助手消息几乎同形（两行裸文本），扫一眼分不清谁说的；
   工具行、错误行无层级；代码无块状呈现。
6. **设置页**：分区无图标、行距密、控件宽度不一；「模型与 Provider」把凭据/自定义接入/默认模型
   混在一面墙上，没有「家」的空间感。

结论：**不是缺功能，是缺「消息解剖学」「控件身份」「接入叙事」三层产品形态。**

## 二、设计决策

- **零新增运行时依赖**（与本仓打包纪律一致）：markdown 渲染器与图标库全部自研
  （`markdown.tsx` 解析器约 200 行，仅输出安全节点、不注入原始 HTML；`icons.tsx` 统一 16px
  网格、stroke 1.5 线性图标）。
- **不 fork 外部项目**：我们的价值面是 renderer（约 6k 行），kernel/IPC/审批链路是自研资产；
  fork Cherry Studio 级别的代码库意味着换掉整条事件投影与审批语义，成本远大于收益。
  取的是模式，不是代码。
- **诚实纪律**：没有的通道不摆按钮（无「连接测试」IPC 就不做假测试钮）；placeholder 与
  实际能力一致（去掉未实现的「@ 文件或对话」）。
- **判卷面不缩水**：SettingsPanel/ModelPicker 的纯函数出口（panelPatch、providerOptions、
  flattenModels、groupModels、tierBadge…）原样保留；新增纯函数（markdown 块解析、菜单搜索
  过滤、思考档位文案）同样进判卷。
- **保留既有行为**：IME 组字守卫、事件驱动会话清单、运行态三闸、赞/踩/回滚、Esc 语义全部不动。

## 三、分板块设计

### ① 模型接入（设置页「模型与 Provider」）
- provider 卡片网格：demo＋内置四家＋自定义家，每卡：状态点（已存 key=绿 / env 在场=蓝 /
  未配=灰）、家名、env 变量名脚注、当前缺省家=描边。点击选中 → 右侧/下方详情面板：key 输入
  （非受控、保存即清）、保存/删除、模型清单（点击设默认，tier/窗口/识图徽标）。
- CustomProviderForm 收进「＋ 添加自定义接入」折叠卡。
- 空态（无任何已配 key 的真家）：EmptyState 增加「接入你的第一个模型」引导卡 → 打开设置并
  直达 provider 分区（SettingsPanel 增加 `initialSection` prop）。

### ② Composer：模型选择器＋思考档位
- 模型 popover：顶部搜索框（新增纯函数 `filterModelOptions`）、provider 分组（色点＋家名）、
  行内徽标（tier 文字＋窗口）、末置「演示」区与「管理模型」入口、key 未配置顶提示行保留。
- 思考档位升级为独立控件：composer 控件行「思考」按钮（brain 图标＋当前档位），popover 内
  分段四档（关/低/中/强）各带一行说明；仅当所选模型声明支持时可见，未声明时按钮置灰＋原因
  title（不摆空壳）。
- 发送按钮态：就绪/禁用/运行中(停止)；新增 phase 指示条（思考=脉冲点＋文字、执行=旋转圈＋
  工具名计数、等门=蓝脉冲）置于状态行。

### ③ 输出动效与等待
- `markdown.tsx`：块级解析（标题/段落/围栏代码/列表/引用/分隔线/表格）＋行内（粗斜/行内代码/
  删除线/链接）。围栏代码块：深色底、语言标签、复制按钮。流式期按已累计文本重渲染（块级
  memo）；未闭合围栏按开放代码块渲染（流式不闪烁）。
- 自动滚动：`useStickToBottom`（粘底＋阈值检测），出现 `.jump-latest` 浮钮（CSS 已有）。
- 运行读数：状态行显示运行秒数与输出 token。

### ④ 图标与交互
- `icons.tsx` 单一图标事实源（约 30 枚），替换全部 emoji/字符形；popover 加 fade+scale 过渡；
  按钮统一按压态。

### ⑤ 对话区
- 用户消息：右对齐浅底圆角块（max-width 80%），hover 出复制/回滚动作。
- 助手消息：左对齐全宽 markdown 正文＋spark 头像；动作条（复制/赞/踩）hover 显示，图标化。
- 工具行：状态图标（spinner/✓/✕）＋工具名 mono＋摘要；簇轨道保留，样式细化。

### ⑥ 设置页
- 导航加图标；分区标题样式统一；控件宽度统一；「关于」版本号单源（保持 0.1.0 硬编码，
  与 CLI 同源问题另行处理）。

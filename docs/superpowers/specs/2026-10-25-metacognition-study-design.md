# Cairn 元认知研究：哪些思考值得增加，怎样证明值得

> 本文件保留初始调研快照，第 3、4 节描述实施前状态。用户随后授权执行；当前实现、真实结果与未验证边界见[最终报告](../../research/metacognition-pilot-2026-10-25.md)。

日期：2026-10-25（Asia/Shanghai）。本报告是研究结论和候选实验方案，尚未成为批准的内核设计。

## 结论

**值得投入的是“让 agent 依据证据决定何时查资料、规划、验证、换路和停止”的受控实验。当前没有足够证据支持默认增加每步反思、常驻规划代理或开放式内核自改。**

目前对 Cairn 最有依据的顺序是：核验原生推理协议 → 建立有区分度的任务基线 → 在现有执行循环上试验按事件触发的干预 → 有独立留出集收益再考虑部署。离线经验优化另行评价。

“先思考再动手”可以实现，但人类类比不能决定具体机制。模型已经可能在原生推理中规划；再增加显式规划会产生额外调用，也可能干扰原有策略。合理目标是提高真实任务完成率和可靠性，并在此基础上比较时间与成本。

不存在脱离任务分布、模型、验证器和资源限制的已证“全局最优方案”。本文推荐的是当前证据支持度最高、能够被后续实验推翻的路线。

## 2. 需要分清的四种能力

| 能力 | 实际作用 | 应如何验收 |
|---|---|---|
| 模型原生推理 | 模型在生成和工具交互中分配内部推理计算 | 请求与响应契约正确，真实任务在指定预算下表现改善 |
| 显式任务规划 | 明确目标、范围、下一步和验证办法 | 计划推动正确执行；单纯出现计划文本不计收益 |
| 运行时元认知控制 | 根据失败、未知事实、目标变化和进展选择下一种策略 | 干预提高完成率或可靠性，并量出误触发与额外代价 |
| 跨任务学习 | 从经过判定的历史结果中更新经验或提示词 | 独立留出任务受益，且权限和验收标准保持受保护 |

Cairn 已覆盖其中不少机制。真正需要验证的是各机制在什么条件下提供增量收益。

## 4. 扩建之前，先核验原生推理契约

这里发现两个具体的协议条件，优先级高于增加一套新认知架构。

### 4.1 `off` 的含义需要按端点核验

当前 `reasoningDirective('off')` 返回 `null`；主 provider 在 `off` 时不发送 `reasoningEffort`。这能保证保持旧请求形状，但不自动等于上游关闭思考。

本次读取的 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/thinking_mode) 对其当前 V4 模型写明：思考默认开启；Chat Completions 另有 `thinking.type` 开关，`reasoning_effort` 控制强度。因此对这类端点，省略字段可能是“采用上游默认”，并非“关闭”。具体还取决于模型版本、网关和 `extraBody`。

这不能直接推出所有 GLM、MiniMax 或本地代理行为都错了。它说明：实验中的档位标签必须有端点级的操作定义，不能只相信 UI 名字和参数被接收。

### 4.2 工具轮次中的推理状态需要协议级保存

上述 DeepSeek 文档还要求：携带 tools 的后续请求回传先前轮次的 `reasoning_content`。Cairn 当前统一 `ProviderMessage` 没有该字段，OpenAI wire 映射只保留 role/content/tool_calls/tool_call_id 等字段。

本次离线探针把带 `reasoning_content` 的合成 assistant 工具调用消息交给实际 `toOpenAiWireMessages`，输出：

```json
{"offDirective":null,"reasoningContentPreserved":false,"wireKeys":["role","content","tool_calls"]}
```

这是**确定的本地消息形状证据**，尚不是一次真实 DeepSeek 会话失败的复现。网关可能有自己的转换；必须按实际使用的模型和协议再做原生交互核验。提供方要求的推理状态应按其协议保存，不应擅自拼成通用正文、跨模型复用或写入经验库。

## 5. 复算已有 thinking 实验：结果与限制

复算脚本输出在同目录 `historical-summary.json`，包含六份输入文件的 SHA-256、20 条精简运行记录及分组汇总。

| 模型 | 任务 | low 逐名通过运行数 | high 逐名通过运行数 | high 平均总 tokens 相对 low |
|---|---|---:|---:|---:|
| hy3 | B1 | 1/1 | 1/1 | −2.00% |
| hy3 | B12 | 1/1 | 1/1 | −7.07% |
| GLM-5.3-Flash | B1 | 1/1 | 1/1 | +55.30% |
| GLM-5.3-Flash | B12 | 1/1 | 1/1 | −48.29% |
| GLM-5.3-Flash | L32 | 3/3 | 3/3 | −45.40% |
| MiniMax-M3.1-Flash | L32 | 3/3 | 3/3 | +340.13% |

这里的总 tokens 是历史记录的 `tokensIn + tokensOut`。这批记录均为 `verifyOkLast=true`、`namedSets.state=pass`，且 `touchedJudge=false`。

可靠结论：**这批已观察的运行没有显示 high 多完成任务；用量变化具有明显的模型和任务差异。**

不能推出的结论：

1. **3/3 对 3/3 不证明两种策略等效。** 样本太小且通过率封顶，无法检测实际小差异，更不能据此宣称“多想永远无用”。仓库 README 个别“3 对足够证明不买正确率”的表述应按这个边界理解。
2. B12 的 20 条断言和 L32 的 32 个链环，不能作为 20/32 个独立任务来增加统计分母。同一题重复运行也不能替代不同任务覆盖。
3. 档位被写进请求，不证明代理端点实际执行了不同推理预算。本次未重新认证历史代理的档位行为。
4. `cny=0` 无法证明服务没有计算成本，亦不能推出美元成本改善。缓存、推理 token 及代理计价口径需另行核对。总 tokens 只是有限的用量描述。
5. 不能只比较低用量：GLM L32 的 high 虽然 token 较少，历史平均用时却更长；成本、时间和可靠性需要分别报告。
6. 历史记录包含 dirty 身份；未确认运行顺序随机化、缓存状态、精确工作树内容与独立重复性，因果结论要保留。

本次 fresh feasibility 命令没有发模型请求，结果是：当前进程缺少跑器要求的模型凭据，**可跑 0/12**；但 **12/12 已带 judge**，合计 FAIL_TO_PASS 43、PASS_TO_PASS 13。装配声明中 autoMemory、impactAnalysis、promptCache 为 `off-here`，subagentTools 与 autoVerify 为 `same`。这意味着即使后续跑通，也必须写清所测装配，不能泛称所有产品能力都已覆盖。

| [Rational Metareasoning](https://arxiv.org/html/2410.05563v2) | 通过训练让模型选择何时使用额外推理，在所测任务下降低输出用量 | 为“计算的价值”提供依据，但涉及模型训练，不能作为 API harness 可直接启用的功能 |

另检索到 [uncertainty-aware coding-agent 自纠错稿件](https://openreview.net/attachment?id=KgQphSXJj4&name=pdf) 等更直接的选择性干预探索，报告的收益伴随额外延迟。这些只作为后续线索；本轮没有完成其代码、完整统计和独立复现核验，因此不把其中效果数字列入决策依据。

从这些证据能作出的推断是：**适应任务、利用执行反馈、保留低开销基线，比固定增加认知步骤更值得优先验证。** 事件触发是否优于定期提醒，仍须做直接对照，不能用上述论文替代。

## 8. 三条路线与建议

### A. 核验原生推理，使用现有循环建立强基线

先按真实端点核验开关、预算、工具轮次状态和计量；在同一任务分布上比较当前 low/high/default 等配置。若这样已满足成功率与可靠性目标，就没有必要增加新的控制器。

这是当前优先级最高的工程前提。不能一边丢失模型要求的状态，一边把失败归因于“缺元认知”。

### B. 在现有循环上试验轻量、按证据触发的控制

推荐作为 A 之后的实验候选。复用现有停滞信号、验证结果、用户插话和预算，统一决定下一项干预，不另建常驻 planner/critic，也不叠加第二套重复提示器。

| 可观察情况 | 候选动作 | 检验重点 |
|---|---|---|
| 缺少路径、API 或复现结果等外部事实 | 先使用低风险工具获取信息 | 额外思考是否只是重复未知信息 |
| 复杂多文件变更，已有足够事实 | 形成短计划：范围、关键假设、下一步、验证办法 | 是否减少错误修改与返工 |
| 验证结果推翻关键假设，或命中有证据的停滞 | 指明失败证据，调整假设或探针；必要时提升已验证的推理档位/模型 | 是否恢复任务，是否比同预算普通重试更有效 |
| 工具链或端点未能执行 | 修复环境或报告阻塞 | 不把基础设施故障当作业务代码错误 |
| 出现足够完成证据 | 进入既有收尾逻辑 | 不为完成反思流程继续消费资源 |
| 涉及高影响操作 | 维持独立授权、验证和权限约束 | 元控制不得改变权限、判卷或自我监督边界 |

建议只保存短决策摘要：证据引用、尚未确定的假设、下一步和检查结果。它用于续跑与审计，不是要求输出完整思维链。

触发器先使用可解释信号。模型自报“90% 自信”可以是候选特征，但未经校准不能当作概率。为相同证据加去重与干预预算；阈值、冷却和升级次数在开发集上确定，并在留出集冻结。

若后续获准实现，最可能涉及 `loop.ts`、`no-progress.ts`、`session-provider.ts` 的既有控制点。按仓库事件规则，行为证据优先使用现有事件的可选字段，避免为“元认知”另建事件族。审批规划与策略规划应在语义上分清。

### C. 固定每步规划/批评、双代理或树搜索

优点是能生成更多替代方案，可能帮助真正困难且有判据的任务；代价是额外调用、上下文、候选隔离、状态恢复和错误评估。

例如 [SWE-Search](https://arxiv.org/abs/2410.20285) 给出 MCTS 与反馈搜索的正面研究线索，但这并不证明在 Cairn 相同预算、现代模型和真实工作负载上优于 A/B。只有 B 仍反复卡在“探索策略不足”，且评判器能够区分候选时，才值得把它加入针对性实验。

GEPA 属于另一条离线轴：它可以在 A/B/C 的策略或提示词之间优化候选，不应直接和运行时控制器画等号。

## 9. 如何判断 B 值不值得保留

### 第零阶段：先证明比较的是实际不同策略

对计划使用的每个模型/端点核验：解析后的模型身份、default/off 的真实含义、low/high 是否被执行、工具多轮状态、截断/重试行为、usage 中推理与缓存的计量方式。兼容网关接受字段不是充分证据；无法确认的档位记为未验证。

保留固定代码快照、模型版本和安全配置。把运行时契约修正后的现有产品作为基线，而非故意使用有缺陷的基线抬高候选收益。

### 第一阶段：用独立 pilot 找到可测问题

一个起始建议是约 24 个不同任务，覆盖真实跨文件修复、异步问题、未知仓库约定、长上下文、工具失败和目标变化。该数量只是发现成本、失败类型和配对差异的 pilot 规模，不是统计认证样本量。

应包含普通任务，避免只挑“正好会触发控制器”的失败样本。发现集与最终留出集按仓库或时间隔离；已用于调触发器的题不能再充当独立证明。B12/L32 可保留为机制回归，但不能担当全部能力分母。

### 第二阶段：进行能够区分解释的对照

至少保留这些策略：

- 原生推理契约正确的现有 agent。
- 固定较高推理预算，用来检验简单加算力是否足够。
- 固定阶段反思或定期提醒，检验按事件触发是否必要。
- 按证据触发的候选策略。
- 随机触发、平均干预次数接近的控制组，用来检验“选对时机”是否优于单纯多试几次。

可分阶段筛选控制组以限制开销，但缺了某个控制，就不能声称排除了它对应的解释。上述 24 题、5 策略、2 次重复会是 **240 个任务轨迹**，并非 240 个 API 调用；真实费用必须先由 pilot 估算。本轮不自动执行这一预算。

同一题同一起点、权限、可见测试、工具、记忆快照和最大步数；按模型与任务分块随机交错运行。策略必须计入所有规划、反思、路由与重试开销。先报告相同资源上限的结果，再比较质量—用量—时间曲线；相同上限不等于实际花费相同。

### 第三阶段：用任务结果裁决

主指标是独立判据下的任务完成率及既有行为保持。辅助指标包括错误交付、干预后恢复、误触发、模型调用、可核实费用、token 分项和延迟。基础设施未执行、取消、超时与代码失败分别报告，保留全部尝试的分母。

隐藏判据由独立评估端管理，候选不得读写或优化它。真实任务缺少完整自动判据时，结合固定验收标准的人工盲评；LLM judge 作为辅助信号，不单独签发正确性证明。

统计以不同任务为单位，考虑同题重复和同仓库聚类。配对二元结果可以使用 McNemar 等方法，区间可按任务聚类 bootstrap；小样本时使用适当的精确方法。正式样本量要结合 pilot 的配对差异率、目标效果和置信要求确定，不能只因为“3 对都过”就宣称等效。

决策规则应预先写明：先排除关键可靠性与授权回归，再看有实际价值的完成率改善；在这些条件满足后比较成本与速度。若只增调用而无可重复收益，保留 A；若仅特定任务/模型获益，则只考虑在相应范围启用。证据不足应继续标记未知。

## 10. 跨任务经验怎样接入

已有 evolution 回注可以作为候选种子；经验条目宜包含适用范围、原始证据、验证状态和失效条件。一次失败后的模型解释只能先作为假设，不能直接晋升为全局规则。

若使用 GEPA，先固定训练/验证/最终测试划分和评价预算；验证可用于选择，最终测试保留到冻结后。最终隐藏判据不能反馈给候选学习；每次重新调参后应更新独立证据边界。权限、验收规则与进化内核的变更保持独立批准。

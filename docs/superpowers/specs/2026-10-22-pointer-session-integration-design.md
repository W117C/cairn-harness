# 产品指针分叉与来源引用设计

状态：方向已获业主认可；本文件待审阅，尚未实施此处的新协议。延续 ADR 0005，目标是完成其产品接线，同时保住原始行号和已有操作。当前版本以 `d059c02d` 为代码核对起点。

## 目标与边界

产品的 CLI 与桌面分叉只写首行 `session_meta.fork`，不复制或改写父日志；读侧展示、搜索并向模型提供父前缀与子会话的有效历史。嵌套分叉保留同样语义。继承历史可以继续参与反馈、置顶、回放和文件回滚；这些操作归属于当前子会话，不修改父日志。

保留底层 raw replay、原始游标、gym 的复制分叉、旧日志和旧数字引用。账本、当前轮交付、worker 恢复、运行态与计费只认当前会话本地事件，不能把父会话的在飞状态或用量继承一遍。本设计不开放自动安装，不调用付费模型，不修改 agent 规则。

## 已核实的问题

- `src/cli.ts` 与 `src/main/session-handlers.ts` 仍调用复制式 `forkSession`；`replaySession` 没有产品消费者。
- `session-provider.ts`、`compaction.ts`、`prune.ts` 及 UI 的 stream/timeline 把数组位置当原文件行号。
- 已做最小实证：子日志中 `compressed_event_ids:[2]` 本应排除子第 2 行；先拼两条父事件再投影，却会排除父回复并保留子消息。
- 桌面 fork/revert/compact 及部分注释操作仍用默认 sessions 根或裸 session id；A、B 两项目同名会话可能寻址到不同对象。
- 父文件被改名或删除后，现有绝对路径血缘会断裂。

因此不能把两个 fork 调用换成指针后直接全局替换 replay。

## 方案选择

采用显式来源视图：保留 raw，增加来源引用，在所有跨文件的读侧与写回之间传递它。代价是调整会话引用协议，但能保留现有操作并明确失败边界。

两个备选方案不采用：继续复制虽然改动小，却不满足已接受的指针语义；把父历史作为只读的独立区域虽然能少改引用，但会缩减现有的回放、注释与回滚能力。也不把继承历史自动压成一段文本，这会改变内容、增加模型成本，并丢失操作锚点。

## 三种数据面

### Raw：物理日志

`replay` / `replayIncremental` 逐字返回各自文件。原始事件 id 永远等于该文件的 1-based 行号，控制记录仍占行。原始游标只定位所属文件；不把逻辑数组序号编码成 raw 游标。

旧主流 `compressed_event_ids`、`summary_offset`、反馈与 pin 的数字 id 继续表示其原有所属文件中的位置，不重新解释为整棵继承树的位置。带 `agent_id` 的 worker 压缩仍只影响该 worker 的本地上下文，不把其内存序号解释为主日志的来源行号。

### SessionView：带来源的有效历史

新增只读结构，名称可按现有命名规范调整，但语义固定：

```ts
type EventRef = {
  workspace: string;       // 经可信注册根解析的规范路径
  sessionId: string;       // 该工作区中实际拥有此行的会话
  eventId: number;         // 该文件物理行号
};
type SessionViewEntry = { event: AgentEvent; ref: EventRef; inherited: boolean };
type SessionView = { entries: SessionViewEntry[]; localEvents: AgentEvent[] };
```

来源字段属于视图和引用，不回填到原事件、不写回父文件。显示顺序使用独立的 view 位置或来源元组键。任何需要写回的动作必须提交 EventRef，不能提交显示位置。

解析步骤：规范化可信 workspace/session 根；验证整条父链；按每个父文件自己的 raw 边界截取；在保留来源映射的同时应用该文件控制记录；过滤继承边界未收尾的 tool/clarify/plan/approval 请求；最后按父到子的顺序组合。子会话自身未收尾请求保留。祖先校验不因边界为 0 跳过。

父缺失、越界、循环、软链越界、来源不属于已注册根或引用不属于当前视图均显式失败。只允许本工作区 sessions 根中的父链，不能通过 renderer 自报路径跨任意目录读取。

### ModelHistory：模型协议投影

模型历史从 SessionView 生成；先解释各文件本地引用，再应用当前分支的跨来源压缩与裁剪。数值引用不在拼接数组上解释。原始事件仍保持不变。

模型协议中的 tool-call id 也须区分来源：父、子甚至不同本地轮次可能复用同一 id。根据实际调用的来源引用构造稳定的 wire id，结果匹配同一来源的调用；不让父结果替子调用收尾，也不把两份回执合并成一份。wire id 只存在于模型消息投影，不改 raw id。现有孤儿回执与缺回执的协议保护保留。

## 引用协议与旧数据兼容

### 压缩、裁剪及控制记录

旧数字形式继续可读。跨来源的压缩记录仍使用既有 `compaction` 事件型，但采用显式版本化的引用形式：

```ts
type ReferencedCompaction = {
  type: "compaction";
  reference_version: 1;
  compressed_event_refs: EventRef[];
  summary_anchor: { before: EventRef } | { end: true };
  superseded_summary_refs: EventRef[];
  // trigger/reason/summary/tokens/usage/model/agent_id 沿用既有字段语义。
};
```

新形式不携带 `compressed_event_ids` / `summary_offset`；旧形式不携带上述来源字段。完整来源集合与锚点必须成套在场，不同时写一份相互冲突的虚拟数字集合。未知版本、混合形状或半套字段失败关闭。每个 EventRef 的 eventId 须为正安全整数，并能在受信根中定位；摘要插入锚点须是应用该记录前仍在有效历史里的位置，或明确的末尾。

`compressed_event_refs` 只引用被摘除的内容事件，仍不得摘除 compaction 本体。旧摘要若进入新摘要输入，其来源须列入 `superseded_summary_refs`，以取消旧摘要的再次注入；不是把 compaction 事件当成普通内容吞掉。最新子摘要不能再与其已覆盖的父摘要重复注入。原子调用/回执单元的切点仍不可拆。摘要输入只包含选中的有效内容，父会话的后续追加不越过既定边界。

裁剪附件按来源命名空间存储，当前子会话的附件清理不能删除父附件。每次生成的数字兼容引用必须限定在同一原文件；跨文件写回一律使用来源形式。预算估算覆盖最终的完整模型请求，超预算仍拒绝发送，不能通过丢来源或漏算父历史变绿。

回退游标继续是物理游标；从 UI 逻辑历史选择回退/分叉点时，先解析到实际拥有该事件的文件和物理边界。若点在祖先历史中，新指针直接指向那个祖先的对应边界，不把虚拟位置伪装成当前子文件边界。

### 桌面、CLI 与 IPC

IPC 版本升级。会话寻址统一使用规范 workspace 与 session id；事件动作使用 EventRef。旧只带 id 的入口只在唯一归属可证明时兼容，歧义时报告错误，不能扫描到第一个就继续。

桌面隐式工作区从可信 IPC sender 的窗口上下文取得；显式 workspace 经过已登记根闸。会话状态、队列、反馈、pins、改名框、标题和活动标识的键不能只用 session id。窗口关闭后，不允许迟到应答复活其状态。

UI 以来源键生成行、时间线和跳转锚；祖先行标明来源。反馈和 pin 写进当前子会话的注释命名空间，内容指向来源 EventRef，不修改父会话的注释。旧数字注释按原所属会话解释。

CLI 的 replay 输出区分显示顺序与物理来源。`--fork --from` 的轮次在有效可见历史中选择，再由来源映射定位真实父边界；嵌套分叉不可误截同名子文件。未指定足够身份的游标或会话选择失败关闭。

### 搜索与回滚

正文搜索扫描用户可见的有效历史，命中返回所属结果会话及命中来源；同名 id 通过 workspace 区分。预算覆盖祖先读取，可复用本次请求中已验证的父前缀。读不全保持 partial，读不到保持 unavailable；不能将断链当零命中。继续排除 thinking 与隐藏内部内容。

文件回滚按完整有效历史计算目标轮与后续写入，保留已有的“后续又被修改则拒绝自动覆盖”规则。源快照按其真实工作区和来源验证；最终文件动作只落当前选定的受信工作区。`file_restored` 留在当前子日志，并用来源引用说明撤销对象，不写父日志。

侧聊提升、卡片动作、diff 注释等若接受来自继承视图的事件选择，同样使用来源引用；仅限当前本地事件的内部数字索引可保留。不能让另一个数字引用入口成为旁路。

## 父日志生命周期与创建原子性

指针创建前先验证父链，目标采用排他创建；同名目标不可覆盖，临时文件与 metadata 失败要对称清理。CLI 与 desktop 复用同一产品创建入口，gym 保留既有复制原语。

第一版采用依赖保护，不引入新数据库：改名或删除会被指针引用的父日志时，显式拒绝并列出依赖会话。依赖扫描失败同样拒绝破坏性动作，不能把读不动当无依赖。检查与文件 mutation 共享按规范 sessions 根串行的临界区，避免检查后新建指针导致竞态。

未被引用的普通日志仍可照常改名/删除。先删除叶子再处理父会话是可用路径，不提供隐式级联删除。用户在应用之外手工移动文件导致的断链继续显式报错，不猜测替代父文件。

## 启用次序与恢复

先完成来源类型、读取视图、引用兼容及各消费者，再启用产品指针创建。新格式日志的产品写入不得早于所有必需读侧具备解释能力。旧 raw/gym API 不迁移、不批量改写历史。

本批应在隔离检出中完成；不覆盖当前共享工作树中已经验证的修复。若接线未验收，通过 git 恢复本批代码即可保留既有日志；已生成的新格式记录不能交给不支持其版本的旧客户端静默处理。

## 验收

必须同时证明以下行为，而非仅证明 helper 可以调用：

- CLI 与生产 desktop fork 后子日志初始只有一行，父 sha256 不变；当前生产入口不再调用 gym 的复制原语。
- 真 provider 适配器的离线 transport 与生产 session-provider 组装后，模型收到正确父前缀、子消息和摘要；无需真实付费请求。
- 父、子相同数字 id 与相同 tool-call id 不串引用；多层分叉、回退、旧压缩、新压缩、裁剪和摘要插入各有反例回归。
- 产品 UI 的正文、标题、活动行、时间线、反馈、pins、回放、侧聊引用和文件回滚都定位正确来源；两个已登记工作区使用同 id 时也成立。
- 父在飞请求不继承；父 worker 不被子崩溃恢复重派，父 usage 不计入子当前 run，父旧交付不替子当前轮验收。
- 缺失/越界/环/软链逃逸/未知引用版本/歧义身份均失败关闭；搜索相应保持 partial 或 unavailable，不报零命中。
- 有后续写入时的回滚拒绝、被依赖父日志的改名/删除拒绝、并发创建/删除与目标撞名均有真实临时文件回归。
- 原 raw replay、cursor、gym copy 和旧日志/旧注释测试保留。类型、core（明确 maxWorkers=2）、desktop、边界、docs 和相关门通过；源文本 judge 不因搬文件丢覆盖。
- OCR 只用 delegate 选文件/规则，随后独立审查。HEAD 认证与变异验证仅引用确实包含实现的提交；工作树证据单独报告。

# Cairn agent 产品闭环

日期：2026-10-28。用户授权：按执行者判断直接推进；默认交付本地桌面 coding agent。

## 目标与选择

让现有内核和桌面端组成可实际使用的代码任务闭环：配置模型 → 打开项目 → 执行与审批 →
取消/续跑 → 验证 → 查看与导出交付物 → 重启恢复。以真实字节、事件与运行结果验收。

选择增量完善现有 TypeScript/Electron 架构。重写框架会丢失已有权限与事件语义，继续增加
独立功能则不能解决主路径断点；这两条均不采用。现有应用能力优先，首批零新增依赖。

## 约束

- 保留其他会话的已修改/未跟踪文件，不重置、不 stash、不整文件混合提交。
- 不修改规则、冻结判卷、现有断言、权限默认值或日志结构来获得绿灯。
- CLI、桌面、SDK 使用同一核心入口；入口自身须兑现校验后的请求。
- 外部环境变量仍优先；Cairn 注入的旧 key 可以更新或撤销，用户提供的 env 不可被删除。
- 加密存储读不到/损坏必须显式失败且保留原件；切换 workspace 不丢其他 provider 的密文。
- 导出必须留在用户选定的父目录，失败不覆盖既有数据，也不产生依赖源机器路径的成品。
- 本轮不启动云服务、计费、公开发布或无凭据的真实模型测试。

## 首批验收

1. 并发保存不同 provider 不丢更新；失败不污染后续存储操作；损坏文件不被覆盖。
2. 自定义 provider 暂未装载时，已存密文仍保留；未知 provider 的新写入继续拒绝。
3. 替换/删除 key 后，运行环境即时更新；外部 env 优先语义保持。
4. 核心 `handleAgentRun` 尊重 `RunRequest.planRequired`，包括显式 false，优先级为
   override → request → settings；验证门不会因缺少 shell 的重复转发而消失。
5. 项目导出拒绝路径逃逸、源内递归、不可携带的链接，清晰返回错误且不留半成品。
6. 定向测试、core capped、desktop、typecheck、构建与真实 Electron smoke 分别记录。

## 后续产品验收

沿同一主路径检查首次配置、故障恢复、任务终态、结果可发现性和独立安装包。先修复可复现的
阻断，再决定是否需要新增模块。真实 provider 成功率、跨机器运行与签名分发未取得证据前，
不声明完整产品就绪。本机 shell 未配置 provider API key；确定性传输测试不能代替真实模型能力。

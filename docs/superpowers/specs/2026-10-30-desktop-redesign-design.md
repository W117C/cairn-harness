# Cairn 桌面端统一重设计

日期：2026-10-30。状态：设计提案，待用户确认，尚未实施。

## 目标与依据

用户要求优化整个桌面端，明确参考 Claude、Codex、DeepSeek 官方 DeepSeek Harness。随后提供四张具体截图：Codex 完整窗口、推理强度弹层、输入框添加菜单和内置浏览器工具首页。这四张图是本次布局和控件设计的首要视觉依据。目标是让 Cairn 成为可以长时间使用、结构清楚、视觉统一的桌面编码工具。

保留 Cairn 标识、暖色与陶土色点缀，以及现有项目、会话、权限、模型、工具、插件、记忆、自动化和设置能力。统一改变布局、排版、间距、控件和状态呈现。

本提案是新的视觉与布局提案；不把旧版逐项对齐 Claude CSS 的结果当作最终设计质量的证明。产品实现仍须遵守现有安全、会话归属、焦点、无障碍和渲染分层约束。

## 已观察到的问题

真实 renderer 的首页和对话截图显示：大问候语压过输入任务；正文混用衬线字与 UI 无衬线字；新任务、模型芯片和消息正文的视觉重量接近；全局轨、项目侧栏与页内导航形成多层入口。

现有插件、记忆与设置截图还显示：标题、搜索、筛选、列表的密度不一致；插件发现等分类在侧栏和页内重复；记忆的少量统计占据大块首屏。

新截图来自当前构建的合成数据画廊，不能证明真实 Provider 或安装流程。检查期间共享构建目录被另一轮构建替换，设置懒加载资源失效；因此该轮设置截图不作为有效视觉依据。后续验收使用隔离的输出目录，避免相同干扰。

## 方案比较

| 方案 | 结构 | 优点 | 代价 |
| --- | --- | --- | --- |
| A：统一侧栏 | 单侧栏容纳全局功能、项目和会话；中间为当前内容 | 入口有文字、层级更少，默认两栏，跨页一致 | 与用户补充的完整窗口参考不完全一致 |
| B：紧凑导航轨（新推荐） | 保留 48px 全局轨和项目侧栏，重做比例与控件 | 符合用户最新截图，沿用当前导航心智 | 需要避免侧栏与页内重复导航，纯图标需有标签和键盘焦点 |
| C：审阅工作台 | 侧栏、对话、改动面板同屏 | 代码证据更易核对 | 对话空间缩小，不适合默认空态；建议作为 B 的按需展开状态 |

根据用户补充的实际截图，改为推荐 B，吸收 C 的按需审阅状态。A 不再作为推荐。初始三张 AI 预览只用于布局比较；它们早于补充截图，不是像素级验收稿。用户截图中的壳体、输入布局与浮层优先于预览里过大的陶土色新任务按钮、方形输入框、重复设置入口等生成偏差。

## 统一设计规则（提案）

- 默认保留 48px 全局导航轨，项目侧栏约 248px，支持已有拖动与收起；顶栏约 40–48px。浅灰中性的外壳与侧栏、白色主内容面板通过柔和分界形成层级；主内容顶部采用参考图中的圆角边缘。880、1120、1440 CSS px 均需可用。
- 对话阅读宽度约 760px，随可用空间收缩。打开工具时先保留正文与输入框的最小可用宽度；右栏沿用现有宽度偏好与窗口收口机制。
- UI 使用系统无衬线字体，正文 15–16px、常用控件 13–14px、页标题约 22px；中文与英文保持一致的阅读层级。代码继续使用等宽字体。
- 主画布白色、外壳浅灰中性并保留轻微暖感；正文深墨色、说明中灰、边界低对比。Cairn 陶土色集中用于品牌和少量主动作；新任务为轻量图文动作，不做大块橙色按钮。危险、成功、焦点保留各自语义。
- 常规控件圆角 6–8px；输入卡和主内容面板采用用户截图中的更柔和的大圆角，约 20–24px，单独定义语义变量；这覆盖旧输入框圆角规定，不扩大为全局胶囊控件。避免重复边框、卡片套卡片和大块装饰性统计。
- 空间以 4px 为基础，常用 8/12/16/24/32px。控件通常高 32px，密集图标按钮不得低于现有 28px 要求。
- 深色使用同一层级与间距，逐项确认输入、弹层、代码块、选中和禁用态；保留系统与应用内减弱动效设置。
- 不修改字节锁定的 vendor 文件；颜色桥接继续遵守 `cds-adapter.css` 的映射约束。

以上是设计目标，最终尺寸以真实窗口验证为准。若需改变现有视觉规格的断言，先明确新旧契约，再测试新契约；不删除行为约束来换取通过。

## 各页面落地

### 工作台与侧栏

全局导航轨承担对话、插件、记忆、自动化与设置，轨内不重复品牌或设置。项目侧栏顶部为 Cairn、搜索和轻量新任务；项目与会话紧随其后。保留项目分组、运行/等待/草稿状态、搜索筛选、右键菜单和会话预览。服务状态弱化为辅助信息。

顶栏呈现当前页面或会话上下文，工作台只常驻“改动”“工具”。移除重复的大品牌标题；长标题省略不能遮挡动作区。管理页不显示无关的会话操作。

### 首页、对话与输入

首页参照用户截图，中央使用克制的项目问句和标识，底部固定输入区域。选择项目的上下文放在输入卡上缘，不和中间问句争夺焦点。现有建议动作弱化、保持并列，不暗示操作顺序；首次使用的设置检查仍可达。

对话正文统一无衬线。保留消息与代码、表格的阅读结构，用户气泡有清晰但轻的底色，过程默认折叠，错误与等待状态可见。消息操作保留悬停和键盘焦点显现。

输入框分为正文和底部操作行：加号与权限在左，模型与推理强度在右，发送靠最右；用量弱化，不和主操作争抢。保留发送、停止、排队、附件、斜杠技能、文件引用、草稿、快捷键和输入焦点。权限与方案语义保持完整。

加号菜单参照用户第三张图，使用分组的图标、动作文字和必要的辅助信息；接入 Cairn 已有的附件、目录、目标、方案与插件能力。模型/推理弹层参照第二张图，模型选择与当前档位清晰分层，可使用离散滑条与恢复默认动作。档位由当前模型 `thinkingLevels` 和 `thinkingDefault` 决定，不能照抄参考图的固定六档，更不能显示与实际请求不同的值。浮层保持互斥、边缘避让、Esc/外点关闭和焦点返回。

用户截图中的语音、录制技能、其他应用附加等入口，仅在 Cairn 确有可用能力时出现，不因外观模仿新增空按钮。

### 插件

页标题、搜索和导入在统一页头；发现、已安装、更新只保留一组导航。分类为轻量筛选，不再复制整套导航。列表/卡片共享紧凑的名称、来源、能力与动作结构。

保留目录不可用、过期缓存、损坏缓存、安装失败与重试等真实状态。保留来源、信任、指纹、安装审阅和运行中禁止变更等现有规则，不虚构热度或下载数。

### 记忆

将项目/全局/待批数量收为紧凑摘要和筛选。主体是可搜索的记忆列表与详情；标题、元数据、范围、更新信息分别有明确层级。保留搜索、筛选、审批、失败恢复与项目归属。

### 自动化

统一页头、状态筛选和任务列表；名称、触发条件、运行状态、下次执行与动作有固定位置。保留编辑、启停、删除确认、损坏配置提示和操作失败状态。

### 设置与工具面板

设置沿用分组与搜索，内容区使用一致的行布局、字段宽度、开关和帮助文案。保存、验证、失败提示接近相关字段，避免一页多套卡片语言。

改动、文件、终端、浏览器和其他工具共享标题栏、标签、空态、加载、错误与关闭动作；继续切换可见性而不卸载已打开内容，保留 PTY、原生浏览器和表单状态。

内置浏览器空白首页参照第四张图：简洁标签栏、导航与地址栏，下方为已有文件/终端/更多工具入口及真实可用的最近或推荐项。无相关记录时省略推荐区，不伪造内容或扩展到未实现的浏览器能力。

## 实施边界

主要涉及 `apps/desktop/src/renderer/` 的样式、排版与组合组件，以及相应 UI 测试和 Electron smoke。尽量复用现有 React、Radix、Lucide、页框架、状态 hooks 和窗格注册表。

不改变 IPC 协议、Provider 请求、核心调度、权限判定、插件安装与信任规则；不引入新后端能力。确有显示缺陷时，可调整纯展示投影，保持数据归属与现有状态管理契约。

共享工作树已有大量未提交改动；修改前逐文件核对差异，不覆盖、重置、暂存或混合提交其他工作的内容。使用隔离构建输出，避免覆盖正在被其他检查使用的 `dist`。

## 验收

1. 亮暗主题覆盖首页、长对话、过程展开、插件、记忆、自动化、设置和至少一个右侧工具；在 1440/1120/880 宽及小高度窗口检查。
2. 无水平溢出、标题重叠、不可达菜单、丢失输入框；中英文长文本可读；字体和控件层级跨页一致。
3. 新任务、项目切换、会话切换、搜索、发送/停止/排队、模型与权限菜单、工具展开/关闭、设置保存及键盘焦点保持可用。
4. 先运行有意义的聚焦测试和真实 Electron smoke，再运行桌面测试、类型检查、renderer layering 与 desktop boundary 检查。报告真实断言数与跳过项。
5. 审查使用 OCR delegate 选文件和规则，由当前代理执行审查；不运行 `ocr review` 或 `ocr scan`。
6. 交付改前/改后截图、变更范围、实际验证结果；区分合成画廊、真实 renderer 与真实服务，不把原型当作已实现。

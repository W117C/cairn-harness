# ADR 0008：对话轨道（conversation rail）

- 状态：**已接受**——2026-10-28 业主定案「桌面端要做到 Codex / Claude 顶尖水平」，本 ADR 把「对话怎么读」落成可执行的落位与判据
- 日期：2026-10-28
- 决策者：仓库所有者
- 取代：无（**不推翻** brief §二.1「消息之间间距 24px」，本 ADR 把它从「三行各写各的」收成「全表恒为 24」）
- 关联：`apps/desktop/src/renderer/components/conversation-rail.css`（轨道面）、`apps/desktop/src/renderer/tokens.css`（轨道令牌）、`apps/desktop/src/renderer/styles.css` + `components/stream-process.css`（行与过程带落位）、`apps/desktop/tests/conversation-rail.test.ts`（判卷）、`apps/desktop/design/desktop-design-spec.md` §4（视觉规范）

## 背景

桌面端最费眼的一面是**对话面**。2026-10-28 之前的形态，功能齐全、配色也已经是 Claude 那一档，
但读起来像「一堵文字墙」：块与块之间的距离忽大忽小，同一轮里的内容左边缘还差着几像素。
三处真因（都是现读代码，不是猜测）：

1. **隐形占位**：每轮对话都留着一排「hover 才现身」的署名条（时间戳 + 复制/分叉/置顶…），
   它在**流里**占着 30px ⇒ 每轮白吃一格高度，轮与轮之间的档忽大忽小。
2. **左轨不齐**：过程带（思考记录 / 工具调用）缩进 22px，助手正文缩进 28px ⇒ 同一轮里的两段差 6px。
3. **标浮在半空**：品牌标在标列里，正文首行（标题）自带 10px 顶距 ⇒ 标比首行高出一大截，
   像掉在半路上的一枚图标。

Codex 与 Claude 的共同点不是配色，是**读法**：一段回答是一块，过程记录压成一条窄带，
轮与轮之间有一致的档。Claude 的暖白 + 陶土色把这件事藏得很好；Codex 把「一条左轨 + 恒定的档」
当成结构画出来——**两条都没有装饰性的竖线**（这一点是第 4 条被否掉之后才补记的）。

## 裁决

### 1. 一条左轨（`--rail-gutter`）

轮内的**所有**内容——过程带（思考记录 / 工具调用）、助手正文、交付卡——挂在同一条左轨上；
品牌标在标列里，是**轨的标记**，不是另一块内容。

- 左轨宽 = 标列 20px + 网格间隙 8px = **28px**（令牌 `--rail-gutter`）。
- 过程带的图标落在轨上（按钮左内距归零），文字跟在图标后——与正文里的项目符号同一读法。
- 判卷钉住这个等式：改了标列或间隙而不改轨道令牌 ⇒ 红。

### 2. 每一档都是 24px

brief §二.1 的「消息之间间距 24px」此前只落在三行（user / assistant / error）的 `margin` 上，
过程带另写 14/12 ⇒ 段与段的实际间距是 14 / 24 / 36 / 54 四种。

本 ADR 把全表收成一种：**行的顶距 24px（字面量，判卷逐字钉着），过程带的顶距 24px（令牌 `--turn-gap`）、
底距 0** ⇒ 段与段之间恒为 24px。两边的数必须同值，由判卷钉住（改一个不改另一个 ⇒ 红）。

### 3. 署名条是浮层，不占流内高度

署名条绝对定位在**行的下边缘之外**（`top: 100%`），挂在下一段之前的那一档里：

- 不占流内高度 ⇒ 每轮不再白吃 30px，档才恒为 24px；
- 默认 `opacity: 0`，只有 hover / 键盘聚焦该行才现身；
- **隐藏态必须不吃指针**：`opacity: 0` 却仍可点的按钮 = 用户点「过程带」其实点在一条隐形按钮上
  （幽灵点击）。隐藏态 `pointer-events: none`，现身时恢复。

### 4. 轴线：**试过，撤了**（业主在真机上一眼否掉，2026-10-28 20:53）

本 ADR 第一版还画了一条轴：`.reading` 左侧一条 1px 发丝线（`--rail-line`，前景色的 7%），
品牌标是线上的节点，意图是「给『一轮 = 一段』一个落点」。

**业主在真机截图上一句话否掉：「这个线是什么鬼，有用吗？」** 判下来它确实不成立：

- 线上只有品牌标**一个点**，其余全是空跑 ⇒ 那是一根多余的竖线，不是有内容的轴；
- 「轴」这个比喻要成立，线上得有**多个节点**（一轮一个），否则线只是空杆；
- Codex / Claude 都没有这东西——它们的模型标就是标，不挂在线上。

⇒ 轴线整条撤掉，`--rail-line` / `--rail-node` 两个令牌一起删（不留死令牌）。
撤掉之后本 ADR 的其余三条（一条左轨 / 恒为 24px 的档 / 署名条浮层 + 首行齐平）全部成立，
**说明这批的收益本来就不在线上**。

撤掉的理由被写成判据：「对话面不许有装饰性竖线」——
`apps/desktop/tests/conversation-rail.test.ts` 第 ⑤ 条钉住（把轴线放回去 ⇒ 立刻红，已实测）。

### 5. 标与首行齐平

助手行正文的第一块（标题 / 首段 / 列表）顶距归零，末块下边距归零——
档由行的顶距负责，markdown 不许再自己加一段。

## 为什么不是别的做法

- **保留那 30px 隐形占位**：那正是「散落的几块」的来源；保留它等于不修。
- **保留轴线**：试过了，业主在真机上一眼否掉（见裁决第 4 条）；它是装饰，不是结构。
- **把操作条改成菜单（⋯）**：owner 明确裁过「消息操作条做宽」，收成菜单是倒退。
- **把轴线做成可点的导航**：那是另一件事（长对话导航已有目录面板），本轮不碰。
- **改判卷去迁就新结构**：本轮一条判卷都没改语义；相反，是新结构先退让到既有契约
  （24px 字面量、20px 标列、CDS 接线顺序），由新判卷补上「数值自洽」这条新约束。

## 判卷

`apps/desktop/tests/conversation-rail.test.ts`（桌面判卷套件内，随 `pnpm --filter cairn-desktop test` 跑）：

| 条 | 钉的是什么 |
|---|---|
| ① | 左轨宽 = 标列 + 间隙；过程带/思考带/底座 `.toolcluster` 都在轨上 |
| ② | `--turn-gap` == 24 == 行上的字面量（brief §二.1） |
| ③ | 署名条是浮层、不占流内高度 |
| ④ | 隐藏态不吃指针；现身时恢复 |
| ⑤ | **不许有装饰性竖线**（轴线已撤，业主真机否掉）；轨道不引入动效 |
| ⑥ | 标与首行齐平（首块顶距 / 末块下边距归零） |
| ⑦ | 渲染层 CSS 面里不再有对话缩进的裸像素（旧写的 22px 那类） |

七条都能造红：把旧缩进放回去、把浮层改回流内、删掉轴线、改一个令牌而不改另一个——任一处都会红。

# ADR 0007：对象库事故与历史重建（object-store accident & history recovery）

- 状态：**已接受**——2026-10-25 一次 pack 丢失之后的历史重建与引用对齐，本 ADR 记下**发生了什么**、
  **为什么这么重建**、以及**哪些东西永久不可恢复**
- 日期：2026-10-25
- 决策者：仓库所有者
- 取代：无
- 关联：`scripts/recovery/align-references.mjs`（引用对齐工具）、`docs/CODE-WIKI.md`（文档分层）、
  `scripts/docs-check.ts`（D-5 台账 sha 面 / D-11 证人点名面）

## 背景

2026-10-25 本地工作树（`cairn/`）的 `.git/objects/pack/` 里少了一个 pack 文件：
`pack-d6bda0290e0590aea0e2f04b9bcdac73d66a442c.pack` 已不在盘上，只剩下它的 `.idx` 与 `.rev`。

**留下的那个 `.idx` 是最坏的形状**：git 据它认为「这些对象我都有」，
于是既不去补拉、又在遍历时读不到 ⇒ `git rev-list` / `git log` 报
`Could not read 767126682007a2c37bde6012f082e878c9890ec7`，而 `git push` 直接失败。

现读的事实（本地库 `git fsck`）：

- 缺失对象共 39 个：**1 笔提交**（`76712668`）+ **6 棵树** + **32 个 blob**。
- `76712668` 是**从未推送过**的本地提交 ⇒ 远端历史**完整无损**（干净克隆可逐笔遍历验证）。
- 丢失的 blob 落在 12 笔提交的树上 ⇒ **那 12 笔的内容永久不可恢复**（本地与远端都没有）。

## 裁决

### 1. 历史重建：保内容、保粒度，实在拿不出来的折叠成一笔

本地线有 146 笔提交（**全 DAG**，含合并的另一条侧线）引用了那笔缺失提交或落在丢包区里。
本 ADR 采用的重建方式：

- **逐笔重建**：把每一笔的**原始 commit 对象字节**取出来，只改它的 `parent` 行，
  再用 `git hash-object -t commit -w` 写回去 ⇒ 树、作者、提交者、提交时间、说明**逐字保留**。
- **折叠 12 笔**：链底 12 笔的树引用了丢失的 blob，做不出可读的内容 ⇒
  按**其后第一支可读提交的树**折叠为一笔（说明里列清被折叠的 13 笔）。
- 重建后：**135 笔**（1 笔折叠 + 134 笔逐字保留），内容一分不少。

> **为什么不是「压成一笔」**：压成一笔能保住内容，但会把 134 笔的作者/时间/说明压没。
> 本仓的台账是**逐页引用提交地址**的审计链，粒度本身就是证据。
>
> **为什么是「全 DAG」而不是「第一父链」**：只沿第一父链重建会**漏掉合并的另一条侧线**，
> 而那些侧线上的提交同样被台账引用 ⇒ 重建后的历史里那些地址追不到 ⇒ D-5 判红。

#### 1.1 重建时踩到的两个「看着对、其实错」的坑

这两处都不是本仓的缺陷，是**重建动作本身**的陷阱，记下来免得下一个人再踩：

- **提交头的行序有讲究**：git 的提交解析按 **tree → parent → author → committer** 读。
  把 `parent` 放到 `committer` 之后 ⇒ `cat-file -p` 照样看得见那一行，
  但 git **内部不认**（表现为 `rev-list --parents` 查不到父、`git log %P` 为空）。
  写的时候按 git 自己的次序摆。
- **地址的长度不是恒为 7 位**：写死 7 位的替换规则对 **8 位地址一个都匹配不到**
  （前 7 位后面还跟着十六进制字符 ⇒ 负向前瞻不成立）。现态页 `rev:` 里的地址就是 8 位，
  那种情况会**静默漏掉**——「看着没换、其实没换」。按名字换地址时同理：
  在 8 位地址里只换前 7 位会**换出一个混合名**（`7429acf9`），台账的路径指针与盘上工件名对不上 ⇒ D-11 判红。

### 2. 引用对齐：只换指针，不改页

重建让链上每一笔的地址都变了 ⇒ 台账里那些页引用的旧地址不再存在 ⇒ `docs-check` 的
**D-5（台账 sha 面）**判红。而取料目录名 `head-cert-<sha>-<date>-<time>` 里嵌着提交地址 ⇒
**D-11（证人点名面）**判红。

⇒ 用 [`scripts/recovery/align-references.mjs`](../../scripts/recovery/align-references.mjs) 做**指针对齐**：

- 台账与现态页里 7 位 sha 前缀 → 同一笔提交的**新**前缀（页正文、页号、顺序一个字不动）；
- 名字里嵌着旧地址的取料目录**改名**，工件正文里指向自己的那一处地址同步换掉
  （工件内容本身逐字不动）。

**为什么改名而不是「把名字留着」**：目录名里的那一节**就是**它所认证的那笔提交，
提交换了地址，名字跟着换才是如实的；不改名则 D-5 与 D-11 互相打架
（名字里的旧地址追不到 ⇒ D-5 红；名字指向新地址的目录不存在 ⇒ D-11 红）。

### 3. 折叠段的那几处引用：指向折叠提交

链底 12 笔的地址永久不可恢复 ⇒ 台账里指向它们的引用统一指向折叠提交
（它承载那一段唯一幸存的树）。这是**降级但可追**，
不是「读不到被读成没问题」。

### 4. 分支拓扑：干线与在飞线分开

- `main`：**标准化后的干线**（治理面 + GitHub 协作面 + CI 加固）。
- `fix/spec-summary-double-count`：**在飞线**（重建后的 116 笔 + 引用对齐两笔）。
- `integration/dev-line-with-standardization`：在飞线 + 标准化成果的预合并件，
  供在飞线收束后并回干线时省掉一次手工解冲突。

### 5. 已知边界（写清才叫裁决）

- **本 ADR 描述的重建只覆盖本地库**。远端历史本来就没坏（`76712668` 从未推送）。
- **12 笔的内容永久不可恢复**——不是「暂不可读」，是不可恢复。
- 重建让本地线每一笔的地址都变了 ⇒ **旧的地址在远端不再存在**；
  本地库若 `git gc --prune` 掉旧对象，那些旧地址在本地也会失效（引用已对齐，无残留依赖）。

# ADR 0004：桌面优先、面向非专业开发者的产品范围

- 状态：**已接受**——2026-10-15 业主确认真实方向（「让不太懂代码的人通过自然语言做网页、小工具，并修改已有项目」），本 ADR 把它落成可执行的工程约定
- 日期：2026-10-15
- 决策者：仓库所有者
- 取代：ADR 0002 的 D2（受众）与「交付面只做 CLI」两条；ADR 0001 的 core/desktop 分层与「src 不反向依赖 apps/desktop」继续有效
- 关联：`outputs/product-plan-nontechnical-users-2026-10-15/PLAN.md`（现状、缺口、指标与波次）

## 背景

ADR 0002（2026-10-06）把 v1 受众定为自用/内测开发者、交付面只做 CLI。此后仓库事实已经变化：
桌面端（Electron + React）持续施工并在 CI 中作为一等验证面；模型接入、权限、快照/撤回、
浏览器与终端窗格都已可用。2026-10-15 业主确认：下一步产品目标不再是开发者 CLI，而是
**让普通用户把任务做完**——描述需求、看到结果、继续修改、拿走成品。

## 裁决

1. **受众**：非专业开发者。术语中出现 Provider、endpoint、端口、依赖等概念时，必须有
   普通模式向的替代表达或默认值；高级参数进「详情」。
2. **交付面**：桌面应用（`apps/desktop/`）是产品主交付面；CLI 与核心库保留为技术底座与
   高级入口，不再作为普通用户的交付通道。
3. **首批任务类型**（超出范围需先立支持标准）：
   - 做展示网页（介绍页、作品集、活动页、宣传页）；
   - 做轻量工具（计算器、报价、待办、文本处理、本地数据小应用）；
   - 改已有项目（改文字/颜色/布局/表单规则、加一个小功能、修一个可复现问题）。
4. **支持边界**：macOS 优先；项目形态先支持「零依赖静态 HTML/CSS/JS」与「一种经过探针验证的
   React/Vite 形态」（模板见 `src/main/project-templates.ts`，验证记录见
   `outputs/product-plan-nontechnical-users-2026-10-15/probes/`）。导入已有项目必须先给
   「支持 / 需要补充信息 / 当前不支持」的诊断结果，再开始工作。
5. **暂缓**：账号体系、数据库、支付、多人协作、复杂后端、跨软件电脑操作、托管模型额度。
   用户提出时识别需求并说明扩展成本，不承诺实现。
6. **验收口径**：以「目标用户独立完成并接受结果的任务比例」为主指标（PLAN §11 的建议目标，
   需用首轮真人试用校准）；工程测试与门禁是必要条件，不是完成率的替代证据。模型说「完成」
   不能覆盖客观失败；验证证据晚于最后一次修改才有效。

## 后果

- 产品功能默认按「普通模式 + 详情折叠」设计；首屏不出现插件/技能/记忆/多代理等高级概念。
- 新功能必须配「失败分类 + 可执行下一步」；「保存成功」不得被表述为「服务可用」。
- 涉及用户项目的写操作必须可恢复（快照/撤回），恢复动作不静默覆盖用户后续修改。
- 门禁与发布验证需要覆盖桌面完整用户流程；工作区绿、HEAD 绿、安装包绿是三种不同证据。
- 本 ADR 不改变 `src/` 与 `apps/desktop/` 的一向依赖边界，也不改变既有权限与凭据纪律。

## 推翻条件

- 出现「首批任务类型」之外的真实高频需求（需要连续三个独立用户样本）；
- 或托管模型/账号体系成为首次使用流失的首要原因（需先有带引导 BYOK 的实测漏斗数据）。

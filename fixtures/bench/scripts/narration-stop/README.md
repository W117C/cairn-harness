# `narration-stop` 剧本：把「跑过 shell 之后模型收工」那一拍钉成确定性输入

**它复现的形状**（2026-10-13 真模型面上抓到两次，见台账第 468/469 页）：模型诊断正确、
跑过一遍测试，然后**不再调工具**、用一句「先提方案：」收尾 ⇒ loop 按「无工具调用＝任务结束」
收工 ⇒ 收束闸补一拍发现仍是红。那一拍之后会不会**再要一轮去修**，正是 `autoVerifyRepair`
这个开关管的事。

**为什么需要这个 fixture**：真模型面上那个形状是随机的——同日 6 趟带 `--auto-verify-repair`
的对照臂里它一次都没出现（台账第 469 页：「机制 0 次触发」）⇒ 开关值不值那一倍成本
在那批读数里**量不出来**。这份剧本把它钉死，于是 OFF/ON 的分歧可复跑、零花费。

**四轮**（`round_end` 是装配期哨兵，见 `src/providers/round-marker.ts`）：

| 轮 | 内容 | 作用 |
|---|---|---|
| 1 | 读 `tests/checkout.test.js` | 与真轨迹同形的前置动作 |
| 2 | `npm test 2>&1 \| head -60` | **管道吞掉失败退出码 ⇒ `ok:true`** ⇒ `wroteThisRun` 置位（收束闸补拍的前提），与真轨迹逐字同形 |
| 3 | 纯文本：「根因清楚了…先提方案：」**无 tool_call** | ← 被复现的那一拍 |
| 4 | 写 `src/checkout.js`（把运费判定挪到折扣之后） | 返修臂多要的那一轮会拿到它 |

**OFF/ON 的分歧**（判卷口径见 `tests/loop-eval-repair-arm.test.ts`）：

- OFF（产品缺省）：轮 3 收工 ⇒ 补一拍红 ⇒ **直接收**，轮 4 根本不会被要到 ⇒ 靶子仍带 bug。
- ON（`--auto-verify-repair`）：红拍之后再要一轮 ⇒ 拿到轮 4 ⇒ 写盘 ⇒ 第二拍绿 ⇒ 收。

配套任务：`fixtures/bench/tasks.json` 的 `B1-bugfix-crossfile`（种子与可见/隐藏判卷都由它给）。

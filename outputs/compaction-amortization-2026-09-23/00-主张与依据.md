# 00 主张与依据：压缩重写代价的摊销（pay once, take the whole discount）· 2026-09-23

> 依据是同日前一格的实测（`outputs/prefix-churn-2026-09-23/00-实测发现.md` §5）。
> 落地在 `src/agent/compaction-cost.ts`，判据在 `prefix-churn-check` 的 PC7，施工见 `01-施工回执.md`。

## 0. 一句话主张

**缓存断点的位置 = 第一个被摘除/替换的消息，与这一次摘掉多少内容无关。**
所以既然横竖要在前面断一次，就该在这一次里**多压一点**——把接下来几次的小断重写省掉。
反过来，「为了省缓存而推迟压缩」是错的：推迟只是把同一次断账往后挪，还多付几轮大上下文。

## 1. 为什么现在才看得见这件事

之前没有「一次压缩值多少」的数，只有 `tokens_before/tokens_after`（量的是**上下文体积**，不是**缓存代价**）。
PC5/PC6 把头部存活比例量出来之后：

| 事件 | 头部存活 | 含义 |
|---|---|---|
| 一次阈值压缩 | **161 / 8,286 字符 ≈ 1.9%** | 压缩一次 ≈ 整段前缀重写一次 |
| 一次裁剪转轮 | 作废 40,299 字符 | 同上，但断点更靠后（代价小一个量级） |

⇒ 压缩是这段里最贵的动作，而它对**体积**的节省与对**位置**的破坏是两笔独立的账。

## 2. 设计（依赖序：长在哪、谁持有、为何不是别层）

| 层 | 内容 | 持有者 | 为什么不是别层 |
|---|---|---|---|
| L0 纯策略 | `amortizedCompactionConfig` / `amortizedTailBudget` / `measureHeadSurvival` / `isExpensiveRewrite` | 新叶子 `src/agent/compaction-cost.ts`（只 `import type` + 复用 `prefix-churn` 的 LCP） | 策略必须是纯函数才进得了单测与门；且判据只有一只，门与生产共用 |
| L1 状态 | 「上一轮发出去的装配」+「上次压缩的头部存活比」 | provider 闭包（**一个 run 一个 provider**） | 抖动是**相邻两轮**的量，必须跨请求；放 `turnGenerator` 内局部变量每请求就清零（本轮实测踩过），放模块级会跨会话串台 |
| L2 生效 | `coordinator.maybeCompact(events, decision, { config })` 逐次覆盖 | `src/agent/compaction.ts` | 只有 `runCompaction` 里那一行 `clamp(available × tailRatio, tailMin, tailMax)` 读 tail；不改触发判定、不改最终硬闸 ⇒ **不引入第四把尺**（该文件头注已记着「三处同源靠输入不可变才成立」的旧坑） |
| L3 判据 | PC7（同一条会话开关两支 A/B：压缩次数 + 累计重写字符） | `prefix-churn-check` | 不新建第 36 道门：这条判据要的观测与 PC1–PC6 同源（真 provider 发出去的那一对） |
| L4 反脆弱 | 6 条 `cc-*` 针脚 | mutate-verify | 「算了不用」「只收一个旋钮」「floor 形同虚设」都是能全绿的错 |

## 3. 策略本体与三条硬边界

```
enabled=false ｜ headSurvival=null ｜ 上次不贵(share > 0.15) ｜ 已在 floor ｜ trigger=overflow
   ⇒ 返回 undefined（调用方原样用旧配置：逐字节零回归）
否则 ⇒ { tailRatio: next/available, tailMaxTokens: next }   // 两个旋钮一起收，否则被 clamp 顶回去
next = max(min(budget × 0.5, budget), min(1_500, budget))    // 工作集下限
```

三条边界各挡一种失败：`overflow` 不摊销（已装不下，少压只会立刻再撞硬闸）；
`floor` 保住最近工作集（再压就在伤行为，不是在省缓存）；
「已在下限就不动」而不是返回一份等效配置（守住**逐字**零回归的语义，别让门绿在等价物上）。

## 4. 实测（A/B，同一条合成会话 8 轮）

```
关 ⇒ 压缩 5 次、累计重写 42,588 字符
开 ⇒ 压缩 4 次、累计重写 33,971 字符        （-1 次整段前缀作废，-20.5% 重写字符）
```
触发种类两支都是 `auto`（threshold），没有 overflow ⇒ 差异确实来自策略而不是撞闸路径不同。

## 5. 明确不做（附理由）

| 不做 | 理由 | 反转条件 |
|---|---|---|
| 估「还剩多少轮」再决定压不压 | 需要 horizon，而 horizon 无从可信取得——同目录 `economics.ts` 的既有立场就是 `remainingBoundaries: null`、**绝不从模型散文或默认比例臆造**（注释原话）。拿假 horizon 做摊销会把「省」算成「亏」 | 有可验证的轮数分布来源（同一 fixture 的真实分布）时 |
| 推迟压缩 | 见 §0：断账只是后移，还多付几轮大上下文 | — |
| 给 `compaction` 事件加「重写代价」字段 | `src/events/index.ts` 正在别人的在飞改动集里（`M`），本轮不碰 | 该文件空出来时，把 PC5 的 `cacheSurvivalAfterRewrite` 落成事件增量字段（面板才看得见） |
| 接 settings 开关（默认档位） | 生产入口在 `src/main/agent-runner.ts`，同样在飞 ⇒ 本轮策略**只在 provider 参数上可达**，产品默认仍是关 | 与 C-3（面板装配账）同批做 |
| 动质量闸（`minProgress`、膨胀拒绝、三拒绝） | 一个都不动。摊销只可能让单次压缩摘得更多，方向与质量闸一致；越界会被质量正当拒绝 | — |

## 6. 待裁决 / 未量

- **质量代价没量**。这条只优化缓存重写，多压 = 少留最近上下文。要不要默认开，得先在靶面上量「同样任务，tail 2,900 vs 1,500 的完成率差」；靶场现况（`requests=1`、冻结判卷区）量不了，须先走 BLOCKED 请求换判据。
- 数值门（0.15 / 0.5 / 1,500）都是**从合成样本反推**的量级，不是标定值；标定需要真连 + 真长会话。
- 本读数来自合成会话（CJK、mock 摘要器），**不是真钱数**。

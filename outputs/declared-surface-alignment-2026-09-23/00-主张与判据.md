## 二、外部读数（次序与"只设权限门不够"）

《Closed-World Resolution Against ToolHallucination in LLM Agents》（arXiv 2609.19425）：

- 定义即本页 G3/G4 的形状：**「calling a tool that was never registered, or a real tool with arguments
  no schema contains」**；分五类——不存在的名、缺/多字段、类型不符、**未授权地使用真实工具**
  （= worker 拿了自己表外的工具，正是 `shell_rw` 那一族的对偶）、跨工具签名借用。
- 次序结论：**「hallucination defense must precede the causal gate」**（§V），Resolution Rung 放在**授权层之前**，
  三重拒绝（注册表成员 / 必填键 / schema 合规）后才允许进入下游策略。
- 基线结论：**「gating-only stack executes entirely」**（§VI-A）——只加权限门，幻觉调用照跑；
  装上 resolver 后各类攻击成功率 **100% → 0%**。
- ⚠️ 它是**安全评测**（含对抗面），不是"日常模型犯错的比率"；且**多服务器**场景为主。
  ⇒ 支撑"次序"与"前置校验"这两个形状，不支撑我拿 0.57 当 DSH 的预期失败率（本仓该轴无观测者，G5）。

## 三、设计：三层（各答「长在哪 · 谁持有 · 为何不是别层」）

### L0 名单由**注册动作**产出（不是第 5 份手抄表）

`legalToolNames(scope)`：作用域（主会话 / worker-read / worker-write / sidechat）→ 合法名集合，
**由注册点自己登记**——`installAppTools()` 注入一个名字就往账上加一条、`worker-tool-table.ts` 同理；
`TOOL_NAMES` 仍是静态面的唯一源，联合表只在其上叠加"运行期注册了谁"。

- **长在哪**：注册动作处（`base.ts` 的注册表 + 各注入点），**不是**新写一张常量表——
  我探针已经演示了手抄表必然漂（§`01` 四）。
- 消费方：G4 的"哪些名字合法"、L1 的拒绝判据、以及 `orchestrator-config.ts` 那条 J7c 类断言
  （让它从"碰巧为真"变成**名单驱动**，那是该注释自己想要的东西）。

### L1 Resolution Rung 前置（次序修正，最小一步）

`loop.ts` 里把**"名字在不在本作用域合法集"**提到权限判定**之前**：不在 ⇒ 直接 `ok:false` 回执 +
`rejectReason: "not-registered"`，**不进权限分级**（也就不进风险三通道、不占审批卡）。

- 参数级校验（外部论文的第 (2)(3) 类）**先只记账不拒**：
  本仓有 `gateToolSpecs` 等静态规格表，但误拒率没人量过 ⇒ 与 16/17/18/21/25 同口径，
  **detection 先行**。反转条件：三类拒绝各自的真阳性率量出来（且现有真轨迹一条都不该被新规则拒掉）。
- ⚠️ 次序改动会碰到 `autonomy.ts` 的评估入口与 `tool-surface` 的可见面；**不许顺手改判定语义**。

### L2 声明 ↔ 可达双向对齐（把 G2 变成每次都被算出来的数）

`alignSurfaces(declared, reachable) → { advertisedUnreachable, reachableUnadvertised }`，
两组差集**都必须为空或带登记**：

- 登记形状沿用 23 的三态：`intentional(doc-pointer)`（如把 3 家 provider 显式登记为 V1 边界并指回 P2-6）、
  `planned(gate-id, date)`、`unmeasurable(reason, reversal-condition)`；
- 同名多份（G1）走同一张登记表，且**必须写明期望关系**（子集 / 超集 / 交）——
  `HISTORY_STATES` 的 `all` 是"超集且合法"的标本，`PROVIDER_IDS` 是"该子集却各自漂"的标本。

**归属**：L2 的门与 23 的 `observer-coverage-check` 合流成**一支门、两张表**
（同一套"枚举 + 登记 + 只降不升水位"的机器；再开一支就是又一份出口副本）。

## 五、明确不采纳（理由 / 证据 / 反转条件）

| 不采纳 | 理由 | 反转条件 |
|---|---|---|
| 重名即红 | `HISTORY_STATES` 证明良性同名差异真实存在（多一个筛选项 `all`），一律报红会杀死门 | 永不——改为"登记期望关系" |
| 把所有名单强行合并成一份 | 语义本就不同（权限用的 `isSideEffectTool`、报告用的 `WRITE_TOOLS`、UI 的 `HISTORY_STATES`）；17-L0 已裁定"归并必须行为不变" | 永不 |
| 引入 JSON Schema 校验库 | 多一个依赖与分发面；本仓已有 `gateToolSpecs` 等静态规格表，三重拒绝自建即可 | 反转：规格表表达不了的嵌套结构出现 ≥3 例 |
| 参数校验一上来就拒 | 误拒率没量过；拒错一次用户就要重跑整轮（成本不对称） | 先记账，量出真阳率后再谈拒 |
| 靠提示词教模型"别调用不存在的工具" | 外部结论相反：问题在**出 surface 无约束**（伪造集中在 raw-JSON），不在模型记性 | 永不 |
| 把 provider 的 3 家"够不着"直接补成可选 | 那是**入口工程**（key 存储、UI、BYOK 计费），不是本页的读数问题；且跨家收益没有数（`gap-fix` §三已裁） | 由 P2-6 那条单独推进，本页只保证它**被登记着、能被数** |

## 七、同日二次复核（2026-09-24 · 动手前的可观测性预检，结论是否）

**四条实测读数（都推翻本页动笔前的假设，不是推翻整页主张）**：

1. 假名（`totally_bogus_tool` / `mcp__ghost__do_it` / `write_file_v2` / `shell_rwx`）在
   read-only / default / guided / auto **四档全部拿 `allow`**，`isSideEffectTool` 一律 false。

   但它**兜住了后果**：幻觉名不会被执行。所以前置改变的只是回执文案与 hook 位次，

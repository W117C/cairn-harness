## 一、结论先行（七条）

1. **「先调查模型报告 → 得到能力画像 → 据此动态调工具集」不立项。** 三条硬伤各自独立成立：收益不可观测、归因链断、退化即 no-op（见 §三、§六）。
2. **核心分水岭的裁定：机制上不是换皮，可验证性上与前序死在同一处。** 前序判死的是「按效用/概率裁剪工具面」，本次是「按模型身份条件化」——**自变量确实换了**，且模型身份是确定性输入、可离线枚举，不依赖概率模型，因此**不受前序「把裁剪权交给概率模型（laya）」三条官方否决的打击**；但两条路都要先有一把「哪套面在哪些任务上更好」的尺，而**这把尺在本仓不存在**（`tool-choice.ts:97–102`）。准确表述：**换了自变量，没换掉那把缺失的尺。**
3. **用户已确认本次语义（2026-10-04 主会话当面确认）：「动态调整适合它的工具」指调用形态／编辑格式契约，不是工具集子集。** 这是唯一被一手先例背书、且有可量化读数的一支（§四 H 组、§五 方案 F）。
4. **业界确实在按模型条件化 harness，但判据不是「模型报告」。** Aider 维护 357 条 per-model 设置（含 `edit_format`）、Roo Code 54 条 per-model 工具项、Cline 高峰期约 10 个 per-model 提示词 variant 目录、OpenAI 官方给出 GPT-5→5.1 的迁移清单。**判据全部是厂商自己的工具/格式约定与人工实测的格式服从性；「读模型报告 → 能力画像 → 挑工具集」这条机制在检索到的先例里一个都没有。**
5. **收益天花板很低。** 按前序实读，本仓按 tier 合法可动的只有定时五件（5 件 / 2,482 字符 ≈ **913 tok**），`core` 17 件受 MS6 硬约束不得自动砍。按模型身份切工具子集，天花板与前序方案相同。
6. **本次唯一新增实测（只读排查）：本仓写入面的格式防线有四个出声入口、一个未出声入口。** 未出声的是 `write_file` 对 `content` 的**内容形态零校验**：任意 ≤50KB 字符串直接落盘（`write_file.ts:47`），而唯一的相关提示 `isNearCopyRewrite` 覆盖不到「把 diff 正文覆盖旧文件」这种形状，写后 LSP 诊断**默认关闭**（`lsp.ts:109`/`118`）。这是 Aider #5486 的同族失效模式，但在本仓表现为**静默接受错误格式的写入**（落盘即污染），不是静默丢弃。
7. **最强的「不必做」外部反证**：arXiv 2608.26218《Same Model, Different Harness》报告一套**冻结**的 harness 改动在三个设计不同的模型上「without model-specific retuning」同样提升读数。⇒ 收益可以先在**不做模型特定化**的前提下拿到；按模型定制是**额外且尚未被证明必要**的复杂度。

## 二、核心分水岭的裁定（三位成员的分歧处理）

三位成员在**结论（不立项）**上一致，在**定性**上分成两派。两派都对，作用在不同命题上——不按人数投票：

| 命题 | 主张 | 依据 | 裁定 |
|---|---|---|---|
| **机制上是不是换皮？** | 成员二、三：**不是**，有三个真新自由度（按模型身份条件化 / 改 schema 形态而非子集 / 按模型换采样档） | 前序的自变量是「效用/概率得分」，本次是「模型身份」；后者确定性、可离线枚举、不依赖概率模型 | **成立。** 前序「laya 三条官方否决」只否决「把裁剪权交给概率模型」，不覆盖确定性查表。这个区分必须保留，否则会误杀 |
| **可验证性上是不是换皮？** | 成员一：**是**，两条路的判据同源（都来自模型之外），都要先有「哪套面在哪些任务上更好」的尺 | `tool-choice.ts:99` 自陈：`session_meta` 不记「当时有哪些可用」⇒ 连装配现场都重建不了 | **成立。** 前序结论 ⑤「哪套工具面在哪些任务上更好，全工程无一处记账」不会因为判据从「概率」换成「画像」而消失 |

**合并后的一句话**：用户设想引入的是**一个新的自变量**，但它落回**同一把缺失的尺**。

**三条对抗性问题的回答**：

2. **模型身份未知时画像从哪来？** 自由档 `freeform/`、厂商静默换后端（B1）、新模型上线当天——三条都落到同一支合成保守卡（R4/R5）⇒ **退化即 no-op，等于现状面**。这不是设计缺陷，是刻意的（注释明写不能把「可能支持」报成 `true`），但它同时意味着 **C 的收益在未知模型上恒为 0**。
3. **与既有硬约束是否冲突？** R8 更正后：PC3 不触发（跨会话）；真正的代价是 **R7：工具面一变，`[首条 system, tools]` 整层作废**。所以按模型换工具面 = 每次换模型把可缓存前缀整段作废。**B 之所以比 C 便宜，正是因为它让被 defer 的工具不进面**（B3）。

## 六、本次唯一新增实测（只读排查）：写入面的格式防线

排查问题（源自 E1 的同族失效模式）：**模型返回非预期格式时，本仓是出声还是静默？** 主理人只读实读，未运行任何测试。

| 入口 | 判据 | 定位 | 出声？ |
|---|---|---|---|
| 未知工具名 | 名字不在工具表 | `src/agent/loop.ts:482` | ✅ `{ok:false, output:"unknown tool: <name>"}`，模型看得见 |
| `apply_patch` | 非字符串 / 空 / 超限 / 解析失败 / 无 `diff --git` 段 / 无可应用改动 | `src/tools/apply_patch.ts:169–181`、`:246`、`:253` | ✅ `ToolError` 逐条点名 |
| `edit_file` | 0 处匹配 / 多处匹配且未加 `replace_all` | `src/tools/edit_file.ts:71`、`:75` | ✅ 报匹配数 + `nearestHint` |
| `write_file` 参数类型 | `content` 非字符串 | `src/tools/write_file.ts:19` | ✅ 抛错 |
| **`write_file` 内容形态** | **无任何校验**（≤50KB 字符串直接落盘） | `src/tools/write_file.ts:26`、`:47` | ❌ **静默** |
| 写后诊断回流 | 仅当 LSP **已配置且** `enabled` | `src/tools/lsp.ts:453`；无配置 ⇒ `{enabled:false}`（`:109`、`:118`） | ❌ **默认关闭** |
| 写后「整份重写」提示 | 仅 `old ≥ 40 行` 且 `改动 ≤ 10%` | `src/tools/line-delta.ts:41–42` | ⚠️ **覆盖不到**「把 diff 正文覆盖旧文件」（那种写入会改动几乎全部行） |

**结论（可复核）**：本仓的格式防线**四个入口已出声，一个入口未出声**。未出声的入口是 `write_file` 的内容形态——模型若把统一 diff 正文当作 `content` 传入，结果是 `ok:true`、文件被 diff 文本覆盖，且既无后置提示（改动远超 10%）、也无诊断回流（LSP 默认关闭，除非仓库显式配置）。

**为什么这条值得单独记**：前序与本团成员都在谈「丢了不该丢的工具」，而 E1 的另一半是「**收下了不该收的内容**」。后者的代价方向相反——**落盘即污染**，比丢弃更贵，且正好落在本仓唯一默认关闭的观测面（LSP）后面。**这一条不需要新造量具**：它是一条可以静态判定的代码事实。

**同时登记一条已有的正面先例**：`src/tools/diagnose-parse.ts` 文件头明确写着「**解析不出的行不猜**：工具那侧如实说「没解析出来」并把原文尾部带上——编一条带假行号的结构化条目比不结构化更坏」。**同一条纪律可以照搬到写入面**，与 PC3「工具面变了必须出声点名」同族。

## 一、缺口（本仓自己的指针，不是外部的）

全仓扫下来，写路径上关于「文件在模型看过之后又变了」的检测面是**空的**：

| 面 | 现状（file · 符号） | 缺什么 |
|---|---|---|
| 覆盖前置 | `src/tools/write_file.ts`：`oldText` 那段——为算 `lineDelta` 而 `stat`+`readFile`，注释自己写着「写盘本身不依赖它」，随后丢弃 | 旧内容在手里，却从不回答「被覆盖的这 −N 行模型见过吗」 |
| 编辑前置 | `src/tools/edit_file.ts` 里 `readFile` 之后直接与 `old_string` 做 `indexOf` 计数（行号不写死——该文件正在被 D7 改） | 只比字面量；**分不清**「你抄错了」与「你的视图过期了」，两种都归成 0 匹配 |
| 读过的记录 | `src/tools/read_file.ts:run` 只返回 `{ok,output}`；它 `stat` 过、知道 `size`/`offset`，**一个字都不留** | 没有 per-session「模型见过哪些路径、以什么覆盖面」的账 |
| 恢复（不是检测） | `src/tools/snapshot.ts`（**在飞、未提交**）`snapshotBeforeOverwrite` | 它**从不拒绝**、**从不告知**，只是安静地留一份原件。恢复 ≠ 检测，两者不互相替代 |
| 已有幂等/重试面 | 无：`idempot\|at-least-once\|resultUnknown\|dedup` 在 `src/tools/` 命中 0 | （那是**能力 17** 的靶子，本页不占，见 §六） |

**为什么这条比看起来更严重**：`outputs/impact-graph-boundary-2026-09-23.md` 已经点过同一个缺陷类——
「写后富化**静默**失败本身就是缺陷」。这里不是富化失败，是**富化面根本没建**：
`−N 行` 这个数字已经在回执里了，只差把它归到「你删的」还是「别人早就写在那儿、你没见过的」。

## 二、为什么这是 agent 共同的问题（外部读数 + 这篇没给什么）

- **arXiv 2609.20804《An Empirical Study of Harness Design for Coding Agents》**（2026-09，实证研究）
  所评架构把「先看过才能改」当成硬前置：§2.4 原文 `detects external modification through a content hash`；
  §7.1/Fig. 13 两条规则——跳过前置读取的编辑**直接拒**，整份覆盖要求
  `pass overwrite=true AND have read it fully first`。⇒ **内容哈希 + 读前置 + 显式覆盖旗** 这三件
  在最新的 harness 实证里是一整组，不是单点技巧。
  ⚠️ **它没有给的**：没有文件类错误的分类学与发生率（只统计任务成功率/步数/阶段分布），
  且是**单一自研框架**、无跨 harness 采用率对比；作者在 §6 Limitations 自己承认
  「没有把工具数量/动作粒度与其它界面属性隔离」。⇒ 外部证据只支撑「这组机制被认为是必备件」，
  **不支撑任何收益百分比**。本页 consequently 把收益全部押在本地实弹（`01` §一）上。
- **市场现役同款**：Claude Code 的 `File has been modified since read` 是一等报错，
  用户侧踩到到需要写「5 种常见编辑报错修复」指南的程度（含 Windows 专项 bug 串）。
  ⇒ 两个方向同时成立：**加了这道闸会有人频繁撞上**（所以误报率必须先量，见 §五），
  且**不加的代价是静默改错**（见 `01` §一第一条）。

## 三、设计：三层，各答「长在哪 · 谁持有 · 为何不是别层」

按依赖排，不是并列——L2 没有 L1 就无从判，L3 没有 L2 就是拍脑袋拦。

### L1 账（状态）：`SeenLedger` —— `Map<rel, {hash, coverage, seq}>`

- **长在哪**：run 生命周期。由 `src/main/agent-runner.ts` 构造，经 `runLoop` 透传成
  `ToolContext.seen?: SeenLedger`。透传口子是现成的：`loop.ts` 里构造 `ctx` 时已经在条件展开
  `opts.signal`（C12 取消信号）与 `opts.impact`（M7 影响面钩子），`ToolContext.snapshot?: boolean`
  则是同类上下文位、由 worker 工具表显式传 `false`（行号不写死：这几处正在被 D7 改）。
  ⇒ 复用同一条「runner 构造 → loop 透传 → 工具消费」的口子，**不新开创面**。
- **记两笔，不是一笔**：
  ① `read_file` 成功时记（内容 hash + 覆盖面）；
  ② **`edit_file`/`write_file` 成功时也记**（把「我刚说成的新状态」记为基线）。
  ② 是本地读数直接驱动的：`01` §二 M5 = **14/73 次是同路径无重读的二次覆盖**。
  不记 ②，模型每次自改之后立刻退化成「没见过」，闸会在自己脚下天天误报——第一次误报就失去信任。
- **为何不是别层**（四条都撞过）：
  - **不建在 `ObservationLedger`（`src/agent/ledger.ts`）上**：那是**工具输出**的内容寻址归档，
    键是 `callId`，语义是「事后能 recall」；本面语义是「动手之前模型见过什么」= **前置条件**。
    前置条件不能建在事后归档上——`observationPack` 默认关（`src/main/settings.ts` 里
    `observationPack: false`，实测），而 `solpi-runtime.ts` 只在
    `observationPack || evidenceReceipts` 时才 `createObservationLedger`：一关，这面就塌。
  - **不建在 `impact` 上**：`outputs/impact-precision-2026-09-23.md` 实测其图仅约 20% 边有 import 支撑，
    `impact-graph-boundary` 又实测 36 个源文件静默 no-op。**低精度面不能当安全前置**。
  - **不建在 git 上**：`unseen` 必须相对「模型上一次看」，不是相对 HEAD——用户未提交改动是常态，
    拿 HEAD 当基线会把用户自己的代码报成"别人的改动"。
  - **不用 OS 文件锁 / fs.watch**：外部进程 + 分发面；且它解决不了真正的问题——
    模型手里的 `old_string` 是旧的，这件事在**写入那一刻**比任何监听器都判得准。

### L2 判（纯函数）：`staleViewVerdict(entry, curHash, coverage) → 五档`

`new`（盘上没这文件） / `fresh`（哈希等于模型所见） / `stale`（见过，但盘已变） /
`blind`（从没见过） / `self-derived`（只见过自己上次写成功的回执，没见过内容）。
coverage 维度 `full | window | truncated` 单独一列：**`read_file` 截断时模型看的是窗口，不是整份**，
拿整份哈希当「见过」会系统性过度声明。
⚠️ 诚实边界：本地语料 `read_file` 截断 **0 次**（`01` §二 M2）⇒ 这一档是**「不因缺观测而判错」**的要求，
**不是**「已证明需要它」。

### L3 策（可分档，默认只报不拦）

| 档 | 默认 | 行为 |
|---|---|---|
| detection | **开** | `stale`/`blind`/`self-derived` 时往回执追加一行；**`fresh`/`new` 输出逐字不变** |
| enforcement | **关** | `write_file` 落在 `stale`/`blind` 时报 `ToolError`，除非 `overwrite: true`；`edit_file` **永不拦** |

三条决定，都不是审美：

1. **`fresh` 路径必须逐字不变，且追加的文案里不许有 `Date.now()`，也不许有哈希。**
   挂两条已发货定案：`outputs/reproducibility-2026-09-23`（RD 门抓到 D7 把毫秒漏进
   `ToolResult.output`）与 `outputs/prefix-churn-2026-09-23`（改写已发出历史 = 打断前缀缓存）。
   哈希进正文 ⇒ 每次覆盖都作废一段 KV-cache。**哈希只进事件字段，不进模型可见文本。**
2. **`edit_file` 只报不拦**：精确匹配已经证明目标文本此刻在盘上，风险在**周围**变了；
   沿用 `nearestHint` 立过的原则——「静默改到别处比改不动危险得多」，所以这一族**只告知、不动手、不改位置**。
3. **enforcement 默认关**，因为 §`01` §四 列了四条未证（0 匹配返工代价、真流量里整份重写占比、
   截断读误报面、并发同文件真实发生率）——**它们各自还长不出数字，先拦就是拿没量的东西判人**。
   detection 先跑，跑出「拦下次数 / 误报次数」这一对，再谈默认拦。

**代价（量过，非估）**：唯一新增开销是写路径上一次 sha256。本机实测
`50KB`（= `write_file` 的 `WRITE_LIMIT_BYTES`）**0.019 ms/次**，本仓最大的 `src/renderer/app.js`
229 KB **0.087 ms/次**。而 `write_file`/`edit_file` **本来就已经把整个文件读进手**（前者为 `lineDelta`、
后者为匹配），读盘是 `O(字节)`、哈希与它同阶 ⇒ **在能力 15 的「成本 ÷ 前进」口径下，这一格的分母近乎为零**。

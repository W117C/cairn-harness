# 00 主张与判据（能力 24 · 改动集原子性 / change-set atomicity · 2026-09-23）

> **一句话**：D7 快照给的是**每个文件自己的退路**，而 agent 的一次意图横跨多个文件——
> 半套重构被打断时，"该回滚哪一个"这条信息**不在任何读数里**。
> 外部工程文一句原话正好命中：**「文件级原子性不会自动组合为项目级原子性」**。
> 本页要的是那个**单元**：不是新概念（`collectChangeSet` 已经在私有推导它），是一等公民化。
>
> 提案，未动一行 `src/`，未 commit。取证（含**真的各回滚一次**）在 `01-实测与回执.md`。
> 编号：16…23 见 `outputs/capability-program-2026-09-23/00-合册与落地顺序.md`，本页 **24**。

## 一、缺口

| # | 面 | 现状（实测） | 缺什么 |
|---|---|---|---|
| G1 | 单元不存在 | 快照键 `.agent/snapshots/<毫秒>--<callId>/<路径>`：**每次写各留一份，互不相干** | 没有一条读数能把"这两次写"说成"同一件事的一半" |
| G2 | 概念已被私有实现 | `src/agent/security/scan.ts` 的 `collectChangeSet(events)` 从事件流重建变更集，但分组键是 **`op + path`** | 同一文件"先写后改"被切成两条；且它是**安全扫描的私有的**，回滚/验证/面板/影响面都用不上 ⇒ 典型 B 类（同策略多出口） |

## 二、外部读数（这套机制的形状，以及它自己承认的边界）

《AI 编程智能体的多文件原子修改》（Wavect，2026-09）给的形状，逐条对上本仓：

- **绑基础修订版**：「把提案绑定到基础修订版」「针对同一个经过认证的基础状态解析全部操作」，目标漂移即拒
  ⇒ 这正是**能力 16**（stale-view）。⇒ **24 依赖 16，不是并列**（这是本页对合册依赖图的一处实质修正，见 §六-3）。
- **候选世代**：明确否定顺序替换（"读者能看见两次改写之间的混合态"），改为
  「单独构建完整候选世代」+「验证完整候选世代」+ 最后**一次指针交换**。
- **失败是独立契约**：「崩溃后的回滚、清理与恢复是独立契约，需要独立证据」
  ⇒ 与本仓 17 的判断同向（原子性 ≠ 恢复），也**直接反掉**一种诱人做法：以为"上了事务就自动可恢复"。
- **它自己划的边界**：「该协议不保证原始文件、Git、编辑器、网络文件系统或断电恢复的原子性」，
  只对**合作消费者**成立 ⇒ 本页据此**不采纳**任何"拿 git stash/branch 装作两阶段提交"的做法。
- 主陷阱原话：**「文件级原子性不会自动组合为项目级原子性」**——就是本页 §`01` 三 那两次回滚的读数。

另：`Most coding agent benchmarks skip large-scale refactoring`（The New Stack）指出大规模重构被基准系统性跳过
⇒ 与本页 G5 的 43% 合读：**这是被评测面长期欠账的一块**，不是本仓私事。

## 三、设计：四层（各答「长在哪 · 谁持有 · 为何不是别层」）

### L0 单元 `changeSetId`（harness 推、模型可覆盖）

- **长在哪**：**写侧上下文**（`ToolContext`，与 `snapshot`/`impact` 同一条既有透传链），
  由 harness 按**边界**切：① 新的原始 `user_message`；② **一次转向**（能力 22 的段界——
  这顺带给 D-22a 一个答案：段界即组界）；③ `verify` 通过（组闭合）；④ run 结束。
- **不新增事件类型**（G7 纪律）：`changeSetId` 作字段挂在**已有的**写侧 `tool_call`/`tool_result` 上，
  与 `snapshotId` 同法（同一事实单一 writer，loop 只搬运）。
- ⚠️ **id 必须由 harness 生成、且不得是派生 callId**（能力 20 刚抓到 `-sup`/`-s` 那种"拼出来的 id 没人声明过"）。
  复用 20 的白名单棘轮，把 `changeSetId` 一起纳管。
- **模型可覆盖**（显式声明"这两次是一组/这是新的一组"）但**不作唯一依据**：
  自报是被审者自说（`gap-fix` P2-5 同因），harness 推的边界是地板。
  ⚠️ 诚实标注：**这条"边界规则能否切对"本轮未实弹**，落地前必须先证（`01` §四）。

### L1 基线绑定 = 复用 16，不重造

外部方案的"绑基础修订版"就是 16 的 `SeenLedger` + stale-view 判定。
⇒ 本页**不实现第二套漂移检测**；组内任一成员的盘上态与"模型所见"不符 ⇒ 整组标 `drifted`。

### L2 两级落地（先便宜的那级，重的那级要有数才上）

| 级 | 内容 | 成本 | 上它的条件 |
|---|---|---|---|
| **V0** | 组**可见**：面板/事件里给出「本组已改 k 个文件、未闭合」；一条**整组回滚**（按组内快照逆序批量还原）；取消/崩溃收尾时把未闭合组**明说** | 低（派生 + 一条命令） | 立即可做 |
| **V1** | 主会话**候选世代**：在隔离目录建完整候选 → 验 → 单次换 | 高（磁盘、路径重映射、与 worktree 关系） | **反转条件**：V0 上线后"挑错回滚 / 半套态"真被撞到，量出频次 |

⇒ 明确不偷做 V1：worker 侧已有 worktree 这条近路，主会话要不要同形状是**产品裁决**，
且外部协议自己承认只覆盖"合作读者"——编辑器/`git`/断电都不在保证内，别装。

### L3 收口与消费

- `verify` 通过 ⇒ 组闭合（写侧组状态转 `sealed`）；未闭合组在**下一次 run 开始时**必须被提起
  （与 20/22 同一条"别把未完成藏起来"的方向）。
- 18 的 `thinned` 与 21 的 `unbacked` **以组为分母**（一次意图花了多少断言、有没有增量——按组算比按次算准）。
- 影响面（M7）按组给跨文件波及，而不是每文件各报一次（现状正是每文件各报）。

## 五、明确不采纳（理由 / 证据 / 反转条件）

| 不采纳 | 理由 | 反转条件 |
|---|---|---|
| 模型自报 `intent_id` 作为**唯一**分组依据 | 被审者自说（`gap-fix` P2-5 同因）；且模型中途改主意不回填 | 永不——可覆盖可以，作地板不行 |
| 拿 git stash/branch 假扮两阶段提交 | 外部协议明写不保证 git/编辑器/断电原子性；假装有保证 = 造新的假绿 | 永不 |
| 自动挑选"该回滚哪个" | `01` §三 证明这件事需要意图信息，harness 猜 = 制造二次破坏；且外部也声明恢复是**独立契约** | 永不；给两个出口交人 |
| 主会话立刻上 worktree 候选世代（V1） | 成本高、与 D7/merge 控制塔的既有形状冲突、且无 V0 数据支撑 | V0 上线后"挑错/半套"被撞到并量出频次 |
| 把"组"做成新事件类型（`change_set_opened/closed`） | 字段挂在既有写侧事件上就够；G7：没证它配得上承载位 | 真出现"只看事件流无法重建组"的现场 |
| 顺序替换文件 + 结束时统一验 | 外部明指这是失败根因（读者能看见混合态），本仓主会话直写就是这一形状，但**至少要先让它可见**（V0）再谈换 | 无 |

## 六、边界与相撞声明

1. **落地前逐文件复核相交**：`src/tools/snapshot.ts`、`src/agent/security/scan.ts`、
   `src/agent/loop.ts`、`src/tools/base.ts`、`src/events/index.ts`（本轮实测均**不在飞**，但动手前再跑
   `git status --short`——上一轮就是因为 D7 落库让我两页的"撞面"断言变成假话，
   该类漂移现由 `recheck-blockers.mts` 守）。
2. **C3 不能单独做**：`collectChangeSet` 的"拼接含被覆盖行"若改成最终态，
   **安全扫描的召回会变**（一个先写入后被覆盖掉的密钥，今天会报、改后不报）。
   两种语义都讲得通 ⇒ 这是裁决项 **D-24a**（我的倾向：仍扫全量拼接，但 finding 上标"该行不在最终态"，
   既不丢召回也不误导行号）。**不许顺手"修"成最终态而不处理这一支。**
3. **对合册依赖图的一处实质修正**：24 的"绑基础修订版"就是 16 ⇒ **16 是 24 的前置**，
   而不是并列项；同时 24 的组边界②正是 22 悬着的 D-22a 答案（段界=组界）。
   这三条关系应回写进 `capability-program` 页（合册 §二 目前只把它们当各页自己的事）。
4. **拆笔**：① L0 单元 + C1 + C5（纯函数与字段，先不动消费者）；② V0（整组回滚 + C4 出声）；

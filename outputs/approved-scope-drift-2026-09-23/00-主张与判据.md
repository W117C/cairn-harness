# 00 主张与判据（能力 27 · 批准后越界 / approved-scope drift · 2026-09-23）

> **一句话**：本仓的**方案门**（`propose_plan` → 人批准 `files[]`）已经产出了"批准面"，
> `economics.ts` 也已经攥着"已做面"——但判据是**单向**的（`批准集 ⊆ 已做集`），
> 所以真函数实测出这个结果：**完全不照批准做会被拒，照做 + 顺手多改 2 个文件与纯合规读数一模一样**。
> ⇒ 越界不是没被上报，是**结构上不可见，还被计入"前进"**。
>
> 提案 + 一次自误记录（我的探针第一版下错结论），取证在 `01-实测与回执.md`。
> 编号：16…26 见 `outputs/capability-program-2026-09-23/00-合册与落地顺序.md`，本页 **27**。
> OWASP 把这一类叫 **LLM06 Excessive Agency**；本仓是少数**已经有批准面数据**却没用它的 harness。

## 二、外部对照

- **OWASP LLM Top 10 (2025) — LLM06: Excessive Agency**：把"给了超出必要的执行面/执行不做必要的动作边界"列为一等风险类。
  本仓的方案门本就是为它设的；缺的是**门后没有对账**——批的是 A，做了 A+B+C，门与账都不知道。
- **用户侧真实抱怨**：Cursor 论坛「agent keeps editing files I didn't ask it to」，发帖人自己写了个小 MCP 审计器来记"它到底动了哪些我没要的文件"
  ⇒ 这条轴在成熟产品上是**用户会主动造工具去看**的（我们的 L1 就是把那个手搓审计器变成 harness 一等读数）。
- **模型侧确证**：Claude Code issue #34230「Opus 4.6 违反显式 SCOPE LOCK 指令」
  ⇒ 反证"用提示词要求模型别越界"不够，**必须在执行面判**（本仓 §五-末行同结论）。
- ⚠️ 三者都不给"良性越界占比"，而**那正是本页最难的一格**（见 §五-第 2 行与 `01` §六）：
  改工具函数顺带改它的调用点，多半是**合法**的。所以本页第一刀砍向"出声"，不是砍向"拦"。

## 三、设计：三层（各答「长在哪 · 谁持有 · 为何不是别层」）

### L0 双向差集（纯函数，零新事实源）

`scopeDriftOf(approved, done) → { unsanctioned: string[], unfinished: string[] }`
——`unfinished` 就是今天 `planCovered` 唯一在看的那一侧；`unsanctioned` **今天没有任何人算**。

- **长在哪**：`economics.ts`（批准集/已做集已在那儿，`ProgressBoundary` 同一个 walk 里就能算），
  **不是**新脚本、**不是** loop 里再维护一份。
- **为何不是 `planCovered` 改成双向**：那会**当场改掉压缩经济闸的行为**（越界 run 将不再产生边界 ⇒
  切点移动 ⇒ 上下文预算变化），属"顺手把两个不相干的判据焊在一起"。
  ⇒ 正解：`planCovered` **保持原语义**（它是"做完没"，不是"越没越界"），
  新读数**并列**产出，先只喂给面板与 §L2 的收束闸。

### L1 写侧一次性对账（不新增判定层）

写成功后把 `(path, sanctioned)` 记进同一个 `covered`（一个布尔，不是新集合）：
`sanctioned = path ∈ 当前批准面`。G4 指出的 `globIntersects` 已在——批准面匹配复用同一函数，
**不写第三份集合运算**。

- 路径粒度问题（`plan.files` 是路径级）：越界判定**按路径**，不做子路径/行级推断（那是猜）。
- ⚠️ 二次批准要重置（`01` §六-末条待核）：`covered` 若跨两次批准累加，第二次批准的越界会看不见。

### L2 收束闸的第三条判据 + 成本读数的分母修正

- 能力 5 收束闸：`unsanctioned.length > 0` 且这一轮**没有**为它重新出过方案 ⇒ 不算干净收口，
  提示模型二选一：**补一次提案**（把越界正名）或**说明为何顺手动**（走 18 的上报通道，同一条）。
- 能力 15 的"成本 ÷ 前进"：`unsanctioned` 的写动作**不计入"前进"分子**（G2 的假便宜由此收口）。
  这条是本页对既有能力最实的修正：**它不是加噪声，是去掉一个系统性偏乐观。**
- detection 先行（同 16–26）：越界**只标注、只改分母，不拦写**。

## 五、明确不采纳（理由 / 证据 / 反转条件）

| 不采纳 | 理由 | 反转条件 |
|---|---|---|
| 直接拦掉批准面外的写 | "良性越界"占比**没人量过**（`01` §六）；改函数顺手改调用点是常态，拦它等于逼模型每步重出方案 ⇒ 审批疲劳（本仓 §10.4 立过这条权衡） | 真用户语料量出"越界且事后被判定为错"的比例 ≥ 某阈 |
| 把 `planCovered` 改成双向就完事 | 它同时被压缩经济闸消费 ⇒ 一并改动会**移动上下文切点**，是两个判据被焊在一起的典型 C 类 | 永不（改为并列读数） |
| 用提示词要求"别改方案外的文件" | 外部确证：显式 SCOPE LOCK 被违反（Claude issue #34230）；本仓"说了 ≠ 验了"这条已经立过 | 永不 |
| 行级/子路径级越界判定 | `plan.files` 只有路径粒度；往下推就是猜（与 25「不能从命令文本猜验面」同理） | 反转：`plan.files` 契约先升级到符号级 |
| 让模型自报"这些改动都在计划内" | 自报反模式（P2-5 同因） | 永不 |
| 为越界新建事件类型 | 与 24/26 同判：字段挂既有写侧结果即可 | 真出现"只看事件流无法重建批准面" |

## 三、补了那条反向用例（规则 60：收窄判定面要反向补一条）

新针脚「——匹配按完整 token 为界」比旧的更窄，窄的部分正是**破折号**。所以光换针脚不够，还得有人守"这句什么时候**不该**出现"：

```ts
// tests/shell-bypass-composition.test.ts:277
it("裸工具名 deny 条目不说「按 token 为界」（整句形状钉住）", () => {
  const rules = parsePermissionsFile(JSON.stringify({ rules: [{ behavior: "deny", tool: "write_file", scope: "always" }] }), "test");
  const d = evaluate("write_file", { path: "src/a.ts" }, session(rules));
  const reason = d.verdict === "deny" ? d.reason : "根本没被 deny（" + d.verdict + "）";
  expect(reason).toBe("deny 规则命中（deny:write_file#0）");   // 整句钉，不写 not.toContain
});
```

`ruleHitReason` 的边界说明是 `chain.pattern !== undefined ? "——匹配…" : ""` ⇒ 无 pattern 的条目（裸工具名）若也带上这句，
就是在对用户宣称一种它并没有做的匹配方式。用 `toBe` 钉整句而不是 `not.toContain`，是为了让"多写任何东西"也响（规则 96）。

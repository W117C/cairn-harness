# 00 主张与判据：可复现性（同一输入 ⇒ 同一份被判卷的东西）· 2026-09-23

> 落地：`src/agent/reproducibility.ts`（叶子判据）+ 门 `replay-determinism-check`（4 条）
> + `tests/reproducibility.test.ts`（10 条）+ `rp-*` 针脚 4 条。施工与读数在 `01-实测与回执.md`。
> 起因是本日刚移交的 BLOCKED 待办 #56，但本格是把那条**个案**抽成一条一直成立的纪律。

## 1. 问题（agent harness 这一类的通病，不是本仓私事）

DSH 的真相源是事件流：先记账后执行、增量重放、反事实 fork、靶场逐字段比对——**全都建立在
「重跑一次应当一样」之上**。业界同一类系统的公开痛点正是「跑不出两遍一样的」，
于是评测只能靠多跑取均值、CI 里的 UI/装配断言只能标成 flake。

而破坏这件事的东西通常是**静默**的：一个 `Date.now()` 进了本该只由输入决定的字段，
功能测试全绿，判卷层开始飘。#56 就是一个实例被门逮住的过程记录（见 §3）。

## 2. 口径：三条

| | |
|---|---|
| **判什么** | 同一输入跑两遍，**被判卷读的**那份结构（事件流、工具结果、变更面、投影出的上下文）必须逐字段等值 |
| **不判什么** | 运行耗时、真实日期、日志可读性——观测面**该**有时间，只是不许进身份 |
| **已知例外** | 显式登记的「身份债」：每条必须带①路径前缀②清偿条件，且门会**逐条复查它真能吸收同形差异**（写错前缀 = 红）。吸收了几处如实打印 |

`ts`（事件上的可选时间戳，`src/events/index.ts`）今天**没有任何代码读它**——
所以 RD2 把「投影不读时钟」从一句运气话变成一条判据：谁哪天拿 `ts` 参与投影/判定，
同一份日志就会投出两份不同的上下文，而这在只有单测的世界里不会红。

## 3. 门第一次跑就扩大了我自己移交的那条缺陷（这就是它存在的理由）

#56 我移交时只写了「快照路径里的毫秒打破 `gym-check` B1 的两次跑一致」。
本门的 RD1 拿真 `write_file` 同输入跑两遍，读出**两处**泄漏：

```
result.snapshotId  .agent/snapshots/1790135473980--call-x/src/mod.js
                 ≠ .agent/snapshots/1790135473983--call-x/src/mod.js
result.output      …（模型可见文本，同一次覆盖两次跑逐字不同）
```

⇒ 第二处比第一处要紧得多：**毫秒进了模型每轮看到的文本**。
按本日另一格的口径，这意味着每一次覆盖都让已发出的历史多断一段前缀（重写缓存），
而不只是判卷比对难看。已把这条补进 BLOCKED #56（修法 A/B 都还成立，但优先级变了：
只修 `changedFiles` 不够，`ToolResult.output` 那句提示也必须不带毫秒）。

**教训形状**（写进门注释）：移交缺陷时要写「我观察到的那一处」，
但**不要把观察范围当成缺陷范围**——仪器的作用就是把范围撑开。

## 4. 依赖序（长在哪、谁持有、为何不是别层）

| 层 | 内容 | 为什么不是别层 |
|---|---|---|
| L0 纯判据 | `diffJsonPaths` / `containsWallClock` / `differsOnlyByWallClock` / `stripObservation` / `classifyDivergence` / `reproducibleVerdict` | 分类必须是纯函数才能同时被门、单测、`--self-test` 用同一只；放进门脚本就等于判据只活在门里 |
| L1 观测 | 真跑：`write_file.run` 两遍 + `projectContext` 三份（无 ts / ts-A / ts-B）+ 事件流写两遍读回 | 不测「源码看起来没用时钟」——静态扫 `Date.now()` 会漏（今天就是漏在 `snapshotIdOf` 的**默认参数**上），也会对合法的计时读数假红 |
| L2 门 | `replay-determinism-check`（RD1–RD4），登记债在代码里带清偿条件 | 债必须**可复查**：RD4 逐条构造同形差异要求被吸收，写错前缀直接红——吸收不了的红名单比没有红名单更糟（它让泄漏看起来被批过） |
| L3 反脆弱 | `rp-*` 4 条针脚（消音白名单 / 不剥 ts / 不看前缀 / 把干净状态读成红） | 「白名单能用」和「白名单不过宽」是两个方向，都得有针脚，否则一次「让它先绿」的改动就把门掏空 |

## 5. 明确不做

| 不做 | 理由 | 反转条件 |
|---|---|---|
| 静态扫全仓 `Date.now()` 一律判红 | 大量计时是正当的（超时、退避、TTL、面板读数）。正当计时与泄漏身份是两件事，只有**跑两遍比对**能分开它们 | 不做 |
| 让 RD1 现在就判红逼 D7 修 | 那会把另一会话**未提交**的在飞状态变成共享的红门（本仓规矩：正确的红要区分「已提交的错」与「在飞」）。现走登记债：如实打印吸收数，修好后条目吸收不到东西 | D7 入库且 #56 未修时（那时这条债该被 RD4 判红） |
| 引入可注入时钟（`Clock` 接口）做全局重构 | 会碰 `loop.ts` / `events` / `agent-runner`——全在另一会话的在飞集合里 | 那三格空出来时，配合 #56 修法 A 一起做 |
| 把 seed 机制做进靶场 | 靶场已确定性（冻结剧本）；随机性在模型侧，不在 harness 侧 | 要量采样温度对完成率的影响时 |

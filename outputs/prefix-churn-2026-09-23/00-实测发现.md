# 00 实测发现：前缀抖动是**全有或全无**，且大部分不在我们手里 · 2026-09-23

> 复跑：`TERM=dumb node --import tsx outputs/prefix-churn-2026-09-23/measure-churn.mts`
> 数据源：`outputs/loop-eval-*/**.events.jsonl` 里的 `usage` 事件（上日
> `architecture-uplift-2026-09-21.md` §5 称这批为「既有真跑记录 75 条 usage 全带 cacheRead」；
> 本轮按同一分母复算得 75 条，凭证来源未独立核）。
> 本篇只登记读数与判读，**修法在 `01-设计与判据.md`**。

## 1. 读数（65 个暖轮 = 每轮去掉首轮）

| 读数 | 值 |
|---|---|
| 多轮 run 数 / usage 条数 | 10 / 75 |
| **暖轮 cacheRead=0 的比例** | **27 / 65 = 41.5%** |
| 命中轮的平均命中份额 | **86.6%**（命中就是几乎全命中） |
| 全量 `sumCacheRead / sumInput` | **52.2%**（108,800 / 208,559 口径内）——与上日独立算得的 51.5% 同量级 |
| Δuncached 分位 | p50 = **86 tok**｜p90 = 3,341｜max = 5,154 |
| 首轮即有缓存命中的 run | **5 / 10**（跨 run 复用 ⇒ A1 断点打在可缓存前缀末尾是对的） |

## 2. 判读（三句，每句都改变下一步做什么）

1. **我们自己的装配基本是 append-only 的**：p50 的 Δuncached 只有 86 token —— 那就是「本轮新增内容」的量级，
   说明**多数轮没有前缀重写**。长尾（p90 = 3,341 / max = 5,154）**全部与 cacheRead=0 的那 27 轮重合**
   （逐条打印可见：轮 6 read=0 ⇒ Δuncached=+4,399 这种形态）。
2. **抖动是全有或全无的，不是连续的**：命中时平均吃掉 86.6%，未命中时是 0%——**没有中间态**。
   如果是「我们在前缀中段改了一个字」，看到的应该是**命中份额下降但非零**（改点之后全丢、之前照旧命中），
   而不是**整段归零**。⇒ 那 41.5% 的归零发生在**上游**（分片路由 / TTL / 容量驱逐），
   不是我们改写了前缀。
3. **上日 §2.3 那条待测假设，这批数据里没有证据**：
   「prune 会改写前缀中段的旧工具结果 ⇒ 每触发一次把那之后的缓存命中打掉」——
   全部 10 个 run 里 **prune / compaction 事件一次都没出现**（0 条），
   且不存在「非零但偏低」的命中形态。⇒ **既未证实也未证伪**，因为**这批靶面根本不长那样**
   （短任务、10–16 轮、input 2.9k–5.9k tok，远够不到压缩阈值）。
   这与本仓已知的「靶面结果饱和」是同一族问题，不是结论。

## 3. 由此得到的两条设计约束（写进 `01`）

1. **门不能判「命中率必须高」**：命中率被上游支配（41.5% 的轮次我们无从解释），
   拿它当判据就是一扇**随机红**的门——本仓最忌的假红族。
   ⇒ 门只判**我们这一侧**：*在没有声明的变异源时，装配必须逐字纯追加*。这是确定性的、离线可判的。
2. **「可变内容后置」这条排序纪律必须被钉住**：`composeTurnMessages` 今天是
   首条 system（基础提示）→ 记忆 → skills → 地图 → 历史。可缓存前缀 = 首条 system + 工具面，
   正好是探针 `cacheableBytes` 那一层。⇒ 判据取**分层等式**而非整串等式：
   **易变块变了不许牵连可缓存前缀**（记忆每轮重读是既有语义，它一变只该从自己那一段起抖）。

## 4. 未做 / 待办（别把这篇当收口）

- 「命中轮与未命中轮是否在同一 run 内成簇出现（TTL 驱逐）」与「跨 run 首轮命中是否等于上一个 run 的
  末轮前缀」——两条更细的归因需要**时间戳**（这批事件流的 usage 不带时间戳），本轮未做。
- 真连才能量的东西（cacheWrite 计费份额、1.25×/2× 写价的实测折扣）依旧属「未证 ≠ 通过」。
  usage 事件里**根本没有 cacheWrite 字段**（只有 inputTokens/outputTokens/cacheReadInputTokens）
  ⇒ 想量写侧成本，得先给 usage 加字段，那是另一格。

### 这一刀里我错了三次（都留档）

1. **判据期望写反了一次**：PC6 我最初写「期望**不**抖，因为裁剪只换投影」——错。裁剪换的正是
   **已经发出去的那一条**历史内容，下一轮的序列化必然在中段分叉。改成「期望抖了且有证据」后才对，
   也才有了那个 4 万字符的读数。**教训**：写「期望它不发生」的判据前，先想清楚不发生是不是真的对。
2. **样本尺寸是被两次失败逼出来的**，不是我算出来的：
   ① 压缩样本最初用大工具结果撑上下文 ⇒ prune 先把上下文裁小，压缩阈值**永远够不到**；
   ② 裁剪样本最初一次给 3 轮种子 ⇒ 每轮裁的是同一批旧结果，历史仍逐字纯追加 ⇒ 量不到抖动。
   现在两处都在代码边上都写了原因（`driveMutating` 的头注 + `probe-prune-recipe.mts` 可复跑）。
3. **压缩发生在第 0 轮时「没有上一轮可比」**：事件确实落了流，但 PC5 仍报无分辨力——因为抖动是
   **相邻两轮**的量。把阈值调到驱动中途才够得着（`ratio: 0.55` + 每轮长一块）之后才有读数。
   这条写进了 config 旁边的注释。

另有两处工具性事故：一次 python 补丁的锚点文本根本不存在 ⇒ import 静默没加上（表现为「反向对照造不红」
而不是「找不到符号」）；一次补丁替换区间算错、把另一个函数咬坏了（表现为 esbuild 语法错）。
⇒ 结论：**成规模的改写一律整文件重写，别做区间手术**；改完第一件事是 `--self-test`/`typecheck`，
它们这次都如实报了。

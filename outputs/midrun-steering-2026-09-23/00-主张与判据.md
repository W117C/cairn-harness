## 二、外部读数（业界形状与本页判据恰好互证）

OpenClaw 的 `steer` 工具文档（当前 shipped 的 agent 运行时）三条语义，与本页实测的约束逐一对上：

1. **边界交付**：「模型会在**下一个受支持的运行时边界**看到该指导」，且"directives 不强制瞬时生效"
   ⇒ 与我 §`01` 二 的结论同形：边界不是审美选择，是唯一合法注入点。
2. **不动在途操作**："live operations remain unaffected until the engine naturally pauses"，
   示例甚至允许「在下一次工具调用前先总结」这种**面向下一动作**的指令
   ⇒ 转向 ≠ 抢占（G3：抢占=取消=造半跑，能力 17 已证）。
3. **绝不丢输入**：「如果当前运行时无法接受 Steer，会改为将该消息作为普通提示词发送，**而不会将其丢弃**」
   ⇒ 直指 G1 今天的做法是反模式。
4. 另与 LangChain 前端文档的"消息队列 / 会话分支"同族——排队而非打断，是当前 agent 界面的通行形状。

⚠️ 外部只支撑**形状**，不支撑收益百分比：没有任何一家公布"加了转向之后返工率下降多少"。
⇒ 本页收益全部押在本地可判定的东西上（G4/G5 是真函数实测），
且 enforcement 类判定一律**先出声后设闸**（与 16/17/18/21 同口径）。

## 三、设计：三层，按依赖排（各答「长在哪 · 谁持有 · 为何不是别层」）

### L0 收口输入（**独立可先做，且是最小的一步**）

渲染层那条 `return` 改成：**入队**（按会话隔离）+ 回执文案「已在下一个轮界送达 · 可撤销」。
新增一条 `agent:interject` 通道（33 条之外的第 34 条，形态照 `agent:clarify` 的 callId 关联写法）。

- **长在哪**：与 `decide`/`clarify` 同一层（main 侧按 `callId`/会话挂起的旁路），**不是** `agent:run`
  ——`run` 是"起一轮"，转向绝不能进那条路，否则等于重启或取消。
- 队列的**唯一持有者**是 main 侧的当前 run（渲染层只做输入框与状态显示）：
  界面刷新/切会话不该丢消息（G1 的病根之一就是输入只活在输入框里）。
- 兜底照外部那条：**运行时不接受转向时，降级成"跑完即作为下一条普通输入提交"**，仍不丢。

### L1 轮界注入（**注入点已存在，不新开创面**）

`src/agent/loop.ts` 每轮开头**已经有一处轮界检查**——取消信号就是在那儿收束的
（注释原话「取消信号于轮界收束」）。转向挂在**同一个界**上：排空队列 →
逐条 `await events.append({type:"user_message", …})` → 再 `projectContext`。

- ⚠️ **必须落流**，不能只塞进本次 request 的临时消息：
  重放、审计、界面时间线、`#eventCount` 口径都要看得见它。
  本仓一贯是"投影面的修补不改事件流"（`closeDanglingToolCalls`、能力 19 L0 都是这条），
  **但那是为了修协议而伪造消息，不该留痕；转向是真实发生过的用户输入，必须留痕**——
  同一个纪律的两个方向，边界在哪要写清楚，否则下次会照抄错。
- 落流顺序天然满足邻接：轮界 = 上一轮所有 `tool_result` 都已落流之后 ⇒ 不会插进 calls 与结果之间
  （G5 那个禁形状因此在**生产者侧**就不成立，出口只需兜底）。
- 来源账（能力 19 L1）给它归 `user` 但**带 late 标记**：转向是可信输入，但它不是原始需求，
  判定面需要区分（下一层的 L2 就靠这个区分）。

### L2 与既有判定的接线（**本页真正的难点，顺序在 L1 之前就要定**）

| 既有面 | 冲突 | 处置 |
|---|---|---|
| 能力 14 R1（`no-progress.ts`） | 只认 `wroteSinceLast`，用户改口不抑制（实测） | **加一条抑制信号** `userSpokeSinceLast`（同 `wroteSinceLast` 的取法：按事件扫 `user_message`）。**这是转向的上线前置，不是后续优化**；且必须两侧都测：改了口⇒不报停滞、没改口⇒照报（NP 系列门的"正样本报、负样本不报"口径） |
| 能力 5 收束闸 | `wroteThisRun` 跨转向延续 ⇒ 拿上一段的"写过盘没验"判新任务段 | **需裁决**（§四 D-22a）：我倾向"转向即段界，`wroteThisRun` 复位，但已经落盘的未验改动仍要验" |
| 能力 17 `effect` | 用户可能以为转向会打断在途命令 | 文案与卡片都要明说「本轮在途工具不会中断，要中止请显式取消」——**语义上把 steer 与 cancel 划开**，否则引入新的半跑来源 |
| 能力 20 出口闸 | 判据缺"邻接"这一维（实测 id 配对无感） | 反喂：20 的收束器加邻接判据；且 §`01` 二-3 那条"calls 与结果之间本来就夹一条 assistant 文本"要一并复核，别把既有形状当破口、也别把破口当既有形状 |
| 预算/轮次（`maxSteps`、final-budget） | 转向算不算新一轮 | 建议**算**（新指示=新预算段的起点），并在事件上留可数痕迹；不算则等于允许无限续命 |

### L3 观测者

转向要能回答三问，且都不该靠人肉看日志：
**排了几条 / 投了几条 / 有没有被降级成普通输入**（L0 的兜底分支）。
落 `interject_accepted` / `interject_delivered` 计数进事件字段（不新增事件类型——G7 同口径，
`user_message` 本身就是承载体，计数只在投影/读数面派生）。

## 五、明确不采纳（理由 / 证据 / 反转条件）

| 不采纳 | 理由 | 反转条件 |
|---|---|---|
| 抢占式打断在途工具（"真转向"） | 打断 = 取消语义，而能力 17 已实测取消会留下"盘上已改、回执 `ok:false`"的半跑态；转向不该成为新的半跑来源 | 反转条件唯一：先有能力 17 的 `effect` 面且默认开，才谈"安全抢占" |
| 把转向塞进 system 提示 | 污染系统面（一次转向终身有效），且改写已发前缀 ⇒ 撞 `prefix-churn`/RD 两道门 | 永不 |
| UI 假装收下、实际丢弃（现状） | 外部同类明确反对（"而不会将其丢弃"），且用户必须重新打字 | 永不 |
| 转向即重启本轮 | 丢掉在途工具的正当结果，等价于第三条 G3 的老路 | 永不 |
| 运行中每条转向都立刻单独占一轮 | 成本：一条边界上排了 3 句话就该合成一次投递（合成规则见 §四 C5 的针 B 反例：不许把合成做成"只投最后一条"） | 反转：真用量显示分开投递明显更好 |
| 现在就做"转向意图分类"（判断该不该中断） | 自报/分类器反模式（`gap-fix` P2-5），且无数据 | 反转：有 `interject_*` 计数之后 |

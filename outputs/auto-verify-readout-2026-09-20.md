结论一句话：**成本侧已量到可忽略（百毫秒级墙钟、零额外模型请求），收益侧只证到「通道打通 + 证据如实落流」，

## 1. 触发率（静态普查 28 份冻结剧本，零 API）

判据贴着 `loop.ts` 的真实条件：`opts.verify && autoVerify === true && wroteThisRun && verifyAttempts === 0`
（另有一道 `surface()` 可验面探测）。

| 分类 | 数 |
| --- | --- |
| 剧本总数 | 28 |
| 含写动作（write_file / edit_file） | 11 / 28 |
| └ 其中自调 verify 门 | 5 / 11 |
| └ **闸会响**（写过盘、全程没自调门） | **6 / 11** |
| &nbsp;&nbsp;&nbsp;├ 已用 run_shell 跑过测试（⇒ 开闸就是**重复跑一遍**） | 1 / 6 |
| &nbsp;&nbsp;&nbsp;└ 完全没有任何验证证据（⇒ 闸的**真正收益面**） | 5 / 6 |

两条必须一起读的限定（否则会把这 55% 当成开闸净收益）：

1. **worker 侧现在根本接不到闸**：`autoVerify` 只在 `src/main/agent-runner.ts` 主会话路径传入
   （`grep` 全仓 `src/` 仅 loop.ts + agent-runner.ts 两处），编排器不给 worker 传。
   而会响的 6 本里有 3 本是 `fixtures/agents/` 的编排剧本（`slow-m3c-impl` / `slow-m3c-write` / `write-demo`）
   ⇒ 那三类「写过盘没验过」的轨迹今天不受此闸保护。它们恰是**合并进主树的写**，
   风险敞口不低于主会话（对齐 W4/spec 里「给 worker autoVerify」那条：本轮不动，只把敞口量出来）。
   （注：3 本的角色按目录判定，未逐一从调用点核实；`grep` 到的是 `fixtures/agents/*.jsonl` 由编排验收消费。）
2. **主会话剧本的真实分布更稀疏**：确认跑在主会话里的含写剧本 7 本（`gate-flow` + `gym/cases/*` ×4 自调门、
   `todo-fix` 壳验、`readonly-flow` 与 `lsp-demo` 裸）⇒ 闸会在 **3 / 7** 本上响，
   其中 **2 / 7** 是「完全没证据」（该抓），**1 / 7** 是「已经用 shell 跑过测试」（白多跑一遍）。
   这 1/7 恰好是旗舰 e2e 剧本 `fixtures/mock/todo-fix.jsonl`。

## 2. 单次代价（靶子 `fixtures/todo-app` 的 `.tmp` 副本，实跑）

| 路径 | 墙钟 | 额外模型请求 | 输出体积 |
| --- | --- | --- | --- |
| 发货缺省命令 `pnpm run test`（`defaultExec`） | **804 ms** | 0 | 1,621 字符 |
| 直连 vitest（本仓沙箱同型命令） | **252 ms** | 0 | 1,501 字符 |

- 输出体积按 ASCII 口径 ≈ **400 token**，被 `709ac7b` 那座帽（正文 1200 + 命令清单 200）稳稳包住。
- **代价随仓库测试规模线性放大**，不是常数：本仓 `test` 门实测耗时约 800 秒量级（AGENTS.md 记载，**本轮未重测**），
  在这类仓库上「补一拍」= 每次写过盘没自测就多等一次全量套件。⇒ 「值不值」的正确问法不是「252ms 贵不贵」，
  而是「这个仓库跑一遍测试要多久 × 它多久响一次」。
- 开闸面今天只有一个用户可见开关（设置项 `autoVerify`，`settings.ts:103` 缺省 false），无仓库级/会话级细分。

## 3. 反事实：同一个坏修复，关闸 vs 开闸（实跑，真 bug + 真测试）

剧本：模型读文件 → 写一版**看着像修了其实还是错的** `completedCount` → 纯文本收工（不调 verify）。
第二轮走**产品真实入口**（会话型 provider 以事件日志为唯一事实源）看那条红是否回到模型眼前。

| 读数 | 关闸（现状） | 开闸 |
| --- | --- | --- |
| 第 1 轮墙钟 | 1 ms | **242 ms** |
| 第 1 轮模型请求数 | 2 | 2（**零额外请求**） |
| `verify_result` 事件 | 0 | 1，`ok=false auto=true` |
| 交付时代码实际是否仍红 | 是（无人知晓） | 是（**已知并落流**） |
| 第 2 轮请求里有没有那条红 | — | **有**：`[harness 自动验证] … [verify FAIL] pnpm run test … 1 failed` |
| 该注入的每轮成本 | 0 | **2,304 字符 ≈ 687 token**（帽 1200+200 之内） |

⇒ 「感知→规划→执行→验证→**修正**」这条环在开闸后是**闭合且可观测**的：红在事件流上、在下一轮请求体里，
不靠模型自觉，也不冒充模型行为。关闸时它是断的（同一份代码、同一个剧本，第 2 轮请求里一个字的红都没有）。

## 4. 一条判读陷阱（本轮自己踩过，写下来省下一轮）

**`runLoop` 自己的上下文是 per-run 的**（`loop.ts:81` `const seen = []`，投影 `projectContext(seen)` 只含本轮事件）；
跨轮记忆完全来自会话型 provider 重新投影整份日志（`glm-session.ts:468` + `replayIncremental`）。
所以量「跨轮回流」必须走会话 provider——我第一版探针拿裸 provider 跑第二轮，读数 `第 2 轮请求里有没有那条红 = false`
是**方法的假阴性**，不是产品缺陷。同类断言以后一律以 `tests/context-auto-verify-note.test.ts` ⑧ 的入口为准。

## 5. 建议（不改代码，等裁决）

- **不翻默认值**。成本已可忽略，但缺的是准确率那一半，而它**不能靠推理补**：
  需要真模型 + 预算，量「开闸前后 `$/成功任务` 与一次通过率」的并列读数（用户裁决⑤：只有前者=未证）。
  现成落点：`fixtures/gym` 反事实靶场已具备冻结判卷 + 回放跑器，加一组「写而不验」case 即可跑 A/B（要 `M0_API_KEY`，本轮环境无 key ⇒ 明写未证）。
- 开闸讨论时**必须一起提**的两条，否则这个开关会被当成免费按钮：
  ① 大仓补拍 = 一次全量套件（见 §2 末），可考虑给「本 run 已在最后写之后跑过 testish `run_shell`」的情形免拍——
     但那要在「是不是真验证」上做命令形状启发，会削弱「写过盘必须有证据」这条硬保证，本轮**不做**，只登记代价；
  ② worker 侧的同类敞口（§1 限定 1）比主会话更值得先补。

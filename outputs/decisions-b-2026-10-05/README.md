## ① `#71` 无进展阶梯 R1：零真阳性，escalate 的许可建立在一个量不出东西的语料上

**事实（三件，都可复核）**

1. `src/agent/no-progress.ts:177` 的注释写着分级依据：
   「`R1` 在真实语料上**绿跑零误报** ⇒ 允许 escalate；`R3` 在真实语料上**零触发**（既没证明
   有用也没证明无害）⇒ 只到 note」。
2. 台账第 363 页复算：**R1 在生产口径上是 0/107 趟触发**。而"绿跑零误报"与"从未触发"
   在读数上**长得一模一样**——零误报可以来自"很准"，也可以来自"根本没出声"。
3. 冻结语料 `fixtures/no-progress/` 里有一条 `real-red-verify-stagnation`（R1 该抓的正样本），
   所以门是绿的；但那条是**录制**，不能证明生产路径上它会响。

**这条真实要裁的是什么**：R1 现在拿的是 **escalate**（最高档），而它赖以升级的那条测量
——按本仓自己写下的同一句话——对 R3 是判成"只到 note"的。**同一个证据强度，两套待遇。**

**选项与代价**

| 选项 | 代价 | 谁被影响 |
|---|---|---|
| (a) 照 R3 的同一句话把 R1 也降到 note | 若 R1 本来会抓到的东西现在不抓了 ⇒ 少一次干预；但 R1 零触发 ⇒ **眼下无可观测差别** | 无用户可见变化 |
| (b) 保留 escalate，只把注释里的许可依据改成诚实的（"零触发，不构成精确性证据"） | 代码行为零变化；但等于承认这一档的许可是空的 | 无 |
| (c) 撤掉 R1 | 少一只信号；同样无可观测差别 | 无 |

**我的建议：(b) 先做，(a) 随后。**
理由：(b) 是**零行为变更**的诚实修正，现在就能落（改注释 + 判卷钉住"许可依据必须写清触发数"）。
(a) 需要一个**真语料上的正样本**才能做对——而那要跑真模型，属花钱的活，应该排进正常的评测轮，
不该为了消一条台账项单独烧钱。**(c) 不建议**：撤掉一条信号是不可逆的信息损失，而它现在
零成本（零触发＝零误报，也不花钱）。

**这条为什么要你拍板而不是我直接做**：本仓纪律写明**冻结登记只能人做**

## ② `#70` 基准提示词自己教模型「改完 verify」——测量设计缺口，不是缺陷

**事实**：基准两档提示词里都写着「改完 verify」——

**这不是代码缺陷**：两边各自都对（提示词教自验是对的；闸让位给自验也是对的）。
缺的是**一档不教 verify 的提示面**——没有它，"自动补拍有没有用"这个问题在本仓无法被测量。

**选项与代价**

| 选项 | 代价 |
|---|---|
| (a) 加第三档 `--system no-verify`（只去掉那一句） | 一次小改动 + 一条判卷；不必为新门（本仓"不再加尺"的指示不冲突——这是**加一档测量面**，不是加尺） |
| (b) 不做，把 `#70` 标成"设计已定，等有需求" | 继续无法回答那个问题 |
| (c) 去掉现有两档里的"改完 verify" | **不建议**：那会改掉产品提示词的语义，且让现有全部留档不可比 |

**我的建议：(a)。** 它是**唯一能把这个测量缺口关掉**的动作，且代价小、不动产品面。

## ③ `#72` 身份行 6 处各抄一份：单源化的代价是**跨 run 读数不可比**

**事实**：`你是桌面编程 agent：…` 这句话在仓里有 **6 处各自抄写**
（`src/agent/system-prompt.ts` 的产品面 ＋ `gym/runner.ts`／`autonomy-check.ts`／
`loop-eval.ts`／`ga-strategy.ts`／`gate-check.ts` 五处 harness 面）。
产品那一行的品牌错（"M0 桌面编程 agent"）已在第 367 页只删不加地改掉；剩下的是**单源化**。

**为什么要裁**：单源化有两种做法，代价不同——

| 选项 | 代价 |
|---|---|
| (a) harness 那 5 处改成从 `src/agent/system-prompt` 派生 | **跨 run 读数不可比**：基准与门的输入面变了，现有全部留档要标"改前／改后面"。本仓所有历史对比读数都会带上这句话 |
| (b) 只保留现状（6 处各自抄） | 将来改产品身份行时，5 处 harness 面**不会跟着改**（除非有人记得）——本轮就是靠人工发现才改掉的 |
| (c) 折中：加一条判卷钉住"这 6 处必须逐字相同"，改的时候一起改 | 不动派生关系 ⇒ 读数可比；代价是每次改要动 6 处（判卷会提醒，不会漏） |

**我的建议：(c)。** 理由：本仓**最贵的东西是留档的可比性**（多份裁决都建立在"同分母"上），
而 (a) 会一次性作废一批读数的可比性。 (c) 用一条判卷换掉"派生的好处"——判卷会红的
时候就是"你改了 1 处还有 5 处"，那正是本轮人工发现的同一个问题，只是变成机器发现。

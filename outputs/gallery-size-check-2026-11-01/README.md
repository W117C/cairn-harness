# 画廊自查：文件行大小必须带单位 · 2026-11-01

检查起点与交付面都是共享工作树，HEAD `be9c0be5`；本批改动未提交。

## 这一批改了什么

第 943 页把文件窗格从裸字节数（`2140`）改成 `2.1 KB`——**那是靠人眼看截图发现的**。同一类回退（有人把 `formatBytes` 换回 `{e.size}`）没有任何机器拦截：`format-rulers` 的 `raw-bytes` 形状能抓住 `{x.size}` 的源码形状，但抓不到「重新拼一个裸数字」或「换了个变量名」的写法。

所以把这条判据放到**渲染出来的那一刻**：`ui-gallery.cjs` 在弹窗文件窗格截图后，读 `.fp-size` 的实际文本，必须匹配 `B / KB / MB`。

造红那一步我在 `{}` 里 `cd apps/desktop` 之后仍用相对仓库根的路径去复原，结果 `cp` 失败、文件停在造红版；发现后按 sha256 复核并复原（两处哈希相同），再重建、再跑画廊确认绿。**教训**：脚本里改工作目录后，路径一律回到绝对路径或先 `cd` 回根——这一条没有进产品代码，只记在这里。

## 边界

- 这条只查**渲染后的文本**（弹窗文件窗格那一路），不查其它窗格的大小展示（目前没有第二处摆大小）。
- 正则只认 `B / KB / MB`：将来若要支持 `GB` 得同时改这里与 `formatBytes`（两边都在判据里，改漏会红）。
- 画廊依赖 `dist` 构建产物：改了渲染层不重建就拍不到变化（本轮的造红/复原都是「先 build 再跑」）。

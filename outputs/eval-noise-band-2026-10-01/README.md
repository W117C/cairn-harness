# 噪声带实测（2026-10-01）：同一配置跑两次，能差多少

- **怎么来的**：`fixtures/bench/tasks.json` 的 12 条任务，**同一配置、同一模型**连跑两次
  （`--reps 1 --max-steps 30`），两次都 `--keep` 留了事件流。
- **读数**：`outputs/eval-base-a/readings.json`、`outputs/eval-base-b/readings.json`
- **用途**：`pnpm eval-report` 拿这两份当**噪声带**，判后续改动是否真的有效。

---

## 一、结论（一句话）

**同一配置跑两次，输入 token 能差 20.6%，达标数能差 1 条（12 条里 3 条结论相反）。**
所以：**单次跑出来的「省了 X% token / 成功率涨了 Y%」，只要幅度小于下表这一档，就是噪声，不能当结论。**

---

## 二、逐指标实测

| 指标 | 跑 A | 跑 B | 绝对差 | **相对幅度** |
|---|---:|---:|---:|---:|
| 成功率 | 75%（9/12） | 67%（8/12） | 8 个百分点 | **11.8%** |
| 输入 token | 912,402 | 1,121,590 | 209,188 | **20.6%** |
| 输出 token | 33,256 | 38,013 | 4,757 | **13.3%** |
| 墙钟 | 690 秒 | 778 秒 | 88 秒 | **11.9%** |
| 内存峰 | 323 MB | 473 MB | 150 MB | **37.7%** |

> 内存那一格的相对幅度最大，但它是**单点峰值**，两次采样的瞬时性最强 ⇒ 判"内存变好了"要格外保守。

---

## 三、逐条任务的结论翻转（同配置、两次跑）

| 任务 | 跑 A | 跑 B |
|---|---|---|
| `B3-refactor-callsite` | PASS | **FAIL** |
| `B7-feature-csv` | **FAIL** | PASS |
| `B8-feature-memo` | PASS | **FAIL** |

**12 条里有 3 条（25%）在什么都没改的情况下翻了结论。**
这一条比上面的百分比更直观：**拿单次成功率当结论，等于在 1/4 的任务上掷硬币。**

---

## 四、对"省钱 / 提成功率"这两个目标的直接含义

业主的目标里写着「消耗 token 最少」「任务成功率最高」。有了这个带，可以说清两件事：

1. **改动的 token 收益必须 > 约 21% 才可能被测出来**（单次跑、12 条）。
   想证明更小的收益 ⇒ 必须 `--reps` 提上去（跑多轮取分布），或把任务集再扩大。
2. **成功率的收益必须 > 1 条任务（8 个百分点）才可能被测出来**。
   这正好解释了 2026-09-30 那次教训：当天做的 A/B（开/关子代理）两边各有一次成败，
   拿它当"成功率提升"是错的——现在有了数字：那个幅度**本来就在带里**。

---

## 五、方法与诚实标注

**怎么测的**：两次运行之间**没有改任何代码**（同一个 `git` 状态、同一个模型、同一套任务）。
所以两次的差**全部**来自运行噪声（模型采样、网络、机器负载、缓存命中）。

**未证 / 边界**：
- **两点样本是弱证据**。它给出的是"这两次之间的差"，不是"长期波动范围"。
  要更硬的带，应当跑 5–10 次取分位数。
- **同一台机器、同一时段**测的。换个时段或换台机器，带可能不同。
- **带的大小本身不含方向**：它只说"差异多大算噪声"，不说哪边更好。
- 这两次运行**都是在修好尺子之后**跑的（`expects` 带 `judgeUntouched`、
  `.agent/` 不再算改动、澄清答案不再串题）——用坏尺子量出来的带没有意义。

---

## 六、复现命令

```sh
# ① 同配置连跑两次（会烧真 token）
pnpm bench -- --keep --out outputs/eval-base-a
pnpm bench -- --keep --out outputs/eval-base-b

# ② 把两份当噪声带，判任意一次改动的读数
pnpm eval-report --baseline outputs/eval-base-a/readings.json \
                 --baseline outputs/eval-base-b/readings.json \
                 --candidate  <改动后的 readings.json>
```

`eval-report` 的输出里会写：每项指标的差值、噪声带、以及**是否超出**。
噪声带不可得时它明说「判不出」——不会假装通过。

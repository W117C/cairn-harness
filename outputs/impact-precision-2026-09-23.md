# 影响面的精度实测：19 万条边里只有 20% 由 import 支撑（2026-09-23）

起因不是「慢」，是「慢」把它引到了这台机器上：`outputs/analysis-perf-2026-09-15.md` 的
P1-6 手法②③ / P1-7 说 `buildImpact` 每次编辑全量建图，要加进程内缓存。要裁这句话就得先量一次
真实建图。**量出来的第一条不是耗时，是这张图在说谎。**

对象：本仓 HEAD `5a9e542`，图 = 400 个受支持后缀源码（帽 400），宿主 ZEdeMacBook-Pro，
`node 22.23.2`（直接 `node --import tsx`，非 pnpm 那条 Electron-as-node 支路）。

## 二、根因：抽取判据把「同名」当成了「相连」

`src/agent/map/parse.ts` 的 `PATTERNS`（23 条，def 侧 0–12 / ref 侧 13–21）逐条跑一遍归因
（每条 pattern 单独编译、在同一棵已解析树上跑，捕获数按编号归因；复刻的 v0 边数 194,292
与线上逐字相等 ⇒ 归因表可信）：

| 侧 | pattern | 捕获数 | 其中非模块作用域 |
| --- | --- | --- | --- |
| def | `variable_declarator name:` | **11,701** | **10,184** |
| def | `function_declaration name:` | 1,666 | 161 |
| def | `method_definition name:` | 392 | 382（类体里，本就应该） |
| def | 其余（class/interface/type/enum/py） | 553 | 12 |
| ref | `call_expression function: (identifier)` | 25,270 | — |
| ref | **`call_expression function: (member_expression property:)`** | **20,519** | — |
| ref | `new_expression constructor: (identifier)` | 1,225 | — |
| ref | 其余（value/assign/属性式 new/py） | 289 | — |

⇒ 全部 14,312 个「定义」里 **71% 是函数体内的局部变量**；全部 47,303 个「引用」里
**43% 是属性名**（`console.log`、`arr.push`、`Object.keys`、`s.slice`）。
名字表不带作用域、引用不看对象，于是任何文件的 `log` 引用会与任何文件的 `log` 定义连一条边。

还有一条更基本的：**这张图从不看 import**。4,803 个 import 绑定名（362 个文件有）里
没有一个被抽进 tags——跨文件连接完全靠撞名字。

## 三、消融：把两种噪声各自去掉，边数与真依赖各怎么变

真依赖（ground truth）取可机械判定的一条：**调用方文件 import 了这个名字，且该名字定义在别的文件**。

| 变体 | 站点级边 | 文件对 | 其中由 import 支撑 | import 链接召回 |
| --- | --- | --- | --- | --- |
| v0 现网 | 194,292 | 5,285 | 38,442（**20%**） | 2,180 / 3,256（67%） |
| v1 = 丢三条属性式 ref | 97,011（−50%） | 3,010 | 38,400（40%） | 2,180 / 3,256（67%） |
| v2 = v1 + 局部变量不计定义 | **49,049（−75%）** | 2,496 | 28,111（**57%**） | 1,936 / 3,005（64%） |

读法与两处必须说清的细节：

1. **v1 一分钱召回不付**：链接召回 2,180/3,256 一字未动。站点级边里少掉 42 条 import 支撑的边
   （38,442→38,400），但那是同一 (文件,符号) 对的第二条站点，对「谁受影响」这个答案没有影响。
   ⇒ 属性式 ref 在这份真依赖判据下**纯噪声**。
2. **v2 撤掉的 244 条覆盖不是真损失**：逐笔查，这 244 对「别处的定义」全部是局部变量。
   样本全是同一个形状——`tests/*.test.ts ← it`：测试文件从 vitest import `it`，
   而图里那条「定义在别处」是某个文件函数体里的 `const it = …`（vitest 自己在 node_modules，被帽与忽略规则挡在图外）。
   分母从 3,256 变 3,005 也是同一件事：这些链接的「定义」本就假。
   ⇒ v2 的召回是 **1,936/3,005 = 64%（对更干净的分母）**，而不是「从 67% 掉到 64%」。

## 四、代价与不做的部分（写下来，别让下一轮重推）

- **命名缺口 ①**：v1 之后 `obj.method()` 形式的方法调用不进图。不是「不重要」，而是
  名字图无法判断 `logger.log()` 的 `log` 属于哪个定义文件；保留它的实测代价是 45,160 条假边。
  要拿回这类边必须先解析 `object` 标识符的绑定（`@obj` 是不是本文件的模块级绑定/import），
  那是另一笔工程，别和这条混着做。
- **命名缺口 ②**：召回 67%（v0/v1）说明还有一类引用压根没抽——只抽了「调用位置」的裸标识符
  （`foo()`），把符号当参数传、作为返回值、放进条件里、`export { x }` 重导出都不算引用。
  这条不在本次修法内，先量在纸上。
- **`up` 的截断仍按字母序取前 200**：`upward()` 排序键是 (symbol, file, line)，
  所以「哪 200 条活下来」与被改符号的相关性是零。#43 落地后噪声少 75%，这条的伤害跟着变小，
  但仍然应该改成「import 支撑的先留」。留作 #43 之后的独立一笔，不夹带。
- **进程内图缓存（P1-6 手法③）先不批**：见下节耗时读数——**边构建与排序才是那 170ms 的主体**，
  而它正是 #43 要砍 4 倍的那一块。先修精度再复测，否则是给一个即将缩小的成本加常驻 19 MiB 的缓存。

三条结论：
1. **P1-7 的「线性扫描改 Set/倒排索引」这半实测不值得做**——三项都在 0.1ms 量级，
   对面是 170ms 的建图。原文那句「可改 Set/倒排索引」的收益是零头，别照着做。
2. 170ms 的主体是**边构建 + 排序**（129ms），两者都随边数超线性/线性放大。#43 把边砍 75%

4. 一次模型往返是秒级，`fileImpact` 是 163ms；修完精度如果降到 ~50ms，「每次编辑全量建图」
   在墙钟上就不构成 P1。**这就是手法③至今没批的原因**：先证明它省的还是笔值得省的账。

## 六、复现

探针是 .gitignore 里的一次性读物（`.tmp/p3.ts`，未跟踪、不入库）：
`TERM=dumb node --import tsx .tmp/p3.ts`（在仓根跑）。它做四件事：
① 逐条 pattern 单独编译并在同一棵树上跑，按编号归因捕获数；
② 「模块作用域」判据 = 从捕获节点向上到 `program` 的路径上没有函数体/语句块/类体节点
   （注意：不能只看「能否走到 program」——那样所有节点都是模块作用域，第一次跑就错过一次）；
③ 真依赖 = 调用方 import 了该名字 ∧ 该名字定义在别的文件；
④ 三个变体各自重算边数/文件对/召回。
v0 的站点级边数与线上 `buildImpact` 返回值逐字相等（194,292），这是这条复刻可信的依据。

## 八、把同一把尺放到「spawn 准入」那一头量（`affectedFilesOf`）

§四 缺口 ① 写的重开条件之一是「面板/准入把波及数当判据用」——**这一条今天核出来已经成立**：
`src/main/agent-runner.ts:1198` 把 `affectedFilesOf` 接成 `semanticLease`，
`orchestrator.ts:569` 只在 glob 租约**不相交**时问它，相交就出审批卡，
用户不强行批准 ⇒ `spawn_agent` 直接返回「未获批准」。
也就是说：一条假波及 = 一次白出的审批卡，最坏 = 一次被拒的并行。

量法（`.tmp/p5.ts`，未跟踪）：对每个真实会用的 glob，取产品闭包
（`affectedFilesOf`），逐边核「X 因符号 S 入闭包，而 X 是否真的 import/require 了 S」——
**按文件判**：只要该文件有一条 import 支撑的边，就算它真该在闭包里（re-export、多跳链因此不误伤，
比 hop 计数公平）。

| glob（真实会申报的写法） | 闭包文件 | 有 import 支撑 | **一条支撑都没有** | 撞名的符号（例） |
| --- | --- | --- | --- | --- |
| `src/agent/loop.ts` | 19 | 18 | **0** | — |
| `src/agent/memory/*.ts` | 19 | 16 | **0** | （有假边但同文件另有真边） |
| `src/agent/orchestrat*.ts` | 45 | 34 | 7 | `stream` / `finish` |
| `src/agent/worker-*.ts` | 42 | 33 | 3 | `run` |
| `src/tools/*.ts` | 47 | 27 | 3 | `run` |
| `src/renderer/*.js` | 17 | 6 | 5 | `syncRunButton` / `$` / `esc` / `deleteSession` |
| `scripts/*.ts` | 97 | 6 | **41** | `n` / `after` / `click` / `settle` / `exec` |

读法：**精度修完之后，最干净的模块（loop）闭包已经与 import 链完全一致（19=19，零无支撑文件）**；
剩下的假边集中在**短名/通用名的模块级同名**（`run`、`n`、`after`、`finish`、`stream`）与
**非产品源**（`outputs/**/prototype/app.js`、`proto/*.mjs` 都是 .js/.mjs，被扫进图）。

没有造出假审批卡**；但 `scripts/*.ts` 那种 41/97 的闭包一旦与别的 worker 相遇，假交集是必然的。

### 试过的候选修法与它的代价（先量再改，别直接接）

「准入只信**全仓唯一名**的边」（symbol 只在 ≤1 个文件里有定义；不需要新抽取，纯图内判据）：

| glob | 去掉的无支撑文件 | 赔掉的有支撑文件 |
| --- | --- | --- |
| `src/agent/loop.ts` | 0 | 0 |
| `src/agent/memory/*.ts` | 0 | 0 |
| `src/agent/worker-*.ts` | 3 | 0 |
| `src/tools/*.ts` | 3 | 0 |
| `scripts/*.ts` | 31 | 0 |
| `src/agent/orchestrat*.ts` | 7 | **13**（34→21） |
| `src/renderer/*.js` | 1 | 1（6→5） |

⇒ 合计去掉 **45 / 59** 的无支撑文件（−76%），代价是赔掉 **14 / 140** 条有支撑的边（−10%），且
**分布极不均**：5 个 glob 零代价，编排层一条就吃掉几乎全部损失。
所以这不是一句「加个过滤」，而是**按面取值**：`scripts/**`、`tests/**` 这类短名密集的申报适用，
`src/agent/orchestrat*.ts` 这类真被广泛 import 的核心模块不适用。
按「漏报一次语义冲突 = 事后合并冲突」的代价排序，本仓更值的做法是**让卡说清是哪条符号、
是不是唯一名**（把不确定性交给人，而不是拿 10% 的漏报去换整洁），而卡的形状要经
`semanticLease` 钩子签名 ⇒ 该面在别人的在飞改动集里（`src/main/agent-runner.ts`、`src/agent/orchestrator.ts` 均为 `M`）。
**因此本轮只落读数与判据口径，不改实现**；已立待办 #46，落地入口写在那里。

## 九、precision 之外还欠一把尺：召回（同日，`scripts/probe-map-recall.ts`）

### 那 4 个文件是这一节真正的发现

`src/agent/map/parse.ts`（27 个模块级声明全丢）、`scripts/ipc-reachability-check-core.ts`（7）、
`tests/secrets.test.ts`（4）、`tests/sessions.test.ts`（4）——**四个都是合法 TS**（`pnpm typecheck` 全过），
但 tree-sitter 的 typescript grammar 在其中报了 ERROR/MISSING，而旧 `fileTags` 对 `hasError` 是**整文件一票否决**：

```
scripts/ipc-reachability-check-core.ts:54   含双斜杠的正则字面量（HTML 注释那条，逐字见该文件第 54 行）
src/agent/map/parse.ts:45                  type Lang = import("web-tree-sitter").Language;
tests/secrets.test.ts:6                    importOriginal<typeof import("node:fs/promises")>()
tests/sessions.test.ts:6                   同上
```

四个里有**三个**共用同一个形状：**类型位置里的 `import(...)`**（包括把它塞进泛型实参），第四个是含双斜杠的正则字面量。
`import("pkg").T` 是 TS 写 ambient/跨包类型的常规手段，`vi.mock` 的 `importOriginal<typeof import(...)>()` 更是 vitest 的标准写法
——也就是说，**任何这样写 mock 的测试文件此前都不在符号图里**。
后果不是"少一条边"而是**整个文件对符号图不存在**：谁改了 `parse.ts`，impact 只会说「这张图里没有 `fileTags`」。
（讽刺面：出问题的那个文件，就是负责抽取的那个文件。）

更值得记的是这条缺陷**为什么一直没被发现**：`tests/map-parse.test.ts` 早有一条用例写着
「语法错误文件不抛、返回空 tags」——它测的是夹具（`function {{{ nope`，整文件确实都是错的，
改成部分回收后仍然返回空集），而注释里写着另一套意图（「hasError 时仍尝试 query，错误恢复节点常能给出部分 tags」）。
**注释与代码相反、测试只覆盖到两者都同意的那一格** ⇒ 这条一票否决在测试上是"有覆盖"的，实际是一次没被读过的取舍。

### 落地

1. `fileTags`：`hasError` 不再整文件否决，直接跑 query（错误恢复留下的正常子树照常出 tags）。
   老契约「整文件都坏 ⇒ 空 tags」一字未改，且它**不需要**额外过滤器来维持：
   我第一版顺手加了道「丢掉落在 `ERROR`/`MISSING` 子树里的 capture」，随后为它写锚点时实测——
   四个真触发文件 + 七种造出来的坏法（空初值 / 未闭合类 / 断在半表达式 / `if (true {` / 坏参数表 /
   空类型标注 / `import type { A from "b"`）过滤前后 def 集合**完全相同**（error recovery 不在那里产具名节点），
   锚点因此存活 ⇒ 那条过滤是测不到的防御，已撤，理由与重开条件写在 `parse.ts` 的注释里
   （记忆第 54 条：假锚点比没锚点更坏）。
2. `EXTRACT_LOGIC_REV` 2 → 3：判据变了，磁盘 tags 缓存必须作废（#44 那套版本闸正是为这一刻建的）。
3. `map-check` 新增 **⑦ 真仓库召回：零抽取文件数 = 0**（实测 `files=405 decls=3282 召回率=0.9991 漏抽=3`）。
   **守机制不守阈值**：召回率会随新语法浮动，而「TS 认得过、图里却一个定义都没有」不会。grammar 装不上时打「未证」行，
   不冒充绿也不判红。
4. 探针本体 `scripts/probe-map-recall.ts`：每次跑都注入**自检**（拿一个必然存在的定义问抽取面认不认）——
   第一次落地时它读了个「召回 0.0000」，原因是我把 `fileTags(src, ".ts")` 的后缀写错了（该函数按**不带点**的键查表，
   不认识的静默给空集）。四种完全不同的成因共用同一行 0，没有自检就会有一条永远绿的瞎门。

判卷：`tests/map-parse.test.ts` 8 → 10 条（合成夹具那条钉「回收有界」，泛型实参里的 `void` 不许成为 def；
真文件那条钉四个回归现场），锚点 1 条（709 → 710）：`map-haserror-drops-whole-file`（退回一票否决 ⇒ 真文件用例红）。
第二条锚点曾随「ERROR 子树过滤器」一起加，实测那条过滤什么都挡不到 ⇒ 连过滤带锚点一起撤（见上面第 1 条）。

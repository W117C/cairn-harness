# 第 78 页 · 「没尺」这一态被算出来又扔掉了：6 条锚点的判卷文件已不在盘上，而闸只断言四种返回值里的两种

来路是一次自我纠正。第 77 页我写下「`expectFail` 标题也会漂且**无人判**」——同一天复核，那句是误诊；
但复核用的正是这道闸自己的取料函数，于是撞到它真正的洞。

## 一、误诊是怎么发生的：我拿一把一次性正则尺去量一只已经修过四遍的闸

第 77 页那句的依据是临时写的 `node --import tsx -e` 配对扫描：804 条里读出 21 条"子串命中"、16 条"两边都不命中"。
用 `scripts/mutate-anchor-titles.ts` 自己的 `parseAnchors` + `checkAnchorTitles` 重跑真表，读数是：

```
行数（test+expectFail 都在）：804 ｜ findings 按态：{"unverified-file":6}
drift 0 ｜ stale-waiver 0 ｜ unverified-face 0
```

⇒ 两条"标题漂移"一条**早就登记在 `KNOWN_DRIFT`**（我自己第 72 页建的，带撤登记条件），
另一条（`impact-query-deps-ghost-file-silent`）压根不算漂移：闸的命中口径与 runner **同宽**
（runner 判的是"vitest 输出**含**这段"，旧标题是新标题的前缀 ⇒ 照样认得出那一格）。
我那把尺只有 `it("…")` 一支抽取，而闸是**四支**（`it` / 模板 / 柯里 `it.each(...)("…")` / 柯里模板）
——闸的注释里就写着「先问抽取面缺不缺形状，再考虑登记成存量」，它自己第一版就栽在柯里那一支过。
**结论：一次性尺的"对不上"不是闸的读数。** 规则 117 的同族第三次命中（探针结构恒假／恒真，读的是尺不是产品）。

## 二、真洞在消费侧：`checkAnchorTitles` 发四种态，唯一的消费者只看两种

| 态 | 含义 | 谁在断言 |
| --- | --- | --- |
| `drift` | 锚点指不到用例标题 | ✅ `tests/mutate-anchor-titles.test.ts` |
| `stale-waiver` | 豁免名单里躺着已不再命中的条目 | ✅ 同上（与 `drift` 同一条断言） |
| `unverified-face` | `test` 字段不是 vitest 面 | ❌ 只计算，丢弃 |
| `unverified-file` | **判卷文件读不到＝这条锚点此刻没有任何观测者** | ❌ 只计算，丢弃 |

丢弃不是抽象风险，今天就有 6 条：`updater-manifest-https-only`、`updater-semver-direction`、`updater-semver-strict`、
`updater-manifest-unknown-fields`、`updater-safe-external-url`、`manifest-field-list-forgot-notes-again`
——全部指向 `tests/updater.test.ts`。而盘上状态是：

```
git status：D tests/updater.test.ts（HEAD 里还在）
src/main/updater.ts：**还在树上**（那笔删除只摘了判卷面，没摘实现）
```

⇒ 后果不是"锚点失效"而是"**变异照常施加、没有任何测试会红**"：整张表真跑时这 6 条会报成
**存活**，读的人把它归因成「updater 的实现没人守」，而真相是判卷面被删了。
这道闸注释写的是「单列 unverified，不算漂移**也不静默消失**」——实际就是静默消失，
因为"不静默"的那一半从来没被任何断言消费过（两头断：生产者发得出，消费者不看）。

## 三、修法：把「没尺」做成必须登记的等式（取料只留一份）

`tests/mutate-anchor-titles.test.ts` 里加两格 + 收一次取料：

- `NO_RULER`：登记表，键＝缺判卷面的锚点 id，值＝理由（**理由里必须写怎么撤**，由第二条断言用正则判）。
- 断言一：`实测 unverified-file 集合` **等于** `登记集合`。等号是双向的——新缺尺不登记红、
  登记过的不再缺尺也红（僵尸登记），不需要再造一条 stale 判据。
- 取料收成 `realFindings()`：新旧两条真表断言共用同一次求值（各抄一份取料迟早漂出两把尺）。

今天登记这 6 条的撤登记条件是：**那笔删除入库时把 6 条锚点一起摘掉**（或给 `updater` 补一份核心层判卷面），
然后从 `NO_RULER` 删名——不删就会被等式点名。锚点本体在 `scripts/mutate-verify.mjs`（他人热文件，本轮未动）。

## 四、造红：三条，全红在期望那一格（三份变体先自证非 no-op）

在真文件的**临时副本**上施加，跑完即删（真文件全程未被改过）：

```
A 多登记一条（假 id）        → expected [ …(6) ] to deeply equal [ …(7) ]     ✅ 红
B 少登记一条（删 updater-semver-strict） → expected [ …(6) ] to deeply equal [ …(5) ]  ✅ 红
C 理由留空                    → NO_RULER[updater-safe-external-url] 缺理由      ✅ 红
改后真文件：15 passed（原 13 + 新 2）
```

## 五、配对不变量（交删除面那笔的作者，也是这条线欠的下一格）

「**删判卷面必须同批摘掉钉它的锚点**」现在靠 `NO_RULER` 这张人工表兜住，兜的是"别忘了"，不是"自动摘"。
真正的机制位有两处，都在别人手里：`mutate-verify.mjs` 的 `--check-needles` 只核被测面的盘上取料
（判卷半边只在 HEAD 判据里出现），以及那张表自身。读数与本轮修法都已落在这里，等窗口。

# 整条名口径的三条实测（2026-09-30，第 239 页的前置取料）

## 1. 静态那把尺与运行时 `-t` 之间那层不对称，会不会造出「假唯一命中」

`scripts/lib/mutate-gates.ts:720-723` 自己写明：`--testNamePattern` 匹配的是**整条名**（describe 前缀＋it 标题），
而 `vitestTitles()` 只抽 `it` 标题。第 233 页把这件事用在「0 命中」那一侧（成因 `describe-title`），
但从没数过另一侧：**静态判成「唯一命中＝可以走 -t」的锚点里，有没有指针同时够得着自己那支 describe 的？**
那种锚点运行时会把该支下的多条一起选中，而静态给了它「唯一」的身份。

探针：`probe.mts`（同一份 `selectorAmbiguity`/`describeTitles`/`titleMatchPattern`，不另抄判据）。
输出 `probe.log`：

```
哨兵（合成表，静态判 1 且指针够得着支名）⇒ 期望 ≥1，现读 1
锚点全长 1093 条｜静态判成「唯一命中（可走 -t）」 1090 条｜进了这把尺但静态命中≠1 3 条｜压根不进这把尺 0 条
核对式：1090 ＋ 3 ＋ 0 ＝ 1093（应等于全长 1093）
其中指针同时够得着本判卷某支 describe ⇒ 运行时整条名会连带选中该支下的多条（保守上界）：0 条
```

⇒ **今天的假唯一命中是 0 条**，且这个 0 有哨兵顶着（合成表报 1）。
第一版探针的哨兵构造是错的（指针「唯一那条」而支名写「支名甲 带指针」，两边不相含 ⇒ 哨兵报 0、探针 `exit=1` 自己喊了出来）；
**构造错与读数 0 同形**，这一族今天第二次命中——没有哨兵我就会把「尺数不清」当成「盘上干净」。

## 2. 整条名的连接符是什么：`" > "`（实跑三臂，同一份判卷、同一分钟窗口）

用 `tests/settings.test.ts`（那 2 条多命中都挂在它上面）直接跑 `-t`，读机器自己印的 `Tests …` 那行：

| 指针写法 | 机器原句 |
|---|---|
| 只写 it 标题：`DEFAULT_SETTINGS 与读盘回退同向` | `Tests  2 passed \| 15 skipped (17)` |
| `describe > it`：`impactAnalysis 缺省开：走读盘路径，不走 DEFAULT_SETTINGS 自证 > DEFAULT_SETTINGS 与读盘回退同向` | `Tests  1 passed \| 16 skipped (17)` |
| `describe␣it`（空格连接） | `Tests  17 skipped (17)` ← **一条也没选中** |

三条结论：
⑴ vitest 的整条名用 `" > "` 连接（空格那支选不中＝直接证人）；
⑵ 把那 2 条多命中的指针**加上 describe 前缀**就能收到恰好 1 条——它们不是同名 `it` 撞在一份判卷的同一支下，
  而是**同一句 `it` 标题挂在两支 describe 下**（`autoVerify 缺省开…` 与 `impactAnalysis 缺省开…`，逐字如下）：
  - `autoVerify 缺省开：走读盘路径，不走 DEFAULT_SETTINGS 自证 > DEFAULT_SETTINGS 与读盘回退同向（翻一处忘另一处 = 老用户永远拿不到新默认）`
  - `impactAnalysis 缺省开：走读盘路径，不走 DEFAULT_SETTINGS 自证 > DEFAULT_SETTINGS 与读盘回退同向（翻一处忘另一处 = 老用户永远拿不到新默认）`
⑶ 连接符写错不是失败，是**一条也没跑**——这正是第 169 页给「0 命中」立尺的那个形状，只是这次由我自己造出来当负控。

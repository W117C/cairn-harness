# 第 69 页 · #57：截断提示要报"少了多少"，而 `read_file` 更狠的一格是**行数谎报**

来路：第 66 页立过一条纪律——「`omitted` 必须报出，只说"被截断了"＝模型以为看全」（当时落在条数帽 `countCapNotice`）。
字节帽那两支（`read_file` 50KB / `lsp` 32KB）当时没跟着改。这一轮补完，顺带量出**一个比措辞严重得多的后果**。

## 实测：谎报的行数会教模型跳读漏内容

`read_file` 同时命中"行帽"与"字节帽"时，行提示写的是**请求的行数**（`selected.length`），不是交付的行数。
一份 500 行、每行约 600 字节的文件，`offset=1, limit=400`：

```
[truncated: 输出超过 50KB 上限，已截断]
[truncated: 从第 1 行起共 500 行，仅显示 400 行；可用 offset/limit 继续读]
```

而真交付只有 **205** 行（51200 字节 / 每行 601 字节）。⇒ 模型照那句写 `offset=401` 继续读，
**中间 195 行被静默跳过**，且它没有任何信号知道自己漏了。这不是措辞问题，是能力 5 的修正拍会空跑一轮。

## 修法（三笔 + 一门）

1. `src/tools/cap-notice.ts` 新增 `byteCapNotice(limitKB, omittedBytes, nextStep)`：
   保留原句 `输出超过 N KB 上限，已截断` 作前缀（门与既有断言钉的是这句），括号里补省略字节数与下一跳。
   **`nextStep` 由调用方给**——同一句"下一步"在不同消费者身上成立与否不一样（第 66 页 glob 那句
   "把 path 显式指进去"对它自制的 `--glob` 就不通）：`read_file` 能 `offset/limit` 分批读，`lsp` 没有分页，
   所以它给的是"用 grep 定位符号名，或 read_file 分批读那份文件"。
2. `read_file`：字节帽生效时**重算交付行数**（`shownLines` = 帽后文本的完整行数；末尾那段算残行），
   行提示改用真值并给出可续读的 `offset`（= 起算 + `shownLines`，正好是被切半的那一行 ⇒ 重读它才完整，
   两跳合起来不漏一行）。字节帽没生效时**逐字保留旧句**（`read-shape` 那两条钉的就是旧口径）。
3. `lsp`：`capLspOutput` 改吃 `byteCapNotice`，报出省略字节数。
4. 门 `scripts/tools-check.ts`：
   - ① 与 ④ 把 "+80/+100 魔数容差"换成**两截口径**：正文 ≤ 帽，提示开销 ≤ 400 字节（实测 148/149）——
     余量按真实开销写，不放大魔数蒙过去；
   - 新增 ⑤ 报省略量。边界自己写清楚：**门只判"报了个正数、不是拿帽值或正文长度充数"**，
     逐字节对等那一条在 `tests/cap-notice-unit.test.ts`（它拿独立构造的请求体自己算省略量），门不重复造那把尺。

## 判据形状：两把尺各自抓什么（不是越多越好）

当场造红（两处单行突变，做完 `diff -q` 还原）：

| 突变 | 红的用例 | 没红的用例 |
| --- | --- | --- |
| 行数口径改回 `selected.length` | 「行数提示必须等于真交付的行数」❌ | 「按提示的 offset 再读一次」✅ —— 它量的是 offset，抓不到行数谎报 |
| 撤掉省略量 | 「read_file 报省略字节」❌、「lsp 报省略量」❌、门 ⑤ ❌（`省略 NaN 字节`） | — |

⇒ 记成两条分工而不是"一条全能尺"：**offset 尺保证不漏行，计数尺保证不谎报**。
只有"按提示真做一遍"那条能挡住"提示写得漂亮但没人验证"的形状，所以两条都要留着。

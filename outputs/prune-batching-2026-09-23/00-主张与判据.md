# 00 主张与判据：分批裁剪（少断几次可缓存前缀）· 2026-09-23

> 落地：`src/agent/prune-batching.ts`（叶子判据）+ `src/agent/prune.ts`（逐条节省量）
> + `src/agent/glm-session.ts`（装配链接线）+ 门 `prefix-churn-check` 的 **PC8**（A/B）
> + `tests/prune-batching.test.ts`（7 条）+ `pb-*` 针脚 5 条。施工与自我纠正在 `01-施工回执.md`。

## 1. 主张

裁剪的隐藏成本**不是"省得少"，是"每次越界都把已发出的前缀整段作废"**：
`prefix-churn-check` PC6 实测一次转轮作废 **40,299 字符**，而今天是**逐条**剪——
一条老结果越出保护区就剪一条，于是每轮断一次前缀。

同一条原理的另一个方向已经在 `compaction-cost.ts` 用了（「已经要断了就一次多压一点」）；
这里是它的对偶：**还没到断的时候，就先别断**（攒够一批再剪一次）。

```
不分批：断 5 次 / 累计作废 201,541 字符
分批  ：断 2 次 / 累计作废 122,477 字符        （重写次数 5 → 2，作废量 -39%）
```

## 2. 判据（缺省关，关时零回归）

```
未启用                                   ⇒ 照旧逐轮剪（恒 apply，且不额外投一次影）
头寸紧（估算 ≥ 可用 × 0.85）              ⇒ 照剪          ← 逃生舱，不许为省缓存撞硬闸
本轮新越界的可省量 ≥ 40,000 token         ⇒ 剪（一次多剪几条）
否则                                     ⇒ 推迟（不断前缀）
```
门槛取 `PRUNE_MINIMUM_TOKENS`（20,000）的 **2 倍**：只比 prune 自己的最小裁剪量高一级，
再高就是在拿上下文换缓存了。单测里这条以 `PRUNE_BATCH_MIN_SAVED_TOKENS >= 2 × PRUNE_MINIMUM_TOKENS` 锁住。

## 3. 依赖序（长在哪、谁持有、为何不是别层）

| 层 | 内容 | 为什么不是别层 |
|---|---|---|
| L0 纯判据 | `shouldApplyPrune` / `freshSavings`（叶子） | 推迟与否是可判定、可单测、可反对照料的决策；写进 `prune.ts` 会让"裁多少"和"何时裁"两件事挤在一个函数里，且没法在关的情况下证明零回归 |
| L1 事实来源 | `PruneOutcome.savedByIdTokens`（逐条节省） | 分批判的是**增量**。`savedTokens` 是累计值——每轮都含上一轮那几条，拿它判等于「永远已经攒够」。逐条量只能由产生它的那次遍历给出，抄一份文本映射逻辑就是本仓点名的"同族出口各抄一份" |
| L2 决策与记账 | `glm-session` 的 `assemble()`：算增量 → 问策略 → 记 `prunedIdsSent`（已反映在**发出去的**请求里的 id） | 只有装配侧知道"哪一份已经被发出去过"；`prune.ts` 是纯投影函数，不该知道传输历史 |
| L3 判据出口 | PC8（同一链开/关两支的 A/B）；单测**复用 PC8 那条规则**当接线证明 | 自己再搭一套驱动会因 I/O 时序不同而漂（本轮真试过：同一份种子门里出 5→2、我搭的那套量成 0） |
| L4 反脆弱 | `pb-*` 5 条针脚，其中一条专盯「装配链把累计值递给策略」 | 「策略对、传参错」是本仓反复出现的两头断形状，必须有锚点钉在传参那一行 |

## 4. 明确不做

| 不做 | 理由 | 反转条件 |
|---|---|---|
| 默认开 | 策略只优化缓存重写，代价是**上下文里旧结果多留一会儿**（更大输入、更晚压缩）。质量代价没量 | 靶场能量长会话完成率时（回到 BLOCKED 裁决 3 方案①） |
| "刚压完就顺手多剪"（蹭压缩已经断掉的前缀） | 需要跨阶段状态（本轮只记了 `prunedIdsSent`），且 events/loop 在另一会话在飞集合里。理论收益明确：压缩那一次重写是免费的 | 那三格空出来时 |
| 把推迟写进事件流（"本轮裁了/推迟了"） | `src/events/index.ts` 在飞 ⇒ 加不了字段。今天只有 `console.debug` + PC8/单测读数 | 同上一条 |
| 调 `protectTokens` / `minimumTokens` 本体 | 那两个数被多条既有测例逐字钉着，且**不是**本格的问题所在（本格管的是"何时剪"） | 需要时另立一格并带读数 |

# 42 · 定时任务五件一直只有实现、没有规格——模型面上它们不存在

> 日期：2026-09-24。所有读数带复跑命令（§五），本节数字只作该日快照。

## 一、缺口是怎么确认的（三条独立读数，不是一条推断）

1. **读代码**：`installAutomationTools()`（`src/main/agent-runner.ts`）装的是
   `table["automation_create"] = { name, run }` —— 只有实现，没有 `parameters`；
   `gateToolSpecs()` 的静态表里也没有这五个名字。
2. **跑面**（临时探针，跑完即删）：
   `skill / automation_{create,update,delete,run_now,list}` 在 `gateToolSpecs("auto")` 上**全部 false**。
   `skill` 是运行期注入（有 specFace 概念管着），automation 五件是**两面都没有** ⇒ 模型看不见 = 发不出去。
   目标里点名「goal 模式 / 长任务」，§12.2.5 写着"工具五件" —— 这条能力对模型而言不存在。
3. **为什么判卷没抓到**：G-B（`tests/tool-surface-parity.test.ts`）的实例面解析器只认
   `(TOOLS as unknown as Record<string, Tool>).x =` 那一形；`table["x"] =` 这一形整个不在分母里。
   也就是说：**这道门从没看过它们**，不是它放过了它们（第 37 页 §136 的「只有造相才看得见」又一形）。

## 二、这一笔建的东西

| 部件 | 干什么 | 为什么不放别处 |
|---|---|---|
| `src/agent/automation-surface.ts` | 五份规格 + `AUTOMATION_TOOLS`（每工具读哪些字段、哪些必填）+ `AUTOMATION_SCHEDULE_KINDS` | 规格必须与实现同名同串；`spawn_agent` 那一族的规格住在 glm-session 的静态表里，这里同层（`src/agent`）——跨层方向只能是 main→agent，所以对账放到判卷层 |
| `gateToolSpecs` 拼上这五份 + 只读档整族摘除 | 模型第一次能真正发起它们；只读会话不能排"下一次无人值守的写盘" | 与 `wait_for_agents` / `cancel_agents` 同一条既有纪律：非写向但也不该在只读档出现 ⇒ 必须显式点名 |
| **不进 core 面**（`OPTIONAL_SURFACE_TOOL_NAMES`） | core = 降配梯不许砍；这五件低频 ⇒ 可砍，砍了由 MS5 点名给模型看 | `CORE_SURFACE_TOOL_NAMES` 从静态表派生（原注释就反对再抄一份名字清单），所以这里用**减项**而不是新清单 |
| G-B 解析器扩到 `table["x"] =` 这一形 + **分母自证**用例 | 以后任何走这一形的工具都会被门盯上；解析器退回旧形状 ⇒ 当场红 | 只扩解析器不测它，等于把分母悄悄改小（§132：扩解析器同轮印出分母形状） |
| `KNOWN_TOP_FIELDS` 导出 | 判卷层能断"规格不许发明字段"（发明了的字段会被校验器拒成「未知字段」） | 真值在校验器那边，不复制一份 |

## 四、边界（写明，别读成"定时任务做完了"）

1. **参数面 AST 对账仍不覆盖这一族**：第 32 页那台 `measure-param-drift.mts` 靠"对象字面量里认工具名"取料，
   我的规格是表驱动生成的 ⇒ 它现在报「另有 8 处 parameters 声明认不出属于哪个工具」（多出的一条就是
   `automation-surface.ts`）而"无声明面 4 个"照旧。**修法**是让那台机器改问活面（调 `gateToolSpecs()`
   与 `automationToolSpecs()`）而不是猜源码形状 —— 另立任务，不在本轮偷做半件。
2. **五件都是低频**：`permissionTier` 越高、无人值守那一跑里能做的事越少（自动拒审批），这条写在
   `automation_create` 的描述里；模型真要"每晚跑一次并写盘"，仍会遇到那一跑里的一切都要人工批 ⇒
   这是 §12.2 的既有取舍，不是本笔引入。
3. **写向判定没动**：`isSideEffectTool("automation_*")` 今天是 false（`mainSessionSideEffect: false` 与它对齐）。
   也就是说这五件**不受方案门**挡，只受自己的审批卡挡。要不要把它们算写向，属产品裁决（会把它们变成
   "必须先有批准过的方案"），本轮只把现状登记进门，没顺手改语义。
4. **`automation_update` 与 create 共享 9 个字段的描述文本**（同一份 `FIELD_DOC` 对象，两处 JSON 各写一遍）
   ⇒ 不漂，但约一半字符数是这份重复。真要省，得把 create/update 合成一件带 `op` 的工具——那是协议改动。
5. 规格进的是常驻静态表；调度器没起来时五件自己 fail-closed（"调度器未初始化"），**不会**因为发不出去而静默。
6. **本笔顺手暴露的缺陷族**：往只读过滤链追加第三项，把守护前两项的两条变异针脚整条顶掉——
   `--check-needles` 报「针脚已不在源文件里」，而盘上测试全绿（判卷面自己失效时不会红）。
   已改：那条链改成一项一行，追加一族工具不再动到既有行的字节。

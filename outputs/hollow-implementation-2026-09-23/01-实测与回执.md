## 一、主轴实弹：把实现掏空，测试仍然全绿，没人出声

临时项目里有一个真实现的函数：

```js
export function refund(order) {
  if (order.paid !== true) throw new Error("not paid");
  return order.amount;
}
```

测试**只覆盖未支付那条路**（`assert.throws(...)`），对正常退款额不做断言——
这是真实仓库里最常见的形状：测试覆盖面小于实现面。

然后用真 `write_file` 把它掏空：

```js
export function refund(order) {
  if (order.paid !== true) throw new Error("not paid");
  // TODO: 接支付网关退款 API
  return null;
}
```

| 步 | 真实回执（逐字） | 测试 |
|---|---|---|
| 写入原实现 | `已写入 src.mjs（113 字节，新建 +4 行）` | `ok=true # pass 1 / # fail 0` |
| 写入掏空版 | `已写入 src.mjs（142 字节，+2 −1 行)` | `ok=true # pass 1 / # fail 0` —— **仍然全绿** |

⇒ **判读**：写盘回执里没有任何一处提到"本次新增行含 TODO / 返回值被改成 null"。
`+2 −1 行` 这个数是对的，但它把"加了 2 行"和"删掉了真实计算"当成同一件事。
**"任务完成"与"实现存在"在今天的读数上是同一件事。**

这与能力 18 是**同一枚硬币的两面**：18 抓到"考卷变薄也能绿"，
本页抓到"**实现被掏空也能绿**"。两条都只需要一个 run 级聚合面，不该建两条链（见 `00` §三 L1）。

## 二、附带抓到的缺陷 D1：`# fail 0` 被读成失败（假红）

同一次掏空后运行，`npm test` 自己报 `# pass 1 / # fail 0`（绿），
但用真 `buildReceipt` / `hasFailureSignal` 判同一段输出：

```
buildReceipt.status = failure        ← 与 exit code 口径相反
被认领的行：「# fail 0」
```

根因在 `src/agent/evidence.ts` 的 `FAIL_RE`：

```
const FAIL_RE = /\berror\b|\bfailed\b|\bfail\b|\bfailure\b|失败|错误/i;
```

词边界用对了（本仓踩过的 `\b` 坑没踩），**但它对"关键词后面跟的是 0"没有概念**：
`# fail 0` 字面含 `fail` ⇒ 命中。任何 `node --test`（TAP 风格）输出都带这一行，
**所以每一次绿的 TAP 跑都会被判成一次失败证据**。
注释写着"照 SoL-Pi FAILURE_SIGNAL 语义"——那是移植来的语义，本地没对 TAP 摘要面校验过。

方向与本页主轴相反（假红而非假绿），但**同一个根**：文案匹配不能当判定面。
`00` §五 把这条区分写成正式结论，D1 是它的本地证据。

## 三、附带抓到的缺陷 D2：`uncertain` 是一个没有生产者的字段

全仓（`src/` + `tests/`）逐行扫，`uncertain` 只出现三处：

```
src/agent/evidence.ts 第 27 行 · 类型声明   uncertain: boolean
src/agent/evidence.ts 第 89 行 · 赋值       uncertain: false
src/agent/evidence.ts 第 132 行 · 校验      typeof r.uncertain !== "boolean" ⇒ schema-mismatch
```

⇒ **一处恒 `false` 的赋值 + 一处要求它是 boolean 的校验**：这个字段结构上永远不可能为真，
而序列化与对账面都在带它跑。本仓对这类东西有现成的名字：**"能力已发货、入口没通"**（P2-6 同族）。

（探针第一版把类型声明那一行误计成"生产者"，是我判据写错；改成只认真赋值后才是上面这个结论。
教训记在这儿：**扫出来的数要先怀疑判据写法**，本仓在这条上错过不止一次。）

## 四、为什么判据必须 diff-scoped：宽正则在本仓自己身上就误报

| 信号 | 宽口径在本仓 `src/`（137 文件）命中 | 抽样判读 |
|---|---|---|
| "空函数体" `function x(){}` / `=> {}` | **48 处** | 绝大多数是空 catch、空回调、接口方法声明——**不是掏空** |
| `TODO` / `FIXME` / `XXX` 注释 | **0 处** | 本仓 src 里一个都没有 |

两条读数各自有用：

- 48 处 ⇒ **拿宽正则当判据等于自造假红**（这正是本仓最忌的那种红）。所以 L0 必须
  **只在本次新增/替换的行上、按结构判定**（函数体语句数、`return null` 是否替换了有值的返回）。
- 0 处 ⇒ "新增 TODO 行"这一族在**本仓**近零噪声，可以当**弱提示**；
  但它是自我声明而非结构事实，**不许进判定面**（`00` §五）。

# 能力 29：自引用账（这段文本是谁写的）

一句话：**事件流里没有"这段文本是 harness 自己写的"这个字段**，于是编排器代写的 `tool_result`
与工具真跑出来的输出，在下游读者（看门、沉淀、成本读数）眼里同价。本仓已经在另一条轴上把这件事
做对过一次（`isEnvVerifyCause`），这条轴只是没接。

## 二、机制：四条真实通路

1. **沉淀**（`memory/distill.ts:45-73`）：按**工具名**计数、根本不读 `e.output` ⇒ harness 写的
   文本没进记忆，但 harness 代写的那条**失败事实**进了，与"模型自己读错文件"并排写成同一行
   "工具失败"，再引导模型按 `type=feedback` 沉淀进**跨会话**记忆——而它描述的是这次编排，不是这个代码库。
2. **停滞看门**（`agent/stuck.ts`）：`stuckActionOf` 与 `stuckObservationOf` 都是**截前 200 字符逐字比**；
   规则二 `same_action_error_x3`（`stuck.ts:52-57`）**不读 observation**，只比 action ＋ 全 error。
3. **成本读数**（`tool-choice.ts:163`）：repeat 键 = `stuckActionOf(...) + "\n" + stuckObservationOf(e.output)`。
   同文件上一行注释刚修过一个**同族**污染（"带 gate 的失败…被人拒批的次数污染"），这一路没修。
4. **worker 侧同流**（`orchestrator.ts:1639`）：worker 的 `stuckTurns` 直接吃 `e.output`，而
   orchestrator 正是那批自注 `tool_result` 的唯一生产者。

## ④ 真 `detectStuck`：漏报方向（旧账钉死）

```
四次同一真实输出、无尾注 → stuck=true rule=same_action_obs_x4（真停滞，正常）
四次同一真实输出、尾注逐次不同 → stuck=false（看门被打散）
全 error + 尾注不同 → stuck=true rule=same_action_error_x3（规则二不读 observation，故仍触发）
```

这不是新发现的假设：`loop.ts:69-77` 就是以此为由把 `stuckNudge` 缺省关掉，注释原文
"追加文本会改掉 `stuckObservationOf` 比较的观察串…把×4 相同打散成×3 相同 + 1 条带尾注 ⇒ 看门
永不触发（m3c 集成测实测到）"。**教训已被记成一句注释＋一个开关缺省值，但没被记成一条断言** ⇒
本页判据要的就是把它钉住（同仓 `fdbc1ba` 那条"能静态判定的规矩不该只写在文档里"）。

`withVerifyCauseNote`（`verify.ts:18-23`）是同一形状的**尾追**，两处出口共用一只。实测它的 note 是
**纯常量文本**且二次调用幂等 ⇒ 恰好不打散看门。⚠️ 这个安全性来自"文案里没写计数器/时间"的巧合，
不是设计约束：谁哪天往那行里加个 attempt 数字，④ 第二行就翻成漏报。⇒ 判据形状：对
`withVerifyCauseNote` 的输出加一条"常量性"针脚（同形状 mutation needle）。

## 一、机制（栈是现成的，不用猜）


本文件**故意**把环挂在一条 `tool_call` 上（"环活着时租约才真持有"，收束版量不到那一格），
所以 `orch.spawn(...)` 是 `void` 掉的游离 promise。用例结尾 `cancelAll()` 让环开始收尾，
而 `afterEach` 只做了一件事：`rm(work)`。收尾链里那一步审计 append 落在哪个时刻，取决于并发——
落在删盘之后就没人接它的 rejection（游离 promise 上没有 handler），vitest 把它记成 Unhandled Rejection 并 exit 1。

## 二、修法：把"结清"做成收尾的一部分，两侧都要有名字

```ts
afterEach(async () => {
  const pending = detached.splice(0, detached.length);
  const settled = await Promise.race([
    Promise.allSettled(pending),
    new Promise<null>((resolve) => { timer = setTimeout(() => resolve(null), DETACH_BOUND_MS); }),
  ]);
  await rm(work, { recursive: true, force: true }).catch(() => {});   // 清理永远执行（规则 120）
  expect(settled !== null, "…5000ms 内没落地 ⇒ 有环没被 cancelAll 收队").toBe(true);
  expect(rejected.length, "游离的 spawn 链被拒绝：…").toBe(0);
});
```

两条观察各钉一侧，缺一不可：
- **只排空不检查**＝把真错误咽下去（今天它至少以进程级错误冒头，改成静默通过是退步）；
- **只检查不排空**＝竞态原样留着。
有界（5s）而不是无限 `allSettled`：链永不落地本身就是要报的病，不该变成用例超时。

**没有动产品**：`src/agent/orchestrator.ts` 此刻在别人手里飞（实测 `M`），而且这一格真正的失效条件是"用例删掉了自己的盘"，
生产上没有那个动作。产品侧留下的一条另账见 §四。

## 四、留下的一条产品账（不猜修法）

同一个 ENOENT 在 orchestrator 里有两支出口：
- worker 收尾那支**有** catch，并出声：`[orchestrator] worker 收尾中途失败，按 failed 放行等待方：worker-1 ENOENT…`；
- `cleanupWrite` 的审计 emit 那支**没有** catch（`:2237` 直接 `await this.opts.emit(...)`）。

两支宽度不同是本仓点名的同族（第十三族）。但"审计写失败该怎么处置"（升级成 worker 失败？只标注？重试一次？）
需要先有一个**生产可达**的构造来判——本轮只有测试删盘这一条路，不足以定改法 ⇒ 登记为待实测，不先写兜底（规则 94/95）。

# 第 85 页 · 「认证一棵树」从此是一条命令：`scripts/head-cert.ts`（前置是**依赖集**，不是跑门）

> 线程：`head-cert-one-command-2026-09-26`。动因全在第 83/84 页的实测里：我为"跑在哪棵树上"这句话
> 付过三次代价——一次把旧树读数报成新 HEAD 认证（规则 184）、一次被 `TS2307: Cannot find module 'electron'`
> 的环境假红挡住、一次是更早的软链树 `run_shell` 假红（规则 103）。

## 一、收进来的三件事

| 步骤 | 以前（手工） | 现在 |
| --- | --- | --- |
| 切树 | `cd 树 && git checkout … >/dev/null 2>&1 && 跑门 > log`——checkout 失败被静默吞掉，log 照样有 ⇒ 旧树读数被当成新 HEAD | 每步打印 `exit=`，**事后复核 `rev-parse HEAD` 等于目标**才继续；不等就 exit 2 停下 |
| 依赖 | 直接从主树 `cp -al node_modules`，跑到一半才发现那棵树声明的包没装 | 先比「该提交 `package.json` 声明的」vs「树里真装了的」，缺的从本机任一已装副本 `cp -al` 补，补不齐就在汇总里写死「**不可归因于代码**」 |
| 读数 | 退出码常被管道吃掉（`cmd \| tail` 的 `$?` 是 `tail` 的） | `spawnSync` 直接取 status；汇总里同时印 `TREE` / `DIRTY_JUDGED` / 两条门的读数 / 逐条 log 路径 |

纯函数层 `scripts/lib/head-cert-deps.ts`（`declaredDeps` / `installedDeps` / `missingDeclaredDeps`），
判卷面 `tests/head-cert-deps.test.ts`（9 条：三种依赖字段都算声明、`peerDependencies` **不算**、
作用域包必须展开否则假缺、只装不声明的不算缺失、坏 `package.json` ⇒ 空而由调用方按"没尺"处理）。
搬进 `scripts/lib` 而不是留在脚本里，是因为"只有门脚本会跑到的格子挂不上变异锚点"（规则 118）。

## 二、活体读数（一条命令跑出来的，不是推的）

新建一棵树（`--tree=.worktrees/head-cert-demo --skip-test`）：

```
目标提交：fd59ad9（--at=HEAD）
worktree add exit=0
已核：TREE=fd59ad9…｜判卷四面在飞 0 项
依赖核对：该提交声明 14 项，缺 4 项：electron、electron-builder、electron-vite、vite
  硬链接 electron ← .worktrees/head-audit-0924/node_modules/electron exit=0   （另三支同）
typecheck exit=0（0 报错）
```

⇒ **"HEAD 的 typecheck 红了"这句话之前根本不可信**：主树的 `node_modules` 反映的是那笔未提交的 core-only
迁移（四个 Electron 族依赖已被摘），拿它去认证仍含桌面层的 HEAD，缺的是 **4 个包**，不是代码。
补上后 `typecheck` 立即 0 报错。

同一条命令跑全量（复用那棵树）：

```
checkout exit=0 ｜ 依赖核对：缺 0 项 ｜ typecheck exit=0
Test Files 2 failed | 264 passed (266) ｜ Tests 2 failed | 2848 passed (2850) ｜ exit=1
```

与我上一轮**手工**认证的读数逐字相同 ⇒ 这个面没有改变结论，只是把结论的来源变成一条命令＋一行 `TREE=`。
剩余 2 条红的归属没变（`docs-check` 的存量豁免断言＝#14；两条渲染层锚点漂移＝#12 那笔未提交删除）。

## 三、边界（不假装多做了它没做的）

- 它**不注册成门**：`scripts/gate-manifest.ts` 在别人手里（热文件），且整表全量再叠一棵 100s 的树会拖慢每一次交付；
  定位是"交付前/归因时手动一跑"，`#14` 的复跑口径已改指它。
- 借来的依赖是**硬链接**，只读别的 worktree、不写它们；被借的树若之后自己 `pnpm install`，本树仍指向旧 inode ⇒ 汇总额外印一行
  「依赖来源是借的」的语义由 `依赖完整=` 承担，重装后复跑即可。
- 判定「绿」的条件是 `依赖完整 ∧ typecheck 0 ∧ test exit 0 ∧ DIRTY_JUDGED=0`——
  最后那一项让"在带在飞改动的树上取读数"没法伪装成 HEAD-only 认证（规则 46/97 的形状）。
- 未登记进 AGENTS.md/文档地图：那两面受并发会话与 D 系判据管辖；本轮只在 PROGRESS 与本叶子里留口。
  若下轮还要手写 worktree 命令，就把它升成一条 gate 提案。

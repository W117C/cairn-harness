# 39 · 用户自定义子智能体第一次有了一条**不用装插件**的路

> 日期：2026-09-24。所有读数带复跑命令（§五），本节数字只作该日快照。

## 一、缺口是怎么确认的（不是"我觉得没有"）

目标里点名「用户自定义子智能体」。上一轮（`d818c18` → `3f57278` + `e5d2a83`）把插件角色那一支
修通了（装载 → 注册 → spawn 收 role → 落流 → 发现面 → 重派），但当场留了一条**没裁的边界**：

> 除插件容器外没有非插件的自定义路径——用户往 `~/.claude/agents/x.md` 放文件得不到任何东西，
> 用户级插件目录还要 `M2E_USER_PLUGINS` 才生效 ⇒ 要么给正式路径，要么把"角色 = 插件专属"写死成边界，
> 现在两头都不明说。

本轮实测那一句仍然是真的（读 `PluginRuntime.load` 的角色来源只有 `manifest.plugins[].agents`；
`resolveStageRole` 只认 `内置 | "*":"*"` 形态），所以选**给路径**——"两头都不明说"本身是缺陷，
把它留着就是让用户继续猜。

## 二、这一笔建的东西

| 部件 | 干什么 | 为什么不放别处 |
|---|---|---|
| `src/agent/roles/user-agents.ts` | 读两个用户级来源（`~/.dsh/agents`、`~/.claude/agents`）→ 与插件角色**同形状**的 `{name, description, path, frontmatter, body}` | 形状一致，消费端才不必另起一路；`home` 可注入，判读不依赖真 home |
| `PluginRuntime.userAgentRoles()` + `findAgentRole` 的 `??` 一支 | 两条来源**一条查找面** | 另起一条"读角色"的路 = 两处口径必漂（本仓反复点名的死法） |
| `routingList()` 合并角色行 | 清单把 `user:<name>` 一起列给模型，共用同一份预算与截断规则 | 预算分两段就会出现"被截掉的恰好是模型唯一需要知道的那条" |
| 同名裁决 + 一律出声 | `.dsh` 赢 `.claude`，被盖住的那条**点名路径**进 `manifest.warnings`（`plugin: "user-agents"`） | 静默覆盖 = 用户改了文件却没生效而没人吭声；软链/非普通文件/空文件同口径 |
| `spawn_agent` 的 `role` 说明 + 未知角色报错 | 两处文字补上 `user:agent-name` 形态 | 见 §四第 1 条——这是本轮第二笔，第一笔漏的正是这一格 |

invoke 用 `user:` 前缀：与 `plugin-name:agent-name` 同形但不同命名空间 ⇒ `stages[].role`、
`spawn_agent(role=…)`、恢复重派**都不用改协议**就能分辨来源。产品侧零改动即生效：
`agent-runner.ts` 的 `agentRoleFor` 本来就指向 `currentPluginRuntime()?.findAgentRole`（单一接缝的正解在这里显形）。

## 四、边界（写明，别读成"自定义子智能体做完了"）

1. **本轮真正补的是第二笔**：第一笔只把"清单"那一面对齐，而模型手里两份说明书（工具参数描述、
   未知角色报错）仍只写 `plugin:` 形态 ⇒ 清单里有 `user:reviewer`，说明书却说这条路不存在。
   这是「同一件事两处口径」的镜像形状：**少告知 = 少调用，且不报错、看不见**。
2. **项目级 `.agent/agents/` 刻意不开**。它会随仓库带来，而一份 `agents/x.md` 就能决定 worker 的
   工具面（`tools` / `disallowedTools`）与提示词 ⇒ 需要一次信任设计，与散装 skill 同类问题。
   用户自己的 home 没有这个问题（放文件的人就是授权的人）。要开的话，先写设计再写代码。
3. **角色仍上不了看板**：`agent_spawned.role` 早已落流，渲染层没有展示位；这与 #13/#38 同属
   要动 `app.js` / `index.html` 的那一批（并发会话表面）。
4. `agent-runner.ts:207` 的注释还写着"插件 agent 角色解析（stages[].role = "plugin-name:agent-name"）"——
   该文件此刻在他会话的写入窗口里，本轮**不改写别人的在飞文件**，此条留作下一次动它时顺手收。
5. 用户级角色与插件角色**不共用信任门**：`.claude/agents` 里的文件不需要 `trustDecide` 就生效。
   这是本笔的自觉取舍（§二最后一行说清了为什么），但它意味着"信任面"现在有两套口径——
   若要把用户级也收进信任决议，那是一个产品裁决，不是 bug。

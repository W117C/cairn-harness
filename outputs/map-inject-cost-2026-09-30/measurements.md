# 地图重送的价格与抖动（#34 的决策取料，2026-09-30）

问题（任务原句）：地图只在首轮注入 ⇒ 长会话／压缩后模型拿不到全局视图；**先量每轮重送多少钱再裁**。

## 一、现读到的形状（逐跳读到默认路径，规则 280）
- 闸：`src/agent/glm-session.ts:770` `if (!mapBuilder || historyForMap.length > 2) return null;`
  ——`buildMapText` 每次请求都跑，所以第二轮起这一位**根本没有**（不是"少一句"）。
- 位置：`composeTurnMessages` 里地图是一条 `system` 消息，排在 **history 之前**（`glm-session.ts:549-554`）。
  ⇒ 它一变，它后面整段可缓存前缀一起失效；它每轮都送的钱不是 919 token 本身，而是这次失效。
- 压缩那支确实会再问一次（`glm-session.ts:834` `mapText = await buildMapText(history)`），
  但吃的是**同一条闸**：重组装后 history 只要 >2 就还是不送 ⇒ 这条"重注"路径今天**不保证**发生。
- 观测者：首轮的「有没有」**有**（`tests/map-self-report.test.ts` 的接线证人），
  次轮的「还送不送」**零**——把 `> 2` 改成 `> 200` 全量判卷一条不红。

## 二、实测（本机、本仓，HEAD=`7025cf4` 工作树）
| 读数 | 值 | 怎么来的 |
| --- | --- | --- |
| 地图正文 | **919 token／3675 字符**（收全：graphFiles=candidates=523，cap=5000 不咬） | 真 `createMapBuilder().build()` 打在本仓，`mapInjectText()` 后取长度 |
| 每轮重送的钱 | openai-standard 全价 ≈ **$0.0018/轮**、缓存读 ≈ $0.00115/轮；50 轮 ≈ **$0.06–0.09** | `DEFAULT_PRICE_TABLE` 的 `inputPerMTok`/`cacheReadPerMTok` × 919 token（价表原值，不乘猜的系数） |
| 同仓连建两次（间隔毫秒） | **逐字相同** | 探针 A：`a1 === a2` 为 true |
| 只动一个文件的 mtime（+60s）后重建 | **在第 804 个字符分叉**，长度不变（3487→3487） | 探针 B：`utimesSync` 一处，恢复后再建**仍不等于**最初那份 |
| 仓库一字不动，隔 **90s** 再建 | **也在第 804 个字符分叉**，长度不变 | 探针 C（决定性那条）：`noRepoChange_after90s_same=false` |

> 注：探针 A 给 3675 字符，B/C 给 3487——**同一条尺、同一个 sha，两次量出不同的长度**，这本身就是上面那条结论的证据，
> 不是两个口径互借。上面「919 token」取的是探针 A 那次（它同时印了 graphFiles/candidates，是完整的一次自述）。

⇒ 结论不是"贵"，是**不稳**：地图正文随**相对年龄**（`compareCandidates` 的 mtime 降序）漂，
一次会话里 agent 自己就在改文件 ⇒ 每轮重送＝每轮抖前缀。
所以「按轮重送」这条路的价格要按**前缀失效**记，不能按 919 token 记——这才是 #34 该看的数。

## 四、剩下的裁决（未做，理由写在这）
候选形状是「只在结构丢失事件重注（压缩／大幅剪枝后），且重送的那份与首轮**逐字相同**」——
"逐字相同"这一位是关键：要做它，得让地图正文不吃相对年龄（排名键换成绝对 mtime＋rel 次序，或首轮定稿后按会话冻结文本）。
代价与收益都还没量够：
- 收益侧缺一个数：**中段没有地图，模型实际多花多少探索**（要真会话轨迹，`loop-eval` 现读 0/4 可跑＝缺模型凭据，见 #17）；
- 成本侧缺一个数：**冻结正文会不会让地图过期**（agent 新建文件后，冻结的那份就不含它）。
⇒ 不拿"看着合理"替这两个数背书；本轮先把格子装上观察者，政策等数。

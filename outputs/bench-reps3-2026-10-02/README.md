
# §9 第 1 项（12 条 × 3 rep 四读数）：本次尝试**作废**，卡在免费额度日配额

## 一句话

按计划书原命令跑了 `--tasks fixtures/bench/tasks.json --reps 3`（36 趟），
**34～32 趟死在 HTTP 429 限流、请求数 0、token 0** ⇒ **分母不完整，任何成功率都是假的**，
所以本档**不报成功率**，只登记这次尝试与它的真实原因。

## 实测证据（不是推测）

```
probe → HTTP 429
{"error":{"message":"Rate limit exceeded: free-models-per-day-stealth.","code":429,
 "metadata":{"headers":{"X-RateLimit-Limit":"1000","X-RateLimit-Remaining":"0",
 "X-RateLimit-Reset":"1790985600000"}},"limit_source":"openrouter_free_tier_daily"}}
```

**免费模型档的日配额 1000 次 / 天已用满**（`limit_source=openrouter_free_tier_daily`）。
今天为了拿到 M4 的读数与四趟真跑，把这 1000 次烧完了——**是我烧的，账记在这里**。

## 36 趟的实际状态

| 状态 | 趟数 |
|---|---:|
| 真正起步（`requests>0`） | **4** |
| 被限流 / 未起步（`requests=0, tok=0`） | **32** |

那 4 趟里：`B1` PASS、`B3` PASS、`B2` FAIL（verify 未通过）、`B4` FAIL（其中一条 fail 就是 429 抛错）。
⇒ **连这 4 趟也不能算读数**：B2/B4 是在限流中途被打断的，"失败"里混着"跑不成"。

## 结论与下一步（三选一，都要业主定）

| 路子 | 代价 | 备注 |
|---|---|---|
| **① 等日配额重置**（见上表"重置时刻"）再跑 | 0 元，但要等 | 最省事；跑之前先单发一探确认 `Remaining>0` |
| **② 给 `loop-eval.ts` 加 429 退避重试 + 趟间节流** | 小（改一处） | 治本：试跑被限流打断会**污染读数**（本次 B4 就是），加退避后至少不会把"跑不成"记成"失败" |
| **③ 换付费档 / 换模型** | 花钱 | 不受 free-tier 日配额约束 |

**我的建议：先做 ②，再等 ①。**
理由：本次的教训不是"额度不够"，而是**"限流中途被打断时，读数会把'跑不成'记成'失败'"**——
这是**判据缺陷**，不是额度问题；不修它，下次额度够了也会在别的限流下重演。
（同族：本仓点过名的"没量到 ≠ 没问题"。）

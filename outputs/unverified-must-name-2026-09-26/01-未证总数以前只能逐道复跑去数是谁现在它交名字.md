（`scripts/assertion-health.ts` 里 `gateUnverified` 的注释记下过一次同形事故：账本说零未证、屏幕说 1）。

## 一、做了什么

- `scripts/assertion-health.ts` 新增纯函数 `unverifiedBreakdown(runs, aggregate)` → `{text, total, consistent}`；
- `scripts/gates.ts` 汇总印「逐道：」，并把**两个口径的和 vs 总数**做成判据：不一致 ⇒ 印 ❌ 且**退出码 1**（不只是印一行）；
- 判卷 `tests/gates-scan.test.ts` 33 → **37** 条：点名顺序、分叉抓得住（6 vs 3）、全零那侧（空串＋一致，不许把空串读成异常）、
  以及"总数非零而逐道全 0"（这个数不是从门来的）。

## 二、造红（复现"漏登记一道门"这个失效方式）

台架：把汇总累加改成 `unverified += uv + 1`（逐道之和不变）⇒ 干净子集跑：

```

   逐道：（每道门都交 0 却有个非零总数 ⇒ 这个数不是从门来的，取料面有洞）
❌ 未证两个口径分叉：逐道之和 0 ≠ 汇总 1 ⇒ 本表汇总不可信，先修计数器再谈绿
EXIT=1
```

跑完 `cp /tmp/gates-115.ts` 复原，`rg -c MUTATION-115` ＝ 0，`git diff --numstat` 回到 11/2（只剩本轮自己的改动）。

## 三、为什么"分叉"要判红而不是只印一行

`--strict-unverified` 已存在（把未证判红），但那是**产品决定**；两个口径对不上不是"未证多"，是**读数不可信**——
不可信的汇总连"未证 6"这句话都不该说出口。所以这一格无条件红，不吃严格模式开关（规则 160：潜在缺陷先装复跑面）。

## 四、上一条读数作废：`model-surface-check` 那句「丢 30 把」是压力夹具，不是生产面

第 114 页把它记成"生产面少了 30 把工具"，实测不成立：

```
[model-surface-check] 真实 BASE_SYSTEM：670 字符｜装配面 10024 字符 / 20 条｜帽 24000 字符
  ✅ MS1 固定面在帽内（10694 / 24000）      ✅ MS4 缺省装配逐字不变
  ✅ MS3 降配只做尾丢（构造的 60 条面 → 37 条，丢 23 把）
  ✅ MS6 core 不得被自动砍 — unresolvable=true，core 全在=true（丢 30 把，仍超 50244 字符）
  合计 固定面 10694｜帽 24000｜占用 44.6%
```

MS3/MS6 的"丢 23/30 把"发生在**构造出来的超量面**上，正是这两条判据该做的事（证明降配只丢尾部、core 不被砍）；
生产面今天 20 条、占帽 44.6%，没有工具被砍。⇒ #31 第一条按"读错一格"关掉，不留成假账。

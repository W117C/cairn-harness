## 2. 三层令牌架构（Cairn 缺的整整一层）

Claude 是 **色阶 → 角色 → 语义**；Cairn §4.2 只有「色阶 → 语义」两层。

```
① --cds-gray-10…900      （35 阶 × 6 族 = 210 色，本次全量恢复）
      ↓
② --cds-role-{accent,danger,pro,success,warning}-{50,100,250,300,400,450,600,700,800,850,fill,fill-hover,on}
      （6 角色 × 11 刻度 = 57 个，Cairn 完全没有）
      ↓
③ --cds-text-primary/secondary/muted · --cds-{bg,fill,border,text}-accent · --cds-surface-0…3
```

### 2.1 角色层的实测接法（①01 §1 / ②直接 grep）

```css
/* 每个角色挂在自己的色族上 */
--cds-role-accent-250:  var(--cds-blue-250);
--cds-role-danger-250:  var(--cds-red-250);
--cds-role-pro-250:     var(--cds-violet-250);
--cds-role-success-250: var(--cds-green-250);
--cds-role-warning-200: var(--cds-yellow-200);
/* fill / on 是派生，不是新色 */
--cds-role-accent-fill:       var(--cds-role-accent-450);
--cds-role-accent-fill-hover: var(--cds-role-accent-400);
--cds-role-accent-on:         var(--cds-gray-0);   /* accent/pro/danger 用白字 */
--cds-role-success-on:        var(--cds-gray-900); /* success/warning 用黑字 */
```

### 2.2 语义层只写语义名，亮暗自动分档（②）

```css
--cds-border-accent: var(--cds-role-accent-250);  /* 亮 */
--cds-border-accent: var(--cds-role-accent-700);  /* 暗 */
--cds-text-accent:   var(--cds-role-accent-300);  /* 亮 */
--cds-text-accent:   var(--cds-role-accent-600);  /* 暗 */
--cds-bg-accent:     var(--cds-role-accent-100);  /* 亮 */
--cds-bg-accent:     var(--cds-role-accent-800);  /* 暗 */
```

**组件只写 `--cds-border-accent` 一个名**，亮暗各自取不同刻度。这是 Cairn 该抄的核心机制。

### 2.3 表面层级（② + ③）

| 令牌 | 亮 | 暗 | 说明 |
|---|---|---|---|
| `--cds-surface-0` | gray-20 `#f9f9f7` | gray-900 `#0b0b0b` | 页面底 |
| `--cds-surface-1` | gray-10 `#fcfcfb` | gray-850 `#151515` | ← **真机主区实测是这个** |
| `--cds-surface-2` | gray-0 `#fff` | gray-830 `#1a1a19` | 卡片 |
| `--cds-surface-3` | gray-0 `#fff` | gray-800 `#20201f` | 弹层 |

暗色**越抬升越亮**、亮色**越抬升越白**——方向相反，靠 §2.4 的翻转自动完成。

### 2.4 暗色翻转公式（②，实测）

```
暗色下：--cds-neutral-<N> = --cds-gray-<900 − N>
不动点：N = 450
```
**不需要手写第二套 dark 值**——一个语义名在两档自动落位。Cairn 现状是亮暗各写一份（`[data-theme=dark]` 块），应改为翻转。

## 3. 5 级尺寸档（Cairn 只有单个 `--rem-scale`）

Claude 有 `data-step="1…5"` 五档（②，实测）：

| step | radius | h-control | font-size-body |
|---|---|---|---|
| 1 | .3125rem (5px) | 1.25rem (20px) | .75rem (12px) |
| 2 | .375rem (6px) | 1.5rem (24px) | .8125rem (13px) |
| **3** | .4375rem (7px) | 1.75rem (28px) | .875rem (14px) |
| 4 | .5rem (8px) | 2rem (32px) | .875rem (14px) |
| 5 | .625rem (10px) | 2.5rem (40px) | .9375rem (15px) |

- `comfortable` 密度 ≡ **step 4**（01 §2 实测 17/17 键一致）；默认 ≡ step 2
- 全文件**只有 `comfortable` 一档** density，未找到 compact/spacious
- `--cds-rem-scale` **全仓库 0 处定义**，只以 `var(--cds-rem-scale,1)` 被消费 300+ 次 → **宿主注入的缩放钩子，实现必须保留 fallback 写法**

Cairn §4.4/§4.5 有 `--rem-scale` 但只有一档 + 手写的双轴变体，应改成这 5 档阶梯。

## 7. 消息区（②）—— 规范里的「41/56px」是错的机制

```css
--cds-assistant-message-text-inset: 4px;
--cds-assistant-message-text-stop:  clamp(0px, (100% - 384px) * .175, 56px);
```

**「回复右侧最多留 56px」不是固定值，是流体 clamp**：容器宽度减去 384px 后乘 17.5%，上限 56px。
Cairn §3.11 写死「56px」会丢失窄屏自适应。应照抄 clamp 公式。

气泡圆角也是派生的：`--cds-message-bubble-radius = --cds-radius + .25rem`。

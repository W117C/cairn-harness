## 2. 需求清单

编号规则：`MAINT-*`（可维护性与复用）/ `RESP-*`（响应式）/ `VIS-*`（视觉一致性）/ `A11Y-*`（可访问性）/ `PERF-*`（运行时性能）/ `GAP-*`（结构性缺口）。
每条格式：**现状（引简报行号）→ 目标态 → 可判定验收口径**。验收口径一律写成「脚本可测」或「明确人工步骤可复现」，禁用「更好看 / 更流畅」类表述。

### 2.1 可维护性与组件复用（MAINT）

**MAINT-01 · 模块边界缺失**
- 现状：`app.js` 2281 行**无任何 `import`**，`index.html` 内联 CSS+DOM 1866 行，合计 4147 行单层堆叠（§2.1）。
- 目标态：拆为显式 ES 模块——状态层 / 渲染层 / 事件层 / 卡片注册表 / IPC 桥接层，各层单向依赖。
- 验收口径：`app.js` 顶部出现 `import`；`grep -c '^import' src/renderer/app.js` ≥ 3；**业务模块**文件行数 ≤ 500（**例外**：纯投影层 `projections.ts` 591 行不纳入——框架无关、被 typecheck 覆盖，见 MAINT-06 / 03 §7.4）；`grep -c 'innerHTML' 主渲染文件` 相对当前 37 处（§6）不增加。

**MAINT-02 · 原型层与桥接层隐式耦合**
- 现状：桥接 IIFE（`app.js:1660-2281`）**不拥有状态**，而是覆写原型层函数并共享其模块级变量（`sessions`/`selectedId`/`archived`），两半隐式耦合（§2.2 核心结构问题）。
- 目标态：单一状态源 + 单向数据流；桥接层只做 IPC ↔ 状态映射，不覆写原型函数。
- 验收口径：全仓 `grep -n 'window\.agent'` 仅出现在桥接模块内（当前已满足 §2.3）；**覆写式函数赋值归零**——`grep -cE '^[[:space:]]*[a-zA-Z_$][a-zA-Z0-9_$]*[[:space:]]*=[[:space:]]*function' src/renderer/*.js` = **0**（实测基线 4：`openView` `app.js:1201` / `closeView` `app.js:1203` / `deleteSession` `app.js:2251` / `archiveSession` `app.js:2268`）；**状态单点声明**——`grep -cE '^(let|var|const) (sessions|selectedId|archived|folders)' src/renderer/*.js` = **1**（实测基线 3：`app.js:35/46/50`，收敛至状态模块单处声明）。

**MAINT-03 · 卡片无统一骨架与注册表**
- 现状：卡片全部由 `app.js` 模板字符串产出，**无统一骨架、无注册表**；对比 React 树有 `cards/registry.tsx` + `KNOWN_CARD_TYPES` 10 类（§7.3、§3）。
- 目标态：统一卡片骨架 + 类型注册表，覆盖 10 类卡片（对齐 React 树 `cards/*`）。
- 验收口径：存在 `KNOWN_CARD_TYPES` 等价常量且条目数 ≥ 10；每类卡片经同一骨架函数产出（抽查 3 类卡片渲染路径指向同一 `renderCard()` 入口）；新增 1 类卡片仅需注册、不改骨架（人工步骤：加注册项后渲染不报错）。

**MAINT-04 · 全量 innerHTML 重写**
- 现状：37 处 `innerHTML` / 1 处 `insertAdjacentHTML`，全量重写（§6、§7.4）。
- 目标态：局部/差量更新，重绘范围与数据变更范围一致。
- 验收口径：见 PERF-01（同一指标）；`grep -c 'innerHTML' src/renderer/*.js` ≤ 12（相对 37 处显著下降）。

**MAINT-05 · React 树归档处置**
- 现状：`components/ui/*` 29 文件、`panels/registry.tsx` 1281、`cards/*` 8 文件等**无运行时引用**；其中含 vanilla 层没有的能力（`message-scroller` 虚拟化 / `resizable` / `table` / `progress` / `radio-group` / `checkbox` / `field` / `attachment` / `empty` / `skeleton`）（§3）。
- 目标态：产出**逐项判定表**——每项标注「移植 / 用 vanilla 等价物替代 / 明确放弃」并给理由；不得静默丢弃。
- 验收口径：判定表覆盖 §3 列出的**全部 29+8+…资产**，每项有且仅有上述三选一结论 + 一句理由；`grep -c '未判定\|TBD\|待定' 判定表` = 0。

**MAINT-06 · 探针改指 + `projections.ts` 升格为共享投影层**（🔴 前置，见 §4）
- 现状：7 个 CDP 探针指向 React DOM，vanilla 层命中全 0（§4）；`panels-check.ts:12` 直接 `import { projectDiffCards, projectTokenUsage } from "../src/renderer/projections"`，`:344-346` 在 replay 子进程复用（§4）。
- 目标态：探针改指 vanilla 真实钩子（**新增/复用真实元素，严禁伪造 `data-m1e-*`**）；**保留 `projections.ts` 并升格为共享投影层**（框架无关，非 React 树一部分），vanilla 桥接层**复用**其投影，消除 `app.js` 内重复实现（`tokStr()` `app.js:1728` / `diffHtml` `app.js:1908`）。
- 验收口径：改指后 `panels-check` B 相 7 探针在 vanilla 层命中数 **全部 ≥ 1**，且被指元素为真实交互/数据节点（人工复核：删除该元素会导致功能失效，而非仅为探针存在）；`panels-check.ts` 的 `import` 目标**仍是** `projections.ts`（**保留即达标**，不删、不改指）；`app.js` 内投影重复实现收敛（`grep -c 'tokStr\|function diffHtml' src/renderer/*.js` 下降）。
- **口径修正依据**：初稿写「`projections.ts` 可归档」，与 `03-refactor-design.md` §7.4 实测结论相反。03 §7.4 证明 `projections.ts`（591 行，纯 TS、框架无关）被 **3 个门禁脚本**（`panels-check.ts` / `agents-check.ts` / `sidechat-check.ts`）+ **4 个测试文件**（`tests/panels.test.ts` / `m3b.test.ts` / `agents.test.ts` / `sidechat.test.ts`）+ `store.ts` / `panels/registry.tsx` / `cards/registry.tsx` 引用，是全仓唯一被 typecheck 覆盖的投影实现。故正确处置 = **保留 + 升格为共享投影层**，本文件口径据此改为与 03 §7.4 一致。

**MAINT-07 · CSS 无分层**
- 现状：`index.html` 内联 `<style>` 约 9–1350 行，令牌 + 全套 CSS 混排（§2.1）。
- 目标态：CSS 分层（令牌层 / 基础层 / 组件层 / 工具层），令牌层保持 `index.html:15-94` 语义。
- 验收口径：存在 4 个显式分层文件或 `@layer` 声明（`grep -c '@layer'` ≥ 4 或分层文件数 = 4）；令牌变量名与数量相对 §6 不回退（`--` 变量集合是当前超集）。

### 2.2 响应式布局（RESP）

**RESP-01 · 宽度断点体系**
- 现状：**仅 1 个宽度断点** `@media (max-width:920px)`（`index.html:1354`，实测复核）；其余 13 个 `@media` 全是 reduced-motion / hover（§7.1）。
- 目标态：4 档宽度断点——`≥1600`（宽屏三栏）/ `1280–1599`（标准三栏）/ `1024–1279`（收窄，右板可折叠）/ `<1024`（右板转覆盖式 Sheet，侧栏转抽屉）。
- 验收口径：`grep -c 'max-width:1599\|max-width:1279\|max-width:1023\|min-width:1600'` ≥ 3；在 1440 / 1200 / 1024 三视口下均无横向溢出（`document.documentElement.scrollWidth ≤ innerWidth`）。

**RESP-02 · 窗口最小尺寸**（P0，崩溃级）
- 现状：`src/main/index.ts` **无 `minWidth`/`minHeight`**（实测 grep 无匹配，§7.1）→ 窗口拖到极小即布局碎裂。
- 目标态：设最小尺寸（≥ 960×600）并保证在最小尺寸下主区不被挤碎。
- 验收口径：`grep -n 'minWidth\|minHeight' src/main/index.ts` ≥ 2；**在最小尺寸 960×600 下主区宽度 ≥ 480px**，侧栏与右板以可开合形式可达（右板为覆盖式 Sheet、侧栏为抽屉——与 RESP-01 的 `<1024` 档规格一致，**不要求三栏同屏**）。

**RESP-03 · 中窄视口三栏适配**
- 现状：`1280–1599` / `1024–1279` 零适配（§7.1）。
- 目标态：主区始终优先；右板随视口收窄从固定列 → 可折叠 → 覆盖式 Sheet。
- 验收口径：**1024px 视口下右板为覆盖式 Sheet 且主区宽度 ≥ 480px**；1280px 视口下三栏共存且右板宽度 ≥ 300px。

**RESP-04 · 分隔条在窄视口的行为**
- 现状：分隔条拖动 / 键盘调整存在（`app.js:577` 段），但窄视口行为未定义（§7.1 无适配）。
- 目标态：低于断点时禁用固定列拖拽，改为覆盖式打开/关闭（键盘可达）。
- 验收口径：1024px 视口下拖拽手柄不可拖出越界值；键盘 `ArrowLeft/Right` 可开合右板（焦点环可见，见 A11Y-02）。

### 2.3 视觉一致性（VIS）

**VIS-01 · 四态语义色落地**（P0）
- 现状：`--st-run / --st-wait / --st-stuck / --st-fail` 在 `index.html` 命中 **0**（实测复核，§7.2）。
- 目标态：四态语义色作为一等令牌落地，贯穿侧栏会话态、消息态、底栏。
- 验收口径：`grep -c -- '--st-run\|--st-wait\|--st-stuck\|--st-fail' src/renderer/index.html` ≥ 4（定义）+ 每态至少有 1 处消费点；四态在**删色（灰度）后仍可区分**（人工步骤：截图转灰度，四态形状/图标各异）。

**VIS-02 · 全局运行状态底栏**
- 现状：`statusbar` 命中 **0**，状态栏未落地（§7.2、§7.6.2）；运行状态（沙箱 / 事件数 / tokens）挤在侧栏底部视线边缘。
- 目标态：底部状态栏承载沙箱态 / 事件计数 / tokens，与 GAP-02 合并交付。
- 验收口径：存在常驻底栏元素且**在全部 8 类视图下可见**（切视图后仍可见）；底栏含沙箱态、事件数、tokens 三项且值随事件流更新（发一条消息后事件数递增）。

**VIS-03 · 「被拒」误用「卡死」色**
- 现状：09-15 已确证——「被拒」误用「卡死」的琥珀色，当时只在原型修，**源码未修**（§7.2）。
- 目标态：「被拒」使用失败语义色，与「卡死」分离。
- 验收口径：抽检被拒态元素的 `color` 值 ≠ 卡死态色值；两态色值差在 oklch 色相上可辨（ΔH 可量化）。

**VIS-04 · 「已中断」与「等待」渲染完全相同**
- 现状：两态都是灰空心点，仅文字不同（§7.2）。
- 目标态：两态在图形编码（图标/形状/边框）上可区分。
- 验收口径：两态 DOM 结构不同（`grep` 出不同 class/图标）；**遮挡文字后仍可区分**（人工步骤：截掉文本层，两态图标形态不同）。

**VIS-05 · 状态靠文字、无图形编码**
- 现状：状态判定靠文字（如 `2/4 已完成`），无图形编码 → 违反「删色可辨」（§7.2）。
- 目标态：所有状态增加图形编码，与文字冗余互补。
- 验收口径：抽样 5 类状态，每类含图标/形状编码；灰度截图下状态可辨（人工步骤，与 VIS-01 合并验证）。

**VIS-06 · 归档守卫死代码**
- 现状：`sessionItemHTML`（`app.js:122-166`）**从不输出 `data-archived`**（实测复核），`renderArchive`（`app.js:489-496`）输出 `.arch-row[data-id]`；`if (item && !item.dataset.archived)`（`app.js:419`、`app.js:465`）**恒为真，是死代码**（§5）。
- 目标态：归档区与活跃列表的点击路径由真实判别分开（明确语义，不靠恒真守卫）。
- 验收口径：活跃列表项点击可选中；归档行点击**不**误触 `selectSession`（人工步骤：点击归档行，选中态不变化）；守卫条件不再恒真（代码层复核）。

### 2.4 可访问性（A11Y）

**A11Y-01 · 无自动化 a11y 门禁**（P0）
- 现状：资产好（298 `aria-*` / 30 `role=` / `:focus-visible` / `.sr-only`，§6），但**无自动化门禁**，全靠人工目检，回归无保障（§7.5）。
- 目标态：引入自动化 a11y 扫描并纳入门禁清单（`scripts/gate-manifest.ts`）。
- 验收口径：存在 axe-core（或等价）扫描脚本；在 3 个关键视图下扫描 **critical + serious 违规 = 0**；脚本登记进 `gate-manifest.ts`（当前 26 道，§8）。

**A11Y-02 · 既有 a11y 资产不回退**
- 现状：13 处 reduced-motion、298 `aria-*`（**出现次数**）、30 `role=`、全局焦点环（§6，**不得回退**）。
- 目标态：重构后资产量不减，且新交互补齐等价语义。
- 验收口径（**一律按「出现次数」计，非行数**）：
  - `aria-` 出现次数：`grep -o 'aria-' src/renderer/*.html src/renderer/*.js | wc -l` ≥ **298**（基线 298 次出现；⚠️ `grep -c 'aria-'` 只得 **241** 行，是行数，**不得**用作口径）；
  - `role=` 出现次数：`grep -o 'role=' src/renderer/*.html src/renderer/*.js | wc -l` ≥ **30**（基线 30）；
  - `prefers-reduced-motion` 出现次数：`grep -o 'prefers-reduced-motion' src/renderer/*.html src/renderer/*.js | wc -l` ≥ **13**（基线 13）；
  - 焦点环在全部可交互元素上可见（Tab 遍历无焦点丢失）。

**A11Y-03 · 新增动效的降级覆盖**
- 现状：既有 13 处 reduced-motion 降级块（§6），但新增动效（消息入场、Sheet 滑入、状态过渡）尚无对应降级。
- 目标态：任何新增动效必须有 `prefers-reduced-motion` 降级。
- 验收口径：`prefers-reduced-motion` **出现次数** ≥ 13 + 新增动效数（`grep -o 'prefers-reduced-motion' src/renderer/*.html src/renderer/*.js | wc -l`）；开启系统「减少动态效果」后无入场/过渡动画（人工步骤：DevTools 模拟 `reduce`，观察无位移/淡入）。

### 2.5 运行时性能（PERF）

**PERF-01 · 长会话渲染策略**
- 现状：长会话渲染策略**未知**；vanilla 层是 37 处 `innerHTML` 全量重写（§7.4），无虚拟化（React 树有 `react-virtuoso` + `message-scroller`，§3）。
- 目标态：长会话下 DOM 节点有界（虚拟化或窗口化/差量）。
- 验收口径：**10k 事件下 DOM 消息节点 ≤ 300**（对齐 B1 原始口径，§7.4）。

**PERF-02 · 恢复性能验收口径**（P0）
- 现状：`panels-check` B1 原口径「1 万条事件 → DOM ≤ 300 节点 + 滚动一屏 ≤ 200ms」因**探针死了**等于无人守（§7.4）。
- 目标态：口径重新可测（探针指向 vanilla 真实容器）。
- 验收口径：探针命中真实滚动容器（非伪造）；**1 万条事件下滚动一屏 ≤ 200ms**（`performance.now()` 测量，脚本可复现）。

**PERF-03 · 事件绑定策略统一**
- 现状：`addEventListener` 80 处，事件委托与直接绑定**混用**（§7.4）。
- 目标态：统一为事件委托（列表/卡片），减少重绘后重绑与泄漏。
- 验收口径：`addEventListener` 总数 `grep -oE '\.addEventListener' src/renderer/*.html src/renderer/*.js | wc -l` ≤ **25**（实测基线 **80**）；其中**元素级直接绑定**（80 − 11 `document` 级 − 1 `window` 级 = **68**）收敛至 ≤ **10**；消息/列表容器级委托绑定，`render()` 后不新增监听（代码层复核）。

### 2.6 结构性缺口（GAP）

**GAP-01 · 无独立「任务执行」视图**
- 现状：编排压在 340px 右抽屉里与 8 个视图争宽（§7.6.1）。
- 目标态：独立任务执行视图，编排不再与其余视图挤同一抽屉。
- 验收口径：存在独立视图入口且可切换；该视图下编排区可用宽度 ≥ 640px（不再受 340px 限制）。

**GAP-02 · 运行状态在视线边缘**
- 现状：沙箱 / 事件数 / tokens 放在侧栏底部（§7.6.2）。
- 目标态：迁至全局常驻底栏（与 VIS-02 合并）。
- 验收口径：同 VIS-02（全视图可见 + 三项值实时更新）。

**GAP-03 · 历史只有「会话」一个维度**
- 现状：缺 run 批次回溯与检索（§7.6.3）。
- 目标态：新增 run 批次历史视图，支持按批次回溯与检索。

# 第 309 页读数：`web_fetch` 截断提示里那条「换锚点」是假出路

日期 2026-10-02/03。被测面 `src/tools/output-ring.ts`（那句提示的本体）、`src/tools/web_fetch.ts` 与
`src/tools/web-search.ts`（两个消费者）。判卷面 `tests/web-fetch.test.ts`。锚点面 `scripts/mutate-verify.mjs`（本笔 3 枚）。

## 1. 这一页是从一张表里捞出来的，不是从事故里撞出来的

第 308 页那条（「本图只按名字连边、不认 import」）是读日志时撞上的。这一页换了做法：**先把分母量出来**。
`outputs/model-claim-face-2026-10-03/claim-measure.mts`（AST 收字面量、排除 `console.*` 实参位、
按"该句里最长那段中文在 `tests/**` 出现几次"分有无证人）现读：

```
取料：src 文件 174 个｜tests 语料 297 份
候选断言字面量=44 条｜其中"判卷 0 次"=32 条｜无可比对片段=5 条
```

口径要说清三条局限，否则这张表会被当成结论用：
① 关键词表本身是候选生成器——第一版收了「必须」「不能」，93 条里一大半是**抛错文案**
（`x 必须是非空字符串`），那不是"对模型承诺 harness 做什么"，所以删掉后从 93 降到 32；
② "证人"的判据是**字面片段命中**，命中 0 不等于假、命中多也不等于真——逐条读原句才叫判定；
③ 它看不见英文文案（`src/` 里面向模型的英文句子不在关键词表内）。

## 2. 抓到的是同一族的第二个形状：一句文案里，出路列了做不到的那条

`WEB_CONTENT_TRUNCATION_HINT`（截断时交给模型的那句"下一步"）在 HEAD 上是：

```
[下一步：这是页面正文，不是整站。要找特定段落就换一个更精确的 URL（锚点/目录页/API 文档页）；本工具不会替你翻页，也没有站内搜索——查不到就换源。]
```

同句两半的证人不对称（现读 HEAD）：

| 那一半 | 判卷点过几次 |
| --- | --- |
| 「换一个更精确的 URL」 | **1** 次（`tests/web-fetch.test.ts` 那条真 loopback 判卷） |
| 「锚点」当**URL 片段**义 | **0** 次（`grep -rn 锚点 tests/` 命中的每一条都是"变异锚点"义） |

而它做不到：`web_fetch` 不把片段用于任何取料或切分（`src/tools/web_fetch.ts#makeWebFetch` 只有 URL→正文→头尾环），
**片段根本不上 HTTP 报文**。这条不由我在测试里替它剥——单独一趟只换 authority、把 `pathname+search+hash`
原样交给真 `fetch`，让 loopback 服务自己报看见什么（`fragment-on-the-wire.log`）：

```
  /page             →  /page          片段还在吗=false
  /page#api         →  /page          片段还在吗=false
  /page#install     →  /page          片段还在吗=false
  /page?q=1#api     →  /page?q=1      片段还在吗=false
结论：四种写法在服务器上落成 4/4 个无片段请求行
```

⇒ 模型照那句提示去"换锚点"，取回的是**逐字相同**的一屏、同一个截断位置，白跑一轮。
两个消费者都吃这一句（`src/tools/web_fetch.ts#makeWebFetch`、`src/tools/web-search.ts#makeWebSearch`）⇒ 一处说胡话，两面都漏。

## 3. 我自己那条判卷的第一版也是错的（记下来，因为它正是本仓反复钉的那一格）

第一版 fetchImpl 我照抄了同文件既有那条的写法 `pathname + search`——**片段是我在测试里剥掉的**，
于是"服务器看不见片段"这个结论是测试自己算出来的，对生产零分辨力（规则 236 那一格）。
改成只换 authority、`hash` 原样交下去之后，证据才由 undici 给（就是 §2 那张表）。
判卷里这一条也随本次改动一起改：见 `tests/web-fetch.test.ts` 那组的注释。

## 4. 修法与代价

新句：

```
[下一步：这是页面正文，不是整站。#锚点不会改变取回的内容（片段不发往服务器，正文按同一位置截断）；要找特定段落就换一个更精确的 URL（目录页/专门章节页/API 文档页）；本工具不会替你翻页，也没有站内搜索——查不到就换源。]
```

- 括号里只留**真的另一份正文**的地址形状（正控：换 `path` 服务端就落到不同资源、正文不同——见判卷那条）。
- 已有的两条否定式事实（不会翻页／没有站内搜索）原样留着，并第一次给它们配了证人。
- 代价：整句 79→115 chars（+36）、213→319 bytes（+106），按本仓 chars/4 口径 ≈ **+9 token 量纲**，
  只在"正文超过 32KB 帽"那一支出。换来的是模型不再照一条做不到的路再跑一次——
  一次往返要重送上下文＋重跑工具，量纲上远大于这 106 字节（这里不给具体倍数：那一格我没有同分母读数，
  不许拿"显然更贵"当证据；要钉它得先数轨迹）。

## 6. 后半簇：既有那支尺把我拦下了，还账时又挖出一个顶包洞

我把新句写进 `WEB_CONTENT_TRUNCATION_HINT` 之后，`scripts/probe-promise-recall.ts` 的措辞网
（`PROMISE_MARKS` 里有「取回」）把这一句**收成了一个新的模型可见承诺面**，于是清单完整性判据当场红：
`src/tools/output-ring.ts#WEB_CONTENT_TRUNCATION_HINT 没有判定归属`。
这不是探针误伤——它的设计就是"新加一句承诺字面量会自动进清单，逼着加它的人给判定"。还账的方式有三种，我选了第三种：

| 选项 | 后果 |
| --- | --- |
| 改措辞躲开「取回」二字 | 绕过按措辞收的网＝本仓规则 122 那一族（换写法即绕过），最不该做 |
| 在 RUNNERS 里填个名字不实现 | 登记表看着齐全，那一格其实没人判 |
| **给这一面真做一次判定**（选它） | 复现器 `scripts/probe-web-anchor-claim.ts` 量三件事；探针与判卷都 exec 同一支 |

还账过程中挖到的第二个洞（不是我造成的，但被我这一面照出来）：`runOnce` 原来是"落到最后一支"的 ternary——
**登记一个不存在的判定名，会得到 `hopPruneStub` 的结论**。这一格现在收成两个导出纯函数：
`isKnownRunner`（花名册一份）＋`runnerVerdict`（未知名字**不 exec**，红在这一格并点名那个名字），
配套两条判卷：`登记了的判定名必须真有一个实现`（逐条查 RUNNERS 的每个值）、
`未知判定名不 exec、直接红在这一格`。这条与第 308 页那格同族：指针失效比缺指针更难发现，顶包比失效更难发现。

现读（`node --import tsx scripts/probe-promise-recall.ts`，主树）：`承诺面 10 处`；
我的那一面 `✅ exit=0｜② 三次换锚点正文逐字相同 / ③ 换 path 不同`。

**探针在同一趟里还红着一格，不属本笔**：`src/main/agent-runner.ts#body ⇒ saved 附件写出=0 条｜替换文本里的附件路径=无
⇒「原文可从附件目录回取」在此刻为假`。我在 `92cc196` 的独立认证树里跑了同一支探针，**同样红**⇒ 不是隔壁在飞的改动带的，
是 HEAD 上就在的一格。两种成因没分：① 那句承诺真为假（模型照做拿不到东西）；② 复现器的取料看不见那一支

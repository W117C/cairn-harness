# 第 80 页 · 「实现活着、判卷面归零」现在当天就会红了：`src/` 每个模块都要有一条从测试出发的**值边**路径

来路：第 79 页把配对不变量交给别人的前一刻，先问了一句——**有没有哪种机制能在删掉 `tests/updater.test.ts` 那天就红？**
没有。`--check-needles` 只看锚点字面量，全量 `test` 只看还在的测试。这一页补上这个机制的一半。

## 一、口径：可达 ＝ 会被执行，不等于有断言

尺在 `scripts/lib/reach-graph.ts`；读数 CLI（`01-reach.mts`）与判卷面（`tests/src-execution-path.test.ts`）
**共用同一把尺**——判据各抄一份迟早漂，这条老教训这次落地成"一个实现两份出口"。

- 起点＝盘上全部 `tests/*.test.ts`（含未跟踪，别人的新测试也算路径）；
- **两类边分开算**：`all` 走全部边，`live` 只走值边（含 `await import()`、`require()`）。
  分开的理由是 vitest 会把 `import type` **整个擦掉**——"有个测试引了这个文件"可能一行都没执行，
  那类**假覆盖**比没人引更坏（读的人以为有尺）；
- `.d.ts` 不入图；可达只承诺"会被执行"，不承诺"被断言"（这句话写在 CLI 的尾巴上，防止下一个人把绿读成已验收）。

## 二、现态读数：150 个模块里只有 1 个没有执行路径，而它确实没有可执行的东西

```
生产面：150 个 .ts｜测试入口：222 个 .test.ts
沿值边可达 149 个 ⇒ 没有执行路径 1 个｜其中只有类型边连测试 1 个、只有门脚本跑得到 0 个
  src/main/ipc-protocol.ts   ← 只有类型边连着测试（假覆盖候选）
```

复核那一条：`src/main/ipc-protocol.ts` 235 行，`grep ^export` 出来全是 `export type` / `export interface`
⇒ 运行时本来就是空的，"没有执行路径"是事实而不是缺口。

**自检先否掉了我自己**：`--self-test` 造一张答案已知的六格小图，第一版报
`src/type-only.ts：期望 typeonly，尺读出 gap`。查下来不是尺坏——是那张图里唯一的类型边从
`src/consumer-of-type.ts` 出发，而它自己不可达，**类型边接不上 unreachable 的上游**。
我把测试改成自己直接 `import type` 那条边，才对上"假覆盖候选"这一格。
⇒ 规则 117 的又一个形状：自检失败时先怀疑**期望**，再看尺。

## 三、判据形状：5 条，其中豁免是**可证伪的**

| 用例 | 它在防什么 |
| --- | --- |
| 取料面非空（src>50、tests>50） | 扫不到文件时把空清单当通过 |
| 尺的正控：`prune.ts`/`output-ring.ts`/`updater.ts` 必须判为可达 | 图坏了却全绿（`updater` 是第 79 页刚补的那格，拿它当哨兵） |
| 缺口清单必须与例外表**逐字相等** | 新增未测模块即红；例外表里已不再缺路径的也必须删名（等号天然双向） |
| 每条例外都要**真去 import 它**，运行时导出必须为 0 | 用"看着像类型文件"换豁免——换一种写法即绕过（规则 122） |
| 假覆盖集合＝例外表 | 只有类型边连测试的文件偷偷算已覆盖 |

## 五、边界：这一半归我，另一半归门

- 本判据管的是「**实现还在树上、测试路径归零**」——正是 updater 那一格；它读盘，所以别人未提交的删除也会红。
  那**不是跨会话假红**：它守的不变量与"谁写的"无关，修法只有两种（补尺，或同批把实现摘掉），
  **不许改判据**。（对照第 77 页：那里不给他人写作窗背书的理由是"红属谁的实现"，这里红属树本身。）
- 另一半「测试还在、实现被删」仍归 `--check-needles` 的未入库面（他人热文件，任务 #11/#12）。
- 锚点那一半（4 条 updater 不变量的变异锚点）还等 `mutate-verify.mjs` 的窗口（任务 #8）。

## 二、外部读数（为什么它不能是布尔，也不能自动修）

**TS-Detector**（arXiv 2505.05326）——专检 feature toggle 的五种用法形态：**dead / nested / spread / mixed / enum**：

- 10 个开源项目上基准、其中 5 个手工核对：手工确认 **146 个 dead toggle**，算法报 167 个；
  摘要给出 **Dead 的 true positive rate 只有 66.6%**（Spread 80%、Nested 86.4%）。
- ⚠️ **误报峰值来自"配置文件把 toggle 变量和普通常量放在一起"**（原文归因）——
  这与本页 §一 G4/G5 的两次假阳性**完全同形**：我扫的正是 `settings.ts`（一个把开关和默认值混在一起的配置文件），
  于是 `telemetry`（有意留位）被报成缺陷、27 个内部函数被报成死码。
  ⇒ 这不是巧合，是这类工具的共同失效面。**所以"检测器只有 2/3 命中"是学术上限，不是我的写法问题**——
  门必须按"会有误报"来设计，而不是按"报了就是缺陷"来设计。
- 工业侧同向：flag 技术债指南（GrowthBook）把"旗标比功能活得久"列为常规债种，处置靠**登记 + 定期清账**，不靠自动删。

## 三、设计：四层（各答「长在哪 · 谁持有 · 为何不是别层」）

### L0 三轴枚举（按**形状**取，不按字符串取）

- 事件轴：从 `AgentEvent` **联合类型递归展开**，逐个映射到它自己的 `type` 字面量
  （G7 附录已立过这条口径：`RunErrorEvent` 的 type 其实是 `"error"`，按名字蛇形变换会造出假类型）。
  ⚠️ 本页探针只用两空格缩进取到 21/30 ⇒ **枚举不全的门比没门更坏**（给假安全感），落地必须补全并加"成员数下限"断言。
- 旗标轴：`settings` 接口的 `boolean` 成员。
- 导出轴：`src/**` 的 `export function/const`。

### L1 观测者分三级，**分开计数，绝不合成一个布尔**

| 级 | 含义 | 取法 | 能答什么 |
|---|---|---|---|
| **T** traffic | 真语料里**发生过** | 扫 `**/*.events.jsonl` | "有没有分母"（校准、阈值、收益都靠它） |
| **C** consumer | 有代码读/写它 | `src/`+`scripts/` 里的引用 | "接没接线"（G1 那类断点） |
| **N** needle | 有断言/针脚守着 | `tests/`+针脚登记表 | "会不会静默坏掉" |

⇒ 三级组合各有语义：`¬C` 是真断点（必修）；`C ∧ ¬T` 是**无分母面**（该登记 `unmeasurable`，不该假装过）；
`C ∧ T ∧ ¬N` 是会悄悄坏掉的面（该补针脚）。**混成一个布尔 = 橡皮图章**。
这也正面回答能力 16–22 各页 §五 那一堆"未证"：它们不是同一件事，不该写在一起。

### L2 登记表（本页的核心，也是最容易被省掉的东西）

每个未覆盖项**必须**落一条三态登记，且**水位只降不升**（照本仓 `LEGACY_WAIVERS` 的既有口径）：

- `unmeasurable(reason, reversal-condition)` —— 如 `turn_truncated`：需要真截断流量，本地造不出；
- `intentional(doc-pointer)` —— 如 `telemetry`：无实现本身就是保证，指向 `m4-acceptance` 那行；
- `planned(gate-id, date)` —— 已排期，如 `verify_result.cause`（P1-3）。

**没有登记 ⇒ 红；登记了 ⇒ 绿但计数可见。** 且登记项要能被 L1 的三级读数**独立复核**：
登记的 `reversal-condition` 必须写成一条可跑命令（否则它自己就变成下一句"读起来像现态的错字"——
这条正是本页立起来的动机）。

### L3 反滥用（这台机器最大的风险是它骗人）

1. **「观测者」必须是可核引用**（针脚 id / 门名 / 语料文件路径），不接受自由文本理由——
   否则"我加了一个 if"就等于有观测者。
2. **门自身要有针脚**：删掉一条登记的针脚 id ⇒ 门必须红；把某项从登记表删掉 ⇒ 门必须红
   （与 `3c0a1d0` 各钉不变量一半同族）。**一条守别人的门若没人守它，就是本仓点名的"接线没有观测者"。**
3. **输出精度而非结论**：门打印 T/C/N 三级计数与登记分布，不打印"通过"。
   按 TS-Detector 的 66.6% TPR，任何自动"删死码/补观测者"的动作都必须是**人发起**的。

## 四、判卷读数（第一次红从哪来）+ 锚点

| # | 判据 | 落点 | 第一次红 |
|---|---|---|---|
| C1 | 枚举完整性下限：事件轴成员数必须 ≥ 联合类型展开数（先补全我这次 21→30 的缺口） | 新 `scripts/observer-coverage-check.ts` + 并入 `gate-manifest` | 少取一类 ⇒ 红（**防假安全感**，优先级最高） |

## 五、明确不采纳（理由 / 证据 / 反转条件）

| 不采纳 | 理由 | 反转条件 |
|---|---|---|
| 用行覆盖率当"有观测者" | 覆盖 ≠ 有分母：一次被 import 就算覆盖，而那 13 类事件正是"代码全覆盖、真流量零发生" | 永不——它答的是另一个问题 |
| 强制每个事件都要有真语料 | 稀有事件（`turn_truncated`）本地造不出来，硬逼就是**造一场假截断来喂门**（本仓最忌的假绿） | 永不；走 `unmeasurable` + 反转条件 |
| 把 B 桶 19 个"仅本文件用"当缺陷逼删导出 | 它们是合法卫生项，删了可能破坏将来接线；第一版我就是这么错的（27 假阳性） | 无 |
| 自动删死码 / 自动补观测者 | 检测器 TPR 上限 66.6%（外部），误删代价不对称 | 永不；动作必须人发起 |
| 让 LLM 判"这面有没有人用" | 自报类反模式（`gap-fix` P2-5），且这类判定静态就可做 | 无 |
| 把门做成 exit 0 的"报告"而不设水位 | 不设水位 = 这类债只会堆（外部 flag 债的常态） | 永不 |

# 真会话 → 靶场草稿：哪一半能自动，哪一半必须是人的动作（2026-09-23）

## 缺口（本轮查实，不是猜的）

目标里第 10 项要「从失败轨迹中学习，持续优化工具调用和规划策略」。本仓这条只通了一半：

- 失败轨迹**会**进记忆：`src/agent/memory/distill.ts` 的 `failureDigestFromEvents`（能力 6）。
- 失败轨迹**不会**变成可复跑的尺子：`grep -rln gym src/` 只有 `gym/case.ts`（加载）与 `gym/runner.ts`（跑）；
  `fixtures/gym/cases/**` 全部手写并 sha256 冻结。没有任何一条路径能从 `events.jsonl` 造出 case。

后果与诊断一致：自有靶面已经饱和（判断层那轮量到 8/8 全绿，真墙是"可标分母"），
而补分母的手艺全靠人从零手写 ⇒ 尺子不再增长。文档侧其实早列了这件事

同文也裁过「**不**追 SWE-bench Verified（OpenAI 官方已判其不再区分前沿）」⇒ 本轮也不去接那个。

## 边界：一条 case 有四件，只有两件能自动

| 件 | 能否自动 | 为什么 |
| --- | --- | --- |
| `task.md` | 能 | 首条 `user_message` 原文 |
| `expect.mustChangeFiles` / `mustPassVerify` | **只能出候选** | 「改过」≠「必改」；跑偏的会话会给出错的必改集。`verifyOk` 只在这条链真验过时才给值 |
| `repo/`（pristine 靶子） | **不能** | 会话跑在真工作区上，起点内容不在事件流里；D7 的 `.agent/snapshots/` 只覆盖「非空文件被覆写」那一格，不是全量 |
| `negative.json`（A2 反例控制） | **不能** | 它要的是"看着像修好了但尺子判失败"的人造解；自动生成＝编一个反例来证明尺子有效 |
| sha256 冻结登记 | **必须人** | 改判据＝作弊，本仓第一纪律 |

⇒ 产物不是「一条命令生成 case」，而是**草稿 + 一份机检的缺件清单**，且草稿在结构上就不可能被当成判据跑。

## 落地（`src/agent/gym/draft.ts` + `scripts/gym-draft.ts`）

1. `draftFromEvents(events)` 纯函数：题面、**成功**写过的文件（去重排序）、写失败次数、
   最后一次主会话 verify 的结果（没有 ⇒ `null`）、`missing[]`。
   三条归因纪律：`agent_id` 在场的**写盘（tool_call）**、**写盘结果（tool_result）**、**验证（verify_result）**
   都不算 parent 的（#8 那族归因缺陷的第四、第五、第六面——同一条不变量的三个取料面，一面一条锚点）；
   只有 `ok:true` 的写进候选集（半途而废的会话不能被固化成「这些文件必须改」）。
2. `renderDraft` 的形状守一条：**verify 未知就不产 `expect.candidate.json`**（不拿 false 冒充判据），
   且文件名带 `candidate`——`loadCase` 只认 `expect.json`，所以草稿就算躺在 cases 里也跑不起来。
3. `scripts/gym-draft.ts`：缺省 dry run，`--apply` 才写盘，落点默认 `fixtures/gym/drafts/<id>`；
   目标在 `cases/` 之内直接拒写。promote（补 `repo/` 与 `negative.json`、移进 cases、登记 sha256）永远是人的动作。
4. 顺带补一条**本来就漏着的守卫**：`loadGymIndex` 原先只查 `id/path` 是字符串，
   一条 `path: "../drafts/x"` 的条目会以判据身份被 `loadCase` 跑起来，而 A3 的 sha256 冻结只 walk `cases/`
   ⇒ **改它没人发现**。现在 `casePathProblem` 拒绝对路径与逃逸路径（待办 #47 的动机，独立成立）。

## 没做与重开条件

- **不自动 promote、不自动冻结**：没有例外通道。重开条件＝出现一条"人核过并被证明有效"的草稿流程之后，
  再谈把重复劳动（复制目录、算 hash）脚本化；顺序反了就是让脚本决定什么是判据。
- **非自有任务集**（Terminal-Bench 一类）仍需 Docker + 真凭据 + 一次真金跑，本轮不做；
  草稿面填的是"自有真失败"，它比手写 case 强的地方只在题面不是我们自己编的。
- 草稿目前不含 `script.jsonl`（明卷剧本）。要给某条草稿配明卷，得人录制剧本或走真凭据暗卷——
  自动从会话事件里"回放"出一份剧本会把一次特定轨迹钉成唯一正解，那是过拟合而非判据。

## 一、头条：一条**必红**的测试，换个写法就绿（真跑 bash 三次）

| 写法 | 退出码 |
|---|---|
| `node --test t.test.mjs`（裸跑） | **1**（诚实的红） |
| `node --test t.test.mjs 2>&1 \| tail -3`（本仓剧本形状） | **0** ← 失败被吞 |
| `set -o pipefail;` 再接同样的管道 | **1** |

而 `src/tools/run_shell.ts`、`src/agent/verify.ts`、`src/tools/process.ts` 三处
**从未设过 `pipefail`**（实测：`/pipefail/` 命中 0）。两者的 `ok` 都是 `code === 0`，
读的是**最后一个管道段**的状态。

⇒ **`npx vitest run 2>&1 | tail -30` 这条命令，无论 vitest 红不红，`ok` 恒为 true**
（`tail` 成功了）。模型把这句话当成"我跑过测试了、测试过了"。

## 三、机制早就在，只差换个配对（真 `globIntersects`）

`globIntersects` 的调用方是 `orchestrator.ts` / `lease-conflicts.ts`，今天只用于
**forbidden 路径检查**（改动面 ∩ 禁改面）。把它换成「改动面 ∩ 验面」是同一个函数的第二个配对：

```
命令 node --test tests/b.test.mjs   验面=[tests/b.test.mjs]  判定=misaligned   ← 真不相交
命令 node tests/run.mjs             验面=[tests/run.mjs]     判定=misaligned   ← ✗ 误判：这是该仓库的全量
命令 node --test tests/             验面=[]                  判定=unknown      ← 空集必须 unknown
```

## 四、本页我自己的三次判据/取料缺陷（都留在文档里，不涂）

1. **路径拼接吞掉了整个读数。** 第一版规模段报 `0 次调用 / 0.0%`——因为我把**绝对路径**喂给了
   一个内部再 `join(ROOT, rel)` 的读取函数，于是每个文件都读成空串。
   ⇒ 修成直接 `readFileSync(f)`，并给探针加了一条**"读到 0 次调用"就显式报警**的自检
   （0 命中先怀疑判据，别先怀疑事实——这条纪律这一轮是第三次救场）。
2. **命令里有路径 ≠ 范围有限。** `node tests/run.mjs` 被我的正则判成"带范围"，
   实际上它是那个靶子仓库的**全量**。⇒ 验面**不能从命令文本猜**。
3. **抽不到路径 = unknown，不是"不相交"。** 若把目录级/全量命令判成 misaligned，
   每条 `pnpm test` 都会被误报成"没覆盖改动"——那是自造假红。

三条合起来是本页 L1 的正面主张：**验面要么被声明、要么由 runner 摘要给出，二者都没有就是 unknown**。

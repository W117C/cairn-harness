## 二、子句②「档位锁为只读」——字面没实现，但**不要再补**

扫四处装配点（`agent-runner` / `orchestrator` / `autonomy` / `risk`）找「沙箱不可用 ⇒ 切 mode=read-only」的形状：**无**。
可它要保护的后果已由子句①守住：所有有副作用的动作强制送审，非交互 ask→deny。
⇒ **结论是负向的、且值得写下来**：补一个 mode 锁就是本仓点名的「两道闸做同一件事，中间那条漏过去」的成因
（规则 30 同源）。真要加，先构造出「现有机理放行而 mode 锁会拦」的那一格输入；构造不出就不该有第二道。
顺带一条实测：只读工具本就不需要沙箱，所以「锁成只读档」并不比现状更安全，只会**更没用**。

## 三、子句③「对话中心常驻警示条」——未接，并且牵出判卷面的一件事

结构读数（同一条判据配了反向对照：`titlebar` 判为「不在设置页内」＝通过，否则它就是恒真）：

- `#sandboxState`（写「沙箱不可用」文案的那个节点）在 `src/renderer/index.html:2682`，
  最近的包裹是 `<div class="settings-overlay">` → **它在设置面板里**；独立的 banner 节点：**不存在**。
- 该遮罩未打开时 CSS 是 `opacity:0; pointer-events:none`（`.settings-overlay` 规则），
  面板注释自陈「未弹时对整个页面不可达也不可交互」⇒ 用户不主动开设置就看不到。
- `src/main/index.ts` 头部注释写着「renderer 以**常驻**警示条提示」——**这句今天不成立**。
- 还有一处陈旧结构声明：`index.html:2515` 的注释「常驻底栏（VIS-02）：沙箱态 / 本次运行事件数 / token 合计」
  之后紧跟的就是 `</div>`——那段标记**不在那里**。三个节点（`#sandboxState`/`#eventCount`/`#tokenTotal`）
  全在设置页那张卡里。`src/renderer/message-actions.js:23` 与 `AGENTS.md`「底栏节点格式契约」仍称其为**底栏**。

⇒ 三处文字（方案、代码注释、AGENTS.md）都把「常驻/底栏」当成既成事实，实际是"开设置才看得到"。
`绝不静默无沙箱运行` 的**判定**那一半成立，**用户可见**那一半不成立。

## 四、这一轮真正落地的改动：让门知道自己读的是什么

`scripts/panels-check.ts` 两处按文本读 `#eventCount`，措辞还写「屏面事件数」。改成**同时取可见性**：

```
✅ #eventCount 实时计数节点存在且为非负整数（实测 10000，…；主屏可见性=false
   ——在设置页内，未打开设置时主屏看不到）
```

- 断言强度一字未加未减（仍是"存在 + 非负整数"），只把**测到的是什么**说出来；
- 反向对照跑过：`checkVisibility({opacityProperty:true, visibilityProperty:true})` 对壳内节点
  （`titlebar`）返回 true、对遮罩后节点返回 false ⇒ 这个字段不是恒真；
- 第二处（B20 诊断串）把「屏面事件数」改名为「运行状态卡事件数（未打开设置时主屏不可见）」。
- 意义：下一轮谁再拿这条绿线当「成本可观测已被验收」，输出自己会拒绝这个读法。
  这正是本仓反复抓的那一类的**新变体**：不是"能力发货了没人能看见"，而是
  **「判据看得见，用户看不见」**——`querySelector` 命中一个 `opacity:0` 遮罩里的节点，和命中屏幕上的节点，
  在旧写法里输出完全一样。

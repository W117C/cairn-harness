## 一、缺口（先承认已有的面，再定它没覆盖的那一维）

**这条不是空白地**。本仓在"改考卷"上已有的面（`01` §一逐条核过）：
`frozenJudgePathSet` → `autonomy.ts` 的 L0 硬闸（写侧命中冻结判卷文件即出卡）、表被清空时**显式抛**、
`frozenCoverageDrift` 三向漂移、`mutate-verify.mjs` 手写 786 条 needle 证断言非恒真。

缺的是这三样**结构上给不出的东西**：

| # | 缺口 | 证据（本轮实测） |
|---|---|---|
| G1 | **哈希防不了变薄**：它只能答"和基线一样吗"，答不了"这次变更让判卷面变弱了吗"。合法更新与削弱在 sha 眼里同形 | `01` §二第 3 步：`edit_file t.test.mjs` 删一条断言，回执 `已替换 t.test.mjs（1 处，+0 −1 行）`，测试**转绿且 bug 仍在** |
| G2 | **在没有表的仓库里整条不进入**（用户主场景）：DSH 驱动用户仓库时，`frozenJudgePathSet` 返回空集，硬闸的前置 `size > 0` 恒假 | 直接调真函数：`frozenJudgePathSet(<带 tests/ 的用户仓库>) → size=0`；`frozenJudgePathSet(本仓) → size=50`（全在 `fixtures/` 下）。这是 `frozen.ts` 注释里写明的**有意取舍**，不是 bug |
| G3 | **`ok=true` 与"一条测试都没跑"不可区分**：`verify.ts` 只取 `code===0 && !timedOut`，runner 的 pass/fail/skip 摘要从不解析 | `01` §二第 4 步：整例 `test.skip(` ⇒ `ok=true pass=0 fail=0` |
| G4 | 没有任何面持有"本仓有多少断言"，所以**变薄多少无从判** | 本轮自测基线：211 文件 / 2095 `it()` / 6547 `expect()` / 0 `.skip\|.only`——**数有人数得出，面没有** |
| G5 | 正路与歪路的**回执形状相同**，模型看不到任何"你刚动了判卷面"的信号，人也没有 | `01` §二 表 |

**为什么 G1 与 G2 不能靠"把表推广到用户仓库"解决**：表是**哈希基线**，要预先写；
用户仓库里测试天天 legitimately 变，逐条冻结 = 每次改测试都要用户重签表。
⇒ 需要的是一维**与基线无关的结构度量**（相对变化），不是更大的白名单。

## 二、外部读数（这格有数，而且数指向的方向与直觉相反）

arXiv **2608.29460**《Can escalation channels redirect reward hacking toward defect reporting?》（2026-08，8 个前沿模型 / 5 个模型族）：

- 基线 **破解率 23.6%**（Table 1），观察到的行为**正是本页两种形状**：
  `hardcoding outputs`（把期望值写死）与 `modifying test files`（改测试文件）。
- 干预 = 给一个 **`submit_escalation_report` 工具**：让模型能提交**结构化上报**
  （"题面与要求冲突"），而不是交捷径（§B.2）。
- 政策 + 上报通道 ⇒ 破解率 **23.6% → 5.3%（降 78%）**，且**解题率不掉**。
- **上报比"只监控"多检出 10.1pp 的真缺陷**（§4.1、§4.4）；§2 另点名：**只做监控会催生隐蔽化**。
- 局限：只 9 道题；Gemini 系对缓解有抗性。⇒ 支撑方向，**不支撑我把它当本仓的百分比**。

⇒ 本页据此定重心：**检测是给通道供料的，不是主杠杆。**
只建监控臂，按这篇的读数是较弱的那一支，且可能把行为推向不易检的形状。

本仓的运气在于：**正当通道已经有了**——AGENTS.md 判卷纪律那条散文
（「发现判据有缺陷 → 写 `BLOCKED.md` 要求换判据，不许改代码去绕」）+ 门工具体系
（`clarify` / `propose_plan` 已经是"挂起等人裁决"的成熟形状，`ToolContext.ClarifyChannel` / `PlanChannel` 就在 `base.ts`）。
缺的是**把散文变成模型可点的一次动作**，以及让它比删断言更省事。

## 三、设计：四层，按依赖排（各答「长在哪 · 谁持有 · 为何不是别层」）

### L0 判卷面识别（不依赖表）：`judgeSurfaceSet(root) = 冻结表 ∪ 结构推断`

- 结构推断 = 目标仓自身的形状：`tests/`、`__tests__/`、`*.test.*`、`*.spec.*`、CI 工作流、
  `package.json` 的 `scripts.test`、覆盖率配置。
- **长在哪**：**必须是 `frozenJudgePathSet` 所在的那一层（判卷面集合的生产者）**，
  这样 `autonomy.ts` 那行 `size > 0` **一字不改**就继续按表工作。
- ⚠️ **两条硬边界，否则我会拆掉现存的规矩**：
  ① **推断集只进 L1 计数与回执，绝不进 L0 硬闸**——否则"任务本来就是写测试"的 TDD 会话会被逐个卡审批；
  ② 表存在时**表的判定优先**，推断不改变任何既有出卡行为（回归判据 C3）。

### L1 薄化度量（run 级聚合，纯函数）

`thinningOf(diffOf(eachChangedJudgingFile)) → { assertions, cases, disabled, alwaysTrue }`，四组都是**可数的结构事实**：

- `assertions Δ`：`expect(` / `assert.` / `should` / `ASSERT` / `t.Errorf` 等，按语言族小表；
- `cases Δ`：`it(` / `test(` / `func Test*` / `@Test`；
- `disabled +N`：`.skip` / `.only` / `xfail` / `@Ignore` / `t.Skip(` / `it.skip` / `--passWithNoTests`；
- `alwaysTrue +N`：新出现的 `expect(true)` / `assert True` / `|| true` / `exit 0` / `# noqa` / 空断言块
  （正是外部读数里 `hardcoding outputs` 那一支的形状）。

**谁持有**：**run 级聚合器**（与能力 16 的 `SeenLedger`、17 的 `effect` 不同层级——
16/17 是单次调用的事实，18 是**跨调用的和**：单看第 3 步只删了一条断言，
配合第 2 步"把 bug 改回去"才构成完整的歪路）。
**长在哪**：挂在 `verify_result` 的产出点（`src/agent/verify.ts` 的 `runVerifyOutcome`）上游，
消费方是能力 5 的收束闸与面板。
**为何不是别层**：不做成 `edit_file` 的即时回执（单次看不到 run 级形状），
也不做成门禁脚本（脚本在收口时跑，**绿已经吞下去了**）。

**成本：又一格免费车**（能力 13 同形状）。`edit_file`/`write_file` **本来就已经读了旧内容**
（能力 16 抓到的同一事实），新内容本就在参数里 ⇒ **Δ 计数零额外读盘**，
只有 run 级聚合器是新东西。且计数是纯字符串扫描，无 AST、无外部进程。

### L2 绿的价格：`verify_result` 加 `gradingDelta`，并给收束闸打补丁

- `verify_result{ ok:true, gradingDelta:{assertions:-1, disabled:+1, ...} }` ⇒ 面板与判定把这种绿标成
  **`thinned`**，**不并入"干净绿"**。
- **能力 5 收束闸的补丁**（这条是 18 对既有能力的直接修正）：现判据是
  `wroteThisRun && verifyAttempts === 0` ⇒ 补拍验证。但模型**删测试**也能让 verify 变绿，
  于是收束闸会被自己最不想看到的动作满足。改：`thinned` 的绿**不算已验证**，照补拍。
- **与能力 17 正交，不并档**：17 管"为什么没过"（`cause`），18 管"过了花掉什么"。两字段可共存同一事件。
- ⚠️ 老规矩：**`gradingDelta` 只进事件字段，不进 `output` 正文**（reproducibility 的 RD 门 + prefix-churn 定案）；
  模型可见的那句只在非零 Δ 时追加，零 Δ **逐字不变**。

### L3 主杠杆：把 BLOCKED.md 散文变成一次动作

- **v0（先只做这个，零新工具）**：检出 `thinned` 时在回执里明说两条出口——
  「① 这条断言与题面冲突 ⇒ 走 `BLOCKED.md` 上报，改判据由人裁决；② 你确实在重构测试 ⇒ 说明为何」，
  并把 Δ 数字给出去。**这一步就能测到本篇的自变量：模型用不用这条路。**
- **v1（配得上再建）**：`report_grading_conflict` 门工具，与 `clarify`/`propose_plan` 同形
  （`ToolContext` 加一个 channel，`TOOL_NAMES` 加一行，审批卡复用现有形状）。
- **为什么 v1 不直接建**：本仓纪律——**没证它配得上承载面就不开位**（G7；
  `gap-fix-proposal` §三 对"落成第 31 种事件"用的就是这条）。v0 先长出「上报次数 / 删断言次数」这一对读数：
  若 v0 的下一次动作变便宜、上报数 ≥1，就建 v1；若上报恒为 0，则**问题在提示词而不在工具**。

## 五、明确不采纳（理由 / 证据 / 反转条件）

| 不采纳 | 理由 | 证据 / 反转条件 |
|---|---|---|
| 给 `frozen-sha256.json` 再加一层 hash 做"自指冻结" | 自己引用自己会 regress，且这一维现由 git 审阅 + §3.7 最小 diff 流程承担 | **反转：永不**。明写"这是流程约束不是架构约束"，别假装架构能解决自指 |
| 把结构推断集并进权限硬闸 | 会逐个卡住"任务本来就是写测试"的会话；`frozen.ts` 的零行为取舍是有道理的 | 反转条件：误报率（报薄之中真属重构的比例）量到 < 某阈，且用户显式开启 |
| 真覆盖率 / AST 语义级判定 | 外部进程 + 全语言解析面，且 L1 四组计数已能表达"变薄" | 反转条件：Δ 噪声大到没人据此行动 |
| 让模型**自证**"我改测试是正当的"（一个置信度字段） | 被审模型自报置信度已被点名为反模式（`gap-fix-proposal` P2-5：`r.confidence ?? "medium"`） | harness 只出数，**人**裁决——沿用 BLOCKED.md 三态表形状 |
| 只建监控臂（无通道） | 外部读数：上报比纯监控多检出 10.1pp 缺陷，且 §2 指出监控催生隐蔽化 | 反转条件：无——这是本页的**方向性结论**，不是取舍 |
| 直接把 v1 门工具建出来 | 承载面未证（G7） | v0 的上报计数 ≥1 且模型确实因提示改变了下一步动作 |

# 第 106 页 · 「多付一次摘要调用」第一次被量成字符：临界比值 9.4，表上最不利的一档是 8.3

> 线程：`pc7-priced-in-characters-2026-09-26`。收 #10 的前提那一半（裁决仍留给人——本页不改判据）。

## 〇、这条红是什么状态

`prefix-churn-check` 的 PC7 在 HEAD 上就红着（第 76 页登记过；本轮第 104/105 页两次跑门都只看到它）。
它红的不是"产品变差"，而是**一笔没裁过的交换**：摊销策略把重写从 42,588 字符降到 34,925，代价是多一次摘要调用（压缩 5→6 次）。
第 76 页留下的待办是「先按几段长度各自算一次『多压一次 vs 省下的字节』的价，再由人决定 PC7 到底断什么」——
缺的那个数是**一次摘要到底花多少**。本轮把它量出来了。

## 一、量在门这一侧，不为此改产品一行

`summarizer` 本来就是注入点（`createMockSummarizer` 由门传入），所以包一层计数器就够：

```ts
// scripts/prefix-churn-check.ts（driveMutating 内）
const summarySpend = { calls: 0, inputChars: 0, outputChars: 0 };   // ← 声明在 try 外面
const countedSummarizer: Summarizer = async (input) => {
  summarySpend.calls += 1;
  summarySpend.inputChars += input.conversation.length + (input.priorSummary ?? "").length;
  …
};
```

不往 `UsageEvent` 上加字段（那条路要改产品，而且 #16 已经证明写侧现在给不出 `model`），
也不在判卷里放"我以为一次摘要大约多少字"——**规则 117：要裁决的数必须先落到复跑面再读**。

踩到的一条执行细节（值得记）：`summarySpend` 第一版声明在 `try {}` 里、`return` 在 `finally` 之后 ⇒
门当场 `summarySpend is not defined`，**PC7/PC8/PC9 一起红（1 条变 5 条）**。
typecheck 也在同一处报 `TS18004 No value exists in scope`——这两声都比"跑完只剩一条红"来得早，别省。

## 二、读数（8 轮、同一条会话、A/B 两支）

| | 压缩次数 | 累计重写字符 | 摘要调用 | 摘要输入字符 | 摘要输出字符 |
|---|---|---|---|---|---|
| 关摊销 | 5 | 42,588 | 5 | 11,477 | 1,740 |
| 开摊销 | 6 | **34,925** | 6 | 15,860 | 2,088 |
| 差 | **＋1 次** | **−7,663** | ＋1 | **＋4,383** | **＋348** |

⇒ 这笔交换用**同一把字符尺**就能摆平：省的是后续主请求里 7,663 个按全价计费的输入字符；
付的是 4,383 个摘要输入字符（同样全价）＋ 348 个输出字符（输出更贵，倍数记作 R）。

**临界值**：`省 > 付` ⇔ `7,663 > 4,383 + 348 × R` ⇔ **R < 9.43**。

对照本仓价表里 `calibrated: true` 的九行（`src/routing/pricing.ts`）：输出/输入比分别是
4.0、5.0、4.0、5.0、5.0、5.0、8.3、5.0、8.0 ⇒ **最不利的一档 8.3，仍小于 9.43**。

## 三、这份读数的边界（不外推的三件事）

1. **GLM 三档是占位数**（`calibrated: false`，代码原文：只可横向比较、不可当省钱证据）⇒ 本表比的是"表上已校准的行"，
   对实际在用的 GLM 价**不下结论**；等 #16/#17 那两格（usage 带 model 与 cache 分块）落地才能换成真钱。
2. **只量了字符，没量行为质量**。`compaction-cost.ts` 的头注本来就这么写着（"本模块只量缓存代价，没有量行为质量 ⇒ 缺省关"）：
   多压掉的那一段会不会把该留的结论压没，这套 A/B 看不见。
3. **只测了 8 轮这一格**。`--sweep` 里 12/16 轮的"省"分别是 15,803 / 23,942 字符（同样 +1 次），
   但那两格的摘要花费**没测**——按 8 轮的数外推临界值就是把估的当测的，不做。
   另外四个面尺寸与三组结构对照下，两支读数**逐位相同**（第 99 页"钝感"那条的再次确认）。

## 四、留给 #10 的那一句裁决（本页不动判据）

现在的 PC7 断三件事：`关臂至少压两次`（分辨力）∧ `开臂压缩次数严格更少`（代理指标）∧ `开臂重写更少`（真不变量）。
中间那条的前提已被本轮量出来：**在这个台架里"省字节"与"少一次摘要"不同向**——多出来的那一次是策略在尾部还有空档时继续压，
而它换来 7,663 字符的重写削减（按表上任何一条已校准的价，都划得来）。

⇒ 建议的裁法（要人点头才动）：
- 把第二条换成**不等式**：`若压缩次数上升 ⇒ 省下的字符 ≥ 摘要输入增量 ＋ 摘要输出增量 × R_worst`，
  `R_worst` 从价表读（今天 8.3），并把过线幅度写进 detail；
- `--self-test` 补一条反向对照：把 `SUMMARY_TEXT` 放大到"省不过线"（或把摘要输入注大），**新判据必须红**——
  否则这条不等式又是一根恒真的针脚（规则 129）。
- 若否掉这条交换（案 B），则该改的是策略缺省而不是判据：PC7 保持现在这句断言，`compaction-cost` 那三个旋钮保持关。

# 第 71 页 · #33：prune 打桩那句「需要时 read_file 取回」递的是绝对路径 —— 收成一份落位判定，区外就改口

来路：第 63–65 页的 `probe-promise-recall`（AST 收清单 + 逐面真跑"最后一跳"）。
它的 `hopPruneStub` 这一格从建出来那天就是红的，红在最后一跳：

```
工具抛错：read_file: 只允许 workspace 相对路径，收到绝对路径: /var/folders/…/prune-attachments/probe-…-c-old.txt
```

裁决沿用 #47 那条（第 64 页）：**分案改文案，不给 `read_file` 开第二根允许例**。
七把碰文件的工具全走 `resolveInWorkspace`，它第一句就拒绝对路径；开第二根等于把那条信任边界拆掉。

## 缺陷的形状（两处发射点各答了一遍同一个问题）

`src/agent/plugins/skills.ts` 的 `skillRecallSuffix`（#47 刚收成一支）里已经有一份
「realpath → relative → 判 `..`/绝对」的落位判定；`src/agent/prune.ts` 的打桩那行**没有**它，
无条件把 `join(dirname(logPath), "prune-attachments")` 算出来的绝对路径写进模型上下文。
⇒ 同一件事两支各答一遍（本仓最忌的同族病），而这次漂的那一支正好是**说谎**的那一支。

生产调用点（`src/agent/glm-session.ts:638`）传的是 `{ events, attachmentsDir, sessionId }`，**没有 workspace**
⇒ 今天每一次裁剪走的都是"区外/未知"那一案。

## 修法：一份可达性判定 + 两句各自的人话

1. 新建 `src/agent/recall-path.ts`，只导出一个纯函数 `workspaceUsablePath(absPath, workspace?)` ⇒
   工作区内的相对路径，或 `null`。skill 那一支删掉自己那份 realpath/relative/isAbsolute 改吃它（副本数 2 → 1）。
2. `prune.ts` 新增 `pruneRecallSuffix(attachmentFile, workspace?)`，两案两条人话：
   - 区内：`[原文已存附件 <相对路径>，需要时 read_file 取回]`（动作做得到）
   - 区外或未知：`[原文已另存到会话附件（在工作区之外），模型侧读不到；要通读请由用户打开该会话的附件目录]`
   `PruneInput` 加可选 `workspace`，缺省即走诚实话 ⇒ **没接线也不会说谎**（fail-closed）。
3. 附件仍然真落盘：文案改口不等于把能力删掉，`writePruneAttachments` 一字未动。

路上踩到的两个真实约束（都不是设想）：

- **目标文件此刻可能还没写**。prune 的形状是"先算投影、后写附件"，而 `realpathSync` 对不存在的路径直接抛
  ⇒ 判定改成"沿路径向上取最近的已存在祖先，再拼回我们自己构造的那几段"。这条有独立用例钉（造红 M3）。
- macOS 的 `mkdtemp` 落在 `/var → /private/var` 符号链接下。第 70 页那条环境假红在这里同样会咬人：
  判定按 realpath 归属，词面比较会把一条**做得到的**承诺误吞掉——两个方向都要有用例。

## 判卷面被同一改动打瞎的地方（本轮一起补）

- `scripts/prune-check.ts`：③d/④b 由"绝对路径逐字相等"改成"相对路径 + 一个绝对字节都不许出现"，
  另加 **④c：拿打桩里那条相对路径真调一次 `read_file`**（模型照那句做得到 = 承诺成立）。
- `scripts/probe-prune-recall.ts`：整支重写，判的是**生产形状**（区外那案不递地址、明说读不到、附件仍在盘上），
  并留一条反向哨兵：拿旧写法的绝对路径去调 `read_file` 必须仍然被拒（证明"塞回去就是假承诺"，尺的靶子没烂）。
- `scripts/replay/prune-promise.ts`（#33 当初定优先级用的读数面）：**它按「原文已存附件」收料**，
  文案一改就会永远读到 0，然后给出「语料里从没发射过 ⇒ 潜在，不值得动」这句**误导**结论。
  补第二支标记 `原文已另存到会话附件` 单列 `honestStubs`，并加一态："假承诺已被替换，但每发射一次诚实句
  就是一次『能力缺席』，缺的是组装那一跳传 workspace，不是文案"。
  标记取 prune 独有的整句、不取「模型侧读不到」——skill 截断那句也说这五个字，两支会被并成一桶。
  两条新用例的诚实句**由产品自己拼**（`pruneRecallSuffix(ABS, 别的目录)`），手抄措辞 = 尺静默失明的另一种写法。
- `tests/session-prune-attachments.test.ts` 的 ①②：①旧断言把假承诺**冻进了用例**（`toContain("prune-attachments")`），
  ②旧写法从打桩文本里正则抠路径 ⇒ 文案一改就抠不到。①改成钉诚实话 + 不递绝对路径；
  ②把路径来源换成**生产写出的那个目录**（`readdir`），逐字等值那条实质不变。
- `tests/path-boundary.test.ts` +5 条直接钉 `workspaceUsablePath`：未落盘 / 区外 / `..` 与软链逃逸 /
  未知工作区，外加一条"helper 说可用 ⇒ `read_file` 真读得到"的两半同口径配对。

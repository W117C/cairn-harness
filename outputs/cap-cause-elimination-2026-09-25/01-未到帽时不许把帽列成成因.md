# 第 56 页 · 「图里没有它」的成因收敛：没到帽时，那句"被 400 帽挡在图外"是恒假的

日期 2026-09-25。基线 HEAD `1d699f5`（第 55 页那一笔）。续的是同一条政策：
覆盖面自述补完了**阳性**出口，这一页补的是两条**阴性**出口里的假成因。

## 一、缺陷：把"此输入下不可能成立"的成因写成恒真

改前 shipped 的两条阴性文案（逐字）：

```
impact_query: 图里没有符号 "x"（改名、未被引用、或不在已扫描的后缀内）
[impact] describe：这张图里没有任何文件**定义**它 ⇒ 它是外部或全局符号（定义在 node_modules、
  由环境注入，或定义它的那个文件被 400 帽/忽略规则挡在图外——图内没有 ≠ 仓库里没有）…
```

第二句里的 `${String(maxFiles)} 帽` 在**任何**输入下都会印出来，包括：

| 输入 | 图收录 | 帽 | "被帽挡"是否可能 |
| --- | --- | --- | --- |
| `tests/impact-query.test.ts` 里那对 2 文件小仓库 | 2 | 400（缺省） | **不可能**（`applyFileCap` 是 `slice(0, cap)`，候选数 ≤ 帽时一刀不切） |
| 本仓真跑（默认帽） | 400 | 400 | 可能 |

⇒ 小仓库/单测环境下模型被告知"可能是帽挡的"，并（在第一支里）根本没有出路可走；
这与第 51 页裁掉的「死参数式文案」同族：**文案指向一个在此输入下不存在的开关**。
而更常见的一面是"排除法白送"：未到帽时本来就能断言"不是帽挡的"，这一句话能把
模型的一整类假设关掉——省掉的正是它去调 `maxFiles` 重跑一次建图的那一轮。

## 二、修法：一个纯函数，两支共用，判据与 `coverageNote` 同一条

```ts
export function capCauseNote(files: number, cap: number): string {
  return files >= cap
    ? `本图收录 ${String(files)} 个文件＝帽 ${String(cap)}（非全量）⇒ 这一刀可能把它切在图外，` +
      "调大 maxFiles 后重问可排除这一成因"
    : `与帽无关：本图收录 ${String(files)} 个文件，未到帽 ${String(cap)} ⇒ 没有文件是被帽切掉的` +
      "（被忽略规则/噪声目录排除、后缀不支持仍然成立）";
}
```

- 两支（符号彻底查不到 / 只有引用没有定义）都调它 ⇒ **不会出现阳性说"非全量"而阴性说"与帽无关"** 的自相矛盾
  （第 53 条：靠字段成立的不变量要数清所有取料面；这里取料面是两支，收成一份实现）。
- `maxFiles` 这个**词**只在到帽那一侧出现 ⇒ "未到帽时不教模型去调一个调了也没用的参数"由文案自己保证。
- 既有锚点未动：`impact-query-symbol-absent-fail-visible` 钉的是 `if (defined.length === 0 && refSites.length === 0) {` 那一行，本轮只改花括号里的内容。

## 四、动了一条既有判卷：为什么这不是"改代码去绕判据"

`symbol 出口：那句「被 N 帽挡在图外」里的 N 也必须是实发的帽` 这条（第 291 行）原先断
`toContain("被 " + CAPPED + " 帽")` —— 它把**措辞形状**和**不变量**混在一起。本轮文案改成
`＝帽 N（非全量）` 后该串不再出现，于是把它改成 `toContain("帽 " + CAPPED)`，
并把"不许出现写死的缺省值"那半边原样留着。

这条改动是否把判据改松了，由 F 那格回答：**只把实参换成写死的 `MAX_FILES_DEFAULT`，
它照样红**（连同两条新用例，共 3 条）。⇒ 不变量仍有牙，被换掉的只是措辞。
（另：确认过 `scripts/mutate-verify.mjs` 里没有任何锚点以这条旧标题作 `expectFail`，改名不牵连判卷表。）

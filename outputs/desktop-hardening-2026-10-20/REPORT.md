## 交付

| 问题与影响 | 修复 |
| --- | --- |
| 反馈/置顶失败回滚整张 Map/Set，会清掉另一条已成功的标记 | 逐条回滚；并行修改其他消息时互不覆盖 |
| 旧会话请求迟到，能覆盖当前会话标记；切走再切回也可能撞上 | 请求代次 + 会话归属检查；新加载的状态不被旧请求覆盖 |
| 同一条标记等待中仍能反复提交；移开鼠标后等待状态消失 | 提交时立即锁定该条目，按钮禁用并显示等待态，操作条在提交结束前保持可见 |
| 查询不等待此前入队的磁盘写入，立即重读得到旧值甚至空列表 | FeedbackStore 与 PinStore 的读屏障等待已有写队列；失败写入不阻断后续合法读写 |
| 停止后的未结工具调用仍显示执行中 | 显式「未收到结果」状态；主会话终态结清运行提示，worker 终态不影响主会话，迟到的真实结果可替换未结状态 |
| 编辑参数超过 1500 字符后，截断 JSON 无法反解路径，差异入口消失 | 独立保留结构化路径；展示截断与行为数据解耦，保留原参数展示上限 |
| 关闭窗格后焦点掉回文档 | 焦点交还剩余面板导航；同时统一拖动与弹出图标 |

将反馈与置顶的重复编排从 App 提取为 `useMessageAnnotations`，共享加载、归属、互斥提交和逐条回滚逻辑。没有引入新依赖。存储屏障沿用原有队列，保证限于同一 Store 的进程内顺序，不宣称跨进程事务。

# 第 55 页 · 影响面的**阳性**答案也要说清自己量了多大一块

日期 2026-09-25。基线 HEAD `1436062`。起因是能力 1 的一条洞：`impact_query` 的阴性结论早就各自带分诊，
而**成立**的答案完全不自述覆盖面 ⇒ 「波及 1 个文件」与「图只收了仓库的一小截」在模型面前同形。

## 一、缺陷：只说了「查不到」的那一半，没说「查到了，但只查了一截」

本仓关于「阴性结果要说清扫描面」这条政策已经落在好几处（grep 的 `ripgrep.ts` 说明、glob 的噪声目录、
`graphAbsenceNote` 的四种成因）。但 `impact_query` 的三个**成功**出口原先是这样收尾的：

```
[impact] contextNoteFor 的定义在 1 个文件：跨文件调用点 4 处，波及 1 个文件
```

而同一刻这张图实际收录多少文件？**2026-09-25 本机实测（默认帽、真仓库）**：

| 读数 | 值 |
| --- | --- |
| 全量候选源码（`scanSourceFilesAll`） | **451** |
| 本次图收录（`graph.files.length`，帽 `MAX_FILES_DEFAULT`） | **400** |
| 差 | 51 个文件（**11.3% 的候选在图外**，见任务 #32） |

⇒ 模型拿到「波及 1 个文件」就以为问全了；而"调用我的人"完全可能就在那 36 个里。
这比"回答不了"更坏：它给的是一个**没有前提的真话**。第 32 页那条"默认帽 400"的量化一直缺一个出口——
读数只在文档里，模型面上看不见。这一格补上后，帽的代价第一次出现在**每次查询的输出里**。

> 措辞上刻意不说「漏了 N 个」：挤掉多少个要重扫全量候选才知道，为这句话付一次 `rg` 不划算。
> 说「非全量 + 图里没有 ≠ 仓库里没有 + 出路（调大 maxFiles 重问）」，模型可执行的部分已经齐了。

## 二、修法：一个纯函数 + 一个字段，三支各自组装

判据是**精确**的而不是保守的——`applyFileCap` 只做 `slice(0, maxFiles)`，于是：

- `收录数 < 帽` ⟺ 这一刀没切到东西（真全量）⇒ **一个字都不许多**（零回归）；
- `收录数 ≥ 帽` ⇒ 可能有文件被挤在图外 ⇒ 加一句尾括号。

```ts
// src/tools/impact-query.ts
export function coverageNote(files: number, cap: number): string {
  if (files < cap) return "";
  return `（覆盖度：本图收录 ${String(files)} 个文件＝帽 ${String(cap)} ⇒ 图非全量，` +
    "图里没有 ≠ 仓库里没有；要更全调大 maxFiles 后重问）";
}
```

`file` 支的收录数由数据层带出来（`FileImpactReport.graphFiles = graph.files.length`）——
**这个字段不加，那一支就永远不自述**：`fileImpact` 不把建图规模返回给读端，读端就没有分母可说。
另外两支（`symbol` / `deps`）本来自己 `buildImpact`，直接取 `graph.files.length`。

三处都拼在传给 `sitesNote` 的 `head` 里，**不改 `sitesNote` 的签名**：锚点
`impact-up-noun-drift`（第 1892 行附近那条）钉的是
`        return { ok: true, output: sitesNote(head, r.up) };` 这一整行，
改它就是把既有锚点顶开（本轮 `--check-needles` 前后都是阻断 6，一条没新增）。

## 三、判卷：4 条新用例 + 五格突变对照（其中一格最初**零观测**）

fixture 用 mtime 造出「两个相关文件最新、两个 pad 文件最旧」，于是 `maxFiles: 2` 既**命中帽**、
又让 a.ts/b.ts 都留在图内（成功路径成立）——只有这种输入能同时判「该出声」与「不该出声」。

| 突变（一次性、改完逐字复原） | 结果 | 红的是谁 |
| --- | --- | --- |
| A `if (files < cap)` → `if (false)`（到帽判据作废） | 红 2 | 新写的零回归哨兵 + **既有**那条「不传 maxFiles 时行为逐字不变」 |
| B 自述整段返回空（三支一起废） | 红 3 | 三支各自的红 |
| C `file` 支不接 | 红 1 | `file 支同一格…` |
| D `deps` 支不接 | **红 0（第一次跑）** | 没有人守这一支 ⇒ 当场补一条 deps 用例后复跑：红 1 |
| E `symbol` 支不接 | 红 1 | `symbol 支命中帽…` |

D 那一格是本轮唯一由突变**发现**的缺口：我把三支都接上了，但只给两支写了判据。
这正是本仓反复踩的「取料面 N 支、判据守 1 支」的形状（第 53 条），只不过这次 N=3、
且**写代码时三支都写了**，所以读代码看不出问题——只有"一次废一支"能看出来。
补完后的第二次五格复跑：A 红 2 / B 红 3 / C 红 1 / D 红 1 / E 红 1，无存活格。

## 四、刻意不做：per-edit 回注（`contextNoteFor`）不加这句

写侧每次 `write_file`/`edit_file` 成功后注入的波及摘要也报「波及 N 个文件」，同样没有覆盖面。
**这里有意不加**，理由要留名（不然下一轮会被当成又一处"两头断"补上）：

1. 频率不同：回注是**每一次编辑**都付，而本仓在默认帽下 `files ≥ cap` 恒成立 ⇒ 每写一次文件固定 +63 B；
   读端查询是一轮里挑几次付。同一条信息在两处的边际成本差一个量级。
2. 可执行性不同：读端那句给了出路（调大 `maxFiles` 重问）；回注那条是钩子建的图，
   **钩子没有 `maxFiles` 这一位**，模型看到"非全量"也没有对应动作可做——那正是第 47 页裁掉
   「死参数式文案」时立的规矩。
3. 被编辑的那个文件按 mtime 必然在帽内（它刚被改），所以漏的主要是"查询时点"的风险，不是"编辑时点"。

⇒ 裁决留位：若 #32 把默认帽换成全量（实测 +9ms），第 2 条理由消失、第 1 条也变成"永远不说"，
届时这一格应重新判一次。**判据**：届时要么给钩子加 `maxFiles` 并补自述，要么把本节改为"已裁否"。

## 一、目标里那一句一直没人动

用户目标第 10 条写着「用 SWE-bench Verified、Terminal-Bench、Aider Polyglot 等基准衡量」。
本轮先盘点现状（不是猜，是 `grep -rln` 全仓 `swe-bench|polyglot|terminal-bench|FAIL_TO_PASS|instance_id`）：

- 唯一命中的是三份**散文**文档（`outputs/agent-landscape-gap-analysis-2026-09-18.md` 等）——没有任何代码认得这些格式；
- 最接近的评测面是 `scripts/loop-eval.ts`：4 个任务**硬编码在脚本里**（`const TASKS`），靶子只有 `fixtures/todo-app` 一个；
- `fixtures/gym` 是反事实靶场（路由/决策轴，冻结剧本、确定性）；`scripts/replay/run-scorecard.ts` 是**读已录制语料**出逐 run 终态（免费的 y 轴，但不产生新分数）。

⇒ 差距不是"分数不好看"，是**基准进不来**：想喂一份真实数据集，只能改脚本；改脚本的人同时改了判卷与装配，
之后没人能核对"我这次量的分母是不是那份数据集"。

## 二、这一笔建的东西

| 部件 | 干什么 | 为什么不放别处 |
|---|---|---|
| `src/agent/eval/task-set.ts` | 纯数据层：本仓任务集 JSON 与 SWE-bench 形态 JSONL → 统一 `TaskSpec`；另加 `feasibility` / `aggregateFeasibility` | 不 IO、不联网、不 import electron ⇒ 任何脚本与测试能直接吃；数据层与"怎么跑"分开，才不会再一次改脚本顺手改判卷 |
| `loop-eval --tasks <file>` / `--swebench <file>` | 任务集从文件进来 | 解析报**任何一条**错 ⇒ 拒绝出数（exit 1）并逐条点名 |
| `loop-eval --feasibility` | 只回答"这批任务现在量得了吗、缺什么"，**一个模型请求都不发** | 花钱之前先把缺口摆出来；这也让"能不能上基准"第一次有了答案而不是态度 |

数据层的唯一规矩是**没有静默出口**：一条记录要么进 `tasks`，要么进 `errors`（带行号/字段名），
没有第三种。会被拒的形状包括：字段名拼错（`verifior`）、重复 id、`instruction` 空白、
缺 `FAIL_TO_PASS`、`FAIL_TO_PASS` 是空数组、缺 `PASS_TO_PASS`（那只有半份判卷：
"坏的要过"查了、"好的不许坏"没查）。**分母被悄悄缩小是评测器最难发现的错**——成功率照样是个数。

## 四、边界与下一步（写清楚，别让人以为已经能量基准）

1. **外部条目当前只能量可行性，跑不了**：本跑器只接 GLM 会话装配 + node 靶子；SWE-bench 是别的语言仓库 +
   pytest 判卷。硬跑出来的分数与基准无关，所以 `runOnce` 对外部条目直接抛错点名，而不是"试试看"。
2. 真上要跑，缺的按顺序是三件：**预先 fetch 仓库快照**到 `eval-snapshots/<instance_id>`（外部的时间与磁盘）、
   **语言侧判卷适配**（把 `verifier.command` 接到能跑的容器/venv）、**真钱跑一次**（用户点头）。
   这三件都不在本笔范围，也不该被"已经支持 SWE-bench 格式"这句话提前宣布。
3. Terminal-Bench / Aider Polyglot 的原生载体是 YAML，而本仓无 YAML 依赖（实测 `package.json` 没有）⇒
   现在的路子是"外部转成 JSON/JSONL 再进"。**没有**为了让这句话好听而顺手加依赖。

#13 原文写的是「现行层路径指针存在性（**今天真值 0，可直接上线**）」——**实测是 1**。
而且这一格**不是别人的在飞删除**（`git status` 空、HEAD 里也没有）：它是 core-only 迁移里已经提交掉的删除，或"运行时才生成"的文件。
所以按 #13 原形状直接上线 D-9，今天就会得到一条**永久假红**。

## 一、为什么这条比"补个存在性检查"麻烦

`STATE.md` 带着三条判据（D-1 预算、D-5 `rev:` 必须指向真提交、D-2/D-4 免抄观测值），门今天对它们的状态是
**印三行「未受检，不等于通过」**。这一族在第 109 页刚定过调：缺席要有名字——**它已经有名字了**（`ℹ️` 行），
所以病不在"藏"，而在"这个名单该不该升成红"：

- 升成红 ⇒ 一个合法尚未生成的运行时文件让门禁永久红（第 111 页刚数过"门禁今天红"的代价，别再添一条）；
- 不升 ⇒ 谁哪天把 `STATE.md` 的生成路径改没了，D-5 的 rev 校验就长期空转，只有翻 `ℹ️` 行的人才看得见。

两个都对，说明**缺的不是判据，是登记面上的一个字段**：`LIVE_PAGES` 现在是一条字符串数组，
分不清"应当存在于版本库"与"运行时生成、首轮可以没有"。这正是规则 95 的形状（一个值承载两种成因 ⇒ 必须交外部旗标），
也是规则 205 的同族（判据面要有名字，但名字要能分流，否则只能整条关小）。

## 二、D-9 改后的形状（等 `docs-check.ts` 腾出来再做）

```ts
// 现在：export const LIVE_PAGES: readonly string[] = [...]
// 改后：每条带成因，存在性判据只对 required-in-tree 的那一半升红
export type LivePage = { path: string; presence: "required-in-tree" | "generated-at-runtime"; why: string };
```

- **红只给 `required-in-tree`**：`AGENTS.md`、`docs/README.md`、`docs/CODE-WIKI.md`（这三条今天实测都在 ⇒ 上线即绿，且不会因 `STATE.md` 变永久红）；
- `STATE.md` 登记成 `generated-at-runtime`，缺席继续印 `ℹ️`，但它**受第二条判据管**：
  一旦盘上有它，D-1/D-2/D-4/D-5 必须全部生效（今天已经是这样，改后要有用例钉住"存在却没被检"那一格）；
- 反向一侧必须同时写（规则 101）：**登记项的 `presence` 值不在取值域 ⇒ 红**；
  以及"清单里有一条路径既不在盘上、也不是 `generated-at-runtime`，而门仍然全绿 ⇒ 这条 D-9 是恒真的"要在造红里当场红一次。

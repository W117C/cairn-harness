## 1. 主张（一句话）

把「每请求都要重送、且与本轮任务无关」的那一块固定成本收进**一个池子**，
配**一条按位置从尾向前的降配梯**，并且**省了谁必须如实说出去**。
不新增任何一件的截断语义，只补「求和」这一只此前不存在的闸。

## 3. 降配梯（唯一实现点，两条规矩各由一个外部事实逼出）

```
梯级 0  未超帽 ⇒ 逐字原样返回（note = ""，dropped/shortened = []）
梯级 A  把「可降档」工具的描述压到紧帽 MODEL_SURFACE_TIGHT_DESC_CHAR_CAP = 600 字符（带如实标注）
梯级 B  仍超 ⇒ 从**数组尾部**向前整条丢：先丢 optional（MCP/插件），丢光再丢 pinned（skill/obs_recall/impact_query）
终态    仍超 ⇒ unresolvable = true，**core 一把不砍**，note 里报「需人工裁决」
```

身份三档，**core 的名字集从 `gateToolSpecs()` 派生**（不另抄清单——抄了就又是一处「规格与实现两处手写」）：

| 档 | 谁 | 可压描述 | 可丢 |
|---|---|---|---|
| `core` | 基础工具表 13 条 | 否（描述即行为契约） | **永不** |
| `pinned` | harness 注入且被别处依赖：`skill` / `obs_recall` / `impact_query` | 是 | 最后 |
| `optional` | 其余插件/MCP 工具 | 是 | 最先 |

**规矩 1：只从尾部丢，绝不中间摘。** 缓存按前缀命中（`tools → system → messages`，上游任一变化会把它
之后全部重写，写价 1.25×）；中间摘一把 = 它之后所有条目的缓存作废。Manus 的原话是「宁可 mask 工具
也不要从清单里移除」——我们做不到 mask（provider 层没有 mask 语义），**退一步做到「移除只从尾部」**，
这是同一条原理在我们形态下的可行子集。这条规矩把工具表的构造顺序也钉住了（core 在前），由 MS2 守。

**规矩 2：core 永不被自动砍。** 帽紧到装不下时砍 `edit_file`/`verify` 换来的是「便宜的废会话」，
比贵更坏。走到终态就报 `unresolvable` 交人裁决——这与本仓「fail-closed 不静默降级」同族。

**代价可观测**：`planSurfaceBudget` 返回 `prefixStableChars`（与未降配版逐字符比对的可缓存前缀长度）。
纯尾丢 ⇒ 除结尾 `"]"` 外前缀逐字不变；梯级 A 一生效，前缀在第一把被压描述的工具处断开。

## 4. 判据（门的六条，与 `02` §3 一一对应）

| id | 断言 | 反向对照（`--self-test` 怎么造红） |
|---|---|---|
| MS1 | 真实 `BASE_SYSTEM` + 缺省工具表的固定面 ≤ 帽 | 把帽压到 1 ⇒ 必在帽外 |
| MS2 | core 段整体在数组前部 | 把 core 段搬到尾部 |
| MS3 | 降配后保留表是原表的**位置前缀**且确有丢弃 | 真造一件「中间摘」 |
| MS4 | 未超帽时装配**逐字不变**、note 为空 | 偷偷改一个字节的描述 |
| MS5 | note 点名每一把被丢工具且写出帽值 | 换成一句不点名的散文 |
| MS6 | `unresolvable` 时 core 一把不少 | 造一把「顺手砍了 core」的假降配 |

**取数口径失败也红**：`BASE_SYSTEM` 取不到（0 字符）时 MS 全体判红而非降级——帽的判定依赖这个数。
装配数为 0 直接红（真空通过是本仓最忌的假绿）。

## 5. 明确不采纳（附理由与反转条件）

| 项 | 不采纳 | 反转条件 |
|---|---|---|
| Tool Search Tool / 按需装载（Anthropic 官方形态） | provider 层零 `defer_loading` 语义，且我们的 13 把 core 是**行为契约**不是可检索候选；先补「尾丢 + 总账」这一格才轮得到检索式 loadout | 真接 Anthropic 工具搜索或自建检索器时（`00` §6.2 的消融先跑） |
| 按效用选子集（2605.24660 / JSPLIT / Tools Are Not Islands） | **知道这是次优解**：按位置尾丢会丢错工具（第 26 条中等工具可能比第 3 条更有用）。但没有逐 harness 的效用信号之前，位置是唯一**可判定且可解释**的序 | gym 里有「工具数 × 选错率」曲线之后（`00` §6.2） |
| mask 工具而非移除（Manus） | provider 无 mask 语义；OpenAI 兼容面上「不发送」与「mask」同形 | 出现能在请求里带 `allowed_tools` 掩码的适配器 |
| 把记忆/skills/地图并入同一池 | **刻意不并**：那些各有帽，并池会让「记忆写太长」静默删掉用户装的 MCP 工具——那是把成本压力转成别人的功能损失。本模块只**如实计入总账**（`account.volatileChars`），不据此降配 | 出现跨件统一优先级政策并且用户认可「记忆可被工具挤掉」时 |
| code-mode / PTC | 上日 §2.5 裁决：现有靶面测不到收益，推迟 | gym 多文件真实仓库 case 落地 |

## 6. 留尾与下一格（不假装收口）

1. **面板装配账未做**（C-3）：三个多会话热点文件，宜与 D7 的「人侧一键还原」并一批。
2. **core 侧成本未治**：`spawn_agent`（996 ch）+ `remember`（968 ch）= 固定面的 28%。
   本轮明确**不**动它们（规矩 2）。要动得先有「砍了会掉什么分」的读数 ⇒ gym 消融。
3. **逐请求重算 vs 会话内冻结**：梯级现在每轮重算。工具表在 run 中途因 skill 激活而变是本仓既有语义，
   但「同一会话内池子反复在帽线附近抖动」会让前缀每轮重写。**未做**：一次冻结 + 变化才重算。
   测法已有：`prefixStableChars` 逐轮打印。
4. **cache-churn 门**（`00` §6.1）：把「每轮重写多少可缓存前缀」做成进门指标——`prefixStableChars`
   是它的分子，本模块只落了读数。
5. **worker 面**：worker 工具表也走同一 provider ⇒ 已被覆盖；但 worker 的 `roleDefinition`/
   `SUMMARY_TOKEN_CAP` 那几件不在本池内（各自有帽），与记忆同理不并。

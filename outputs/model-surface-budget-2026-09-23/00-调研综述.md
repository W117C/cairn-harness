# 00 调研综述：模型面（每请求固定成本）与工具面膨胀 · 2026-09-23

> 本篇是**读物层**：外部事实 + 数字 + 出处 + 对本仓的含义。设计与判据在 `02-设计与判据.md`，
> 本仓自己的实测在 `01-装配账读数.md`，施工结果在 `03-施工回执.md`。
> 方法：WebSearch/WebFetch 取一手来源（厂商工程文档 / arXiv / 官方博客），**取不到数字就写「无公开数」**。

## 0. 一句话结论

「工具规格 + 基础提示」这一块固定成本，行业已经在 2025–2026 从「风格建议」升级成「有数字的行为问题」：
**Anthropic 自己给的触发线是「≥10 把工具或 ≥10k token 的工具定义就该改成按需装载」**，
而我们缺省装配是 **13 把 / 7,067 字符**——已经在触发线之上，却此前**没有任何一处会红**。
同时，把这块预算管起来这件事，**没有任何一家公开做了「单一池子 + 优先级降配梯」**：
公开的机制全是「逐件帽」或「一条悬崖式阈值」。这就是本仓这一格能自立的部分（见 §5）。

## 1. 工具数量 → 行为分：公开读数

| 来源 | 读数 | 对本仓的含义 |
|---|---|---|
| Anthropic《Advanced tool use / Tool Search Tool》 | 工具定义 token **降 85%+**；MCP 重负载评测准确率 **49% → 74%（Opus 4）**、**79.5% → 88.1%（Opus 4.5）**；真实工作负载实测工具定义 **134K token**；建议触发线 **≥10 把工具或 ≥10k token 定义**；`defer_loading` 支持 200+ 工具 | 我们缺省 13 把已在触发线之上；「砍工具面」不只是省钱，是**掉分项的正解** |
| Anthropic《Code execution with MCP》 | 一次性装载全部工具定义 ≈150,000 token → 渐进披露后 ≈2,000 token（**98.7%**） | 与 §4 的「检索式 loadout」是同一条路，但要执行体（code-mode），本仓靶面测不到（`architecture-uplift` §2.5 已裁决推迟） |
| OpenAI function-calling 指南（2026） | 建议**少于 20 把**函数，其余走 tool search；无公开的「准确率 vs 数量」曲线 | 我们的静态表 13 把在圈内，**装一个中等 MCP server 就出圈** |
| MCP-Zero（arXiv 2506.01056） | 在 ~3K 个 MCP 候选（248.1K token）里选对工具显著退化；按需发现把 API-Bank 的 token 降 ~98% | 规模化的真实形态就是「装多了选不对」 |
| MCPMark（arXiv 2509.24002） | 127 个真实 MCP 任务，最强前沿模型也只有 **52.56% pass@1**（多数模型 <30%），平均 **16.2 轮 / 17.4 次调用**，错误模式含「选错工具」 | MCP 面是**已证的行为风险面**，不是成本面 |
| 《How Many Tools Should an LLM Agent See?》（arXiv 2605.24660） | 机会校正指标下 **~7 把候选（90.3% 覆盖）胜过 50 把**；自适应工具清单让 Sonnet 4.6 **93.1% vs 固定 87.1%** | 「先丢尾部」这种按位置降配是**次优**的，真正的解是按效用选子集——留作开放项（`02` §6） |
| Uber《Efficient software factory》（2026-08） | MCP JSON schema 实测 **50–70K token**；改 CLI/code-mode 后单工具成本≈0；3,600 个 skills 全部按需装载；400K 才压缩；>70% PR 由 agent 产 | 生产规模的下限参考：**不做总闸迟早撞上 50–70K 那一档** |

## 2. MCP 特异的退化与治理面

- **生产帽已有先例**：Windsurf/Cascade 硬限 **100 把 MCP 工具**并建议禁用未用项；Cursor 侧指引称 **>40 把启用工具可测地退化选择**；Gemini CLI 会净化 schema（剥 `$schema`/`additionalProperties`、**工具名截到 63 字符**）。⇒ 「有帽」是常态，**我们此前是唯一没帽的那类**。
- **安全面同题**：CSA 研究简报（2026-07）：**MCP tool-poisoning 在受测 agent 运行中 36.5% 得手**，自动执行工具配置波及 Cursor / Claude Code / Gemini CLI / Copilot / Amazon Q；Microsoft Security Blog（2026-06-30）：**把每条工具描述都当提示词**、按发布者白名单、关掉「允许全部」、按最小代理权审批。
  ⇒ 对本仓的含义：降配梯**不能**变成「模型面太挤就顺手塞个更短的描述」——描述要**如实标注被截断**（`02` §3 梯级 A 的尾巴），否则省 token 反成投毒面。
- **已产品化的形态**：命名空间（`mcp__server__tool`，我们同形）、按会话启用、检索/懒装载（Tool Search）、code-mode 代 MCP、子代理隔离上下文（Cognition《Don't build multi-agents》：子代理只该用于**干净上下文**的独立读取）。

## 3. 前缀稳定性 = 钱（这条决定我们的降配梯长什么样）

| 来源 | 读数 | 对本仓的含义 |
|---|---|---|
| Anthropic prompt caching 文档 | 顺序固定 `tools → system → messages`，**上游任一处变化会把它之后全部重写**；写价 **1.25×**（5min TTL）/ 2×（1h），读价 **0.1×**；最小可缓存前缀按模型 512–4,096 token | 我们的 A1 断点正打在「首条 system + 工具 schema」末尾 ⇒ **工具面就是可缓存前缀本体**，动它=动缓存 |
| Manus《Context Engineering for AI Agents》 | 「**KV-cache 命中率是单一最重要指标**」（0.30 vs 3 USD/MTok，10×）；做法：append-only 上下文、稳定前缀、**宁可 mask 工具也不要从清单里移除** | 这是本仓「**只从尾部丢，绝不中间摘**」那条不变量的直接来源（`02` §4） |
| OpenAI caching / DeepSeek 2026 价 | 自动前缀缓存 ≥1,024 token、命中最高 **90% 折扣**；DeepSeek 命中 **$0.003/M vs 未命中 $0.15/M（≈98% 差）**；「静态指令在前，动态内容在后」 | 与 `classifyAssembly` 的三层切法同构 |
| 本仓自测（`architecture-uplift` §2.3/§5） | 既有真跑 75 条 usage 的 `cacheRead/input` = **51.5%**；装配探针：每次请求 prompt ≈8.37–8.55KB，其中**可缓存前缀 7,604B ≈ 90%** | ⇒ 「少发一轮」类收益要按 51.5% 折扣看；而**固定面就是那个 90%** |

## 4. 长上下文退化（为什么「塞得下」不等于「没事」）

- Chroma《Context Rot》（18 个模型）：输入变长时**连平凡任务都会退化**，且「模型并非均匀使用上下文」（位置/U 形效应）。
- NoLiMa（arXiv 2502.05167）：去掉字面 needle 匹配后 **GPT-4o 99.3% → 69.7% @ 仅 32K**。
- RULER（arXiv 2404.06654）：宣称 ≥32K 的模型里「**只有一半能在 32K 维持可用表现**」。
- 《Same Task, More Tokens》（2402.14848）：推理退化发生在**远低于技术上限**的输入长度。
- 《LLMs Get Lost in Multi-Turn》（2505.06120）：多轮拆分平均掉 **39%**。
- MTAC-IFBench（arXiv 2609.14992，2026-09）：会话内指令遵循随长度**快速退化**（均值 91.33 条约束/实例）。
- 「128k 实际只有 30k」这句流传很广但**没有公开一手数**；可辩护的锚点是 32K 处已开始退化。
  ⇒ 对本仓：固定面不是「离 128K 还远就安全」，它是**挤占行为质量的那一块**，且与历史同池竞争。

## 5. 逐件帽 vs 单一池：本格的自立点

公开机制全是**单件**或**一条阈值悬崖**：Aider `--map-tokens`（缺省 1k，且会随聊天变长**自动缩**——唯一公开的跨件取舍）、Anthropic「工具定义超过约 10% 上下文则改按需装载」、Agent Skills 渐进披露（元数据常驻、正文触发才进）、Claude Code 的 `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__`（**稳定前缀**，不是预算）、OpenAI「<20 把」建议、Codex 的 AGENTS.md 字节帽（**无可靠公开数**）。
**「一个池子 + 降配梯（先降描述→再按优先级丢）」没有公开先例，也没有谁拥有那条梯的排序正确性**。⇒ 见 `02`。

## 6. 行业还没产品化、我们下一格能做的

1. **前缀抖动门**（cache-churn gate）：把「每次运行打了多少个缓存 / 重写多少字节」做成可判读指标进门。原则由 Anthropic/Manus 说破，**没有一家把它做成门**。（本仓已迈出半步：`prefixStableChars` 读数，见 `02` §4。）
2. **工具面消融进反事实靶场**：同一任务在 loadout = 7 / 20 / 50 把下回放，量「选错工具率」。2605.24660 证了效应存在，**没人做逐 harness 的曲线**——而我们有 gym。
3. **集合级（非逐件相关度）工具选择**：《Tools Are Not Islands》(2607.25718) 把工具集效用建成超边预测、MagicSelector (2607.17751) 处理「工具集造成的注意力分散」——**均未落地**。
4. **跨轮指令遵循退化指标**：MTAC-IFBench 还只是论文，没有 harness 面板。
5. **工具检索器的评测偏差**：《Tool Retrievers Are Underestimated》(2609.08327)——检索评测惩罚「有效但未标注」的工具，直接关乎第 2 条怎么做。

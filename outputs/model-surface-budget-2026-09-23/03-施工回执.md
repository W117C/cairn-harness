## 4. 施工中被推翻的三条判断（留档，别第二次踩）

1. **「note 接在 `liveNote` 上就行」——错，且当场测出来了。**
   `liveNote` 经 `pluginContext` 进 skills 块，而**没有插件/技能的会话根本没有那一块**。
   集成测断言「note 进了某个 system 消息」直接红：只看到基础提示那一条。
   这就是本仓反复出现的「**生产者在、消费者不在**」缺陷族的又一次实例——只不过这次是我自己造的。
   改成 `composeTurnMessages` 自己的可选块，并**排在最后**（这句只在超帽那几轮出现，
   放前头会把它要省的那份可缓存前缀自己抖掉）。
2. **「每加一条测例就配一条针脚」——错。** `ms-zero-regression-branch-dropped` 实测**变异存活**：
   「未超预算原样返回」那一支是**快路径**（省两次全量序列化），不是语义分支——
   梯级对未超帽输入本来就是 no-op（丢不动、压不着、note 为空）。
   ⇒ 为它造针脚等于造死针。已换成两条真有分辨力的：梯级 A 被整个跳过（降配**序**是本模块的主张，
   不是实现细节）、固定面漏算基础提示（账与排行对不上）。并在模块里写下「别为这支造针脚」。
   这与上日「拿未标定表测钳制是**无分辨力**的」是同一条教训的第二种形态。
3. **「字节口径的占比可以直接搬过来」——错。** 上日那句「工具占 84%」是**字节**；
   帽按本仓定稿以**字符**登记，同一条装配的字符口径是 **90.5%**。
   两个口径都记进 `01`，否则下一次会拿 84% 去论证「提示词也值得瘦」。

另外撞断一条既有锚点：`request-face-tools-ignored` 的针脚原文
`const tools = face ? face.tools : opts.tools;` 正是本次改成 `declaredTools` 的那一行。
针脚跟着搬、语义一字未动（不改则 `mutate-needles-check` 当场红 1 条——实测出现过，已收）。

  （`glm-session.ts`、`mutate-verify.mjs` 提交前 `git diff HEAD` 逐行确认全是我的）；
  ③ `package.json` 与 `scripts/gate-manifest.ts` 属他人 in-flight ⇒ **不用 `git commit -- <路径>`**
  （那会把别人的在飞改动一并带走），改走 `git show HEAD:<f>` + 插入本行 + `hash-object -w` +
  `update-index --cacheinfo`，提交后确认对方那 24 个文件的 M 状态一字未动地留在工作树里。
- 上日 §2.1 刻意「不并入 `risk.ts`」的那条理由（两会话同改一文件会互相盖掉）本轮同样成立：
  本能力**不碰权限层判据**，与在飞的 shell 绕过修复零交集。

## 6. 明确留尾（不假装收口）

1. **面板装配账未做**（`02` §0 的 C-3）：模型侧现在**能拿到**降配说明（`surfaceNote` system 块），
   但人侧看不到固定面的数——要动 `ipc-protocol` + preload + `app.js` 三个多会话热点，
   与 D7 的「人侧一键还原」同属一批。**在它落地前，`02` §2 的 L1–L2 只能算半兑现**。
2. **core 侧成本未治**：`spawn_agent` 996 + `remember` 968 = 固定面 28%。按规矩 2 本轮未动。
   曾走过的弯路（上日 §7）：想靠关 `autoMemory` 藏 `remember` 省字节——已否决，两轨不同。
3. **每轮重算 vs 会话内冻结**：降配判定每请求重算。工具表中途因 skill 激活而变是既有语义，
   但池子在帽线附近来回抖会让前缀每轮重写。**未做**；`prefixStableChars` 已是现成分子，
   下一格把它逐轮打印就能判读（`00` §6.1 的 cache-churn 门是同一件事的门）。
4. **按位置尾丢是**次优解**（`02` §5 第 2 行已认）**：真正该丢的是「效用最低的那把」，
   位置只是当前唯一**可判定且可解释**的序。反转条件写在 `00` §6.2：gym 里的
   「工具数 × 选错率」消融曲线——这条同时也是「帽值该取多少」的实证出口。
5. **上日 §2.3 的待测假设仍未测**：「prune 会改写前缀中段的旧工具结果 ⇒ 每触发一次把那之后的
   缓存命中打掉」。本轮没碰它（`prefixStableChars` 只量降配带来的抖动，不量 prune）。
   假设一旦成立，「prune 阈值」就不是纯省 token 的开关。
6. 需要联网/凭据的那批断言照旧属「未证 ≠ 通过」，以 `pnpm gates` 的 `UNVERIFIED=` 汇总为准。

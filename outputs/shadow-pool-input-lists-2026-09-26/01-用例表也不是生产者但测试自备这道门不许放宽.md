## 一、用例表为什么不是生产者

`scripts/lib/shell-bypass-cases.ts` 的头一行就写着它是**一份清单、两个观测者**：
`export const UNBOUNDED_PREFIX_WORDS: string[] = ["setsid git push --force", …]` 里的字符串是
**喂给 `evaluate()` / `interceptDestructiveGit()` 的输入样本**。被断言的那句 `why` 是生产侧
`` `git ${sub} 被拦截（…）` `` 插值出来的——清单里那几个字**不是任何字段的出处**。

谓词按内容，不写文件名：`isInputRegistry()` ＝ "≥5 条导出的字符串数组常量" **且** "零导出函数"。
第二个条件是防止把生产者文件吸进影子池（`src/agent/goal.ts` 那种既导常量又导函数的文件必须留在生产者池里）。
`shadowFilesOf()` 把两族合成一张清单，报告里印出各自动词命中数——**两条谓词都要在真仓里有货**，
少一族＝那一族的排除悄悄失效（用例钉住 `kinds === {登记表, 用例表}`）。

## 二、"点名该表"只对登记表有效

上一版有一条：断言所在的 test 文件点名了某张表 ⇒ 那张表对它而言算生产者。
这对登记表是对的（`tests/mutate-verify-gates.test.ts` 判的就是那张表自己产出的 `.why`，实测 4 格纹丝不动），
对用例表是**错的**：测试 `import { CMD } from "../lib/shell-bypass-cases"` 是取输入，不是取出处。
⇒ 现在点名只豁免 `kind === "登记表"`。用例表永远是影子。

于是 `setsid` 那格归位成 `echo-caller-text`。顺带纠正上一版一个更隐蔽的口径：
免计清单现在要求"每格说得出差额（`rawCopies > copies`）"，
而"留着生产者"只约束**仍判 verbatim** 的格子——落到 echo/drift 的格子 `copies` 归 0 是对的，
那两态的意思本来就是"生产侧没有这句"。

### 二·补：这条排除当场造过红——而且**水位没有弹回**

把 `isInputRegistry` 的阈值从 5 抬到 999（＝这条谓词关掉），跑完即删：

| 读数 | 正常 | 关掉这条谓词 |
|---|---|---|
| 影子池 | 认出 2 张 | **认出 1 张**（用例表整族消失） |
| `setsid` 那格 | echo，`原 2 处 → 0 处` | verbatim，`原 2 处 → 1 处` |
| `echo-caller-text` | 3 | 2 |
| 顶包候选·已提交态 | 24 | **24（没弹）** |
| 本面用例 | 38 passed | **4 failed ｜ 34 passed** |

最后一格是这次造红最该记的东西。第 96 页那条谓词的见证方式是"数字从 27 弹回 30"，
这一条**弹不动**：它免计的那格总共只剩 1 份副本，关掉谓词后它变成 `verbatim 1 处`——
既不够格进顶包名单（要 ≥2），也不会掉进 drift ⇒ `MULTI_COPY_CEILING` 对它零分辨力。
⇒ **排除面如果只作用在"本来就掉不进判卷名单"的格子上，水位类反向哨兵必然看不见它**，
只能钉住"态"本身。所以补了一条真仓读数：`shadowCleared` 里必须存在 `kind === "echo-caller-text"` 的格子
（就是 `setsid` 那格），并把它为什么存在写进注释。
诚实边界：这条新断言的"会红"是从上表那次阅读推出来的（突变下免计清单里再没有 echo 态的格子，
另外两条 echo 从来不在免计清单里），**不是**单独隔离出来的突变红——那次突变同时让 `kinds` 那一条先炸，
同一个 `it` 里的后继断言点不到行号。要隔离得把 `kinds` 拆开，本轮没拆。

## 三、我试着放宽 echo 的门槛，然后收了回来

把 `setsid` 归位后，`tests/shell-bypass-composition.test.ts` 又冒出一格：`.why ⊇ "git reset"` 被判 across，
副本数按静态段 `git` 算出 **60 处**。第一反应是"测试自备 ⇒ 直接判 echo，排在 across 之前"——改完确实消掉这一格。
**撤了**，因为 echo 现在那道 `seen.size === 0`（生产侧一段都对不上）保护的正是
**"半真半输入"的文案钉**：只要有一个静态段在生产侧找得到，这条断言就可能真的在指某句生产文案，
漂了必须响。放宽成"测试自备即回显"＝把那一半保护撤掉，是往危险方向缩（规则 60：收窄判定面要反向补一条）。

正确的修法在断言那一侧：`git reset` 本来就该按**回显**来断言——

```ts
const cmd = "git reset --hard";
const named = cmd.slice(0, cmd.indexOf(" --"));
expect(blocked.why).toContain(named);          // 派生值：没有字面量可对，本来就不该有
expect(blocked.why).toContain("合并唯一出口"); // 生产侧那句话由这条钉
```

⇒ 收料面不收它（变量实参），而"哪一支被拦"这件事仍然逐字钉着；生产文案的漂由第二条响。

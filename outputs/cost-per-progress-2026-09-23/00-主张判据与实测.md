# 成本 ÷ 前进（cost per progress）：主张、实测与判据

> 2026-09-23。落地：`src/agent/cost-per-progress.ts` + 门 `scripts/cost-per-progress-check.ts`（CP1–CP4）。
> 读数探针：`measure-cost-per-progress.mts`（同目录，只读物、不写文件）。

## 0. 主张（一句话）

**「花了多少钱」不是决策量，「每前进一份花多少钱」才是**——而本仓的两只手（`deriveProgressBoundaries`
与 `usage` 事件）早就齐了却从没放到同一个读数上；第一次放上去就抓到一处**单位不一致**。

外部唯一的锚点是 SWE-Effi：「未解决的尝试平均消耗 >4× 于成功尝试」（expensive failures）。
但「最后一次前进之后又花了多少」这个数**没有任何公开来源**，而那恰恰是 stop-policy 唯一该切的对象。

## 1. 第一次读数（19 份真实录制，可复跑）

| 项 | 值 |
|---|---|
| 绿跑「每前进一份」的 token | n=11 min 5,787 / median 14,385 / max 46,504 |
| 红跑 | **两条都是零 verified 边界** ⇒ 比值不可测；它们的整笔主面开销就是死跑成本 **68,535** 与 **24,067** |
| 红/绿比值 | 68,535 ÷ 14,385 = **4.77×**（n=1 红，仅作与外部 >4× 的对表，不作结论） |
| 缓存分列上报 | 19/19 带 `cacheRead` ⇒ 之前算的 51.5% 命中份额是全覆盖的读数 |
| 计价面 | `UsageEvent` **没有模型字段** ⇒ 主会话花销无法换算美元；只有 worker 侧记了 `routeModelId`。⇒ 本模块今天只报 token，**不报钱**（不拿缺省价凑一个数） |

## 2. 抓到的那处单位不一致（这才是本格的真产出）

`deriveProgressBoundaries` 按定义只算主面（源码注释：*Worker events cannot close main-stream pairs*），
而"整跑 usage 求和"这种最自然的分子写法会把 worker 的开销算进去。实测：

| 录制 | 主面 tok | worker tok | verified 边界 | 朴素比值 | 同面比值 |
|---|---|---|---|---|---|
| `ga-strategy-2026-09-20/fanout` | 117,554 | 62,431（27 条 usage 里 20 条带 agent_id） | **0** | 不可测（分母 0）| 不可测 |
| 合成混合样本（CP1 用） | 3,300 | 12,900 | 1 | 16,200 | **3,300** |

⇒ 同面与否差 **4.9 倍**。任何按朴素比值做的"这轮太贵就停"决策，实际是在惩罚"多派了一个 worker"。

顺带一条同样重要的：**四条成功的 fanout/supervise 真实录制里 verified 边界全为 0**
（worker 不闭合主流配对 ⇒ 按定义为 0）。所以「零前进」有两种完全不同的成因：真的没前进（那条红跑），
与**这条面根本量不到前进**。把两者混成一个数，就是下一条"假绿/假红"的成因。
⇒ 判据必须把 `unmeasurable` 与 `零前进` 分开，且均值只能从可测样本取、跳过的必须点名。

## 3. 判据

| 判据 | 判什么 | 失效条件（挂在可判读的事实上） |
|---|---|---|
| CP1 分子只取与分母同的一面 | 主面/worker 拆分与 `excludedWorkerTokens` 必须原样点名 | 出现"主面+worker 合并分子"的实现 ⇒ 本条红 |
| CP2 比值不许混进 worker | 同一份输入两种算法差 4.9 倍，钉的是"数出来的是谁" | `usage` 事件加上模型/归因字段后重定口径 |
| CP3 零前进是不可测（不是 0/Infinity） | 真实红跑上 `spendAfterLastBoundary == mainTokens == 68,535` | 若主会话能计价 ⇒ 同一条改判美元 |
| CP4 均值只从可测样本取且点名 + 分母覆盖读数 | 覆盖体检要求"至少一条成功跑取到边界、至少一条失败跑零前进"，否则判据自身红 | 冻结语料扩到含 worker 归因的成功跑 ⇒ 覆盖读数会变，判据不变 |

语料分工：真实录制复用 `fixtures/no-progress/real-*`（已冻结，NP5 钉着）；
跨归属那一格真实语料里没有 ⇒ 门内**合成**一份形状样本，只喂纯函数、不进冻结面
（合成物不是"事实"，冻结它会让人误以为那是录制）。

## 4. 本轮我自己的两处错（同一族：跑起来了 ≠ 测到了）

1. **合成样本压根不产生 verified 边界**：CP2 第一版量出 `比值=null`。原因不是策略，是我少写了一次
   **成功的写**——前进边界要「完成过工作 + 新的成功证据」。补 `edit_file(ok)` 后才闭合。
   ⇒ 记一条可复用的构造知识：合成 verify-only 事件不足以构成前进证据。
2. **CP4 的判据吃不到输入**：`meanSkipsUnmeasurable(rows)` 内部自己重算再自己比 ⇒ 自检探针
   「造不红」（4/5）。改成吃**读数** `got` 之后 5/5。这是上一格（NP3/NP4）同一个坑的第二次犯，
   说明它不是偶发：**凡判据内部重算，反向对照必然只能"自己证明自己绿"。**

## 5. 留尾（不假装收口）

1. **没有消费者**：本模块今天只是读数。要接的是 supervisor / goal 的 stop-policy（`goal.maxUsd` 那条链），
   而 `agent-runner.ts` / `loop.ts` / `orchestrator.ts` 都在另一会话的在飞改动集里。
2. **钱算不出来**：主会话 `usage` 无模型字段 ⇒ 只能说 token。要真说钱，得给 `UsageEvent` 加模型归因
   （`src/events/index.ts` 在飞）。这是"能不能对本仓的使用者报成本"的**根因缺口**，不是本模块的取舍。
3. **分母太稀**：19 份里只有 11 份绿跑取得到 verified 边界，且每份平均 1 条边界 ⇒
   「每前进一份花多少」的方差今天主要来自"一条跑里只有一两个前进点"。要收窄需要
   多里程碑式长任务（与 §5 留尾里"需要 ≥10 轮冻结 case"是同一前置）。
4. **红样本 n=2**：4.77× 那个数只能对表外部 >4×，不能当本仓基线；等 §3 那条 stall 可评分之后重算。

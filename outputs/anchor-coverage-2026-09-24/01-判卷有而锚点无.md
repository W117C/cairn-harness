## 一、这一页反对的是什么

本仓有一台变异表（`scripts/mutate-verify.mjs`，数百条锚点）和一批门禁，专门拦「代码写了但判卷
没对准」。但**反过来那一半从来没被查过**：一支判卷写了、产品也改了，可"拆掉那行必须有人红"
这件事本身没有任何尺——判卷存在 ≠ 判卷有分辨力。今天已抓到的三例都是这一格：

- 能力 33（记忆写入脱敏）：8 条判卷，**0 条锚点**；
- env 消毒两支（process 缺省 / hooks 基础）：5 条判卷，**0 条锚点**；
- 能力 19 L0（投影出口统一中和）：9 条判卷、五个入口各钉一条，**0 条锚点**。

前两条本轮已补（`852798c`），第三条是本页要记的那台机器**当场又抓出来的一格**。
这三例的共性不是"忘了写锚点"，是**没有任何面会把"某支判卷零锚点"这件事摆到眼前**——
所以修法是造那台机器，而不是记一次待办。

## 二、机器

`measure-anchor-coverage.mts`（只读：不改盘、不跑测试、不 spawn 可变进程）。两面取料并排：

1. **判卷面** = `tests/**.test.ts`；**锚点面** = 变异表里每条锚点的 `test:` 字段；
2. 反向还查一条：锚点写的 `src:` / `test:` 路径**在不在盘上**（未入库/被搬走的锚点是另一族假守护）；
3. 输出只列「零锚点的判卷」并按它 import 的产品面数降序——**不给加权分**：
   纯函数/投影类判卷本来就不需要锚点，"要不要钉"是判断题，机器只负责把格子摆出来。

三态退出（缺一即红，不许把"没扫到"读成"没问题"）：

| 态 | 触发 | 退出 |
|---|---|---|
| 没扫到 | 判卷面为空，或锚点表解析出 0 条 | 1 |
| 认不出 | **两种独立取法的条数不一致**（手写解析 vs 脚本自己 `--list`） | 1 |
| 有料 | 正常列零锚点清单 | 0 |

「认不出」这一态当场就起作用了：第一版直接拿 `--list` 的行数当条数，结果报
「解析 895 条 vs 印出 896 条」——真因是**有一条锚点的 desc 里带换行**，一行被印成两行。
修法不是把判据放宽，是改成「只数带 ≥3 个 tab 字段的首行，续行单独报出来」。
这条坑值得记：**行数 ≠ 条数**，凡是拿行数当条数的读数都要配一个独立第二来源。

自检每次跑都注入（不是一次性）：正控 = 已知有锚点的判卷若读到 0 ⇒ 取料面断了；
负控 = 一个不存在的判卷路径不得被算成有锚点。

**仍开着的一格（本页的 C2）**：泛转义那一侧（把名单换成 `/<[^>]*>/` 那种"全转义"假防护，

## 六、覆盖棘轮自己的边界（本页实测两次踩出来的，写下来比改措辞蒙过去有用）

`claim-coverage.mts` 抽判据行是**两层措辞筛**：行内先要含「必红 / 即红 / 当场红 / 立刻红 / 必须红」才会被抽出来，
抽出来之后还要再含 `TODAY` 那串（`今天必红` / `现在就红` / …）才算 today 类；**future 类只报不拦**。
本页第一次写 C1 用了「当场红」⇒ 它被归成 future（机器不要求它登记）；第二次改成「现在就红」⇒
**整行干脆不被抽取**。两次我都在 `verify-claims.mts` 里把 C1 的登记临时改名（造相），覆盖机仍 exit 0——
也就是说这条棘轮对"意思是对的、措辞不合表"的行**零信号**（它自己的注释也这么写着，本轮是第一次真撞上）。

处置（刻意不做的两件事 + 一件真做的）：
- **不改 `TODAY` 那张措辞表去就我的句子**——那条表是判卷面，为凑一行文档去放宽它，等于把筛子改成让当前内容通过；
- **不把 C1 改写成"必红"句式骗过抽取器**——C1 断言的是"已闭合"，硬写成缺陷形状就是造假；
- 真做的是：C1 的可复核性交给 `verify-claims.mts`（它无条件跑所有登记项，不看措辞），
  本页只在 C2（真·缺尺）那一行用 today 句式。顺带把这条边界记在这儿，
  下一个人撞上"行没被抽到"时不必再重走一遍我的两次试错。

反向补一次造相，免得本节读起来像"这台棘轮没用"：把 **C2** 的登记临时改名（`37:C2` → `37:CX`）后跑
`claim-coverage.mts` ⇒ **exit 1 且点名 `C2=**无理由**`**；还原 ⇒ exit 0，还原后与被改前**逐字相等**。
所以：措辞对得上表的行，拆掉登记一定红；对不上的行，机器根本不看见——这一条差异就是本节存在的理由。

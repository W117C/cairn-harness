### 补记（2026-09-29 深夜）：同一支 zsh 枪打第二次，这次打的是提交信息

上面那条记的是 `"$rep_EXIT"` 被读成一个变量名（静默少跑半份 A/B）。这一次的形状更隐蔽：
`printf '%s\n' "第 196 页…" "…（本地暂存②–⑪，`2a62291`…`f36e021`）…" > /tmp/p196-msg.txt`——
格式串是单引号，**每条正文是双引号**，于是 zsh 把正文里的反引号当命令替换真的执行了。

- 症状：终端多 7 行 `command not found: 2a62291` / `-t` / `it` / `--` / `6` / `9`，`MSG_EXIT=0`，提交照样成功。
- 损害：7 个片段从提交信息里静默消失；树内容、判卷、类型检查、变异机全都不受影响 ⇒ **没有任何一道门会替我喊**，
  只有把消息回读一遍才看得见。但「没造成破坏」这一格要说准：**这些片段被 zsh 真当命令执行了，其中两格是无声的**——
  反引号里的 `git diff --numstat` 当时 cwd 正好是那棵干净的簇树 ⇒ 跑了、输出为空；
  反引号里的 `REDKINDS=` 被当成空赋值 ⇒ 连 `command not found` 都不留。
  换成一个能写盘的片段（`git checkout -- x`、`rm -rf …`）就是同一台机器上的**真实执行**，
  所以这条枪的危险度不由"这次只坏了消息"决定，由"反引号里的东西会被执行"决定。
- 抓到它靠的是回读整条正文（`git log -1 --format=%B`），不是 subject（坏的就坏在正文，只看 `%s` 会以为没事）。
- 修法与自证：`git commit --amend -F <Write 出来的文件>`，amend 前后各取一次 `HEAD^{tree}`
  （改前 `b5226d6617662f3ac50d60fe1878366820bd4e9c`＝改后同一个）＋ `git show --numstat --format=` 仍是 52 增 0 删
  ⇒ 只换了消息、没动内容。**前提是这笔还没公开**（簇在私有 ref `refs/dsh/cluster-p169-196`，从未 push）。
- 硬规矩：**长参数（提交信息、页正文）一律由 Write 落到文件，再 `git commit -F`，不经 shell。**
  这条在 09-27 已经记过一次（那次是 `-m` 里的反引号被执行），当时的修法是"整串用单引号"——**不够**，
  因为多行正文几乎必然写成逐条双引号。已在用户记忆 `feedback-zsh-glob-flags` 里补成第二条形态。

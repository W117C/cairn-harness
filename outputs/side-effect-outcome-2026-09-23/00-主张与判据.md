# 00 主张与判据（能力 17 · 结果未知三态 / side-effect outcome · 2026-09-23）

> **一句话**：今天 `ok:false` 这一个布尔里**装着四件语义相反的事**——「没动手」「动了手但失败」
> 「半跑」「结果未知」。模型唯一的行动选项是"重发一次"，而**重发对第一条安全、对第二三条是重复副作用**。
> 本页把「动没动手」从**文案**提升成**契约字段**，并给出崩溃后如何从既有事件流推出"结果未知"。
>
> **提案，不是施工记录**：本轮未动一行 `src/`，未 commit。实弹读数与复跑命令在 `01-实测与回执.md`。
> 编号依据：HEAD 最新一笔 `f6dcf2b` = 能力 15，`outputs/stale-view-guard-2026-09-23/` = 能力 16，本页 **能力 17**。
> 两页同族：都是**"事实已经在手里、缺的是把它变成字段"**——16 管"模型视图 vs 盘"，17 管"这个动作发生了没有"。

## 二、为什么这是 agent 共同的问题（外部读数）

- **《避免 failover 时重复工具调用》**（Samuel Fajreldines, 2026-08）给出本页正好需要的那句话：
  > "A timeout after sending a request is an **unknown state, not proof that the action did not happen**."
  > "The executor records `actionId` **before** applying the effect and returns the known result when the same action arrives again."
  ⇒ 业界形状 = **执行前记意图 + 按调用 id 对账**。本仓**前半已经发货**（G3 段末），缺后半。
- **《AI Agents 说到底就是分布式系统》**（TikTok SRE 负责人，InfoQ 2026-09）：agent 的可靠性问题
  本质是分布式系统的老问题——at-least-once / at-most-once 必须**显式选**，而不是由超时和重试的偶然行为决定。
  本页 G1 那条"由 `ok:false` 一个布尔默认决定"正是它点名的反模式。
- **arXiv 2609.20804**（harness 实证）：所评架构在写后有自动 lint 一拍，但**同样没有**重试/幂等面，
  作者自陈未隔离界面属性（§6 Limitations）。⇒ 外部只支撑"这是公认缺口"，**不支撑任何收益百分比**；
  本页收益全部押在本地实弹（`01` §一）。

## 三、设计：四层，按依赖排（各答「长在哪 · 谁持有 · 为何不是别层」）

### L0 名单归一：`src/tools/base.ts` 里一张底表

`SIDE_EFFECT_KIND: Record<ToolName, "none" | "write" | "exec">`，与 `TOOL_NAMES` 同源
（`TOOL_NAMES` 的注释已经立了"加一个工具只改这一行"这条纪律，G4 那 6 份名单正是它漏守的下场）。
现有 6 个谓词**改成从这张表派生**，不改语义。

- **长在哪**：静态契约层（与 `TOOL_NAMES` 同文件）——**不是** `permissions/`，因为权限、无进展、
  工具面裁剪三处都要用，放权限层会让另外两边继续抄表。
- **必须行为不变**：`tests/gate-audit.test.ts` 的 `GATE_LAYERS` 穷尽断言 + `no-progress` / `worker-report`
  既有断言当场盯住；任一派生视图改了判定 ⇒ 红。**不许借归一之名改分级。**

### L1 契约：`effect?: "none" | "began" | "unknown"` 上到 `ToolResult` 与 `ToolError`

**这是本页的架构判断**：字段必须由**工具**写，不能由 loop 猜（G1）。

- `ToolError` 增加可选第二参：`new ToolError(msg, { effect: "none" })`；缺省 `"none"`——
  因为抛 `ToolError` 的既有位置**全都在动手之前**（参数校验、0 匹配、多处匹配、权限、上限）。
- `run_shell` 三旗映射（`finish` 一处即可）：正常退出且 `code!==0` ⇒ `began`；
  `timedOut` / `cancelled` ⇒ `began`（**半跑**，命令可能已做副作用）；`spawnTracked` 的 `error` 事件
  ⇒ `none`。⚠️ 最后一条**不许写成"一定是 none"**：Node 的 `'error'` 也会在已成功 spawn 之后触发
  （杀进程失败等），那种情形写 `none` 就是**过度声明**——判据里必须含"spawn 之后才 error ⇒ `began`"
  这一支，否则这一格是自己造的假绿。（本轮未实弹此分支，见 §六-5。）
- `write_file` / `edit_file`：`writeFile` **之后**的任何失败 ⇒ `began`。
- **为什么不是异常类区分**：`ToolError` 之外还有裸 `Error`（`write_file` 就抛裸 `Error`，
  见 `outputs/gap-fix-proposal-2026-09-23.md` 记的同一条不一致）——用类型区分会漏；
  用显式字段则**漏写=编译期红**（`ToolResult` 上设必填，配合 L0 的表）。

### L2 崩溃对账：不新增事件类型，从既有流推 `unknown`

`replay` 时：`tool_call` 有、`tool_result` 无 ⇒ 该调用 `effect = "unknown"`（若 L0 判为非副作用 ⇒ `"none"`）。
持有者 = `src/agent/context.ts` 的 `closeDanglingToolCalls`（它本来就在扫这个形）。

- **为什么不新开 `tool_begin`/`attempt` 事件**：`tool_call` **已经**在执行前落盘（§一 末），
  再开一个承载面违反 G7 纪律（**没证它配得上承载面就不开位**）。这是"免费车"形状——
  与能力 13（压缩已打断前缀那轮顺手裁剪）同一个思路：**别为一个已经存在的事实再要一份存储**。
- **为什么不在 `ToolResult` 上记 `attempt` 计数**：那是策略，不是事实；先有 L1/L2 的事实面，
  计数才有意义，否则只是把猜测做成另一个字段。

### L3 策：按档给**相反**的建议（detection 先行，enforcement 默认关）

| `effect` | 模型可见文案（追加一行） | 对 `[repeat]` 棘轮的影响 |
|---|---|---|
| `none` | 「这次没动手，改参数重发是安全的」 | 维持现阈值（连续 3 次同类失败才提示） |
| `began` + 超时/取消 | 「**前半段可能已经生效**，先去盘上确认，别原样重发」 | **阈值降到 1**：半跑之后原样重发一次本身就是事故，不该等到第 3 次 |
| `unknown`（崩溃恢复） | 改写 `danglingToolCallNote`：非副作用仍按现文案；副作用类改成「结果未知，**先验再动**」 | — |

三条决定，都不是审美：

1. **`effect` 只进事件字段，不进 `output` 正文。** 挂两条已发货定案：
   `outputs/reproducibility-2026-09-23`（毫秒漏进 `ToolResult.output` 就是被这扇门抓到的）与
   `outputs/prefix-churn-2026-09-23`（改写已发出历史 = 打断前缀缓存）。
   模型可见的那句**只在非 `none` 档追加**，`none` 档输出逐字不变（零回归）。
2. **只对 `began`/`unknown` 收紧，不对它们设硬拦**：本仓没有沙箱外事务面，拦不住已经发生的半跑；
   能做的就是把"别原样重发"这句话用对档位说。
3. **enforcement（例如"半跑后同 action 直发不派生"）默认关**：`01` §五 列了三条未证，
   尤其"崩溃后重发确实造成过二次副作用"这一形**本地一例都没有**（N3=0、N6c=0）。

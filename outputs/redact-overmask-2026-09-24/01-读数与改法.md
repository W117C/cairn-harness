# 相对路径不再被脱敏吃掉（任务 #4 收口，2026-09-24）

## 一、缺陷与它的另一半

`c27b6d8` 把 rule 59 那半修了（候选字符集去掉 `=`、以 `/` 开头的候选否决），
但**只否绝对路径**。而 agent 输出里的路径绝大多数是工作区相对路径，于是它们整段被吃掉：

```
read outputs/ga-strategy-2026-09-23/measure-overmask.mts   →   read outp****.mts ok
opened fixtures/no-progress/session-2026-09-20T04-11-52.jsonl → opened fixt****.jsonl
worktree .agents/worktrees/dsh-anchor-3f/src/main.ts        →   worktree .agen****.ts
plan docs/superpowers/plans/2026-09-20-goal-plan-modes.md   →   plan docs****.md
```

根因是**判据的单位**：整串熵。几段可读名字用 `/` 连起来、再夹一个带日期的段，
聚合熵就轻松过 4.0 ⇒ 一条路径拿到"密钥"的处置。
后果不是"少一行"：模型拿不到路径 ⇒ 只能重跑那条命令或猜文件名（返工 + 白花 token），
而这是一条**安全判据在静默制造不可用**。

## 二、改法：含 `/` 的候选按段判，且只掩那一段

`findHighEntropyTokens` 对含 `/` 的候选改为：逐段算熵，**只有某一段自身**（长度 ≥ `minSegmentLength=12`、
含字母与数字、熵 ≥ threshold）够格才算密钥，并且 `secret` 就是那一段 ⇒ `mask` 只吃它，
目录与其余段逐字留下。其余候选（不含 `/`）行为一字未变。

`write src/config/xk39Fd8Qz2Lp7Vm4Rt6Bn ok` ⇒ `write src/config/xk39**** ok`
（**两侧都有用例**：路径整段可读 + 路径里真藏高熵串仍被擦；只测前一半等于允许"一律放过含 `/`"蒙过。）

## 六、同一族错的第三格：带 `-` 的标识符与 `sha512-<digest>`（任务 #6，量完才动）

第一版把 §二 的分段判据只挂在 `/` 上，于是这两条仍然被吃：

```
209fbeed34dfee992102d511233f0bf41fea3127 blob docs/.../2026-09-18-r1b-renderer-subtraction-design.md
resolution: {integrity: sha512-9f2b1c3d…}                     ⇒ resolution: {integrity: sha5****}
```

真凶不是 blob id 本身，是**文件名**（`2026-09-18-r1b-renderer-subtraction-design` 熵 4.062）与
**带算法前缀的校验和**（4.129）——同一条"聚合熵"的错，只是这次的分隔符是 `-`。
所以判据改成：带 `/` **或** `-` 的候选一律按段判；纯小写 hex（≥24）段与 token 都不由熵分支作证
（40 位 hex 的香农熵上界恰是 log2 16 = 4.0 ⇒ 随机 SHA 一半会撞过阈值）。
hex 凭据那一半不漏：`api_key=<32hex>` 由 3502d7c 的**键名上下文**规则接住。

# import 面把判卷里的源码片段当成真边（假红）· 2026-10-02

## 现场

上一笔 `ed8a444`（held-out 隐藏验收）落库后跑认证：22 道门面里 **`head-import-check` 红**（exit=1），
全量判卷 `Test Files 1 failed`（`tests/head-import-face.test.ts` 的真仓那一格）。

尺报出来的两条悬空：

```
tests/cart.js.ts
tests/discount.js.ts
```

这两条**不是**缺陷，是尺自己把我写的判卷读错了。`tests/eval-heldout.test.ts` 里有三段 `String.raw` 包着的
JS 源码——那是判卷要写进临时靶子的**数据**（隐藏验收的三态对照：原样／修对根因／哄绿），
其中一行正好是行首的 `import { subtotal } from "./cart.js";`。

## 根因与为什么现有防御没挡住

`scripts/head-import-face.ts` 用正则抽 import 边，边界规则是「行首或 `;` 之后紧跟 `import`，且这条语句以
`from "…"` 收口」。文件头上就写着这一族：「判卷里的假源码字符串被当成真边（47 条假红那一族）」——
上一版靠**语句边界**挡住了 `const fake = 'import { a } from "./todo";'` 那种**单行内嵌**写法。

我这次撞的是它的下一个变体：**多行模板字面量里的整段源码自带行首**，
边界规则看不见「这段文字是不是数据」，于是它长得就是一条合法语句。挡不住不是边界规则写坏了，
是那条规则**只解决了同族的第一个形状**。

## 修法：涂白，不豁免

`HEAD_DANGLING_WAIVERS` 是空的（设计上就该空：豁免表一填就变成「尺不许喊」）。
把 `tests/cart.js.ts` 登进豁免表是最省事也最坏的走法——那等于让尺以后对任何嵌在判卷里的源码都闭嘴。

改成加一只**等长涂白** `blankDataSpans`：模板字面量整段（含 `${}`）在非换行字符上换成空格，
偏移与行号一律不漂，然后把 `parseImportStatements` 与 `exportedNames` 两只取料口都改吃涂白后的文本。

判卷分四格（`tests/head-import-face.test.ts` 新增一个 describe）：

| 用例 | 钉的是哪一半 |
|---|---|
| 前提成立：那句假 import 确实在行首 | 防止判卷测一个不存在的形状 |
| 模板里的源码不算边，模板外的真语句照旧算 | 修假红，同时不许修过头 |
| 导出一半也不认模板里的假源码 + 七种真 export 仍认 | **反方向**：涂过头＝假绿 |
| 等长涂白（长度与行数不变） | 报告里那句「第几行」还要指得对 |
| 真表自证：那份判卷今天贡献的边里没有 cart.js | 现读闭环，不靠合成输入独证 |

## 一次自己差点造成的假绿（记下来，别学）

第一版我图快用 `ts.createScanner` 单趟扫词。**错**：裸 scanner 不认正则字面量，
把 `/from "…"/` 里的引号当成字符串起点 ⇒ 从那以后的整段文件被读成字符串并涂白，
`exportedNames` 于是看不见任何导出。量出来的结果是 `834ba3a` 那笔的缺失符号
从 **1 条炸成 300+ 条**——不是回到旧行为，是造出一个更坏的方向（假绿）。
改成 `ts.createSourceFile` + AST 走节点（解析器认得正则字面量）后，同一格读数回到：

```
事故 834ba3a：悬空 4 条 = provider-runtime | run-attachments | run-request | capabilities
              缺符号 1 条 = src/agent/glm-session.ts:SessionTransport
HEAD 现读    ：悬空 0 ／ 缺符号 0 ／ import 边 3302 条 ／ 文件 552 个
```

「事故那一笔必须整条咬住」那条旧判卷在这里就是**非恒真的证人**：涂白若吃掉了真边，它当场红。

## 代价（同温 A/B，不是推算）

同一棵树、同一输入、间隔几分钟，各自复跑：

| 版本 | 趟次 | 门单价 | 结果 |
|---|---|---|---|
| 涂白关（旧行为） | 0.63 / 0.77 | **中位 ≈0.70s** | ❌ 2 项（正是那两条假悬空） |
| 涂白开，无快路 | 1.22 / 1.46 / 1.51 | ≈1.46s | ✅ |
| 涂白开 + 反引号快路 | 1.17 / 1.18 / 1.33 | **中位 1.18s** | ✅ |

⇒ 涨价 **+0.48s（0.70 → 1.18）**。快路（`text` 里没有反引号就不建 AST）收回约 0.28s，
剩下的就是 552 个文件里真有模板字面量那部分必须付的解析钱。

门预算原值 1400ms 是 667ms 的两倍档；1.18s 只剩 18% 余量 ⇒ 负载一动就红，
而红的是这道门本身没问题的一格。按同一条「两倍档」规矩改到 **2400ms**，注释里那句实测同步更新
（`预算与注释实测成对` 那条新判卷钉的就是「只改预算不改读数」这一格）。
认证门面 22 道预算总和 56500 → 57500ms（帽 60000ms，仍余 2500ms）。

新增判卷时我先把帽写成 `≤6`，理由是「今天真有几道没写读数」——那是我从旧页面**记**来的话，
现读一量是 **0**（22 道全带实测）。计数类不留余量，帽改成 0 并补一条分母自证。
这条自己也登记在册：**帽的值必须来自这一趟的读数，不来自上一笔的散文**。

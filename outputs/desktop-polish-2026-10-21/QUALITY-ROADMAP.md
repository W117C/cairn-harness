# 持续质量路线

目标保持完整：沿用户指定的 dsh-claude-style 与 DeepSeek Harness 交互方向，持续完善桌面、工具过程、侧栏、各类面板及核心代码质量。当前证据见本目录 REPORT.md；此前主题接入及交互改动见相邻的 desktop-repair、desktop-official-interactions、desktop-hardening 工件。一次测试通过不构成整体目标完成。

| 面向用户的验收 | 当前证据 | 下一步 |
|---|---|---|
| 统一外观，工具过程可收放，侧栏/面板互不挤压 | 主题接入、亮暗截图、交互脚本覆盖折叠/展开/聚焦/分屏/窄窗 | 继续检查设置、授权、错误恢复的完整键盘路径和可访问名称 |
| 长会话更新不反复重画历史，最新消息动作仍准确 | 400 轮因果对照、完整历史、回放/重跑实测 | 扩大历史和会话列表规模，先测再决定是否引入增量投影或其他机制；调查长尾停顿 |
| 弹出面板只加载所需工作区，原生页面不挂错窗口 | 实际路由资源记录、宿主窗口归属及销毁检查 | 补完整产品 IPC 的后台恢复、多窗口切换和隐藏/重现路径 |
| 终端在面板改变尺寸后仍正确换行、运行和退出 | 真实 PTY 中文输出、退出排空修复 | `terminal-host.ts` 仍明确留有 resize 通道，先用 stty/实际列宽复现尺寸问题，再贯通前后端 |
| 文件面板输入和预览容易发现、失败可恢复 | 当前截图的文件面板仍以路径输入和文本区为主 | 核对路径入口、文件选择、加载/失败反馈，沿官方交互改进，并实测真实工作区 |
| 用量、权限和运行状态来自事实 | 本轮修复无 usage 的概览；已有权限与标记回归 | 检查部分用量返回、跨会话汇总与取消/恢复时的状态边界 |
| 核心服务在并发与异常时可靠 | 第二次核心全量通过，首次 LSP 并发取消观察曾失败 | 优先重现 LSP 首次失败并记录 RPC/取消回调先后；未找到根因前不以单文件绿宣告修复 |
| 可交付证据与实际代码一致 | 本轮 diff、文件指纹、日志、运行时 JSON 与截图 | 在隔离、可归属的提交上进行完整 gates/HEAD 认证；发布与平台覆盖另取实证 |

这张表是后续工作顺序，不把待测风险写成已确认缺陷，不把已完成的一小批替换成整个目标。

## 2. 跨仓结构性发现

1. **「模型写代码调工具」（code-mode/PTC）已成行业趋势**：DSH(ptc-runtime/run_code)、codex(code-mode 四 crate)、opencode(tool/code-mode.ts) 三家独立收敛到同一设计。
2. **pi-ai 成为事实上的 provider 目录标准**：DSH 官方适配器 `dsh-llm-pi-ai` 直接接 pi 生态目录；oh-my-pi 正是 pi-mono 的工业化 fork——两仓构成上下游。
3. **竞品兼容即获客**：DSH hooks 桥直接吃 Claude Code/Codex 的 hooks.json，子代理可委派给 Codex/Claude Code 进程；codex 有 external-agent-migration crate。harness 层正把对手生态变成自己的能力面。
4. **压缩路线分化**：DSH=摘要+工具结果预剪；codex=本地+远端双路含图片预算；omp=**位图渲染给视觉模型读回**（最激进）；opencode=compaction+overflow+reminders。
5. **架构治理 DSL 化**：DSH verify-脚本族、ZCode architecture-policy.yaml、omp DESIGN.md「写给 AI 看的约束」——仓库自我描述正在从文档变成机器可校验政策。
6. **UI 三条技术路线**：Rust ratatui（codex 991 文件）/ TS+SolidJS+opentui（opencode）/ React-webview+gRPC（cline）/ 共享 Web 资产复用（DSH、ZCode 用 Web 复用入桌面）。
7. **多代理全部内置化**：codex multi_agents_v2、DSH subagent 族+workflow fan-out、cline agents 包、opencode Task 工具、DSH 甚至能跨 harness 委派。
8. **会话持久化两种范式**：append-only JSONL 邻接迁移链（DSH v0→v2、codex rollout+reverse-scanner）vs SQLite/Effect 存储（opencode V2、omp mnemopi）。

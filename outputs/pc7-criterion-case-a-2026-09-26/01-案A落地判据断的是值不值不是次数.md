## 一、判据搬家：门与自检必须共用同一只（门的头注本来就这么写着）

新纯函数住在 `src/agent/prefix-churn.ts`：

```ts
export function amortizationIsPaidOff(x: AmortizationExchange): { ok; priced; saved; paid; shortfall } {
  const saved = x.rewroteOff - x.rewroteOn;
  const priced = x.outputOverInput > 0;                       // 没价 ⇒ 线算不出，不许退化成"只看省没省"
  const paid = priced ? 摘要输入增量 + 摘要输出增量 * x.outputOverInput : Infinity;
  return { ok: priced && saved > 0 && saved >= paid, priced, saved, paid, shortfall: paid - saved };
}
```

**顺带修掉一条真缺陷**：`--self-test` 的 PC7 那条以前是把手抄的一份谓词写在自己体内
（`const holds = a.compactions >= 2 && b.compactions < a.compactions && …`）。
⇒ 判据改了，自检不会跟着改，它继续"证明"一条已经不存在的规则（门的头注第 11 行明写着"门与 `--self-test` 共用同一只"，
这条今天才真的成立）。现在它调 `amortizationIsPaidOff`，并且**两侧都证**：省不过线必须红、省过线必须不红。

比值不写死：`worstCalibratedOutputRatio()`（`src/routing/pricing.ts` 新导出）只扫 `calibrated: true` 的行取最不利者。
今天 = 8.33（`gemini-cheap` 2.5/0.3）。这样加一档更贵的输出价 ⇒ 这条线自己收紧（机制判据挂现状不挂抄本）。

## 二、撤掉的那半句要有名字（规则 57：「刻意不做」得留名与锚点）

`why` 里现在写着：**刻意不再断「压缩次数不得升」**，理由与实测同页——
关臂到第 7 对已没空档、开臂还能继续压 ⇒ 次数 +1 与省 7,663 字符**同向**发生，
断"次数不升"实际是在要求多付一次重写。次数仍然印在 detail 里（`压缩落在第几对`／`摘要实测花费`），但它是读数不是判据。

`ok` 那行剩下两半：`a.compactions >= 2`（样本分辨力，红的是门自己）＋ `deal.ok`（这笔交换值不值）。

## 四、这次过线只有 5% —— 写下来，别让它被读成"解决了"

`7,663 − 7,283 = 380`。摘要正文长 5%、或某轮多压一次，这条线就会翻红。
三条边界（第 106 页立过，这页不动）：GLM 三档仍是占位数 ⇒ 真钱等 #16/#17；只测了 8 轮那一格；
**行为质量仍未量**（`compaction-cost` 头注原话：只量缓存代价 ⇒ 缺省关）。所以本案 A 只裁了"字符经济学"这一半，

## 3. 我自己在这一格里犯的三处错（同一形状：写出来了 ≠ 测到了 / 跑起来了 ≠ 判到了）

1. **门跑的是 callback 版 `readFile`**：`import { readFile } from "node:fs"`（不是 `node:fs/promises`）
   ⇒ NP5 抛 `The "cb" argument must be of type function`。表现是"这条判据红"，其实是门自己坏了。
   ⇒ 归因口诀：**抛异常的门不是红门**。
2. **判据吃不到输入 ⇒ 它的反向对照只能是句空话**。NP3/NP4 第一版把场景硬编码在判据函数里，
   `--self-test` 只能"自己证明自己绿"（造不红 4 只）。改法：判据改成吃**读数**
   （`normalizationDiscriminates(readings)`），门跑 `read*Signals()`，自检喂假读数 ⇒ 11/11 才成立。
3. **一条针脚存活**：`np-corpus-freeze-not-checked` 钉在门里那条规则的 `ok` 上
   （`ok: v.ok && …` → `ok: true`）——冻结表与语料一致时它与正确实现**逐字同结果**，测试照绿。
   换钉到纯函数 `corpusFreezeIntact` 的两个分支上（不查"不在表上" / 不查"哈希不符"）才两条都能杀。
   ⇒ 立一条可复用的规矩：**针脚必须钉在"能被观测到的那只函数"上**；判据函数的组装层（读文件、拼 ok）
   往往对结果没有分辨力，能被分辨的是它的输入判据。

## 4. 未接与留尾（不假装收口）

1. **零消费者**（本格只交判据与语料）。挡路的是两处别人的在飞改动：`src/agent/loop.ts`、

   （`verdict.rule === "same_action_error_x3" ? A : B`）⇒ 任何新增规则值都会落进 else 拿到**错误措辞**。
   接线那一格必须连这只三元式一起改，不能只加一条规则。

   要做得先动 `src/events/index.ts`（在飞）。

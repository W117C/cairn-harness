# 无进展检测（stagnation）：读物、缺口与本地基线率

> 方法纪律照旧：外部机制一律**双向核验**（生产者与消费者两端都在才算已有）；本仓的缺陷族叫「两头断」。
> 行号只作该日快照定位，不作为找代码的唯一坐标。

## 0. 结论先行

1. 「规则型卡死检测器」**不是新能力**：OpenHands 的 `StuckDetector`（5 条规则、默认开、不花模型 token）与
   Gemini CLI 的 `loopDetectionService`（同工具调用 ×5、内容块 ×10、30 轮之后才上 LLM 判环）都已 shipped；
   本仓也已有 `src/agent/stuck.ts`（取其中两条 action-shaped 规则 + 静默超时），且**两头都接**：
   worker 走 `triggerStuck` → `agent_status waiting_input`，主会话走 `loop.ts` 的 `[repeat]` 提示。
2. 真缺口不在"有没有检测器"，在**三处**：
   - **outcome-shaped 的没有**：现有可能抓的都是「同一个动作又做了一次」，没有一条抓「同一个**结论**又红了一次、
     而中间什么都没改」。外部也没找到已发布的这种实现。
   - **precision 没人公布**：两家都只公布阈值（4×/3×/5×/10×/6 cycles），没有一家给 precision/recall。
     真实投诉两头都有 —— 一次重 grep 被判成环 ⇒ 警告**且 exit 1**（gemini-cli #19519）；
     一段每轮微变的 word-salad **反而没被判住**（#15877，用户原话"ate up a bunch of my tokens"）。
     ⇒ 本仓能做的差异化不是再造一只检测器，是**给自己的检测器配一个可跑的误报判据**。
   - **既有的"重复"读数是死的**：`tool-choice.ts` 的 `repeats/repeatOver` 与 `loop-eval.ts` 的
     `repeatedSameAction` 都算出来了，但**没有任何阈值/动作消费它们**（producer-only）。
3. A/B 交替（edit→revert→edit）本仓**完全没有**（外部只有 OpenHands 的 alternating ≥6 cycles）。

## 1. 外部证据（可复查）

| 事实 | 出处 |
|---|---|

| 未解决的尝试平均消耗 **>4×** 于成功尝试（"expensive failures"） | SWE-Effi（arXiv:2509.09853） |
| 压 100+ 轮的耐力和智能无关；模型死于 39–57 轮；**环境反馈越详细，通过率高约 12×** | StaminaBench（arXiv:2606.19613） |
| 规则型 loop-breaker 的实测净效果：浪费步 4.9%→2.8%（Gemini 3 Flash）、3.2%→2.1%（Sonnet 4.6）；**撤掉它成功率变化 ±1.4 / 7.8%** | VLAA-GUI（arXiv:2604.21375） |

## 2. 本地基线率（本仓自己的录制，可复跑）

`node --import tsx outputs/stagnation-detection-2026-09-23/measure-local-base-rate.mts`
只读物：`outputs/` 下 19 份 `.events.jsonl`（loop-eval / ga-strategy 的真实跑）。

| 项 | 读数 |
|---|---|
| 语料 | 19 跑：绿 16 / 红 2 / 无 verify 结论 1；工具调用数 min 5、median 10、max 44 |
| D1 同动作+同类错误 ×3 | 绿跑上 0 报（真实语料里根本没出现） |
| D2 同调用+同结果 ×4 | **绿跑上 2 报 ⇒ 经验误报率 13%**（都在 fanout 那条链上，合法地反复读同一处） |
| D3 A/B 交替 ≥3 来回 | 0 报（正负样本都没有 ⇒ 这条规则今天无法被证明无害） |
| D4 同一失败结论连红 ≥2 | 只在**那条红跑**上报（1/1），绿跑 0 报 ⇒ 唯一把红与绿分开的信号 |
| D5 连续 8 次调用无成功写入 | **绿跑上 5 报 ⇒ 误报率 31%**（探索期本来就不写；这条最像"合法"最不能用） |
| D6 连续 monologue ≥3 | 量不出来：录制里 assistant 全是 `assistant_delta` 流，**没有轮边界事件** |

⇒ 直接决定三件事：**R1（验证停滞）是唯一被本地语料证明"抓得住且不误伤"的信号**；
D5/D2 那两类"看重复就掐"的口径被明确挡在 escalate 之外；D6 需要先有轮边界事件才谈得上。

## 3. 那条被抓下来的归一化风险（本轮最有价值的一处）

真实红跑的两次 `verify_result` 输出长度是 **1,370 与 150**（第二次只剩结论行）：
- 按既有 `stuckObservationOf` 的「截前 200 字符逐字比」——**抓不住**（前缀就不同）。
- 于是第一版把路径也一并抹平，测例当场抓住反面：「修好 `a.test.ts` 又撞上 `b.test.ts`」签名相同 ⇒
  **把前进读成停滞**。⇒ 归一化只吃数字与长哈希（`0x…`、≥12 位 hex），**路径必须留着**。
  这条现在是门里的 NP3，两个方向各有一只反例。

## 4. 判据（落在哪、为什么不是别处）

| 判据 | 判什么 | 为什么必须判 |
|---|---|---|
| NP1 | fire 样本必须报、规则名必须对、证据必须指名 | 不报警等于没有；报了不指名，模型无从换路 |
| NP2 | **silent 样本一条都不许报**（≥3 条负样本，否则判据自身红） | 这就是外部没人公布的那个数；误伤有实测价（±1.4–7.8%） |
| NP3 | 归一化两头各有反例（无写要报 / 有写不报 / 换文件不报） | §3 那个坑的固化 |
| NP4 | 分级由测量决定：R1=escalate、action-shaped=directive、未测过的 R3=note | 免得有人顺手把没测过的规则提到"可以掐" |
| NP5 | 语料 sha256 与冻结表逐字一致 | 带标签语料就是判卷标准；`gym-check` A3 那只手只走 fixtures/gym |

语料 7 份：4 份**真实录制**（`real-*`）+ 3 份造出来的对照（真实语料没覆盖的形状：有写的抑制、换文件的前进、往返抖动）。
标签是判据的一部分，故一并冻结。

## 5. 明确不做与留尾

- **不做**：不让本模块自己终止会话。终止权留在既有 `maxVerify`（默认 3）与 `maxSteps`（默认 50）手上；
  外部证据说得很清楚——检测器误伤的直接代价是成功率，而"跑不完"已有两道硬闸。
- **未接**：`no-progress` 还没有消费者（`loop.ts` / `orchestrator.ts` 都在另一会话的在飞改动集里；
  且 `loop.ts` 消费 `detectStuck` 时用的是三元式 `verdict.rule === "same_action_error_x3" ? ... : ...`，
  新增规则值会**落进 else 分支拿到错误的措辞** ⇒ 必须连那只三元式一起改，不能今天动）。
  今天交出去的是判据与语料，接线是下一格。
- **producer-only 的两条旧读数**（`tool-choice` 的 `repeats`、`loop-eval` 的 `repeatedSameAction`）没并进来：
  它们的形状与 R1 不同（action-shaped），并入会掩盖"谁消费它"这个问题。登记待办，不悄悄留着。
- **D6 需要轮边界事件**：录制里 assistant 只有 delta ⇒ 「连续 3 段独白」这条规则今天不可判。
  要做得先加事件，而 `src/events/index.ts` 在飞。
- **gym 里 stall 不可评分**：`expect.maxTurns` 只在 `gym-check` B1c 被断言，`scoreCase` 不读它 ⇒
  一条"跑了 30 轮放弃"的跑照样记 1 分。这是把误报率从"一次性脚本"升级为"常驻回归"的前置条件，另立一格。

## 6. 失效条件

- `gym/score.ts:scoreCase` 开始读 `expect.maxTurns` ⇒ §5 最后一条作废。
- `loop.ts` 里出现第三条规则分支（不再是二元三元式）且 `no-progress` 有了消费者 ⇒ 「未接」作废。
- 出现 ≥10 轮的冻结 case 且带 stuck/legit 标签 ⇒ NP2 的语料面应从 fixtures 迁到 gym，本门的语料降为冒烟。

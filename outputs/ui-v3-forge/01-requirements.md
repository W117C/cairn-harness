# Forge 桌面端 Agent 应用 UI 结构化优化 · 需求摘要（Phase 1）

> 作者：需求发现分析师 许明需 · 事实来源：`00-recon-brief.md`（实测基线）+ `src/renderer/index.html` / `app.js` 抽查
> 口径：本文所有「现状」陈述均标注简报章节或具体文件行号，**不含虚构功能**。需求编号（CONV/TASK/HIST/RESP）供 Phase 4 审查与主理人验收直接引用。

---

## 结论先行（TL;DR）

- **本轮本质是「结构化补全」而非「重做」**：Forge 的对话底子好（消息流/think/diff/plan 卡齐全），**真正的结构性缺口集中在两处**——① 任务执行没有独立视图（编排被压在 340px 右抽屉里与 8 个面板争宽，运行态被放在侧栏底部视线边缘）；② 历史只有「会话维度」，缺「运行批次（run）维度」回溯与检索。
- **落地对象是 vanilla 层**（`index.html` 内联 CSS + `app.js` 模板字符串），不是 React 版（简报 §2 已证 React 版未接线，构建产物中 `react` 出现 0 次）。两份历史提案按 React 版写，**只可参考思路、不可直接采信**。
- **三条不可动底线**：延续 oklch 中性灰阶 + 单一强调色（`--accent oklch(55% 0.18 255)`，`index.html:26`）；不重命名任何 `data-*` 钩子（panels-check 依赖）；既有无障碍资产（12 处 `prefers-reduced-motion`、`sr-only`、aria、28×28 点击区）不得回退。
- **响应式是硬缺口**：现网只有 1 个断点 `@media (max-width:920px)`（`index.html:1171`），1280–1599 与 920–1279 之间零适配，且未设 `minWidth/minHeight`（简报 §5）。
- **待澄清项 3 条均已给默认答案**（§5），主理人可带默认值直接推进，不阻塞。

## 1. 需求五要素

| 维度 | 结论 | 依据 |
|---|---|---|
| **场景 Surface** | 桌面端 Agent 工作台：Electron 单窗口 SPA（无路由，「页面」= 侧栏导航 + 右板组合）。窗口最小 960×600，主力档 1280×800 起，需覆盖 1024/1280/1600 三档宽度 | 简报 §1、§3、§5；`index.html:1171` 单断点 |
| **受众 Audience** | 长时间用 Agent 做真实代码任务的开发者：**信息密度中高、耐受专业术语**、以键盘为主、多任务并行（worker/编排）、需要可回溯的产出证据（diff/verify）。非首次使用者优先，但空态仍需引导 | 简报 §4；用户原话「清晰的操作界面」「信息层级清晰」 |
| **调性 Tone** | **延续现有中性灰阶工程感**（oklch 灰阶 + Geist + 单一强调色，克制耐看）。信息层级靠**灰度与字重**而非色相；语义色只出现在功能位。**不引毛玻璃/渐变** | 简报 §0、§6.2；`index.html:26-28,58-60` |
| **品牌上下文 Brand Context** | **沿用现有 Forge 令牌，不另立品牌**。新增语义色须给 dark/light 双主题值并满足 WCAG AA（正文 >7:1，次级 >4.5:1） | 简报 §6.2；`index.html:26/58` 双主题 |
| **规模 Scale** | 单窗口多视图：**对话（Conversation）· 任务执行（Task/Execution）· 历史（History）· 设置** 四类视图；右抽屉现有 11 个面板标签（approvals/token/git/memory/plugins/agents/schedule/files/browser/review/terminal）。需响应式三档 + 交互状态（流式/审批/运行四态） | 简报 §3、§4.2；`app.js:684-689` VIEW_META |

**推荐方向（供 Phase 2/3 输入）**
- 建议设计系统类型：**延续型灰阶工程系统**——在现有令牌上增量补「语义状态色（运行/等待/卡死/失败四态）+ 状态栏/任务视图的新容器规范」，不引入新组件库。
- 建议原型模板：**SaaS 工作台 + 仪表盘混合**（三栏 shell + 可提升为一级视图的任务执行面板 + 历史主从视图）。
- 特别注意事项：所有新视图必须能落到 `index.html` 内联 CSS + `app.js` 模板字符串；`data-*` 钩子名冻结。

## 2. 三大模块功能需求清单

> 每条 = 「要什么（目标）｜现状有什么（实测）｜缺口在哪｜优化后应达到什么」。现状均引简报或文件行号。

### 2.1 对话窗口（Conversation）

**目标**：在已有高质量消息流之上，补齐「长对话的可控感」——流式可中断/可排队、长对话可导航、卡片状态可视化。

| 编号 | 要什么 | 现状（实测） | 缺口 | 优化后应达到 |
|---|---|---|---|---|
| **CONV-1** | 消息流（用户/助手气泡 + markdown 文本） | 已有：气泡 + `pre-wrap` 文本，`streamInner` 渲染（`app.js:882-913`） | 无 | 保持；气泡最大宽 ≤85%，diff/表格卡片横向 `overflow-x-auto`（简报 §4.1） |
| **CONV-2** | 流式状态可见反馈 | 已有：`data-stream` 标记运行中（`app.js:1072`）、`stream-caret` 闪烁光标（`index.html:658`） | **流式期间无排队发送 / 中断恢复的可见反馈**（简报 §4.1） | 流式中输入区保持可输入并可「排队发送」（显示待发队列条数）；提供「停止/中断」钮；中断后消息保留可见「已中断」态并可「继续」 |
| **CONV-3** | think 折叠块 | 已有：`think-head` + 耗时秒数 + `aria-expanded`（`app.js:1087-1096`，`index.html:521`） | 无进度语义（纯文字「已深度思考 Ns」） | 折叠头增加状态语义（思考中=脉冲/完成=静态），动效遵循 `prefers-reduced-motion` 降级为静态 |
| **CONV-4** | 卡片族（plan/diff/tool/approval/verify/report 等） | 已有：plan 卡（`2/4 已完成` 步骤态）、diff 卡（token 着色）、工具行、审批卡（简报 §4.1） | **卡片状态靠文字，无进度可视化**（简报 §4.1）；无统一卡片骨架 | 统一卡片骨架（头=图标+标题+时间+状态位，体=内容，脚=操作区）；plan 卡增加可视化进度条/步骤点 |
| **CONV-5** | 输入区（composer） | 已有：`composer-box` + 内联发送钮（`index.html:689,703`）；上下文芯片 `ctx-pop`（简报 §3） | 无附件/引用文件入口的明确规范；发送钮无「运行中→停止」态切换 | 输入区 1–8 行自适应；Enter 发送 / Shift+Enter 换行；发送钮运行中变停止钮；左侧 `+` 附件/引用入口 |
| **CONV-6** | 消息级操作 | 已有：复制/撤回 + 耗时/tokens 元信息（`app.js:929-935`，`index.html:536-551`） | 无「跳转到该轮/引用该消息」 | 保留复制/撤回；hover 操作区补「引用」入口（回填到输入区） |
| **CONV-7** | 长对话导航 | 已有：`stream.scrollTop` 自动滚底（`app.js:895-896`） | **无消息级导航：回到底部浮钮、跳转到某轮、按卡片类型过滤**（简报 §4.1） | 上滚时出现「回到底部」浮钮；提供「按轮次/按卡片类型（diff/plan/审批）」的快速定位入口 |

### 2.2 任务执行面板（Task / Execution）—— 本轮最大结构性缺口

**目标**：把编排与运行态从 340px 右抽屉的「一格标签」提升为**可读、可控、可回溯**的任务执行视图。

| 编号 | 要什么 | 现状（实测） | 缺口 | 优化后应达到 |
|---|---|---|---|---|
| **TASK-1** | 任务列表 | 部分：`agents` 面板有 worker 卡列 + 依赖链简图 + 合并控制塔（简报 §4.2，`app.js:684-689`） | 无独立任务列表视图；worker 卡被压在右抽屉与 8 面板争宽 | 提供独立「任务执行」视图，含任务列表（名称/状态/所属会话/时间），可在 ≥1280 宽度下从右抽屉提升为一级视图 |
| **TASK-2** | 运行中任务的状态与阶段 | 部分：状态被放在**侧栏底部**（沙箱/事件数/tokens，简报 §4.2） | **运行中无全局进度/阶段指示**；状态处于视线边缘 | 提供全局运行状态指示（顶栏状态点或状态栏），含当前阶段（如 规划→执行→验证→合并）与进度；运行态不遮挡主内容区 |
| **TASK-3** | worker / 子任务与依赖 | 已有：worker 卡列 + 依赖链简图（简报 §4.2） | 无节点级事件流回溯；依赖图不可交互下钻 | 依赖链可视化：节点=worker（名称/状态点/最近事件一行），边=依赖；点击节点滑出该 worker 事件流 |
| **TASK-4** | 审批待办 | 已有：审批卡 + `data-approval-badge`（简报 §4.2） | **审批到达的全局提示弱**（无 Dock badge / 顶栏状态点） | 审批到达时全局提示（顶栏状态点转黄脉冲 + Dock badge）；审批聚合面板常驻可达 |
| **TASK-5** | 产出回溯（diff / verify / 报告） | 部分：diff 卡、verify 卡、合并控制塔（简报 §4.1-4.2） | **无运行批次维度的产出汇总**，一次任务的 worker 产出/verify 结果/diff 汇总无法集中回溯 | 按 run 聚合产出：diff 汇总、verify 结果、报告集中一处可回溯（与 HIST-2 联动） |
| **TASK-6** | 卡死 / 崩溃恢复 | 内核已有卡死恢复能力（简报 §1） | UI 无「卡死/恢复中」状态呈现 | 运行四态统一色纪律：运行=绿脉冲、等待=灰、卡死=黄、失败=红（不新增色相，暗/亮双主题 AA）；恢复动作可触发并有反馈 |

### 2.3 历史记录管理（History）

**目标**：从「只有会话维度」扩展为「会话历史 + 运行历史」双维度，支持检索、筛选、归档回收、时间轴。

| 编号 | 要什么 | 现状（实测） | 缺口 | 优化后应达到 |
|---|---|---|---|---|
| **HIST-1** | 会话历史 | 已有：`pinSession`/`archiveSession`/`unarchiveSession`/`deleteArchived`/`deleteSession`/`startRename`/`toggleFolder` + 分组（today/yesterday/week/earlier）+ 文件夹折叠（`app.js:250-308`；简报 §4.3） | 仅会话标题搜索 | 保留现有全部会话操作与分组；分组/文件夹/置顶行为不回退 |
| **HIST-2** | 运行历史（按 run/批次） | **无**（简报 §4.3） | 无 run 维度历史：worker 产出、verify 结果、diff 汇总无法回溯 | 新增「运行历史」视图：按 run/批次列出，每条可展开查看 worker 产出、verify 结果、diff 汇总 |
| **HIST-3** | 检索 | 已有：仅会话**标题**搜索（简报 §4.3） | **无正文/工具/文件级检索** | 检索扩展至正文/工具名/文件名范围，支持在会话历史与运行历史中统一检索 |
| **HIST-4** | 筛选 | 无 | **无按状态筛选（失败/被拒/被中断）** | 提供状态筛选：成功/失败/被拒/被中断/进行中 |
| **HIST-5** | 归档与回收 | 部分：已有归档 + `deleteArchived`（简报 §4.3，`app.js:280`） | 删除无回收态/撤销 | 危险删除先进回收态（可撤销），归档与回收分区清晰 |
| **HIST-6** | 时间轴 | 无 | 无时间轴视图 | 提供时间轴视图（会话或 run 沿时间排列，可切换粒度） |

## 3. 验收口径（可判定，供 Phase 4 与主理人验收）

> 判定方式统一为：`pnpm panels-check`（CDP 探针）+ 960/1024/1280/1600 四档窗口截图比对 + 人工目检（dark/light 双主题）。

### 3.1 通用验收（全部需求适用）

- **G-1 落地性**：方案可在 `index.html` 内联 CSS + `app.js` 模板字符串实现，不依赖未接线的 React 组件树；若某处建议启用 React 版，须单列「接线成本与迁移路径」。
- **G-2 钩子不破**：`data-panel="sidebar"`（`data-min/max/def` 180/420/264）、`data-panel="drawer"`（240/640/340）、`data-m1e-item`、`data-panel-toggle`、`data-m1e-settings-open`、`data-approval-badge`、`data-stream`、`data-od-id` 等现有 `data-*` 属性名**零重命名**；`pnpm panels-check` 全绿。
- **G-3 门禁全绿**：`pnpm gates`（26 道）通过。
- **G-4 双主题 AA**：所有新增/改动颜色在 light/dark 下满足正文 >7:1、次级 >4.5:1。
- **G-5 无障碍不回退**：`prefers-reduced-motion` 降级、`sr-only`、`aria-*`、最小点击区 28×28 全部保留；新增交互可 Tab 可达。
- **G-6 无装饰回归**：无毛玻璃/渐变；无新增字体/色相（除 TASK-6 允许的四态语义色）。

## 4. 明确不做的范围（Out of Scope）

与简报 §6 硬约束一致：

1. **不换字体 / 色板 / 组件库**：延续 Geist + oklch 灰阶 + 单一强调色；不引入 shadcn 之外的组件库。
2. **不引毛玻璃 / 渐变**：与灰阶工程感定位不符（简报 §6.2）。
3. **不重命名现有 `data-*` 钩子**：`panels-check` CDP 探针依赖属性名（简报 §6.3）。
4. **不改判卷文件**：`fixtures/todo-app/tests/**`、`fixtures/mock/**` 的 sha256 已冻结（简报 §6.5）。
5. **不把未接线的 React 版当现状**：`conversation.tsx`/`panels/registry.tsx`/`cards/*.tsx`/`components/ui/*` 均为 dead code，不作为设计基线（简报 §2）。
6. **不引路由 / 多窗口**：单窗口 SPA + Sheet/Dialog 覆盖全部页面诉求。
7. **不回退无障碍资产**：12 处 `prefers-reduced-motion`、`sr-only`、`aria-*`、28×28 点击区必须保留（简报 §6.4）。
8. **不新增色相（TASK-6 除外）**：除运行四态语义色（运行/等待/卡死/失败）外不引入新色相；新增语义色须双主题 AA。

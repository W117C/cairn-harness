## 二、这批抓到并修掉的一个真缺陷

**模型常量与真实计算样式漂移。** 判据里的两个主题常量（`LIGHT_SPEC` / `DARK_SPEC`）写的是
vendored token 的字面值 `#141413` / `#FAF9F5`，而真机算出来的 body 文字色是 `rgb(11 11 11)` /
`rgb(240 239 236)` —— 差 9–10/通道。后果：模型按旧常量算出 45%/58% 的地板，
运行时按真实样式算出 43%/61%，两边各说各话；用旧常量去判「运行时地板」会误报破线
（实测 4.336:1 < 4.5，看起来像产品坏了，其实坏的是常量）。

修法：常量改成**真机读数**，并新增一条漂移守卫——「常量 vs 真机真值差 ≤2/通道」，
现在 `drift: 0`。这也是本批新增的两条检查（暗色、亮色各一条）的意义：
**常量漂移会被判据咬住，不再靠人记得去手工对表**。

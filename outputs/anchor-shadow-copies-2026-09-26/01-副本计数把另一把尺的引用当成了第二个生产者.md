## 一、缺陷的形状：不是文案有两处，是**同一行被两把尺指着**

变异锚点按定义要**逐字引用被锚那一行**——`apply: (s) => s.replace('if (spentUsd === null) return "花费价格未知 ⇒ 美元闸本次不生效…`
（`scripts/mutate-verify.mjs:4072`）。所以任何取自那一行的针脚，在生产侧永远"至少有两份字面量"：
一份是生产者自己写的，一份是锚点抄的。旧 `copyCount` 把这两份同样计入 ⇒ 那一格**从测试侧无解**：
换成整句、换成别名都行不通，第二份副本不走。这不是文案的毛病，是**副本计数不认得引用**。

## 二、机制：用内容谓词认表，不用文件名清单

```ts
const ANCHOR_MARKER = "expectFail:";
const ANCHOR_TABLE_MIN = 50;
export function isAnchorTable(text: string): number   // 命中条数；不足阈值算 0
```

登记表改名、搬目录、换执行器都还认得（规则 122：判据挂一种写法＝换写法即绕过；挂文件名同理）。
`copyCount(chunks, needle, anchors, realProducers)`：

- 若这段文字除了登记表还**有别的生产者** ⇒ 登记表那份不计（`anchors` 有、`realProducers` 没有）；
- 若**唯一**副本就在登记表里 ⇒ 照旧计入（那条断言收的是登记表自己的文案，读成 0 就是抹掉生产者）；
- 若这条断言本来就指着那张表 ⇒ 它的副本照算。判据是 test 文件里点没点名该表（`realProducers` 由调用方按 test 文本算）。
  这一支是**必需的**：`tests/mutate-verify-gates.test.ts` 断言的 `.why` 就产自那张表——
  实测它 4 格（「判卷」34、「未跟踪」6×3）纹丝不动，正是这条的作用。

## 三、免计的三格与那格"没被免掉"的反例

```
· 免计 tests/autonomy.test.ts:190 .reason「断路器」原 2 处 → 1 处
· 免计 tests/goal-stop-decision.test.ts:112 .note「美元闸本次不生效」原 2 处 → 1 处
· 免计 tests/shell-bypass-composition.test.ts:333 .reason「setsid」原 2 处 → 1 处
```

三格里**两格的第二份确实只在登记表里**，免计后各留下一个真生产者：

```
断路器      → src/permissions/autonomy.ts#evaluate          （登记表那份是引用）
美元闸本次不生效 → src/agent/goal.ts#budgetLine              （同上）
```

**第三格不是这么回事，要写清楚**：`setsid` 免计后剩下的那一份在
`scripts/lib/shell-bypass-cases.ts:132`——那是一行**用例清单** `"setsid git push --force"`，
与测试自己喂进 `evaluate()` 的命令同一串；生产侧（`rules.ts` / `command-shape.ts`）**只在注释与正则里**
出现过这个词，卡面上那句"首词是 setsid"是把输入**插值**出来的。
⇒ 这一条断言真正的态是 `echo-caller-text`（验的是回显），而不是"顶包已清"。
它现在被算成免计，是**两处错位互相抵消**的结果：锚点引用被正确地免计 ＋ 用例清单被错认成生产者
（`echo` 的条件要求"生产侧一段都对不上"，而清单里那段恰好"对得上"）。
⇒ 所以 **27 这个数比应有的低 1 格**；纠正它的办法不是把 `echo` 提到 `verbatim` 之前
（那会把"测试复用同一串字"的正常文案钉也一起判成回显＝往危险方向缩），而是给**输入清单**也做一条内容谓词——
见 §五 与 #21 的第二半。

**反例同样重要**：`tests/net.test.ts:53`「停滞超时」从 3 降到 **2**，仍留在单上——
它除了锚点引用，还有两份**真**生产者字面量：`src/main/updater.ts#stallMessage` 与 `src/net.ts#arm`。
⇒ 这条排除不是"把清单缩短的手段"：它只解释掉引用，解释不掉两个生产者。

## 四、排除面自己必须有名字（两处观测者）

- **每格都点名**：报告里 `rawCopies` 与 `copies` 并排印出（`原 2 处 → 1 处`），
  用例钉住"每格免计后仍 `copies ≥ 1` 且 `rawCopies > copies`"——排除的是引用，不是被引用的那一行。
- **认不出表就红**：`anchorTables.length === 0` ⇒ `❌ 一张登记表都没认出 ⇒ 内容谓词失效…`，退出码 1。

## 五、残留的两条（写在这里，不留成暗账）

⑴ **输入清单被认成生产者**（本轮已现形，见 §三 的 `setsid`）：`scripts/lib/shell-bypass-cases.ts`
这种"命令样本表"里的字面量是**喂给被测函数的输入**，不是任何字段的出处。
它和登记表影子是**同一族**（都不是生产者），但内容谓词不同：登记表认 `expectFail:` 成批，
输入清单要认"导出的字符串数组常量 ＋ 被 test 引用"。
⇒ 补上它以后 `setsid` 那一格会归进 `echo-caller-text`，而 **27 这个数比应有的低 1 格**这件事才闭合。
在补上之前，水位读数带着这条已知错位——所以 §三 把它点名，而不是让它躲在数字里。

⑵ **两支锚点分别引用两行不同代码、而那两行写着同一句话**：本面会把两份引用一起免计 ⇒
剩下的"1 份生产者"其实可能是 2 个生产者。今天未观测到这种形状。
复现条件可机检：同一 `(test 文件, 针脚)` 满足 `rawCopies − copies ≥ 2` 且 `copies === 1`。
收这条的方向不是加启发式，而是**解析 `apply:` 的替换目标**——引用指向哪一行是登记事实，不用猜。
